**Milestone goal:** Touch-first sale-screen components in the ferro-json-ui builtin
catalog — tile grid, selection panel, numpad, quantity/filter primitives — at a tablet
interaction quality bar, derivable from a `ServiceDef` through the projection layer and
agent-authorable through the v16.5 MCP + design-lint boundary. Zero new dependencies; all
components are builtins (never plugins); the seven-intent vocabulary is unchanged.

**Scope decisions (2026-07-04):** form-state cart only (client CartRuntime later un-deferred
into Phase 256); FilterTabs (née CategoryNav) a standalone builtin; Grid `row_weights`
included; Numpad included; barcode keyboard-wedge deferred.

**Vocabulary decision (2026-07-05):** the builtin catalog uses domain-neutral, structural
nouns only (mirroring the seven structural intents); commerce naming is confined to sample
apps and docs. Pre-publish renames in Phase 255: `ProductTile`→`Tile` (breaking — migration
table entry), `ProductGrid`→`TileGrid`, `CartPanel`→`SelectionPanel`, `CategoryNav`→`FilterTabs`;
`data-product-*`→`data-filter-*`; lint ids `pos-*`→`register-*`. No consumer-specific props in
any `ferro-*` crate. The `Register` layout template name (POS-10) is retained as a structural term.

## v16.6 Requirements

### Components

- [x] **POS-01**: Bind an items data path to a `TileGrid` builtin → responsive, touch-first
  tile grid (Tile children via `$each`) with built-in client-side text search. Tiles are
  tap-to-add-only (one tap = one unit; quantity editing lives in the SelectionPanel).
- [x] **POS-02**: `ProductTile` gains additive props — `category`, `image_url`, `color`,
  `stock_badge` — serde-backward-compatible. *(Delivered 254 under the old name; renamed `Tile` in 255.)*
- [x] **POS-03**: A `FilterTabs` standalone builtin filters visible tiles by filter token
  client-side (show/hide), touch targets ≥44px.
- [x] **POS-04**: A `SelectionPanel` builtin renders the running selection as a live
  client-side view of the form state — lines appear as tiles are tapped, per-line
  QuantityStepper + remove, client-computed integer-cents total, EmptyState when empty, a
  confirm-action slot hosting the single confirm POST; pins and internally scrolls within
  `fill_viewport`.
- [x] **POS-05**: A `QuantityStepper` standalone builtin — reusable +/− numeric stepper on
  the Tile hidden-input contract.
- [x] **POS-06**: A `Numpad` builtin — custom tap-surface numeric keypad (≥56px keys)
  writing to a target field, never a native input (software keyboard never triggered).

### Touch Interaction Quality

- [x] **POS-07**: A shared POS touch foundation (`touch-action: manipulation`, `:active`
  press states on the motion tokens, tap-highlight reset, overscroll containment, min
  hit-target constants) centralized in `render/classes.rs`; every class a full literal
  (scanner/safelist-safe). *(Delivered 254 as `POS_*` constants; prefix neutralized in 255.)*
- [x] **POS-08**: POS forms double-submit protected — a `data-disable-on-submit` runtime
  guard plus the documented idempotency-key pattern on the `framework::write` idempotency hook.

### Layout

- [x] **POS-09**: `Grid` gains `row_weights` — asymmetric fill-row weighting, additive
  alongside the Phase 253 `spans` prop.

### Projection

- [x] **POS-10**: A `ServiceDef` renders a working sale screen via a `Register` layout
  template under the **Collect** intent (`emit_register_root` + `ElementBuilder.each()` +
  `fill_viewport`) — the seven-intent vocabulary is unchanged.

### Agent-Authoring Boundary

- [x] **POS-11**: POS design-lint rules ship (`register-fill-viewport`, `register-grid-fill`,
  `register-selection-present`, `fill-viewport-layout-unknown`) each with
  violating/conforming + data-bound fixtures. *(Delivered 254 under `pos-*` ids; renamed in 255.)*
- [x] **POS-12**: MCP + docs surface extended — `json_ui_catalog` entries/count,
  `generation_context` register composition guidance, `docs/src` updates.

### Release

- [x] **POS-13**: `/cassa` sample app flips to the new components (projection-derived
  Register), full CI-exact gate green, single crates.io publish closes the milestone.

## Future Requirements (deferred)

- **CartRuntime** — un-deferred into Phase 256 (tap-tile-adds-one, quantities edited in the
  SelectionPanel; form-state contract unchanged, no `data-cart-target` props hook).
- **Barcode keyboard-wedge input** — keystroke-timing scanner detection (deferred).
- **Layout-name-independent `ferro-fill` chain** — removes the dashboard-family selector
  dependency of `fill_viewport` (deferred; `fill-viewport-layout-unknown` lint mitigates).

## Out of Scope (v16.6)

- **Payment flow** (cash/card/split tender), **receipt rendering**, **shift/session close** —
  the sale screen only; a later milestone.
- **New intents** (`Register`/`Kiosk`) — the seven-intent vocabulary is frozen.
- **Plugin-registry placement** — all POS components are builtins.
- **Hardware integration** (cash drawers, printers, scanner SDKs).
