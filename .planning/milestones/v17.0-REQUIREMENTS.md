**Milestone goal:** Join the two halves of a live-rendering story ferro already carries —
`ferro-projection`'s per-key snapshot + delta broadcast and `ferro-json-ui`'s server-side
rendering — into a declarative `LiveFragment` element that binds a rendered fragment to a
projection key and re-renders in place on delta, server-authoritatively, with no WASM. Two
supporting ergonomics land alongside. Anchor spec:
`docs/superpowers/specs/2026-07-21-live-projection-surface-design.md`.

## v17.0 Requirements

- [x] **LIVE-01** (Phase 259) — Request-scoped `#[memoize]`: a `MemoStore` in request
  extensions plus a `#[memoize]` attribute (fan-out dedup + concurrent-call coalescing via a
  shared future), wired into the `ServiceDef → IntentGraph` render pass so N intents over one
  key issue a single underlying fetch. Request-scoped only (cross-request caching stays
  `ferro-cache`); complements `eager_loading`/`BatchLoad`, does not replace it.
- [x] **LIVE-02** (Phase 260) — **`LiveFragment` element** (the killer feature): a builtin
  JSON-UI element (`projection` + `key` + child template) that renders the current snapshot on
  first paint and re-renders in place on each delta, server-authoritatively; a small no-WASM
  client runtime opens the `ferro-broadcast` socket and swaps inner HTML only (no client state,
  no signal system). Exactly one binding pattern ships (per-key snapshot); list/collection
  reconciliation is deferred (spec non-goal).
- [x] **LIVE-03** (Phase 261) — `asset!("path")` macro: embed + content-type inference +
  `ferro-bundle` registration returning the content-hashed URL (stable across builds for
  unchanged bytes; unrecognized extensions pass through byte-identical). Opt-in
  `ferro assets fetch` subcommand for Iconify sets + Fontsource families, on the Rust toolchain
  alone (no node, no nasm), absent from a normal `cargo build`.
- [x] **LIVE-04** (Phase 262) — `LiveFragment` through the full lockstep checklist
  (`BUILTIN_TYPES` + dispatch + catalog spec + both count assertions + `ferro-mcp` mirror);
  `generation_context` guidance for `LiveFragment`, `#[memoize]`, and `asset!()`; `docs/src`
  sections with a usage example each; single operator-gated crates.io publish (version > 0.2.89).

## Architectural constraints

- No new crates — memoization in `framework` + `ferro-macros`; the live fragment in
  `ferro-json-ui` + `ferro-projection`; the asset macro in `ferro-macros` over
  `ferro-assets`/`ferro-bundle`.
- Rendering stays server-authoritative — the client runtime only opens a socket and swaps HTML.
- One per-key snapshot bound to one fragment; list reconciliation deferred.
- Single crates.io publish at Phase 262.
