# Milestone v9.0: Service Projections

**Status:** In Progress
**Phases:** 84-93
**Total Plans:** 25

## Overview

Introduce a three-layer architecture where services describe business capabilities and UI is generated from those descriptions: Model → ServiceDef → IntentGraph → Renderer → Output.

New `ferro-projections` workspace crate. Services are definitions/schemas — not runtime engines. They compose with existing Ferro primitives.

## Key Design Decisions

1. **Schema-only, not closures.** Guards are `"has_content"` (string), not `|o| o.content.is_some()`. Keeps ServiceDef serializable and introspectable.
2. **FieldMeaning drives rendering.** "This is money" tells the renderer more than "this is f64". Same Rust type, different presentation.
3. **Intent is medium-agnostic.** `Browse`, `Focus`, `Confirm` make sense in HTML, voice, spatial, game menus.
4. **IntentGraph is a directed graph with cycles.** Users can go back, jump sideways. Renderer presents current node + outgoing edges.
5. **Feature-flagged integration.** `framework` depends on `ferro-projections` behind a `projections` feature flag.
6. **Custom graph, not petgraph.** Small graphs (5-15 nodes) with state-dependent edge filtering. Own implementation keeps logic transparent.
