# Requirements — v16.2 ferro-inertia First-Load HTML Shell [ARCHIVED]

> **Archive note.** Reconstructed at milestone close (2026-08-12) from the ROADMAP
> inline phase detail and `238-VERIFICATION.md`. v16.2 is a single-phase milestone
> (Phase 238) that shipped before milestone-close discipline was applied; its
> requirements were tracked as five Success Criteria (SC), not REQ-IDs, and never lived

> milestone-scoped record of that requirement set.

**Milestone goal:** `ferro-inertia` owns the `X-Inertia` JSON contract (part 2 of
Inertia) but had no server-rendered first-load HTML document (part 1). Add the missing
shell so a Ferro + Inertia app can be opened cold in a browser and hydrated from the
backend, via content negotiation on a single handler.

**Reconcile finding:** the HTML-shell substrate already existed in
`ferro-inertia/src/response.rs` (content negotiation + dev/prod asset modes). The real
work was wiring and surfacing — the documented-but-missing `App::set_inertia_config` +
`InertiaConfig::from_env`, structured root-template fields, the same-origin/Vite-proxy
docs, and end-to-end tests. `ferro-inertia` stayed a zero-ferro-dep leaf crate.

**Source:** promoted from `backlog/2026-06-21-inertia-first-load-shell.md`; field-reported
by downstream consumer app `u` (its Phase 5 OQ-4 deferral).

## Requirements (Success Criteria — all met)

- [x] **SC-1**: A non-`X-Inertia` GET returns a full HTML document with
  `<div id="app" data-page="{…}">` matching the JSON-path page object.
- [x] **SC-2**: The same handler with `X-Inertia` headers still returns the JSON
  contract (content negotiation, single handler).
- [x] **SC-3**: Dev mode emits Vite client + entry module tags against `vite_dev_server`;
  prod mode emits hashed `<script>`/`<link>` tags from the Vite `manifest.json`.
- [x] **SC-4**: The root template (title, `<head>` extras, `#app` mount node) is
  configurable with a working default.
- [x] **SC-5**: Docs include the same-origin convention and a Vite `server.proxy` recipe
  for the split-port dev flow (so the session cookie flows).
