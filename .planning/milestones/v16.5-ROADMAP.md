# Milestone v16.5: JSON-UI Design System

**Status:** ✅ SHIPPED 2026-07-04 (published 0.2.86)
**Phases:** 250–253
**Total Plans:** 18 (3 + 4 + 6 + 5)
**Consumer-paired with:** gestiscilo Phase 232 (gated on the Phase 253 publish)

## Overview

Complete the design system above the token layer. ferro-json-ui already had semantic
tokens, semantic-class emission, and themes; this milestone added the missing upper half —
density/motion/focus-ring tokens with opinionated defaults, a canonical variant vocabulary
across all 47 components, and composition patterns codified as machine-readable,
intent-keyed lint rules. The defining capability: **the design system is enforced at the
agent-authoring boundary** — an agent reads the system through ferro-mcp
(`generation_context`, `json_ui_catalog`), authors a spec, and `design_lint` validates
conformance before human review. Pattern archetypes are the seven projection intents; the
design system extends the core abstraction rather than adding a parallel vocabulary.

**Anchor spec:** `docs/superpowers/specs/2026-07-03-json-ui-design-system-design.md`.

**Architectural constraints:** no new crate (pattern rules in ferro-json-ui, tokens in
ferro-theme); lint is diagnostics-only (rendering never rejects on design grounds; the only
failure mode is the opt-in CLI `--deny`); every valid v1 theme remains valid in v2 (new
tokens ship with defaults); single publish at the end (Phase 253).

## Phases

### Phase 250: Token vocabulary v2 + default theme refresh

**Goal:** Grow the fixed vocabulary from 23 → 30 slots — one-knob density (`--spacing`),
frequency-tiered motion (`--motion-duration-fast/base/slow`, `--motion-ease`), a uniform
focus ring (`--color-ring`), a display-font slot (`--font-display`) — every new slot with a
default so existing v1 themes stay valid; refresh the default theme to the documented design
language. **Requirements:** DS-01, DS-02. **Plans:** 3/3.

- [x] 250-01: token constants v2 + Tailwind utility bridge + `ferro-base.css` regen
- [x] 250-02: `default.css` design-language refresh + `make:theme` scaffold + drift guards
- [x] 250-03: `themes.md` v2 docs + type-scaling recipe + visual sign-off

### Phase 251: Component variant discipline + interactive-state pass

**Goal:** One variant vocabulary across the whole component set — normalize all 47 builtin
components to canonical `variant` (primary/secondary/outline/ghost/destructive), `tone`
(neutral/success/warning/destructive), `size` (sm/md/lg), and bring every interactive
component to the quality bar: hover, `focus-visible` ring, disabled, frequency-tiered
motion. **Requirements:** DS-03, DS-04. **Plans:** 4/4.

- [x] 251-01: enum consolidation (`Variant`/`Tone`/`Size`/`CardAppearance`), compiler-driven rename ripple
- [x] 251-02: interactive-state + motion pass (shared class constants, `ring-ring`/duration tokens, disabled uniformity, JS/SSR lockstep)
- [x] 251-03: enforcement + agent surface (schema-walking drift guard, catalog prose, ferro-mcp vocabulary)
- [x] 251-04: migration docs + `ferro-base.css` regen + full gate + Chrome-MCP visual pass

### Phase 252: Design module + lint + CLI

**Goal:** Codify composition patterns as a machine-readable, testable rule set — `Spec`
gains an optional `design` field (`intent` + `allow`), a pure `design::lint(&Spec)` engine
implements the intent-keyed rules, and `ferro design:lint` surfaces findings from the CLI.
**Requirements:** DS-05, DS-06. **Plans:** 6/6.

- [x] 252-01: foundation — `Spec.design`, `Finding`/`Severity`/`DesignRule` types, pure `lint()` engine
- [x] 252-02: single-home catalog extension for element-level `action.confirm.variant`
- [x] 252-03: rules batch A (page-header, prefer-data-table, list-empty-state, row-actions-grouped, breadcrumb-on-subpages)
- [x] 252-04: rules batch B (process-kanban, card-actions-in-menu, create-separate-page, form-default-values, destructive-confirmation)
- [x] 252-05: CLI `ferro design:lint [path] [--json] [--deny]`
- [x] 252-06: app views declare `design.intent` + PageHeader, lint-clean gate, CI-exact gate + docs build

**Verification:** 6/6 programmatic truths verified; CLI output-formatting UAT passed

## Milestone Summary

**Key Decisions:**

- The design system is enforced at the **agent-authoring boundary** (read via ferro-mcp,
  validated by `design_lint`) — not just documented for humans.
- Pattern archetypes ARE the seven projection intents — no parallel page-type vocabulary.
- No new crate: rules in ferro-json-ui, tokens in ferro-theme. Lint is diagnostics-only.
- Token vocabulary grew 23 → 30 with defaults, so every v1 theme stays valid unchanged.

**Technical Debt / Deferred:** none blocking. Consumer adoption (gestiscilo Phase 232) is a
separate repo, gated on the Phase 253 publish.
