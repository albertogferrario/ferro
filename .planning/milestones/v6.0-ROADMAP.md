# Milestone v6.0: ferro-lang — Localization

**Status:** ✅ SHIPPED 2026-02-13
**Phases:** 58-66
**Total Plans:** 11

## Overview

Add localization infrastructure to Ferro via a new `ferro-lang` crate. Provides JSON-based translations, per-request locale detection, validation message localization, and CLI scaffolding. Follows existing crate patterns (ferro-cache, ferro-events).

## Milestone Summary

**Key Decisions:**

| Decision | Rationale |
|----------|-----------|
| Separate ferro-lang crate | Follows existing pattern (ferro-cache, ferro-events), keeps translation engine decoupled |
| JSON translation files | Simple, portable, agent-friendly format |
| OnceLock validation bridge | Zero coupling: framework validation has no dependency on ferro-lang |
| task_local! for locale | Async-safe per-request context, matches session middleware pattern |
| `:param` interpolation | Laravel convention, simple to implement and use |
| `\|` plural separator | Compact format for 2-3 forms in single string |
| Pre-merge fallback at load time | O(1) runtime lookup, no fallback chain per request |
| fn pointer over Box<dyn Fn> | No state capture needed for TranslatorFn, simpler type |
| init() after config_fn() | User can override LangConfig before translator loads |
| Locale validation: 2-letter base + subtags | Locale codes differ from Rust identifiers |
| Coverage report vs fallback locale | Single reference locale for missing key detection |

**Issues Resolved:**
- All 22 validation rules now support localized error messages
- Per-request locale detection with Accept-Language and query param override
- CLI scaffolding for new locales with template files
- MCP introspection for localization status and translation coverage

None.
