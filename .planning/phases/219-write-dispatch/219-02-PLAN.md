## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP agent → handle_tools_call → app executor | Untrusted agent input; tenant_id from authenticated principal (current_tenant), never the payload |
| app executor → Order::find_for_tenant → DB | BOLA boundary; a record not owned by the calling tenant returns None → denial before any mutation |
| guard evaluator → live DB | The is_manager check reads live state, not the 218 visibility cache |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-219-01 | Elevation of Privilege (cross-tenant write / BOLA) | app executor find-then-mutate (Task 2) | mitigate | The executor loads the target via `Order::find_for_tenant(id, tenant_id)`; `None` (record not owned by the calling tenant) → `Err`, denial before mutation. tenant_id is the authenticated principal, never the payload. Test `cross_tenant_write_denied` (Task 3) asserts isError:true AND tenant B's record unmutated (SC#2). |
| T-219-02 | Elevation of Privilege (guard bypass) | guard evaluator + dispatch_write (Plan 01) | mitigate | The app guard evaluator's `is_manager` reads live DB; dispatch_write (Plan 01) re-evaluates it at call time independent of tools/list. The unguarded submit/ship vs guarded approve fixtures exercise both paths. |
| T-219-03 | Tampering (retry double-write) | app path through dispatch_write idempotency (Task 3) | mitigate | The `idempotent_write_e2e` fixture drives two identical app-path calls with one idempotency_key and asserts a single DB mutation (SC#3). |
| Info Disclosure (prompt injection) | structured results (Plan 01) | mitigate | App results flow through the framework's `CallToolResult::structured`/`write_tool_error_result` typed envelopes — no raw record text echoed as instructions (PITFALLS §3, SC#5). |
