regenerated `ferro-base.css`.

Phase-254 consumer (they land in Phase 256 renderers). An unused `pub(crate) const`

`render::classes` a `pub mod` and the POS constants `pub const`, giving a fully-public
`render::classes::POS_*` path that is dead_code-exempt.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `ProductTileProps.categories` → HTML attribute | Category strings (developer- or data-sourced) are written into the `data-product-categories` HTML attribute at render time. This is the one boundary where untrusted text reaches emitted markup this phase. |
| crate source literals → Tailwind CSS generation | The `@source` scanner reads Rust string literals to emit CSS; a dynamic (non-literal) class would silently not generate. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-254-03 | Tampering (HTML/attribute injection, XSS) | `render_product_tile` data-product-categories emission | mitigate | Join then `html_escape(&props.categories.join(" "))` before interpolation; escaping asserted by the `product_tile_escapes_categories` test. |
| T-254-04 | Denial of service (silent CSS non-generation) | POS constants / pos-tap-highlight utility | mitigate | Every constant is a complete class literal; `pos-tap-highlight` is a real `@utility` (Path B, not an arbitrary property); Task 3 greps the regenerated CSS to prove the utilities exist. |
| T-254-05 | Repudiation / Information disclosure | classes module made `pub` | accept | Exposes only class-string constants and their module path; no logic, no secrets. Pre-1.0, breaking API changes are acceptable (no semver guard test exists). |
</threat_model>
