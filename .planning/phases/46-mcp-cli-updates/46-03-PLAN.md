<task type="auto">
  <name>Task 1: Add v4.0 feature counts to application_info</name>
  <files>ferro-mcp/src/tools/application_info.rs</files>
  <action>
Enhance the ApplicationInfo struct and execute() function to include counts of v4.0 features.

Add a new `features` field to ApplicationInfo (or extend the existing struct):
```rust
pub struct ApplicationInfo {
    // ... existing fields ...
    pub features: FeatureSummary,
}

pub struct FeatureSummary {
    pub api_resources: usize,    // count of #[derive(ApiResource)] structs
    pub policies: usize,         // count of Policy<T> implementations
    pub rate_limiters: usize,    // count of RateLimiter::define() calls
    pub broadcast_channels: usize, // count of broadcaster.send() calls
    pub events: usize,           // count of events (already available via list_events)
    pub jobs: usize,             // count of jobs (already available via list_jobs)
}
```

In execute(), call the new tool modules to get counts:
- `tools::list_resources::execute(project_root)` → count resources
- `tools::list_policies::execute(project_root)` → count policies
- `tools::list_rate_limiters::execute(project_root)` → count limiters
- `tools::list_broadcast_channels::execute(project_root)` → count channels

Use `.unwrap_or_default()` or `.ok().map(|r| r.len()).unwrap_or(0)` patterns so application_info never fails due to new tool failures.

This gives agents an immediate overview: "This project has 2 API resources, 1 policy, 1 rate limiter, 0 broadcast channels" — guiding them to call the relevant list_* tools.
