<task type="auto">
  <name>Task 1: Create list_resources and list_policies MCP tools</name>
  <files>ferro-mcp/src/tools/list_resources.rs, ferro-mcp/src/tools/list_policies.rs</files>
  <action>
Create two new MCP tool modules following the established pattern (see list_events.rs, list_jobs.rs).

**list_resources.rs:**
- Scan `src/controllers/` and `src/resources/` (if exists) for structs with `#[derive(ApiResource)]` or that implement `Resource` trait
- For each resource found, extract: struct name, source file path, fields (from the struct definition), any `#[skip]` or `#[rename]` attributes on fields
- Parse the source files using string matching (consistent with how list_events.rs and list_models.rs work — no syn/proc-macro parsing)
- Return `ResourcesInfo { resources: Vec<ResourceInfo> }` where `ResourceInfo` has: name, path, field_count, fields (name + type + attributes like skip/rename)
- Search pattern: look for `#[derive(` containing `ApiResource` in all `.rs` files under `src/`
- Also check for `impl Resource for` patterns

**list_policies.rs:**
- Scan `src/policies/` (if exists) and all `.rs` files under `src/` for `impl Policy<` patterns
- For each policy found, extract: policy struct name, model it guards (from `Policy<ModelName>`), source file path, abilities (method names within the impl block)
- Return `PoliciesInfo { policies: Vec<PolicyInfo> }` where `PolicyInfo` has: name, model, path, abilities (list of method names)
- Search pattern: `impl Policy<` in all `.rs` files under `src/`

Both tools should handle the "no results found" case gracefully (return empty arrays, not errors).
Do NOT create introspection modules — keep the scanning logic directly in the tool files, consistent with list_jobs.rs which does its own file scanning.
  </action>
  <verify>cargo build -p ferro-mcp</verify>
  <done>Both tool modules compile and export execute() functions with correct return types</done>
</task>
