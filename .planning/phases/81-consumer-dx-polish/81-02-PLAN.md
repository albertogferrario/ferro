Add a `validate_args` function that checks tool arguments against the operation's `input_schema` before calling the HTTP client:

```rust
/// Validate tool arguments against the operation's input schema.
///
/// Checks required fields are present and basic type correctness.
/// Returns a list of validation errors, empty if valid.
fn validate_args(
    input_schema: &serde_json::Value,
    args: &serde_json::Map<String, serde_json::Value>,
) -> Vec<String> {
    let mut errors = Vec::new();

    // 1. Check required fields
    if let Some(required) = input_schema.get("required").and_then(|r| r.as_array()) {
        for field in required {
            if let Some(name) = field.as_str() {
                if !args.contains_key(name) {
                    errors.push(format!("missing required field: '{name}'"));
                }
            }
        }
    }

    // 2. Check type correctness for provided fields
    if let Some(properties) = input_schema.get("properties").and_then(|p| p.as_object()) {
        for (name, value) in args {
            if let Some(prop_schema) = properties.get(name) {
                if let Some(expected_type) = prop_schema.get("type").and_then(|t| t.as_str()) {
                    let type_ok = match expected_type {
                        "string" => value.is_string(),
                        "integer" => value.is_i64() || value.is_u64(),
                        "number" => value.is_number(),
                        "boolean" => value.is_boolean(),
                        "object" => value.is_object(),
                        "array" => value.is_array(),
                        _ => true, // unknown types pass through
                    };
                    if !type_ok {
                        errors.push(format!(
                            "field '{name}' expects type '{expected_type}', got {}",
                            json_type_name(value)
                        ));
                    }
                }
            }
        }
    }

    errors
}

/// Returns a human-readable type name for a JSON value.
fn json_type_name(value: &serde_json::Value) -> &'static str {
    match value {
        serde_json::Value::Null => "null",
        serde_json::Value::Bool(_) => "boolean",
        serde_json::Value::Number(_) => "number",
        serde_json::Value::String(_) => "string",
        serde_json::Value::Array(_) => "array",
        serde_json::Value::Object(_) => "object",
    }
}
```

Improve the error handling in `HttpClient::execute()` to produce categorized, actionable error messages.

In `http.rs`, modify the error handling:

1. **Request send errors** — categorize reqwest errors:
```rust
let response = request.send().await.map_err(|e| {
    if e.is_connect() {
        Error::HttpClient(format!(
            "cannot connect to API at {url}. Is the server running? ({})",
            e
        ))
    } else if e.is_timeout() {
        Error::HttpClient(format!(
            "request to {url} timed out. The API may be slow or overloaded."
        ))
    } else {
        Error::HttpClient(e.to_string())
    }
})?;
```

2. **HTTP status errors** — replace the generic `Error::ApiError` with actionable messages:
```rust
if !status.is_success() {
    let suggestion = match status.as_u16() {
        401 => " Check the --api-key flag.",
        403 => " The API key may lack permissions for this operation.",
        404 => " The endpoint may not exist. Verify the API is running and the spec is current.",
        422 => " The request body may have validation errors. Check the required fields.",
        429 => " Rate limited. Wait before retrying.",
        500..=599 => " The API is experiencing server errors.",
        _ => "",
    };
    return Err(Error::ApiError {
        status: status.as_u16(),
        body: format!("{body_text}{suggestion}"),
    });
}
```

3. **In service.rs**, improve the tool error response formatting to be more structured:
```rust

            format!("Connection error: {msg}")
        }
        other => format!("Error: {other}"),
    };

}
```
