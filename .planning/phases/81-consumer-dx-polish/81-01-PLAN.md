<task type="auto">
  <name>Task 1: Add --dry-run flag and startup connectivity check</name>
  <files>ferro-api-mcp/src/main.rs</files>
  <action>
Add a `--dry-run` CLI flag to the Cli struct:
```
/// Validate spec and print tool summary without starting the MCP server.
#[arg(long)]
dry_run: bool,
```

Modify the `run()` function to add these diagnostics:

1. **Spec fetch diagnostics**: After fetching spec, log the byte size. On failure, provide categorized error messages:
   - Connection refused → "Cannot connect to {url}. Is the server running?"
   - Timeout → "Request to {url} timed out. Check network connectivity."
   - DNS failure → "Cannot resolve hostname in {url}. Check the URL."
   - Non-200 status → "Spec URL returned HTTP {status}. Expected 200 with OpenAPI JSON."
   - Non-JSON content → "Spec URL returned non-JSON content. Expected an OpenAPI 3.0.x JSON document."

2. **Spec parse diagnostics**: After parsing, log operation count. If zero operations parsed, log a warning: "Warning: spec parsed successfully but contains no operations. Check that the spec has paths defined."

3. **Connectivity check**: After resolving base_url, make a lightweight HEAD request to the base URL to verify the API is reachable. If it fails, log a warning (not an error — the API might start later): "Warning: API at {base_url} is not reachable. Tools will fail until the API is available."

4. **Startup summary**: Before starting the MCP server, print a summary to stderr:
   ```
   ferro-api-mcp v{version}
   API: {api_name}
   Base URL: {base_url}
   Tools: {n} registered
   ```

5. **Dry-run mode**: If `--dry-run` is set, after the startup summary, print the tool list to stderr and exit 0:
   ```
   Tools:
     - {tool_name}: {description_first_line}
     - {tool_name}: {description_first_line}

   Dry run complete. {n} tools validated.
   ```

For the connectivity check, use `reqwest::Client::new().head(base_url).timeout(Duration::from_secs(5)).send()`. This is a best-effort check — don't fail on it.

IMPORTANT: All output goes to stderr (eprintln! or tracing). Stdout is reserved for MCP JSON-RPC transport.

<task type="auto">
  <name>Task 2: Improve spec fetch error categorization</name>
  <files>ferro-api-mcp/src/spec.rs</files>
  <action>
Improve `fetch_spec()` to return more specific errors instead of wrapping everything as `Error::SpecFetch(e.to_string())`.

Categorize fetch errors by examining the reqwest error:
- If `e.is_connect()` → Error::SpecFetch("connection refused — is the server running at {url}?".into())
- If `e.is_timeout()` → Error::SpecFetch("request timed out — check network connectivity".into())
- If `e.is_decode()` → Error::SpecFetch("failed to decode response body".into())
- Otherwise → Error::SpecFetch(e.to_string()) (keep current behavior)

Also check the HTTP response status before reading the body:
- If not 2xx → Error::SpecFetch(format!("HTTP {status} — expected 200 with OpenAPI JSON"))

After reading the body, attempt a quick JSON validity check (serde_json::from_str::<Value>) to catch non-JSON responses early with a clear message:
- If not valid JSON → Error::SpecFetch("response is not valid JSON — expected an OpenAPI 3.0.x JSON document")

These are pure refactors of existing error paths — no behavioral changes for happy path.
