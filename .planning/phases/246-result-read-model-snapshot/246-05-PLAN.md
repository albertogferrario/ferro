<objective>
Prove the full result path end-to-end with a real `WorkerLoop` draining a DB-backed queue.
This is the phase gate: it asserts the three ROADMAP Success Criteria and the retrieve-by-handle
guarantee that only the DB-backed worker path exercises (the sync-mode `dispatch_immediately`
path does NOT write snapshots — D-08 — so these behaviors are only observable here).

Coverage (from 246-VALIDATION.md):
- SC1 + SC2: enqueue an offload job → drain with `WorkerLoop` → `read_result` by handle returns
  `Some(Completed { value })` with the method's actual return value.
- SC3a: a method returning `Err` until `max_retries` is exhausted → `read_result` returns
  `Some(Failed { error })`.
- SC3b: a method that panics until exhausted → `read_result` returns `Some(Failed { error })`
  (no silent drop).

Purpose: SC#1/#2/#3 are only true if Plans 01–04 compose correctly across the enqueue→claim→
run→persist→read chain. This plan is the executable proof.

Output: `framework/tests/offload_result_round_trip.rs` — a new integration test file (framework
already depends on both `ferro-queue` and `ferro-projection`, avoiding the ferro-queue-tests →
ferro-projection dev-dep cycle, RESEARCH RQ8 Pitfall 6). This plan adds only a test file; it is
file-disjoint from all other plans but behaviorally depends on Plan 04's full wiring (Wave 3).
</objective>
