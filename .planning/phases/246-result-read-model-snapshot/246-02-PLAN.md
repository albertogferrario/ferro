`framework/src/offload.rs` module composes Plan 01's `ferro_projection::snapshot_write`

worker hook (Plan 04) both call these as `::ferro::offload::*`, per the 244/245 convention
that generated code emits only `::ferro::*` paths.

Output: `framework/src/offload.rs` (new), `pub mod offload;` in `lib.rs`, the
`ferro-projection` dep in `Cargo.toml`, and a unit test proving the completed/failed/`()`
round-trips. This module MUST exist before Plan 04's macro references `::ferro::offload::*`.

NOTE — this plan is pure facade + envelope logic. It does NOT wire the worker persistence

```rust
use ferro_projection::{snapshot_read, snapshot_write, ProjectionKey};
use ferro_queue::OffloadSerializable;
use sea_orm::DatabaseConnection;
use serde::{Deserialize, Serialize};

/// Reserved projection name for all offload results (D-13). The 247 broadcast
/// channel derives as `projection.offload.result.{handle}` from this + the key.
pub const OFFLOAD_PROJECTION_NAME: &str = "offload.result";

/// Typed result of a completed or terminally failed offloaded call (D-07).
/// Internally tagged: `{"status":"completed","value":<T>}` / `{"status":"failed","error":"<msg>"}`.
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(tag = "status", rename_all = "snake_case")]
pub enum OffloadResult<T> {
    Completed { value: T },
    Failed { error: String },
}

/// Persist a completed offload result under the handle key. Never fails the job:
/// the CALLER logs on error (Pitfall 5). Returns the projection error for the
/// caller to `tracing::warn!` and continue.
pub async fn persist_result<T: OffloadSerializable>(
    handle_key: &str,
    value: &T,
    db: &DatabaseConnection,
) -> Result<(), ferro_projection::ProjectionError> {
    let state = serde_json::to_value(value)
        .map_err(ferro_projection::ProjectionError::from)?; // () -> Value::Null is valid
    let envelope = serde_json::json!({ "status": "completed", "value": state });
    snapshot_write(db, OFFLOAD_PROJECTION_NAME, &ProjectionKey(handle_key.to_string()), envelope).await
}

/// Persist a terminal-error envelope under the handle key.
pub async fn persist_error(
    handle_key: &str,
    error: &str,
    db: &DatabaseConnection,
) -> Result<(), ferro_projection::ProjectionError> {
    let envelope = serde_json::json!({ "status": "failed", "error": error });
    snapshot_write(db, OFFLOAD_PROJECTION_NAME, &ProjectionKey(handle_key.to_string()), envelope).await
}

/// Read back a result by handle key, deserialized to OffloadResult<T>.
/// Returns Ok(None) when no snapshot exists yet (D-08 — not done, or unknown handle).
pub async fn read_result<T: OffloadSerializable>(
    handle_key: &str,
    db: &DatabaseConnection,
) -> Result<Option<OffloadResult<T>>, ferro_projection::ProjectionError> {
    match snapshot_read(db, OFFLOAD_PROJECTION_NAME, &ProjectionKey(handle_key.to_string())).await? {
        None => Ok(None),
        Some(v) => {
            let envelope: OffloadResult<T> = serde_json::from_value(v)
                .map_err(ferro_projection::ProjectionError::from)?;
            Ok(Some(envelope))
        }
    }
}
```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| offloaded method return value → persisted envelope | The `Output` is serialized to JSON and stored. `Output: OffloadSerializable` bounds the type. In-process, no external input. |
| error message → failed envelope | `persist_error` stores an error string. In 246 the string is a `Display`-stringified framework/DB error (produced by the worker/macro). |
| handle key → snapshot key | The UUID v4 handle key becomes the projection key. Non-guessable (122 bits) but not access-controlled in 246. |

In 246 the envelope is retrieved in-process only (no public endpoint), so disclosure surface is limited. Documented for Phase 247 to sanitize/truncate before any client-facing exposure. Not a 246 blocker. |

Retrieval is in-process (not a public endpoint yet); Phase 247 subscribe MUST add subscriber authentication. Accepted per Phase 245 D-07 stance. |
