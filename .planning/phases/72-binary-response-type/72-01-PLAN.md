  <name>Task 1: Change HttpResponse body from String to Bytes</name>
  <files>framework/src/http/response.rs, framework/src/http/mod.rs, framework/src/lib.rs</files>
  <action>
  **In `framework/src/http/response.rs`:**

  1. Change `body: String` to `body: Bytes` in the `HttpResponse` struct. Add `use bytes::Bytes;` if not already imported (it is — line 2).

  2. Update `HttpResponse::new()`: set `body: Bytes::new()`.

  3. Update `HttpResponse::text()`: convert the `impl Into<String>` to `String`, then wrap with `Bytes::from(s)`. This is zero-copy — `Bytes::from(String)` reuses the heap allocation.

  4. Update `HttpResponse::json()`: `body.to_string()` produces a `String`, wrap with `Bytes::from(...)`.

  5. Add `HttpResponse::bytes()` constructor:
     ```rust
     pub fn bytes(body: impl Into<Bytes>) -> Self {
         Self {
             status: 200,
             body: body.into(),
             headers: vec![],
         }
     }
     ```
     No default Content-Type — caller must set it via `.header()`. This is intentional: binary data has no universal content type.

  6. Add `HttpResponse::download()` constructor:
     ```rust
     pub fn download(body: impl Into<Bytes>, filename: &str) -> Self {
         // Sanitize filename: remove control characters and quote marks to prevent header injection
         let safe_name: String = filename
             .chars()
             .filter(|c| !c.is_control() && *c != '"' && *c != '\\')
             .collect();

         let content_type = mime_guess::from_path(&safe_name)
             .first()
             .map(|m| m.to_string())
             .unwrap_or_else(|| "application/octet-stream".to_string());

         Self {
             status: 200,
             body: body.into(),
             headers: vec![
                 ("Content-Type".to_string(), content_type),
                 ("Content-Disposition".to_string(), format!("attachment; filename=\"{safe_name}\"")),
             ],
         }
     }
     ```
     Auto-detects Content-Type from filename extension using `mime_guess` (already in deps, used by `static_files.rs`). Falls back to `application/octet-stream`. Sanitizes filename against header injection.

  7. Update `body()` method: change return type from `&str` to `&str`, but now derive it from `Bytes`:
     ```rust
     pub fn body(&self) -> &str {
         std::str::from_utf8(&self.body).unwrap_or("")
     }
     ```
     Returns empty string for non-UTF-8 bodies. This preserves backward compatibility — all existing callers use it for JSON/text parsing.

  8. Add `body_bytes()` accessor:
     ```rust
     pub fn body_bytes(&self) -> &Bytes {
         &self.body
     }
     ```

  9. Update `into_hyper()`: change `Bytes::from(self.body)` to just `self.body` since it's already `Bytes`.

  10. Update `Default` impl: `Self::new()` already returns the right thing.

  **In `framework/src/http/mod.rs`:**

  11. Add a module-level `bytes()` convenience function (parallel to existing `text()` and `json()`):
      ```rust
      pub fn bytes(body: impl Into<Bytes>) -> Response {
          Ok(HttpResponse::bytes(body))
      }
      ```
      Add `use bytes::Bytes;` import.

  **In `framework/src/lib.rs`:**

  12. Add `bytes` to the re-export from `http` module (line 68, alongside `json, text`). The function name won't conflict with the `bytes` crate since users import it as `ferro::bytes()`.

  **Add `mime_guess` dependency to framework/Cargo.toml** if not already present. Check with `grep mime_guess framework/Cargo.toml`. It's likely already there since `static_files.rs` uses it.

  **Do NOT:**
  - Add a body enum (Text/Binary) — `Bytes` handles both, `Bytes::from(String)` is zero-copy
  - Add streaming support — out of scope, `Full<Bytes>` is sufficient for KB-to-low-MB content
  - Change the `into_hyper()` return type — it already returns `hyper::Response<Full<Bytes>>`
  - Add `Content-Length` to `into_hyper()` — Hyper handles this automatically for `Full<Bytes>`
  </action>
