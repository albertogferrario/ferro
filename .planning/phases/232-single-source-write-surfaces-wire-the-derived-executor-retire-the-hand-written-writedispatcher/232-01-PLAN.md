<objective>
Relocate the channel-agnostic transition-execution kernel out of `ferro-mcp-server` into a new
`framework::write` module so it can be driven by more than one channel, parameterizing the hardcoded
`mcp.action.*` audit prefix into a `channel` argument. The MCP/JSON-RPC framing
(`handle_write_call`/`handle_confirm`/`handle_request_confirm`) stays in `ferro-mcp-server` and calls
into the relocated kernel. This is the foundation Wave 2 builds the visual write surface on.

The kernel is ALREADY channel-agnostic (verified: `dispatch_write`'s signature has no MCP type —
research §Q3). The only MCP couplings are: (1) `crate::Error`/`crate::Result` → reconcile with a
framework error, (2) the hardcoded audit prefix `"mcp.action.{}"` (`write_dispatch.rs:436,582`) →
parameterize, (3) the confirm seam helpers. The extraction is mechanical, not architectural.

CRITICAL: This plan does NOT delete the `WriteDispatcher`/`ExecutorFn`/`GuardEvaluatorFn` envelope —
that is the live guard-reeval security gate (research §Q4). It is RELOCATED and SHARED, not removed.
SC1 (MCP path uses the derived executor, `match action_name` deleted) was already satisfied by
Phase 231 — this plan PRESERVES it through the move and re-verifies it.

Purpose: One execution kernel in one location, callable by both channels (EXEC-05 coherence constraint).
Output: `framework::write` module; `ferro-mcp-server` reduced to framing that calls into it; MCP tests green.
</objective>
