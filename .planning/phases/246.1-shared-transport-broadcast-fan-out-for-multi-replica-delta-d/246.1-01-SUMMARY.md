## Decisions Made

1. `with_transport` reconstructs the inner `Arc` with fresh `DashMap::new()` maps, mirroring the `with_authorizer` precedent. `with_transport` is invoked at construction before any client connects, so carrying the empty maps forward is correct. This avoids requiring `Client` and `ChannelInfo` to implement `Clone`.

2. `fan_out()` is appended to both `send_to_channel` and `send_to_channel_except`. The except-socket exclusion is a local-only concern; remote replicas have no such socket and should receive the full event. The `matches!(msg, ServerMessage::Event(_))` filter gates both calls identically, satisfying D-04/D-05.

3. `InMemoryTransport` is reachable at `ferro_broadcast::transport::memory::InMemoryTransport` but not re-exported at the crate root. It is a test/dev backend; adding it to the root public API would misrepresent it as production-ready.

4. `MemberRemoved` (emitted by `unsubscribe_internal` via `tokio::spawn` → `send_to_channel`) passes through `fan_out`, which filters it because it is not `ServerMessage::Event(_)`. The D-05 guarantee holds for both presence membership variants through the same filter path.

## Deviations from Plan

None — plan executed exactly as written. The note about DashMap::clone was correctly anticipated: `Client` and `ChannelInfo` are not `Clone`, so the fresh-DashMap construction path described in the plan's parenthetical was used.

## Known Stubs

None. `transport_redis_url` in `BroadcastConfig` is a URL-string field only; async Redis construction is Plan 02. This is intentional, documented in the field's doc-comment, and does not affect any UI or user-visible output.

## Threat Flags

No new network endpoints, auth paths, or external-facing surfaces introduced. The `BroadcastTransport` publish/subscribe boundary is in-memory only in this plan (InMemoryTransport, same process). The untrusted-network form of the subscribe boundary (deserialization of off-process data) lands in Plan 02 and is documented in the plan's threat model as T-246.1-03.
