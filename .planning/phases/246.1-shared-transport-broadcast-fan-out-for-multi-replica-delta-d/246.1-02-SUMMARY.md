## Decisions Made

1. The `redis` dependency is optional with no `default = [...]` entry in `[features]`. The only entry is `redis-transport = ["redis"]`. This keeps the default build byte-for-byte equivalent to the pre-Plan-01 state — no redis compilation, no native tooling, SC2 preserved.

2. `RedisTransport` holds both a `ConnectionManager` (for PUBLISH) and the original `redis::Client` (for SUBSCRIBE). The `get_async_pubsub()` method is available on `Client`, not on `ConnectionManager`, because a pub/sub connection cannot also issue regular commands (D-09). The `ConnectionManager` is cloned per PUBLISH call, providing auto-reconnect without a hand-rolled loop (D-07).

3. T-246.1-06 (hostile Redis instance) is accepted as a documented deployment assumption: the Redis instance is presumed to be a network-isolated resource shared with `ferro-cache` under the same `REDIS_URL`. A compromised Redis can inject or observe deltas; no in-code envelope signing is in scope for this version. This is noted in the `transport/redis.rs` module-level docs.

4. The live integration test uses `uuid::Uuid::new_v4()` to generate a unique channel name per run (`ferro:broadcast:test:{uuid}`). This prevents cross-talk between parallel CI test runners sharing one Redis instance.
