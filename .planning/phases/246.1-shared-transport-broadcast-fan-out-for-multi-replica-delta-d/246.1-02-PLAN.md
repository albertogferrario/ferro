```rust
//! Redis pub/sub shared transport (feature `redis-transport`).
//!
//! Single fan-out channel with per-process local routing (D-08). PUBLISH uses a
//! multiplexed `ConnectionManager` (auto-reconnect, D-07); SUBSCRIBE uses a
//! dedicated pub/sub connection because a pub/sub connection cannot also issue
//! commands (D-09).
#![cfg(feature = "redis-transport")]

use crate::transport::{BroadcastTransport, BusEnvelope};
use crate::Error;
use futures_util::StreamExt;
use redis::aio::ConnectionManager;
use redis::{AsyncCommands, Client};
use tracing::{debug, warn};

/// App-neutral default fan-out channel. No tenant/app identity (project-agnostic-crate rule).
pub const DEFAULT_CHANNEL: &str = "ferro:broadcast";

/// Redis-backed shared fan-out transport.
pub struct RedisTransport {
    manager: ConnectionManager, // PUBLISH — cloneable, multiplexed
    client: Client,             // SUBSCRIBE — get_async_pubsub()
    channel: String,            // single fan-out channel (D-08)
}

impl RedisTransport {
    /// Connect and build the transport. `channel` defaults to `DEFAULT_CHANNEL`.
    pub async fn new(url: &str, channel: impl Into<String>) -> Result<Self, Error> {
        let client = Client::open(url).map_err(|e| Error::transport(e.to_string()))?;
        let manager = ConnectionManager::new(client.clone())
            .await
            .map_err(|e| Error::transport(e.to_string()))?;
        let channel = channel.into();
        debug!(channel = %channel, "redis broadcast transport connected");
        Ok(Self { manager, client, channel })
    }

    /// Connect using the app-neutral default channel.
    pub async fn connect(url: &str) -> Result<Self, Error> {
        Self::new(url, DEFAULT_CHANNEL).await
    }
}

#[async_trait::async_trait]
impl BroadcastTransport for RedisTransport {
    async fn publish(&self, envelope: &BusEnvelope) -> Result<(), Error> {
        let payload = serde_json::to_string(envelope)?; // Error: From<serde_json::Error> exists
        let mut conn = self.manager.clone(); // ConnectionManager is Clone
        conn.publish::<_, _, ()>(&self.channel, payload).await?; // Error: From<redis::RedisError> (Task 1)
        Ok(())
    }

    async fn subscribe_loop(
        &self,
        sink: tokio::sync::mpsc::Sender<BusEnvelope>,
    ) -> Result<(), Error> {
        // Dedicated pub/sub connection (D-09) — cannot share the multiplexed manager.
        let mut pubsub = self.client.get_async_pubsub().await?;
        pubsub.subscribe(&self.channel).await?;
        let mut stream = pubsub.into_on_message();
        while let Some(msg) = stream.next().await {
            let payload: String = match msg.get_payload() {
                Ok(p) => p,
                Err(e) => {
                    warn!(error = %e, "dropping unreadable redis pub/sub payload");
                    continue; // never panic on a malformed payload
                }
            };
            // Strict deserialization: a malformed/hostile envelope is dropped, never
            // partially delivered (threat T-246.1-03).
            match serde_json::from_str::<BusEnvelope>(&payload) {
                Ok(envelope) => {
                    if sink.send(envelope).await.is_err() {
                        break; // receiver dropped — clean shutdown
                    }
                }
                Err(e) => {
                    warn!(error = %e, "dropping malformed bus envelope from redis");
                    continue;
                }
            }
        }
        Ok(())
    }
}
```

Key correctness points (from RESEARCH pitfalls): PUBLISH and SUBSCRIBE use separate connections (Pitfall 1 / D-09); `into_on_message()` consumes the `PubSub` — correct because the channel set is static (Pitfall 4); a malformed payload is logged and dropped, never propagated as a panic (threat T-246.1-03). `ConnectionManager` provides the auto-reconnect required by D-07 — do not hand-roll a reconnect loop.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shared Redis bus → Broadcaster (subscribe) | **Untrusted network input.** Any client with `REDIS_URL` access (or a co-tenant on a shared instance) can publish arbitrary bytes on `ferro:broadcast`. The SUBSCRIBE loop deserializes those bytes and injects the result into local subscriber delivery. This is the primary attack surface of the phase. |
| Broadcaster → Redis (publish) | Envelope originates from trusted local code; the bus itself is the trust boundary (see below). |
| Redis instance (deployment) | Assumed a trusted, network-isolated instance shared with `ferro-cache` under the same `REDIS_URL`. A hostile Redis can inject or observe deltas — a deployment-security assumption, not a code mitigation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-246.1-03 | Tampering / Spoofing (malformed or hostile bus payload) | `RedisTransport::subscribe_loop` | mitigate | Payload is read as a `String` (unreadable → log + `continue`) then strictly deserialized with `serde_json::from_str::<BusEnvelope>`; any parse error is logged and dropped — never a panic, never a partial delivery. The bus grants no capability beyond a local publish: only `ServerMessage::Event` is ever delivered (D-04 filter in Plan 01), so a crafted envelope can at most deliver an Event into an existing local channel, which channel-subscription auth already gates. Acceptance: `from_str::<BusEnvelope>` Err-arm drops (Task 2). |
| T-246.1-06 | Information Disclosure / Tampering (hostile Redis instance) | Redis deployment trust boundary | accept (documented) | Stated explicitly as a deployment assumption: the bus is a trusted, network-isolated instance shared with `ferro-cache`; a compromised Redis can inject/observe deltas. No in-code mitigation is in scope (no envelope signing this phase); documented in `transport/redis.rs` module docs and carried to the phase SUMMARY. |
| T-246.1-07 | Denial of Service (bus flooding — every process receives every message on the single channel, D-08) | `subscribe_loop` fan-out | accept (bounded) | The single-channel topology is a deliberate D-08 trade-off at result-delta volumes; malformed messages are dropped cheaply (a `String` read + one failed `from_str`) before any local fan-out, so a flood of garbage costs deserialization only, not delivery. Sharding is a deferred idea if volume outgrows the model. |
| T-246.1-02 | Denial of Service (bus publish outage propagating into caller) | `RedisTransport::publish` + `Broadcaster::fan_out` | mitigate | `publish` errors surface as `Err`, which Plan 01's `fan_out` logs and swallows (D-06); `ConnectionManager` auto-reconnect (D-07) recovers the PUBLISH path without a hand-rolled loop. Proven by Plan 01's `publish_error_does_not_propagate`. |
| T-246.1-01 | Tampering (loop/echo amplification over the real bus) | origin filter | mitigate | The origin-id echo suppression established in Plan 01 applies unchanged to the Redis path (the SUBSCRIBE loop feeds the same origin-filtered delivery). Proven by Plan 01's `sc1_own_echo_suppressed`; exercised over a real bus by `redis_integration_cross_process_delivery`. |

*No `high`-severity threat lacks a mitigation task. T-246.1-06 (hostile Redis) is an accepted, explicitly-documented deployment assumption, consistent with `ferro-cache` sharing the same instance.*
