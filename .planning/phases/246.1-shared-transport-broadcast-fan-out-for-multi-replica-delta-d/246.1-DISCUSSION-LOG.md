# Phase 246.1: Shared-transport broadcast fan-out - Discussion Log

> **Audit trail only.** Do not use as input to planning, research, or execution agents.
> Decisions are captured in CONTEXT.md — this log preserves the alternatives considered.

**Date:** 2026-08-14
**Phase:** 246.1-shared-transport-broadcast-fan-out-for-multi-replica-delta-d
**Areas discussed:** Transport choice, Loop prevention & delivery, Fan-out scope, Config & failure mode, Redis topology, Connection source

---

## Transport choice

| Option | Description | Selected |
|--------|-------------|----------|
| Redis pub/sub only + trait | Reuse vendored redis 0.27 + ConnectionManager behind an optional feature; `BroadcastTransport` trait for later backends; in-process default | ✓ |
| Postgres LISTEN/NOTIFY only | Reuse ferro-queue sqlx-postgres; ~8KB NOTIFY payload cap; dedicated listener connection | |
| Both Redis + Postgres now | Two transports this phase; doubles impl + test matrix; delays Phase 247 | |

**User's choice:** Redis pub/sub only + trait.
**Notes:** Trait keeps Postgres additive later. Redis already in-tree via ferro-cache; no payload cap.

---

## Loop prevention & delivery

| Option | Description | Selected |
|--------|-------------|----------|
| Origin-stamp + local-first | Process-unique origin id; deliver locally at publish, publish stamped, drop own echo on receipt | ✓ |
| Bus-only uniform path | All delivery (incl. local) happens on bus return; adds round-trip; couples local delivery to bus | |

**User's choice:** Origin-stamp + local-first.
**Notes:** Keeps single-node latency unchanged; local delivery independent of bus (consistent with degrade goal).

---

## Fan-out scope

| Option | Description | Selected |
|--------|-------------|----------|
| Server Events only | broadcast()/broadcast_except() Event path (projection delta + server events); presence/whisper stay per-process | |
| Events + whisper | Also fan out client whispers; whisper is also ServerMessage::Event; except-socket a no-op remotely | ✓ |
| Everything incl. presence | Also replicate presence membership; needs distributed member registry; separate phase | |

**User's choice:** Events + whisper.
**Notes:** Presence membership remains per-process (documented single-node limitation).

---

## Config & failure mode (failure behavior)

| Option | Description | Selected |
|--------|-------------|----------|
| Degrade to local + log | Deliver locally, log bus error, don't fail caller; ConnectionManager auto-reconnect | ✓ |
| Degrade + health signal | Same degrade plus a transport-status/metric signal for operators | |
| Hard-fail the publish | Return error on bus publish failure; propagates outages into request/worker path | |

**User's choice:** Degrade to local + log.
**Notes:** Consistent with D-21 (broadcast failure never rolls back state). Health signal deferred.

---

## Redis topology

| Option | Description | Selected |
|--------|-------------|----------|
| Single fan-out channel | One Redis channel; envelope carries logical channel + origin; local routing; no subscribe churn | ✓ |
| Per-logical-channel subscribe | Mirror each logical channel to a Redis channel; SUBSCRIBE/UNSUBSCRIBE lifecycle + timing races | |

**User's choice:** Single fan-out channel.
**Notes:** Every process receives every message — acceptable at result-delta volumes; sharding later if needed.

---

## Connection source

| Option | Description | Selected |
|--------|-------------|----------|
| Reuse REDIS_URL + override | Read shared REDIS_URL, BROADCAST_REDIS_URL override; dedicated pub/sub conn for SUBSCRIBE, ConnectionManager for PUBLISH | ✓ |
| Dedicated BROADCAST_REDIS_URL only | Require a broadcast-specific URL, no fallback; more config for common single-Redis case | |

**User's choice:** Reuse REDIS_URL + override.

---

## Claude's Discretion

- `BROADCAST_TRANSPORT` = `memory` (default) | `redis` via existing `from_env` pattern.
- Feature-flag name `redis-transport` (parallel to ferro-cache `redis-backend`); no new crate.
- App-neutral Redis fan-out channel literal.
- Origin-id representation (uuid v4 assumed).

## Deferred Ideas

- Postgres LISTEN/NOTIFY transport (additive via the trait).
- Sharded / per-channel Redis topology if volume warrants.
- Cross-process presence membership (distributed registry) — own phase.
- Health/metric signal for a partitioned bus.
