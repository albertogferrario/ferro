<objective>
Build the request-scoped `MemoStore` in the `framework` crate (`ferro-rs`), hold it
in a `tokio::task_local!` (`MEMO_STORE`), enter its per-request scope in `server.rs`,
and re-export the public API at `::ferro::memo`. No proc-macro yet — this plan delivers
the store the `#[memoize]` macro (Plan 02) will reach.

Purpose: the store is the substrate for the whole phase. It must coalesce concurrent
callers via `futures::future::Shared`, degrade gracefully to no-op outside a request
(D-02), and cache the full return value including `Err` (D-04) — all proven by unit
tests before any macro exists.

Output: `framework/src/memo/mod.rs` (store + task-local + tests), `futures` added to
`framework/Cargo.toml`, `MEMO_STORE.scope(...)` at `server.rs:279`, and the re-export
in `framework/src/lib.rs`.

```rust
// framework/src/memo/mod.rs
pub struct MemoStore { /* entries: Mutex<HashMap<MemoKey, MemoSlot>> */ }
pub type MemoSlot = futures::future::Shared<
    futures::future::BoxFuture<'static, std::sync::Arc<dyn std::any::Any + Send + Sync>>
>;

#[derive(Eq, PartialEq, Hash, Clone, Copy)]
pub struct MemoKey { callsite: std::any::TypeId, args_hash: u64 }

impl MemoKey {
    /// Marker: a per-callsite zero-sized type minted by the macro. `A`: the hashable args tuple.
    pub fn new<Marker: 'static, A: std::hash::Hash>(args: &A) -> Self;
}

impl MemoStore {
    pub fn new() -> Self;
    /// First caller inserts `make_fut()` as a Shared slot; concurrent callers get a clone
    /// of the same slot. Lock is released BEFORE the returned slot is awaited by the caller.
    pub fn get_or_insert(
        &self,
        key: MemoKey,
        make_fut: impl FnOnce() -> futures::future::BoxFuture<
            'static, std::sync::Arc<dyn std::any::Any + Send + Sync>
        >,
    ) -> MemoSlot;
}

tokio::task_local! { pub(crate) static MEMO_STORE: std::sync::Arc<MemoStore>; }

/// None outside a request scope (D-02 graceful degradation).
pub fn current_memo_store() -> Option<std::sync::Arc<MemoStore>>;

pub(crate) fn memo_scope() -> std::sync::Arc<MemoStore>; // Arc::new(MemoStore::new())
pub(crate) async fn with_memo_scope<F, R>(store: std::sync::Arc<MemoStore>, f: F) -> R
where F: std::future::Future<Output = R>;
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| request → request | Consecutive HTTP requests handled by the same tokio runtime / worker threads. The only boundary of interest: whether one request's memoized values can be observed by another. |

This phase introduces NO authentication, authorization, tenant-isolation, or data-exposure
surface of its own. The memo store is a per-request performance/correctness optimization.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-259-01 | Information Disclosure | MemoStore lifetime across requests | mitigate | Structural: `MEMO_STORE.scope()` creates a fresh `Arc<MemoStore>` per request in server.rs and drops it when the request task-local scope exits; task-local storage is per-task so no other request can read it. Proven by the "store dropped with request / fresh scope sees no prior entries" unit test in Task 1. No shared/static map exists. |
| T-259-02 | Tampering | MemoKey hash collision within a request | accept | `DefaultHasher` collisions are astronomically rare for practical arg values; scope is a SINGLE request; an attacker cannot craft a cross-request collision because the store is per-request. Documented as a known limitation. No sensitive control decision keys on the hash. |
| T-259-03 | Denial of Service | `future::Shared` panic propagation | accept | A panicking memoized body propagates to all pollers of that slot within the one request that owns the store; it cannot affect other requests (per-request store). Reliability, not security. Documented; `catch_unwind` deferred (RESEARCH Pitfall 2). |

No HIGH-severity open threats. Cross-request/cross-tenant leakage (T-259-01) is mitigated
structurally by construction and asserted by test.
</threat_model>
