**1. `OffloadSerializable` marker trait + blanket impl (D-05).** This is the FIRST use of
`#[diagnostic::on_unimplemented]` in the tree. MSRV 1.94.1 supports it (stable since 1.78).
Name `{Self}` in both message and note; frame the offload isolation boundary. Exact wording is
Claude's discretion, but it MUST name `{Self}` and mention Serialize + DeserializeOwned:
```rust
/// Marker trait: every parameter and return type crossing the `#[offload]`
/// boundary must be `Serialize + DeserializeOwned`. A blanket impl covers all
/// qualifying types; the `#[diagnostic::on_unimplemented]` attribute rewrites the
/// compiler error to name the offending type and frame the isolation boundary.
#[diagnostic::on_unimplemented(
    message = "`{Self}` crosses the #[offload] isolation boundary and must be `Serialize + DeserializeOwned`",
    note = "offloaded parameters and return types travel as a queue payload; implement `Serialize` and `DeserializeOwned` for `{Self}` to seal the module across the isolation boundary"
)]
pub trait OffloadSerializable: Serialize + DeserializeOwned {}

impl<T: Serialize + DeserializeOwned> OffloadSerializable for T {}
```

**2. `HandleKey` newtype (D-07).** A transparent `String` newtype minted from a fresh UUID v4
at enqueue, decoupled from `Job::idempotency_key()`. Derive `Debug, Clone, Serialize,
Deserialize, PartialEq, Eq`. Provide `new()` and `as_str()`. Implement `Default` by delegating to
`new()` (clippy's `new_without_default` fires otherwise — avoid the `-D warnings` failure):
```rust
/// Opaque identity of a single offload enqueue, minted as a fresh UUID v4.
/// Non-secret: uniqueness (not unpredictability) is the only requirement in 245.
/// Decoupled from `Job::idempotency_key()` (D-07).
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct HandleKey(String);

impl HandleKey {
    /// Mint a fresh handle key from a UUID v4.
    pub fn new() -> Self {
        Self(Uuid::new_v4().to_string())
    }
    /// The key as a string slice.
    pub fn as_str(&self) -> &str {
        &self.0
    }
}

impl Default for HandleKey {
    fn default() -> Self {
        Self::new()
    }
}
```

**3. `OffloadHandle<T>` (D-08).** Inert typed wrapper: `HandleKey` + a function-pointer phantom.
Use `PhantomData<fn() -> T>` (NOT `PhantomData<T>`) so the handle is `Send + Sync` regardless of
`T` (Pitfall 2). Mark the phantom `#[serde(skip)]` so serde does not require `T: Serialize`
(Pitfall 4) — this is what makes OFFLOAD-02e hold. Derive `Debug, Clone, Serialize, Deserialize,
PartialEq, Eq`. Expose ONLY the read-only accessors in 245 — NO `.await` / `.subscribe()` (those
are 246/247):
```rust
/// A typed handle to an offloaded call's eventual result. Inert in Phase 245:
/// it carries the enqueue identity (`HandleKey`) and the success type `T`
/// (phantom, zero-cost), but exposes no resolve/subscribe surface — those arrive
/// with the result path (246) and streaming (247).
#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct OffloadHandle<T> {
    key: HandleKey,
    #[serde(skip)]
    _phantom: PhantomData<fn() -> T>,
}

impl<T> OffloadHandle<T> {
    /// Wrap a minted key in a typed handle.
    pub fn new(key: HandleKey) -> Self {
        Self { key, _phantom: PhantomData }
    }
    /// The handle key as a string slice (the eventual projection/subscription key).
    pub fn key(&self) -> &str {
        self.key.as_str()
    }
    /// The handle key newtype.
    pub fn id(&self) -> &HandleKey {
        &self.key
    }
}
```

**4. `Offloadable` trait (D-04).** A supertrait of `Job` carrying `type Output:
OffloadSerializable` (return-side enforcement, D-05) and a provided-default `offload()` that
mints a key and enqueues through the EXISTING `PendingDispatch` path (D-03). Apply
`#[async_trait]` exactly as `Job` does (this resolves RESEARCH Open Question 2 — follow the `Job`
pattern). The macro (Plan 02) emits only `impl ... { type Output = <T>; }`; the body lives here:
```rust
/// Enqueue entrypoint layered on the derived Job. The `#[offload]` trait method
/// itself stays `-> T` in-process (D-01); `.offload()` is the enqueue path that
/// returns a typed handle to where the result will eventually land.
#[async_trait]
pub trait Offloadable: crate::Job + Serialize + DeserializeOwned + Sized {
    /// The method's success type (D-09): `T` for `-> T` / `Result<T, E>`, `()` for `-> ()`.
    type Output: OffloadSerializable;

    /// Enqueue this job and return a typed handle. Enqueue can fail (DB insert),
    /// mirroring `dispatch` (D-02).
    async fn offload(self) -> Result<OffloadHandle<Self::Output>, Error> {
        let key = HandleKey::new();
        crate::PendingDispatch::new(self).dispatch().await?;
        Ok(OffloadHandle::new(key))
    }
}
```
Note on bounds: put `Serialize + DeserializeOwned + Sized` on the `Offloadable` supertrait (not
only on the method `where`-clause) because `PendingDispatch::new` requires them; keeping them at
the trait level lets the macro emit a bare `impl Offloadable for XJob { type Output = ...; }`.
Verify against `PendingDispatch`'s actual bounds while reading dispatcher.rs — if `dispatch()`
needs additional bounds, surface them on the supertrait, not a hidden per-method clause.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-process module → queue payload | The offload payload crosses a serialization boundary. The whole point of the `OffloadSerializable` contract is that the module is sealed across this boundary — a type that cannot serialize cannot leak across it. This is the mitigated boundary; enforcement is compile-time. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-245-01 | Information Disclosure | `HandleKey` (UUID v4) | accept | `HandleKey` is a non-secret opaque identifier, not a security token. In 245 it grants no capability (the handle is inert — no resolve/subscribe). Uniqueness, not unpredictability, is the only requirement; UUID v4 satisfies it. When 246/247 make the handle a subscription key, authorization is layered there, not on key entropy. |
| T-245-02 | Tampering | offload payload serialization | mitigate | The `OffloadSerializable` bound (`Serialize + DeserializeOwned`) is the isolation boundary: a non-serializable type cannot cross into the queue payload. Enforced structurally at compile time via the marker trait bound; no runtime input parsing is introduced in 245. |
| T-245-03 | Elevation of Privilege | `Offloadable::offload()` enqueue path | accept | `.offload()` wraps the existing `PendingDispatch::dispatch()` path — it introduces no new enqueue mechanism, no new auth surface, and no new deserialization of untrusted input. The existing queue's trust model is unchanged. |

No authentication, authorization, session management, untrusted input parsing, cryptographic
operation, or network I/O is introduced in Plan 01. The surface is new Rust types + a
compile-time bound.
</threat_model>
