# Phase 169 — UI Design Contract: StreamText Component

> Visual and interaction contract for the `StreamText` ferro-json-ui built-in component.
> Generated by gsd-ui-researcher. Consumed by gsd-planner and gsd-executor.

---

## Scope Note

This phase ships a single server-rendered leaf component, not a React page or multi-screen
flow. The visual surface is exactly four DOM states of one `<div>` container. The contract
below is proportionate to that surface — it does not invent a full page design system.

**Semantic token vocabulary (established in codebase — do not deviate):**

The ferro-json-ui renderer uses project-scoped semantic class names derived from
`ferro-theme`. These are the tokens available for StreamText:

| Token | Maps to | Used for |
|-------|---------|---------|
| `text-text` | foreground text | streamed content |
| `text-text-muted` | muted foreground | placeholder, loading indicator |
| `bg-surface` | surface background | placeholder span background (if any) |
| `bg-card` | card surface | not used by this component |
| `text-primary` | accent/brand | not used by this component |
| `border-border` | default border | not used by this component |

Custom animation token: `ferro-shimmer` (defined in `SHIMMER_CSS` constant in `atoms.rs` —
already ships as part of the Skeleton component). StreamText does NOT use `ferro-shimmer`;
the loading indicator is a static text span, not an animation.

## Typography

The component has two optional text elements (placeholder and loading indicator).
Both inherit their typography from the established `text-text-muted` token pattern
used by every muted-text span in atoms.rs. No new type scale is introduced.

|------|-----------|--------|-------------|

## Component States

The four visual states of the StreamText component:

### State 1: Initial (before first token)

```
┌─────────────────────────────────────────┐
│ <span data-ferro-stream-placeholder      │
│   class="text-sm text-text-muted">       │
│   Response will appear here…             │  ← placeholder (if set)
│ </span>                                  │
│ <span data-ferro-stream-loading          │
│   class="text-sm text-text-muted">       │
│   Generating…                            │  ← loading_text (if set)
│ </span>                                  │
└─────────────────────────────────────────┘
```

- `placeholder` span present only when `placeholder: Some(...)` is set
- `loading_text` span present only when `loading_text: Some(...)` is set
- Both `None` → container renders as empty `<div>`

### State 2: Streaming (first token received, stream open)

```
┌─────────────────────────────────────────┐
│ The quick brown fox                      │  ← text nodes appended via createTextNode
│ <span data-ferro-stream-loading          │
│   class="text-sm text-text-muted">       │
│   Generating…                            │  ← loading_text remains
│ </span>                                  │
└─────────────────────────────────────────┘
```

- Placeholder `<span>` removed on first token (`placeholder.remove()`)
- Text nodes appended via `document.createTextNode(e.data)` — never innerHTML
- Loading indicator remains until `event: done`

### State 3: Done (`event: done` received)

```
┌─────────────────────────────────────────┐
│ The quick brown fox jumped over the lazy │  ← full streamed text
│ dog.                                     │
└─────────────────────────────────────────┘
```

- `EventSource.close()` called
- Loading indicator `<span>` removed (`loading.remove()`)
- Text nodes remain in place

### State 4: Error (`onerror` fired)

```
┌─────────────────────────────────────────┐
│ The quick brown fox                      │  ← partial text preserved
└─────────────────────────────────────────┘
```

- `EventSource.close()` called
- Loading indicator `<span>` removed
- Any text nodes appended before error remain in place (partial output preserved)
- No error message is injected by the component — host application owns error UX

## DOM Contract

### Container element

```html
<div data-ferro-stream-url="{html_escaped_sse_url}">
  <!-- optional: placeholder span -->
  <!-- optional: loading span -->
</div>
```

- Attribute name: `data-ferro-stream-url` (exactly — the init script queries this selector)
- URL is escaped via `html_escape()` (`render/mod.rs:256`) before interpolation
- No CSS classes on the container div — layout is host-application responsibility
- No `id` attribute — the init script uses `querySelectorAll`, not ID lookup

### Placeholder span (when `placeholder: Some(text)`)

```html
<span data-ferro-stream-placeholder class="text-sm text-text-muted">{html_escaped_text}</span>
```

- Attribute: `data-ferro-stream-placeholder` (queried by init script for `.remove()`)
- Text content escaped via `html_escape()`

### Loading indicator span (when `loading_text: Some(text)`)

```html
<span data-ferro-stream-loading class="text-sm text-text-muted">{html_escaped_text}</span>
```

- Attribute: `data-ferro-stream-loading` (queried by init script for `.remove()`)
- Text content escaped via `html_escape()`

## Interaction Contract

### EventSource lifecycle (JavaScript)

Managed by a single shared init script emitted once via `render_spec_to_html_with_plugins`
when at least one `StreamText` element is present. Script is dependency-free, inline,
IIFE-wrapped.

| Event | Action |
|-------|--------|
| `onmessage` (default SSE event) | Append `document.createTextNode(e.data)` to container; remove placeholder on first token |
| `addEventListener('done', ...)` | Call `src.close()`; remove loading indicator span |
| `onerror` | Call `src.close()`; remove loading indicator span; preserve appended text nodes |

XSS constraint: tokens MUST be appended as text nodes (`document.createTextNode`), NEVER
via `innerHTML` or `insertAdjacentHTML`. This is a non-negotiable security requirement
(CONTEXT.md D-02). Applies equally to `placeholder` and `loading_text` server-side
(both pass through `html_escape()` before HTML emission).

Reconnect constraint: `EventSource` auto-reconnects when a connection closes cleanly.
Calling `src.close()` on `event: done` prevents the reconnect loop. The SSE endpoint
contract ("must emit `event: done`") must be documented in both the catalog description
and the docs section (CONTEXT.md D-03).

## Design Rationale

**Why no CSS classes on the container div:** StreamText renders an arbitrary amount of
text, possibly multi-paragraph. Container sizing, padding, overflow, and font should be
controlled by the application layout, not hardcoded by the component. This matches
`RawHtmlProps`'s pattern of emitting a bare container.

**Why `text-text-muted` for placeholder and loading:** Both are transient, secondary UI
elements that should visually recede relative to the streamed content. `text-text-muted`
is the established ferro-json-ui token for this role (confirmed in atoms.rs at lines 347,
425, 629, 666, 702).

**Why no animation on the loading indicator:** The Skeleton component owns the
`ferro-shimmer` animation for unknown-content placeholders. A loading indicator that
shows explicit text ("Generating…") does not need an animation — the text itself
communicates the active state. Avoiding animation keeps the component minimal and
avoids a dependency on the `SHIMMER_CSS` constant outside its owning component.
