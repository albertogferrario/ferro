<objective>
Delete the blocking Anthropic-only `ferro-cli/src/ai.rs` client and route the
`make:json-view` command's two-pass LLM generation through the `ferro-ai` SDK
(`AiConfig::from_env()` -> `Box<dyn LlmClient>` -> `client.complete(CompletionRequest)`).
After this plan the command works against any configured provider
(Anthropic / OpenAI / Groq / Ollama), not just Anthropic, with no behavior regression.

Purpose: closes AISDK-06 and validates the v12.1 ferro-ai SDK against the existing
LLM consumer before new AI commands (Phase 171) are built on top of it.

Output: ferro-ai dependency added; `ai.rs` deleted; transport-agnostic helpers relocated
into `make_json_view.rs`; `generate_with_ai` rewired with a tokio runtime bridge and the
provider gate switched from `ANTHROPIC_API_KEY` presence to `AiConfig::from_env()`.

This is a transport-swap plumbing migration (D-03) — NOT a generation redesign. The
two-pass behavior, validation, and stderr UX are preserved exactly. The v2 redesign is
Phase 173.
</objective>

<scope_note>
**ROADMAP SC#2 literal-wording correction (carry into verification).** ROADMAP Phase 170
SC#2 literally says "all LLM calls go through `ferro_ai::complete::<T>()`". This is NOT
literally achievable for `make:json-view` and must be read as "through the ferro-ai SDK /
`LlmClient::complete()`" (CONTEXT D-02):

1. Pass 1 is plain text with no schema; `complete::<T>()` always attaches a schema — wrong tool.
2. Pass 2 must carry the catalog's runtime-built schema (`global_catalog().json_schema()`),
   not a `schemars`-derived one. `ferro_json_ui::Spec` does not derive `JsonSchema`, and the
   catalog schema is the validation source of truth (`catalog.validate(&spec)`). Forcing
   `Spec: JsonSchema` would diverge the generated schema from the validator — a correctness
   hazard, explicitly rejected.

Therefore both passes route through the low-level `client.complete(CompletionRequest { .. })`
with the raw catalog schema in `CompletionRequest.schema`. The verifier must accept this as
satisfying SC#2; do NOT fail on the literal `complete::<T>()` wording.
</scope_note>

```rust
fn generate_with_ai(
    client: &dyn ferro_ai::LlmClient,
    file_name: &str,
    title: &str,
    layout_name: &str,
    description: &str,
) -> String {
    // One runtime, reused across both passes (D-01). ferro-cli main() is sync (no #[tokio::main]),
    // so Runtime::new() is safe — no nested-runtime panic.
    let rt = match tokio::runtime::Runtime::new() {
        Ok(r) => r,
        Err(e) => {
            eprintln!(
                "{} Failed to create tokio runtime: {}",
                style("Warning:").yellow().bold(),
                e
            );
            eprintln!("{}", style("Falling back to static template.").dim());
            return templates::json_view_template(file_name, title, layout_name);
        }
    };

    // ── Pass 1: plain-text plan (schema: None, max_tokens 1024) ──────────────
    let (sys1, usr1) = build_json_view_pass1(file_name, description);
    let req1 = CompletionRequest {
        system: Some(sys1),
        messages: vec![Message {
            role: Role::User,
            content: usr1,
            tool_call_id: None,
        }],
        max_tokens: 1024,
        model_override: None,
        schema: None,
        tools: None,
        tool_choice: None,
    };
    let pass1_result = match rt.block_on(client.complete(req1)) {
        Ok(text) => text,
        Err(e) => {
            eprintln!(
                "{} AI Pass 1 failed: {}",
                style("Warning:").yellow().bold(),
                e
            );
            eprintln!("{}", style("Falling back to static template.").dim());
            return templates::json_view_template(file_name, title, layout_name);
        }
    };

    // ── Pass 2: structured spec against the catalog schema (max_tokens 4096) ─
    let (sys2, usr2) = build_json_view_pass2(&pass1_result);
    let schema = ferro_json_ui::global_catalog().json_schema().clone();
    let req2 = CompletionRequest {
        system: Some(sys2),
        messages: vec![Message {
            role: Role::User,
            content: usr2,
            tool_call_id: None,
        }],
        max_tokens: 4096,
        model_override: None,
        // Catalog runtime schema is the validation source of truth (D-02) — NOT schemars.
        schema: Some(schema),
        tools: None,
        tool_choice: None,
    };
    let json_str = match rt.block_on(client.complete(req2)) {
        Ok(s) => s,
        Err(e) => {
            eprintln!(
                "{} AI Pass 2 failed: {}",
                style("Warning:").yellow().bold(),
                e
            );
            eprintln!("{}", style("Falling back to static template.").dim());
            return templates::json_view_template(file_name, title, layout_name);
        }
    };

    // ── Validation (D-03): unchanged from the current implementation ─────────
    match ferro_json_ui::Spec::from_json(&json_str) {
        Err(parse_err) => {
            eprintln!(
                "{} Generated spec failed structural parse: {}",
                style("Warning:").yellow().bold(),
                parse_err
            );
            eprintln!("{}", style("Falling back to static template.").dim());
            templates::json_view_template(file_name, title, layout_name)
        }
        Ok(spec) => match ferro_json_ui::global_catalog().validate(&spec) {
            Ok(()) => json_str,
            Err(errors) => {
                eprintln!(
                    "{} Generated spec failed catalog validation ({} error{}):",
                    style("Warning:").yellow().bold(),
                    errors.len(),
                    if errors.len() == 1 { "" } else { "s" }
                );
                for err in &errors {
                    eprintln!("  - {err}");
                }
                eprintln!("{}", style("Falling back to static template.").dim());
                templates::json_view_template(file_name, title, layout_name)
            }
        },
    }
}
```
**Error-mapping note:** the old helpers returned `Result<String, String>`; the SDK returns
`Result<String, ferro_ai::Error>`. The `Err(e)` arms above interpolate `e` directly via its
`Display` impl, so the existing yellow-warning UX is preserved with no manual `.map_err`. The
`Error` Display guarantees no API-key leakage (its `Provider` variant docs forbid it).
