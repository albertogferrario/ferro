`is_filter_field` predicate (gate order is load-bearing — gate 1 catches write_only fields that
may or may not carry Sensitive meaning):
```rust
use ferro_projections::field::{DataType, FieldDef, FieldMeaning};

pub fn is_filter_field(field: &FieldDef) -> bool {
    if !field.readable { return false; }                       // gate 1
    if field.is_list { return false; }                         // gate 2
    if matches!(field.meaning, FieldMeaning::Sensitive) { return false; } // gate 3
    // gate 5: equality filter on JSON/Binary columns is not useful
    if matches!(field.data_type, DataType::Json | DataType::Binary) { return false; }
    // gate 4: conservative meaning allowlist
    matches!(
        field.meaning,
        FieldMeaning::Identifier
        | FieldMeaning::ForeignKey
        | FieldMeaning::Status
        | FieldMeaning::Category
        | FieldMeaning::Boolean
        | FieldMeaning::Custom(_)
    )
}
```

fn data_type_to_json_schema(dt: &DataType) -> serde_json::Value {
    match dt {
        DataType::Integer => serde_json::json!({ "type": "integer" }),
        DataType::Float => serde_json::json!({ "type": "number" }),
        DataType::Boolean => serde_json::json!({ "type": "boolean" }),
        DataType::DateTime => serde_json::json!({ "type": "string", "format": "date-time" }),
        DataType::Date => serde_json::json!({ "type": "string", "format": "date" }),
        DataType::Uuid => serde_json::json!({ "type": "string", "format": "uuid" }),
        // String, Enum, Json, Binary (Json/Binary already filtered out upstream)
        _ => serde_json::json!({ "type": "string" }),
    }
}

`build_input_schema` — pagination first, then filters; merge the per-field type object with a
description:
```rust
use ferro_projections::ServiceDef;

pub fn build_input_schema(service: &ServiceDef) -> crate::Result<serde_json::Value> {
    let mut properties = serde_json::Map::new();

    properties.insert("limit".into(), serde_json::json!({
        "type": "integer",
        "description": "Maximum number of records to return",
        "default": 25, "maximum": 100, "minimum": 1
    }));
    properties.insert("offset".into(), serde_json::json!({
        "type": "integer",
        "description": "Number of records to skip",
        "default": 0, "minimum": 0
    }));

    for field in service.fields.iter().filter(|f| is_filter_field(f)) {
        let mut prop = data_type_to_json_schema(&field.data_type);
        if let serde_json::Value::Object(ref mut m) = prop {
            m.insert("description".into(),
                serde_json::Value::String(format!("Filter by {}", field.name)));
        }
        properties.insert(field.name.clone(), prop);
    }

    Ok(serde_json::json!({ "type": "object", "properties": properties }))
}
```

```rust
use rmcp::model::{Tool, ToolAnnotations};

fn render(&self, service, _intents, _ctx) -> Result<Tool, ProjError> {
    let name = format!("list_{}", service.name);
    let description = service.description.clone().unwrap_or_else(|| {
        format!("List {} records",
            service.display_name.as_deref().unwrap_or(&service.name))
    });
    let schema_value = crate::schema::build_input_schema(service)
        .map_err(|e| ProjError::Render(e.to_string()))?;
    let schema_obj = match schema_value {
        serde_json::Value::Object(m) => m,
        _ => return Err(ProjError::Render("inputSchema must be an object".into())),
    };
    let annotations = ToolAnnotations::new().read_only(true);
    Ok(Tool::new(name, description, std::sync::Arc::new(schema_obj))
        .annotate(annotations))
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| projection definition → tool inputSchema | The `inputSchema` advertises which fields an agent may filter on. An over-broad surface would expose internal/sensitive columns as queryable. The data is developer-controlled (ServiceDef), but the predicate is the control point. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-197-03 | Information disclosure | `is_filter_field` predicate in schema.rs | mitigate | Conservative allowlist + three exclusion gates (non-readable, list, Sensitive meaning) + Json/Binary exclusion. `test_sensitive_field_excluded` and `test_write_only_excluded` assert sensitive/non-readable fields never reach the advertised filter surface. |
| T-197-04 | Spoofing/Tampering | tool annotation | mitigate | `readOnlyHint = true` set on every rendered tool — agents and clients see the tool is non-mutating; matches the read-only-skeleton scope. |
| T-197-05 | Information disclosure | unmarked projection exposure | mitigate | `render_exposed_tools` filters on `mcp_exposed`; `test_mcp_exposed_filter` asserts unmarked projections produce zero tools. |
</threat_model>
