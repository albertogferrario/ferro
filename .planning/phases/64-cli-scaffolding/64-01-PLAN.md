  <action>
Create the `ferro make:lang {locale}` command following the established make: pattern.

**Command registration (main.rs):**
Add to Commands enum:
```
#[command(name = "make:lang")]
MakeLang {
    /// Locale code (e.g., en, fr, de, pt-br)
    name: String,
}
```
Add match arm calling `commands::make_lang::run(name)`.

**Command module (commands/mod.rs):**
Add `pub mod make_lang;`

**Command implementation (commands/make_lang.rs):**
Follow the make_middleware.rs pattern but adapted for lang files:

1. Validate locale code: must be lowercase letters, optionally followed by hyphen and more lowercase letters (regex: `^[a-z]{2}(-[a-z]{2,})?$`). NOT a Rust identifier check — locale codes like "pt-br" are valid.

2. Target directory: `lang/{locale}/` (relative to project root, matching LangConfig default LANG_PATH="lang").

3. Check if directory already exists — error if it does.

4. Create directory `lang/{locale}/`.

5. Write two JSON files:
   - `lang/{locale}/validation.json` — Copy of English validation messages from template. Use `templates::lang_validation_json()` which returns the full validation.json content (same structure as ferro-lang/resources/en/validation.json).
   - `lang/{locale}/app.json` — Starter application translations from template. Use `templates::lang_app_json()`. This should contain:
     ```json
     {
       "app": {
         "welcome": "Welcome to :name!",
         "greeting": "Hello, :name!"
       },
       "auth": {
         "login": "Log In",
         "register": "Register",
         "logout": "Log Out",
         "email": "Email",
         "password": "Password",
         "remember_me": "Remember Me",
         "forgot_password": "Forgot Your Password?"
       },
       "pagination": {
         "previous": "Previous",
         "next": "Next"
       }
     }
     ```

6. Print success messages:
   ```
   ✓ Created lang/{locale}/validation.json
   ✓ Created lang/{locale}/app.json

   Language files for '{locale}' created successfully!

   Usage:
     1. Set APP_LOCALE={locale} in .env to use as default
     2. Translate the strings in lang/{locale}/*.json
     3. Use t("app.welcome", &[("name", "Ferro")]) in handlers
   ```

**Template files:**
- Create directory `ferro-cli/src/templates/files/lang/`.
- Create `ferro-cli/src/templates/files/lang/validation.json.tpl` — identical to ferro-lang/resources/en/validation.json content.
- Create `ferro-cli/src/templates/files/lang/app.json.tpl` — the starter app translations shown above.

**Template functions (templates/make.rs):**
Add two functions:
```rust
pub fn lang_validation_json() -> &'static str {
    include_str!("files/lang/validation.json.tpl")
}

pub fn lang_app_json() -> &'static str {
    include_str!("files/lang/app.json.tpl")
}
```

**Re-exports (templates/mod.rs):**
The existing `pub use make::*;` in mod.rs already re-exports everything from make.rs, so no mod.rs changes needed for templates. Verify this is the case.

  <action>
Update the `ferro new` project scaffolding to include localization support out of the box.

**1. Update .env.example.tpl — add LOCALIZATION section:**
Insert a new section after the APPLICATION section (before SERVER section):

```
# ==============================================================================
# LOCALIZATION
# ==============================================================================
# Language and locale configuration

APP_LOCALE=en              # Default locale for the application
APP_FALLBACK_LOCALE=en     # Fallback when translation key is missing
LANG_PATH=lang             # Path to translation files (relative to project root)
```

**2. Update .env.tpl — add locale defaults:**
Add after the APP_URL line:

```
APP_LOCALE=en
APP_FALLBACK_LOCALE=en
```

Do NOT add LANG_PATH to .env (the default "lang" is fine and matches convention).

**3. Update new.rs — create lang/en/ directory and files:**
In the `create_directories` function, add `"lang/en"` to the backend_dirs array.

In the `write_backend_files` function, after the storage gitkeep files, add:
```rust
// Language files
write_file(project_path, "lang/en/validation.json", templates::lang_validation_json())?;
write_file(project_path, "lang/en/app.json", templates::lang_app_json())?;
```

The template functions `lang_validation_json()` and `lang_app_json()` are already created in Task 1 via templates/make.rs and re-exported through templates/mod.rs.

**No changes needed to project.rs** — the template functions live in make.rs and are re-exported through the existing `pub use make::*;` pattern.

    - ferro new creates lang/en/validation.json and lang/en/app.json in new projects
