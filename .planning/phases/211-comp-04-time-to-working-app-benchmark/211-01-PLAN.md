<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker base image -> build env | The cold-cache container pulls a public base image and a rustup install script |
| crates.io -> scaffolded cargo build | The benchmark's cargo build resolves ferro-rs + ~200 transitive deps from crates.io |
| benchmark subprocess -> host fs | The warm benchmark writes a full project + target/ into a tempdir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-211-01 | Tampering | rustup install over network (Dockerfile) | mitigate | Pin TLS in the curl invocation: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs` (official endpoint, HTTPS-only, TLS1.2 floor) |
| T-211-02 | Tampering | Docker base image supply-chain | mitigate | Use the minimal `debian:bookworm-slim` base; comment that pinning the image by digest hardens further; no third-party images |
| T-211-03 | Tampering | scaffolded cargo build pulls crates.io deps | accept | The deps are ferro's own published crates + their pinned transitive deps resolved by Cargo.lock semantics; standard crates.io supply-chain, not a new attack surface this phase introduces |
| T-211-04 | Denial of service | tempdir target/ disk exhaustion (warm run) | accept | Warm run is gated (FERRO_BENCH=1, #[ignore]) and human-invoked with a df precheck; default CI never runs it (no second target dir). Low severity, operator-controlled |
| T-211-05 | Information disclosure | committed RESULTS.md / Dockerfile | accept | No secrets in this phase (no API keys); files carry only timing numbers + env spec. Nothing to leak |
</threat_model>
