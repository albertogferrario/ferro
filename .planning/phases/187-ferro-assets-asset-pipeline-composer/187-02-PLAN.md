<objective>
Implement the five text transforms as `Transform` built-ins: `html_minify` (lol_html with the
regression-critical opaque `<script>`/`<style>` handling), `css_minify` (lightningcss),
`js_minify` (swc umbrella `Compiler::minify`), `inject_before_tag` (lol_html structural
injection), and `replace_tokens` (raw-bytes `%%TOKEN%%` substitution across all content types).
Lands the SC-2 inline-script regression fixture proving inline scripts/styles survive byte-correct.

Purpose: Delivers ASSET-F-02 (minify built-ins + inline safety) and ASSET-F-04's structural
injection + token substitution. The opaque-content guarantee (criterion 2) is the single most
failure-prone transform — a corrupted inline `<script>` fires SyntaxError on the live site.
Output: Five compiling, tested transforms exported from `ferro_assets::transforms`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → html_minify / css_minify / js_minify | Untrusted tenant HTML/CSS/JS bytes parsed by lol_html/lightningcss/swc |
| caller → replace_tokens | Caller-supplied token map values are substituted verbatim into output |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-187-06 | Tampering | html_minify corrupts inline <script>/<style> (C-02) | mitigate | element handler ONLY on script/style, NO text handler (D-14); SC-2 fixture proves byte-correct bodies; grep asserts absence of `text!("script"/"style")` |

Crate has no authority over caller-supplied values; low residual risk, not high. |
| T-187-08 | Denial of Service | lol_html parser panic on malformed HTML | mitigate | rewriter.write/end return Result; mapped to Error::transform; no `.unwrap()` on the rewriter path |
