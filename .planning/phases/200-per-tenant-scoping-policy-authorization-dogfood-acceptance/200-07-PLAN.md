  <action>
    1. Create `dogfood/run_dogfood.mjs` — a Node ESM script (no external SDK required; plain
       `fetch` is sufficient and avoids the unverified MCP-SDK dependency, 200-RESEARCH Environment
       Availability). It must:
       a. GET `{APP_URL}/.well-known/oauth-authorization-server` (and protected-resource) to
          discover endpoints.
       b. POST `{APP_URL}/register` (DCR) → capture `client_id`.
       c. Generate PKCE (code_verifier + S256 challenge), print the `/authorize` URL with the
          challenge + redirect_uri, and PAUSE for the human to complete browser login + consent;
          read back the redirect `code` (from a pasted redirect URL or a tiny localhost callback
          listener — choose the simpler; document it).
       d. POST `{APP_URL}/token` with code + code_verifier → capture `access_token`.
       e. POST `{APP_URL}/mcp` `tools/list` (Bearer) → find the order tool name.
       f. POST `{APP_URL}/mcp` `tools/call` for that tool with `{"limit":5,"offset":0}`.
       g. VERIFY: assert the result has `result.content` rows and that every row's `tenant_id`
          equals the authenticated tenant's id; print PASS/FAIL and exit non-zero on FAIL.
       Read `APP_URL` from env (default `http://127.0.0.1:8000` or the app's actual default —
       confirm from app config). Keep it dependency-free (Node ≥18 has global fetch).
    2. Create `dogfood/README.md` documenting: prerequisites (APP_URL, OAuth signing secret env
       var name from OAuthConfig, two-tenant seed applied), the manual steps (user starts the
       server; user performs browser login), how to run the script, and the Claude Desktop config
       block (mcpServers entry pointing at `{APP_URL}/mcp`) as the human-facing confirmation path.
    NOTE: do NOT start the server from the script or from the executor — the user runs it
    (project convention). The script connects to an already-running app.
  </action>
