<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP call payload → dispatch filters | Agent-supplied filters object is untrusted; must never set the tenant scope |
| caller (app handler) → dispatch | tenant_id parameter is trusted (derived from validated token via current_tenant()) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-200-01 | Information Disclosure | dispatch WHERE clause | mitigate | Tenant predicate is a bound parameter (`sea_orm::Value::BigInt`), value comes from the `tenant_id` function parameter only; never string-interpolated, never from `filters`. Two-tenant isolation test proves A's token cannot read B's rows. |
| T-200-02 | Tampering / EoP | dispatch filter loop | mitigate | tenant scope is appended OUTSIDE the filter loop from a separate parameter; the existing filter-key allowlist already excludes non-field keys so an agent cannot inject a tenant override via the filters object. |
| T-200-FAILOPEN | Information Disclosure | dispatch fail-closed branch | mitigate | tenant_column=Some + tenant_id=None returns Err — never falls back to unscoped SELECT. Covered by `tenant_fail_closed` test. |
</threat_model>
