<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /mcp | Untrusted bearer token; BearerAuthMiddleware validates before any handler logic |
| validated token claims → TenantMiddleware | Claims trusted only after signature/aud/expiry validation; tenant resolved against DB |
| session login → /authorize tenant resolver | Authenticated session user's tenant_id binds the minted token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-200-05 | Spoofing / context confusion | middleware ordering | mitigate | Bearer runs BEFORE Tenant; expected_tenant=None in bearer (current_tenant not yet set); TenantMiddleware owns resolution. Plan 06 integration test asserts the resulting current_tenant() equals the web-surface path. |
| T-200-EOP-TENANT | Elevation of Privilege | JwtClaimResolver + on_failure | mitigate | A crafted/unknown tenant_id claim fails DbTenantLookup::find_by_id → on_failure(Forbidden) → 403. Real tenant validated against DB, not trusted from the claim alone. |
| T-200-NEUTRALIZED | Information Disclosure | /authorize tenant binding | mitigate | Without TenantMiddleware on /authorize, tokens mint tenant_id=null (Pitfall 8) and scoping is neutralized. The session-user resolver binds the real tenant at mint time. |
| T-200-03a | Elevation of Privilege | Gate ability registry | mitigate | "view-orders" defined once; the same registry the web surface uses. No MCP-specific permission code (SC-3). |
</threat_model>
