   - 1-2 sentence intro: Ferro provides derive macros that eliminate boilerplate for database models and validation. FerroModel scaffolds CRUD operations; ValidateRules co-locates validation rules with struct definitions.

2. FerroModel section:
   a. Brief explanation: generates create/update/delete/query methods from a SeaORM entity model
   b. Complete entity example (use the posts entity from RESEARCH.md Pattern 5 — NOT users, since users is shown in database.md already):
      ```rust
      use ferro::FerroModel;
      use sea_orm::entity::prelude::*;
      use serde::{Deserialize, Serialize};

      #[derive(Clone, Debug, PartialEq, Eq, DeriveEntityModel, Serialize, Deserialize, FerroModel)]
      #[sea_orm(table_name = "posts")]
      pub struct Model {
          #[sea_orm(primary_key)]
          pub id: i32,
          pub title: String,
          pub body: String,
          pub published: bool,
          pub author_id: i32,
          pub slug: Option<String>,
          pub created_at: String,
          pub updated_at: String,
      }

      #[derive(Copy, Clone, Debug, EnumIter, DeriveRelation)]
      pub enum Relation {}
      ```
   c. Generated API subsection with examples:
      - Create: `Post::create().set_title("Hello").set_body("World").insert().await?`
      - Update: `post.update().set_title("Updated").save().await?`
      - Clear optional: `post.update().clear_slug().save().await?`
      - Delete: `post.delete().await?`
      - Query: `Post::query().filter(Column::Published.eq(true)).all().await?`
   d. Generated Methods reference table:
      | Method | Returns | Description |
      | Entity::create() | CreateBuilder | Builder for inserting a new row |
      | instance.update() | UpdateBuilder | Builder for selectively updating fields |
      | instance.delete() | Result | Deletes the row from the database |
      | Entity::query() | Select<Entity> | SeaORM Select for building queries |

3. ValidateRules section:
   a. Brief explanation: generates a `.validate()` method from `#[rule(...)]` field attributes. Uses Ferro's built-in rules (same functions available in the fluent Validator API).
   b. IMPORTANT distinction: `#[rule(...)]` is NOT the same as the `validator` crate's `#[validate(...)]`. Ferro has its own validation system. Mention that the fluent `Validator::new()` API (documented in validation.md) and `ValidateRules` use the same underlying rule functions.
   c. Complete example (use the RegistrationRequest from RESEARCH.md):
      ```rust
      use ferro::ValidateRules;

      #[derive(ValidateRules)]
      struct RegistrationRequest {
          #[rule(required, email)]
          email: String,

          #[rule(required, min(8))]
          password: String,

          #[rule(required, string, min(2), max(50))]
          name: String,

          #[rule(required, integer, min(18), max(120))]
          age: i32,

          #[rule(nullable, url)]
          website: Option<String>,
      }
      ```
   d. Usage example:
      ```rust
      let req = RegistrationRequest { /* ... */ };
      req.validate()?;  // Returns Result<(), ValidationErrors>
      ```
   e. Available rules reference table:
      | Rule | Description | Example |
      | required | Field must be present and non-empty | #[rule(required)] |
      | email | Must be valid email format | #[rule(email)] |
      | string | Must be a string value | #[rule(string)] |
      | integer | Must be an integer value | #[rule(integer)] |
      | min(n) | Minimum value or length | #[rule(min(8))] |
      | max(n) | Maximum value or length | #[rule(max(100))] |
      | between(a, b) | Value between a and b inclusive | #[rule(between(1, 10))] |
      | url | Must be a valid URL | #[rule(url)] |
      | nullable | Field may be None/null | #[rule(nullable)] |

4. Brief "See Also" section linking to:
   - [Database](database.md) for SeaORM entity setup
   - [Validation](validation.md) for the fluent Validator API

- ALL imports use `ferro::` crate root — `ferro::FerroModel`, `ferro::ValidateRules`
- Do NOT use `ferro::macros::` or `ferro_macros::`

Style: match themes.md — concise, no marketing language, scientific tone.
