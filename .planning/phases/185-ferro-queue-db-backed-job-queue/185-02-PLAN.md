         ```sql
         UPDATE jobs SET status='pending', claimed_at=NULL, claimed_by=NULL, attempts = attempts + 1, available_at = ?now
         WHERE status='claimed' AND claimed_at < ?cutoff AND attempts < max_retries AND queue = ?queue
         ```
       - Step 2 (park exhausted as failed):
         ```sql
         UPDATE jobs SET status='failed', error='visibility timeout exceeded'
         WHERE status='claimed' AND claimed_at < ?cutoff AND attempts >= max_retries AND queue = ?queue
         ```

       ```sql
       INSERT INTO jobs (queue, job_type, payload, status, attempts, max_retries, idempotency_key, tenant_id, available_at, created_at)
       SELECT ?queue, ?job_type, ?payload, 'pending', 0, ?max_retries, ?idem, ?tenant, ?available_at, ?now
       WHERE NOT EXISTS (
         SELECT 1 FROM jobs WHERE job_type = ?job_type AND idempotency_key = ?idem
           AND status IN ('pending','claimed')
       )
       ```
       When `idempotency_key` is `None`, do a plain INSERT (no NOT EXISTS guard). All values parameterized (T-185-01). Branch placeholder style on backend.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| job payload (TEXT JSON) → DB | payload originates from consumer-serialized jobs; stored as opaque text, deserialized by the worker (Plan 03) |
| idempotency_key / queue / worker_id → claim & enqueue SQL | string values flowing into dynamic SQL — the highest-value injection surface in the phase |
| reaper cutoff / timestamps → SQL | computed server-side from Utc::now(), not attacker-controlled |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-185-01 | Tampering | claim/enqueue/reaper SQL | mitigate | ALL dynamic values bound via Statement::from_sql_and_values; zero string interpolation of queue/worker_id/idempotency_key/payload (grep verifies from_sql_and_values present) |
| T-185-04 | Denial of Service | poison job blocking the lane | mitigate | reaper parks max_retries-exhausted claimed rows as 'failed' (status), removing them from the pending claim set so they never block subsequent claims (poison_job_parked test) |
| T-185-05 | Denial of Service | double-claim under concurrency | mitigate | Postgres FOR UPDATE SKIP LOCKED in txn; SQLite raw BEGIN IMMEDIATE (not Serializable) — Plan 05 race test is the proof artifact |
| T-185-06 | Elevation of privilege | cross-tenant claim | accept | tenant_id stored on the row and carried into JobRow; tenant scoping enforced at execution time by TenantScopeProvider in Plan 03 (claim is tenant-agnostic by design — work-stealing across tenants is intended) |
</threat_model>
