<objective>
Build the `ferro-queue` side of `#[offload]`: the inventory-based auto-registration path that lets a
derived Job self-register into the worker with zero bootstrap code, and the round-trip proof that a
dispatched Job runs its `handle()` (including the `Result`-error to job-failure mapping).

This plan owns everything that must exist BEFORE the macro can emit correct code. The macro (Plan 02)
emits consumer-facing paths that must resolve from a crate depending only on `ferro-rs` — the real
`app` crate does NOT depend on `ferro-queue` directly (app/Cargo.toml only lists the `ferro-rs`
package). The macro therefore emits `::ferro::queue::JobRegistrarEntry`, `::ferro::queue::WorkerLoop`,
`::ferro::queue::Job`, `::ferro::queue::Error`, and `::ferro::async_trait`, matching the existing
`#[service]` convention (`let ferro = quote!(::ferro)`). This plan makes all of those resolvable.

Purpose: deliver the "declare once, zero wiring" registration property (D-12/D-13) and pin the
round-trip + error-mapping behavior with automated tests so the macro plan builds against a proven
substrate.
Output: `JobRegistrarEntry` inventory type + collection, an inventory-draining `from_registry`, the
`inventory` dependency on ferro-queue, the framework queue re-export, and the round-trip/registration
test file.
</objective>
