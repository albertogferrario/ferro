rustls/ring, so the `ferro` release binary and `cargo install ferro-cli` build with
no system OpenSSL (no libssl-dev, no pkg-config, no C-openssl cross-build).

any other plan and unblocks the native aarch64 cross-compile (Plan 02).

D-03 (ferro-wallet openssl stays OUT of scope — do not touch it), D-05 (cargo-deny
stays green).

Purpose: Remove the root-cause OpenSSL dependency behind COMP-04 cold-Debian friction
and aarch64 cross-compile fragility.

| build host <-> crates.io / build scripts | ring's build script compiles C/asm; provider crate identity is a supply-chain surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-225-01 | Tampering | TLS backend swap weakening transport security | mitigate | rustls supports only TLS 1.2/1.3, no downgrade path. reqwest `rustls-tls` uses webpki-roots (bundled Mozilla CA set) — note: this is a bundled root store, not the OS trust store; acceptable for CLI/DB/SMTP clients and matches prior native-tls behaviour for these use cases. Verified provider chain selects ring throughout. |
| T-225-02 | Tampering | Supply chain — new crypto provider crate (ring) enters the release tree | mitigate | ring 0.17.14 license (Apache-2.0 AND ISC) already in deny.toml allow-list; `cargo deny check` (Task 3) gates the advisory/license surface. ring >= 0.17.13 patches RUSTSEC-2025-0009 (AES panic); workspace pins 0.17.14. Removing openssl-sys strictly REDUCES advisory surface. |
| T-225-03 | Elevation of Privilege | aws-lc-rs silently selected (requires cmake/C, violates "no external build tooling") | mitigate | Task 3 hard-gates `grep aws-lc | wc -l` -> 0 on the ferro-cli tree. If a future sea-orm/sqlx version flips the default to aws-lc-rs, this check fails the build. |
