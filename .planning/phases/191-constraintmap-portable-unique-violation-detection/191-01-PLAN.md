<objective>
Build the `ConstraintMap` defensive-layer primitive: a consumer-registered map from
DB UNIQUE-constraint violations to field-level `ValidationError`s, plus the
`MapConstraintExt` call-site ergonomic. Detection is backend-portable
(`DbErr::sql_err()` type gate) with bifurcated identity (Postgres constraint name /
SQLite `table.column`). Any non-matching `DbErr` returns UNCHANGED so the caller's
`?` reaches the existing `From<DbErr> for ActionError` passthrough.

Purpose: Close the TOCTOU window the Phase 190 async `unique` rule cannot eliminate —
a concurrent-insert violation surfaces inline under the field, identical to a
proactive failure, instead of leaking raw SQL.

Output: `framework/src/validation/constraint_map.rs` (struct + builder + try_map +
ext trait + inline non-DB unit tests), wired through `mod.rs` and `lib.rs`.
</objective>

Define (private) struct:
```rust
#[derive(Clone)]
struct ConstraintEntry {
    /// Postgres structured constraint name — primary `.on()` key.
    pg_name: String,
    /// SQLite `table.column` discriminator (set via `.sqlite()`).
    sqlite_key: Option<String>,
    /// Logical field the error attaches to.
    field: String,
    /// User-visible message.
    message: String,
}

/// Consumer-registered map from DB UNIQUE-constraint violations to field-level
/// validation errors. Construct per call site (cheap; no global state).
#[derive(Clone, Default)]
pub struct ConstraintMap {
    entries: Vec<ConstraintEntry>,
}
```

Builder methods (consuming `mut self -> Self`, the ferro convention — see rules_async.rs):
- `pub fn new() -> Self` → `Self::default()`
- `pub fn on(mut self, pg_constraint: impl Into<String>, field: impl Into<String>, message: impl Into<String>) -> Self` — push entry with `sqlite_key: None`, return self.
- `pub fn sqlite(mut self, table_col: impl Into<String>) -> Self` — `if let Some(last) = self.entries.last_mut() { last.sqlite_key = Some(table_col.into()); }` return self. Rustdoc: applies to the LAST registered entry; no-op without a prior `.on()`.

final `Err(err)` moves):

1. Type gate (portable, borrows `err`):
   `if !matches!(err.sql_err(), Some(SqlErr::UniqueConstraintViolation(_))) { return Err(err); }`
2. Postgres identity (borrow inner sqlx error; NO #[cfg], NO downcast — `e.constraint()`
   is the `DatabaseError` trait method, default None, overridden by PgDatabaseError):
   ```rust
   let pg_name: Option<String> = match &err {
       DbErr::Exec(RuntimeErr::SqlxError(sqlx::Error::Database(e)))
       | DbErr::Query(RuntimeErr::SqlxError(sqlx::Error::Database(e))) => {
           e.constraint().map(ToOwned::to_owned)

       _ => None,
   };
   ```

3. SQLite identity (parse `table.column` after `": "` — defensive, never panics):
   ```rust
   let sqlite_key: Option<String> = match err.sql_err() {
       Some(SqlErr::UniqueConstraintViolation(msg)) => {
           msg.split(": ").nth(1).map(|s| s.trim().to_owned())

       _ => None,
   };
   ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| DB driver → ConstraintMap | The only parsed input is the DB driver's UNIQUE-violation error message (SQLite `table.column`). It originates from the database engine, not from an end-user request body. |
| Consumer code → ConstraintMap | All constraint/field/message strings are developer-authored at the call site (the registered map), never end-user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-191-01 | Tampering / DoS | SQLite message parse in `try_map` | mitigate | Parse is total: `msg.split(": ").nth(1)` returns `Option`, never indexes/unwraps; a malformed/unexpected message yields `None` → falls through to `Err(DbErr)` unchanged. No panic path. Covered by the inline "never panics" unit behavior + Plan 02 passthrough test. |
| T-191-02 | Information Disclosure | error fall-through | mitigate | On no-match `try_map` returns the ORIGINAL `DbErr` by move; the existing `From<DbErr> for ActionError` applies the current behavior (unchanged by this phase). On match, the raw SQL message is replaced by the consumer's human message — strictly reduces disclosure. |
| T-191-03 | Tampering (SQL injection) | registered constraint/field strings | accept | `ConstraintMap` strings are matched against error metadata only; they are NEVER concatenated into SQL. No injection surface. Rationale: developer-owned, non-SQL-constructing. |
| T-191-04 | Repudiation / silent failure | swallowed errors | mitigate | Contract (SC2): no `DbErr` is ever discarded — every non-match returns `Err(err)`. No high-severity threat; block-on-high gate is satisfied (none high). |
</threat_model>
