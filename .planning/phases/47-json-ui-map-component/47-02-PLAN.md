<task type="auto">
  <name>Task 1: Add Plugin variant to Component enum with custom deserialization</name>
  <files>ferro-json-ui/src/component.rs</files>
  <action>
The Component enum uses `#[serde(tag = "type")]`. Adding a catch-all for unknown types requires care.

**Approach — custom Deserialize implementation:**

The research flagged that `#[serde(untagged)]` on a single variant within `#[serde(tag = "type")]` may not work. Instead, implement a custom deserializer:

1. **Add PluginProps struct:**
```rust
/// Props for a plugin component. The `plugin_type` field holds the original
/// `"type"` value from JSON, and `props` holds the remaining fields.
#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct PluginProps {
    /// The plugin component type name (e.g., "Map").
    pub plugin_type: String,
    /// Raw props passed to the plugin's render function.
    pub props: serde_json::Value,
}
```

2. **Add Plugin variant to Component enum (last position):**
```rust
pub enum Component {
    // ... existing 20 variants ...
    Plugin(PluginProps),
}
```

3. **Implement custom Deserialize for Component:**
   - Remove `#[derive(Deserialize)]` from Component (keep Serialize derive)
   - Write a custom `impl<'de> Deserialize<'de> for Component` that:
     a. Deserializes to a `serde_json::Value` first
     b. Reads the `"type"` field as a string
     c. Matches known types (Card, Table, Form, etc.) — for each, call `serde_json::from_value::<KnownProps>(value)` and wrap in the correct variant
     d. For unknown types, create `Component::Plugin(PluginProps { plugin_type, props: value })`
   - This guarantees built-in components are tried first, unknown types fall through to Plugin
   - Use a match statement for the 20 known types (not a manual if-else chain)

4. **Implement Deserialize for PluginProps:**
   - Custom deserializer that extracts `"type"` into `plugin_type` and keeps the rest as `props`

Keep `#[derive(Serialize)]` on Component — serialization doesn't need custom logic. For the Plugin variant serialization, use `#[serde(serialize_with = "...")]` or implement manually so it outputs `{"type": "Map", ...props}` (flattening plugin_type back as "type").

**Important:** Verify that existing tests for Component deserialization still pass. The 20 known types must deserialize exactly as before.
  </action>

<task type="auto">
  <name>Task 2: Wire plugin rendering into render pipeline and asset collection into build_response</name>
  <files>ferro-json-ui/src/render.rs, ferro-json-ui/src/resolve.rs, framework/src/json_ui/mod.rs</files>
  <action>
1. **Update `render_component()` in render.rs:**
   - Add `Component::Plugin(props)` match arm
   - Look up plugin in registry: `get_plugin(&props.plugin_type)`
   - If found: call `plugin.render(&props.props, data)`
   - If not found: render a visible error div: `<div class="p-4 bg-red-50 text-red-600 rounded">Unknown plugin component: {type}</div>` (helps agents debug missing plugins)

2. **Add `render_to_html_with_plugins()` function in render.rs** (or modify existing):
   - Before rendering, scan the component tree to collect plugin type names used
   - Create a helper `collect_plugin_types(view: &JsonUiView) -> HashSet<String>` that walks the tree and collects Plugin variant type names
   - After rendering, call `collect_plugin_assets()` from the plugin module with the collected types
   - Return a struct or tuple: `(html: String, css_head: String, scripts: String)` where:
     - `css_head` = concatenated CSS `<link>` tags from plugin assets
     - `scripts` = concatenated JS `<script>` tags + init scripts
   - Keep the existing `render_to_html()` signature working (it returns just String) for backwards compatibility — the new function is used by the framework integration

3. **Update `resolve_component_node()` in resolve.rs:**
   - Add `Component::Plugin(_)` arm — plugins have no children to recurse into (they're leaf components from the framework's perspective)

4. **Update `build_response()` in `framework/src/json_ui/mod.rs`:**
   - Replace `render_to_html(view, data)` with `render_to_html_with_plugins(view, data)` (or equivalent)
   - Append plugin CSS assets to the `head` string
   - Set `scripts` field in LayoutContext to the collected JS + init scripts
   - This replaces the empty `""` from Plan 01

5. **Export `render_to_html_with_plugins` and `collect_plugin_types` from ferro-json-ui lib.rs.**
