**Edit 3 — Decide what to do with the unused `_ferro_version_flag` parameter.**

`execute(force: bool, _ferro_version_flag: Option<&str>, dry_run: bool)` currently has `_ferro_version_flag` as an unused, underscore-prefixed parameter. Two options:
1. Keep the parameter as-is (forward-compat). Recommended.
2. Wire it up: `let ferro_version = _ferro_version_flag.map(|s| s.to_string()).unwrap_or_else(|| resolve_ferro_version(&root));` — gives `--ferro-version <X>` CLI override priority.

Choose option 2 — it costs almost nothing and the CLI flag was clearly intended to override the resolver. Rename `_ferro_version_flag` to `ferro_version_flag` (drop the underscore — Rust convention: underscore-prefix is for explicit-unused). Update the call sites in `run` and `run_with` if they pass the flag — quickly grep:

The new body of `execute`:
```rust
pub fn execute(
    force: bool,
    ferro_version_flag: Option<&str>,
    dry_run: bool,
) -> anyhow::Result<()> {
    let root = find_project_root(None)
        .map_err(|e| anyhow::anyhow!("could not locate project Cargo.toml: {e}"))?;

    let metadata = read_deploy_metadata(&root)?;
    let rust_channel = read_rust_channel(&root);
    let bins: Vec<String> = read_bins(&root).into_iter().map(|b| b.name).collect();
    let has_frontend = root.join("frontend/package.json").is_file();
    let copy_dirs_present: Vec<String> = metadata
        .copy_dirs
        .iter()
        .filter(|d| root.join(d).exists())
        .cloned()
        .collect();

    let web_bin = detect_web_bin(&root)?;
    let ferro_version = ferro_version_flag
        .map(|s| s.to_string())
        .unwrap_or_else(|| resolve_ferro_version(&root));
    let ctx = DockerContext {
        rust_channel,
        has_frontend,
        bins,
        web_bin,
        copy_dirs_present,
        runtime_apt: metadata.runtime_apt.clone(),
        ferro_version,
    };
    // ... rest unchanged ...
}
```

```rust
#[cfg(test)]
mod tests {
    use super::*;
    use std::fs;
    use tempfile::TempDir;

    /// Phase 156 Plan 04: assert that the rendered Dockerfile pins to the
    /// Cargo.lock-derived ferro-rs version, not the binary's own version.
    #[test]
    fn dockerfile_pins_to_cargo_lock_ferro_version() {
        let tmp = TempDir::new().unwrap();
        // Minimal project fixture: Cargo.toml + Cargo.lock + frontend/package.json
        // + a Cargo.toml [[bin]] entry so read_bins returns something usable.
        fs::write(
            tmp.path().join("Cargo.toml"),
            "[package]\nname = \"smoke\"\nversion = \"0.1.0\"\n\n[[bin]]\nname = \"smoke\"\npath = \"src/main.rs\"\n",
        ).unwrap();
        fs::write(
            tmp.path().join("Cargo.lock"),
            "[[package]]\nname = \"ferro-rs\"\nversion = \"9.9.9\"\n",
        ).unwrap();
        fs::create_dir_all(tmp.path().join("src")).unwrap();
        fs::write(tmp.path().join("src/main.rs"), "fn main(){}").unwrap();
        fs::create_dir_all(tmp.path().join("frontend")).unwrap();
        fs::write(tmp.path().join("frontend/package.json"), "{}").unwrap();

        // Construct the DockerContext directly via the same code path as `execute`,
        // bypassing find_project_root which depends on the current process CWD.
        let bins: Vec<String> = vec!["smoke".to_string()];
        let ctx = DockerContext {
            rust_channel: read_rust_channel(tmp.path()),
            has_frontend: tmp.path().join("frontend/package.json").is_file(),
            bins,
            web_bin: "smoke".to_string(),
            copy_dirs_present: vec![],
            runtime_apt: vec![],
            ferro_version: resolve_ferro_version(tmp.path()),
        };
        let out = render_dockerfile(&ctx);
        assert!(
            out.contains("--version 9.9.9"),
            "expected the rendered Dockerfile to pin ferro-cli to 9.9.9 (from Cargo.lock); got:\n{out}"
        );
        assert!(out.contains("AS types-gen"));
    }

    #[test]
    fn dockerfile_falls_back_to_env_version_when_no_cargo_lock() {
        let tmp = TempDir::new().unwrap();
        fs::create_dir_all(tmp.path().join("frontend")).unwrap();
        fs::write(tmp.path().join("frontend/package.json"), "{}").unwrap();
        let ctx = DockerContext {
            rust_channel: read_rust_channel(tmp.path()),
            has_frontend: true,
            bins: vec!["smoke".to_string()],
            web_bin: "smoke".to_string(),
            copy_dirs_present: vec![],
            runtime_apt: vec![],
            ferro_version: resolve_ferro_version(tmp.path()),
        };
        let out = render_dockerfile(&ctx);
        let expected = format!("--version {}", env!("CARGO_PKG_VERSION"));
        assert!(out.contains(&expected), "expected '{expected}' in:\n{out}");
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| docker_init CLI `--ferro-version <X>` flag -> rendered Dockerfile | User-supplied version string flows into `cargo install --version <X>`; cargo validates the version syntax |
| Cargo.lock file -> resolve_ferro_version -> ferro_version field -> Dockerfile | Project's Cargo.lock is the source of truth; an attacker who can write to Cargo.lock can influence the pinned version (already in T-156-03-01 register) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-156-04-01 | Tampering | `--ferro-version` CLI flag accepted verbatim | mitigate | Flag value is passed to `cargo install --version <X>`; cargo rejects malformed version strings. The Dockerfile uses `RUN cargo install ferro-cli --version <X> --locked` with no shell interpolation — `<X>` is a single argv element. Acceptable. |
| T-156-04-02 | Information disclosure | `resolve_ferro_version` reads Cargo.lock | accept | Cargo.lock is project-public; no secret leak. |
| T-156-04-03 | Repudiation | docker_template_drift now matches the project's actual version | mitigate | This is a positive change — before this plan, the drift check would warn on every project whose ferro_version differs from the doctor binary's. After this plan, the check matches reality. No new threat. |
</threat_model>
