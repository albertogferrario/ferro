<objective>
Close Phase 217: fix the publish-wave ordering hazard introduced by the new
`ferro-mcp-server → ferro-mcp-oauth` dependency, document the per-tenant API-key
auth surface, and run the full workspace CI gate so the phase ships clean.

Critical operator finding (from planning): `.github/workflows/publish.yml`
line ~275 lists `WAVE2_CRATES="ferro-rs ferro-mcp ferro-mcp-server ferro-mcp-oauth"`
— `ferro-mcp-server` is published BEFORE `ferro-mcp-oauth` in the same wave loop.

`ferro-mcp-oauth`, so publishing the server first will fail (`cargo publish`
cannot resolve a not-yet-published path/version dep). The loop order must put
`ferro-mcp-oauth` before `ferro-mcp-server`. Per the project convention
(MEMORY: "add new crates to publish.yml in the correct wave"), this is a
required edit even though no NEW crate is added.

Purpose: Ship Phase 217 with a correct release pipeline and documented surface.
Output: Reordered publish wave, docs page, green full CI gate.
