<task type="auto">
  <name>Task 1: Run make:api and compile generated code</name>
  <files>ferro-cli/src/commands/make_api.rs</files>
  <action>
End-to-end validation of the code generator:

1. **Build the CLI first**: `cargo build -p ferro-cli` to get the latest binary with Plan 01 fixes.

2. **Examine sample app models**: Read app/src/models/ to understand what models exist and their field structures.

3. **Run `ferro make:api` against sample models**: Execute from within the app directory. Use a single model first (smallest/simplest), then `--all` if the first succeeds. If the CLI requires being run from a project root with specific structure, adapt accordingly.

4. **Attempt compilation of generated code**: Run `cargo build -p app` (or `cargo check -p app`) to verify generated files compile. If the app crate doesn't import the generated modules, temporarily add `mod` declarations and `use` statements as needed.

5. **Fix-iterate loop**: For each compilation error:
   - Identify which template string in make_api.rs produces the bad code
   - Fix the template
   - Rebuild CLI: `cargo build -p ferro-cli`
   - Re-generate and re-compile
   - Continue until `cargo check` succeeds

Common issues to watch for:
- Missing `use` imports in generated files
- Wrong type paths (ferro::X vs full path)
- Incorrect handler signature patterns
- Missing trait implementations
- Wrong SeaORM query builder patterns
- Incorrect error handling (? vs .map_err)

6. **Clean up**: Remove all generated API files from the sample app after validation. Do NOT leave test artifacts committed.

Add a `#[cfg(test)]` module to make_api.rs with regression tests:

1. **Create test model metadata**: Construct a ModelInfo struct (or equivalent — check what make_api.rs uses internally) with realistic fields: id (i32), name (String), email (String), created_at (Option DateTime), is_active (bool).

2. **Call template generation functions** with the test model. If the generation functions write directly to files, test the string-building helper functions instead (the ones that produce the template content).

3. **Assert correct patterns present:**
   - Controller template: contains `DB::connection()?` (NOT `.await`)
   - Controller template: contains `#[handler]` macro
   - Controller index: contains typed Resource vec (NOT `Vec<serde_json::Value>`)
   - Resource template: contains `impl Resource for`
   - Resource template: contains `to_resource` method
   - Request template: validation attributes present

4. **Assert known bad patterns absent:**
   - No `connection().await` anywhere in generated strings
   - No `Vec<serde_json::Value>` passed to `ResourceCollection::paginated`

This serves as a regression test — if templates change later, this catches obvious errors before they ship.
