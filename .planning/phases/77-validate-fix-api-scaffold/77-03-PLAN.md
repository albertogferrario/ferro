<task type="auto">
  <name>Task 1: Run make:api and compile generated code</name>
  <files>ferro-cli/src/commands/make_api.rs</files>
  <action>
End-to-end validation of the code generator:

1. **Examine sample app models** — read app/src/models/ to understand what models exist and their structure.

2. **Run `ferro make:api --all`** (or equivalent) against the sample app to generate API scaffold files. If the CLI can't be run directly, simulate by calling the generation functions or by reading the template strings and manually checking what they produce for a concrete model.

3. **Check generated files compile** — attempt `cargo build` on the app crate with the generated files. Fix any compilation errors in the templates (make_api.rs).

4. **Iterate until clean** — for each compilation error:
   - Identify which template string produces the bad code
   - Fix the template in make_api.rs
   - Re-generate and re-compile
   - Continue until `cargo build` succeeds

Common issues to watch for:
- Missing `use` imports in generated files
- Wrong type paths (ferro::X vs full path)
- Incorrect handler signature patterns
- Missing trait implementations
- Wrong SeaORM query builder patterns
- Incorrect error handling (? vs .map_err)

5. **Clean up generated files** after validation — remove any generated API files from the sample app so we don't ship test artifacts.
  </action>

  <done>make:api generates code that compiles cleanly for real models. All template bugs fixed. Generated files cleaned up from sample app.</done>

<task type="auto">
  <name>Task 2: Add make:api template validation test</name>
  <files>ferro-cli/src/commands/make_api.rs</files>
  <action>
Add a test to make_api.rs that validates template correctness without needing a full app:

1. **Create test model metadata** — construct a ModelInfo/ModelMeta struct with realistic fields (id: i32, name: String, email: String, created_at: Option DateTime, is_active: bool).

2. **Generate template strings** — call the template generation functions with this test model.

3. **Assert templates contain expected patterns:**
   - Controller: `DB::connection()?` (NOT `.await`)
   - Controller: `#[handler]` macro on each handler
   - Controller: proper pagination with `paginate()` and `PaginationMeta`
   - Resource: `impl Resource for` with `to_resource` method
   - Request: `#[request]` macro with validation attributes
   - Routes: `/api/v1/` prefix with middleware
   - Provider: `ApiKeyProvider` trait implementation

4. **Assert templates do NOT contain known bad patterns:**
   - No `connection().await`
   - No `Vec<serde_json::Value>` passed to `ResourceCollection::paginated`

This serves as a regression test — if templates are changed later, this catches obvious errors.
  </action>
  <verify>cargo test --all-features -- make_api</verify>
  <done>make_api has template validation tests that catch known bad patterns and verify correct code generation for a representative model.</done>
</task>
