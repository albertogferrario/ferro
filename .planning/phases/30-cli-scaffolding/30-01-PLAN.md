**1. Add `reqwest` dependency to ferro-cli/Cargo.toml:**
```toml
reqwest = { version = "0.12", features = ["blocking", "json"] }
```
Use `blocking` feature since the CLI main function is synchronous (tokio is only used for db commands internally).

**2. Create `ferro-cli/src/ai.rs` module with two concerns:**

**a) Anthropic API client (`call_anthropic` function):**
```rust
pub fn call_anthropic(prompt: &str) -> Result<String, String>
```
- Reads `ANTHROPIC_API_KEY` from environment (via `std::env::var`)
- Makes a blocking POST to `https://api.anthropic.com/v1/messages`
- Headers: `x-api-key`, `anthropic-version: 2023-06-01`, `content-type: application/json`
- Body: `{"model": "claude-sonnet-4-5-20250929", "max_tokens": 8192, "messages": [{"role": "user", "content": prompt}]}`
- Model can be overridden via `FERRO_AI_MODEL` env var (default: `claude-sonnet-4-5-20250929`)
- Parses response JSON, extracts `content[0].text`
- Returns the text content or a descriptive error
- On missing API key: return `Err` with message suggesting `export ANTHROPIC_API_KEY=...` or `--no-ai` flag

**b) Context assembly (`build_view_context` function):**
```rust
pub fn build_view_context(name: &str, description: &str) -> String
```
Assembles a prompt with three sections of project context:

**Section 1 — Component catalog (hardcoded const string):**
A concise reference of all 20 JSON-UI components with their props, types, and variants. This is a const string embedded in the binary (not read from files at runtime). Format each component compactly:
```
## Component Catalog

### Text
Props: content (String), element (h1|h2|h3|span|p)

### Button
Props: label (String), variant (default|secondary|destructive|outline|ghost|link), size (xs|sm|default|lg), disabled (Option<bool>), icon (Option<String>), icon_position (left|right)

### Card
Props: title (String), description (Option<String>), children (Vec<ComponentNode>), footer (Vec<ComponentNode>)
...
```
Include ALL 20 components: Text, Button, Card, Table, Form, Input, Select, Alert, Badge, Modal, Checkbox, Switch, Separator, DescriptionList, Tabs, Breadcrumb, Pagination, Progress, Avatar, Skeleton.

Include Action struct: `handler (String), method (GET|POST|PUT|PATCH|DELETE), confirm (Option<ConfirmDialog>)`

Include ComponentNode wrapper: `key (String), component (Component), action (Option<Action>), visibility (Option<Visibility>)`

Include JsonUiView builder: `.new().title().layout().data().component().components()`

**Section 2 — Project models (scanned at runtime):**
Scan `src/models/*.rs` files in the current directory. For each model file, extract struct fields (field name + type). Format as:
```
## Project Models
### User: id (i32), name (String), email (String), created_at (DateTime)
### Post: id (i32), title (String), body (String), user_id (i32)
```
If no models directory exists, omit this section.

**Section 3 — Project routes (scanned at runtime):**
Use the existing `generate_routes::parse_routes_file()` function to parse `src/routes.rs`. Format as:
```
## Project Routes
GET /users -> controllers::user::index (name: "users.index")
POST /users -> controllers::user::store (name: "users.store")
GET /users/{id} -> controllers::user::show (name: "users.show")
```
If no routes.rs exists, omit this section.

**Prompt structure (assembled by `build_view_context`):**
```
You are a Ferro framework JSON-UI view code generator. Generate a Rust file that builds a JsonUiView.

[Component Catalog section]
[Project Models section - if available]
[Project Routes section - if available]

## Instructions

Generate a Rust file for `src/views/{name}.rs` with:
- A `//! {Title} JSON-UI view` module doc comment
- `use ferro::{...};` imports (only import types actually used)
- A `pub fn view() -> JsonUiView` function using the builder pattern
- Use real route names for action handlers when matching routes exist
- Use data_path bindings for form fields when matching model fields exist
- Choose appropriate components for the described UI
- Use .layout("app") unless the description suggests auth/login (use "auth")

View name: {name}
Description: {description}

Return ONLY the Rust source code. No markdown fences, no explanation.
```

**3. Register module in main.rs:**

Look for `pub struct {Name} {` and extract `pub field: Type,` lines. This is fast and sufficient for context — it doesn't need to be perfect, just informative for the AI.

**1. Create `ferro-cli/src/commands/make_json_view.rs`:**

Follow `make_controller.rs` pattern. The `run()` function signature:
```rust
pub fn run(name: String, description: Option<String>, no_ai: bool, layout: Option<String>)
```

**Flow:**
1. Convert name to snake_case for filename
2. Validate identifier
3. Check `src/views/` exists (create if not — unlike controllers, views dir may not exist yet in a project)
4. Check file doesn't already exist
5. **If `--no-ai` OR `ANTHROPIC_API_KEY` not set:**
   - Use static template from `templates::json_view_template()`
   - If API key missing and `--no-ai` not set, print info message: "No ANTHROPIC_API_KEY found, using static template. Set the key or use --no-ai to suppress this message."
6. **If AI enabled:**
   - Print spinner: "Generating view with AI..."
   - Call `ai::build_view_context(&snake_name, description)` to assemble prompt
   - Call `ai::call_anthropic(&prompt)` to get generated code
   - Strip any markdown fences from response (```rust ... ```) if AI adds them despite instructions
   - Use the AI response as file content
   - On AI error: fall back to static template with warning
7. Write file to `src/views/{snake_name}.rs`
8. Update `src/views/mod.rs` (same logic as make_controller's `update_mod_file`)
9. Print success message with usage hint:
```
View {name} created successfully!

Usage:
  1. Use the view in a handler:
     use crate::views::{snake_name};

     pub async fn index() -> Response {
         JsonUi::render(&{snake_name}::view(), &json!({}))
     }
```
