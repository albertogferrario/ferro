# Phase 122.2 Plan 02: Revert ferro-cli ↔ ferro-mcp Circular Dependency Summary

Reverted the Phase 123 subprocess workaround. ferro-mcp is now library-only and ferro-cli launches it in-process via `tokio::runtime::Runtime::block_on(ferro_mcp::run())`.

## What Changed

- Deleted `ferro-mcp/src/bin/ferro-mcp.rs`; bootstrap now lives in `pub async fn run()` in `ferro-mcp/src/lib.rs`.
- Removed the `ferro-cli` dep from `ferro-mcp/Cargo.toml` (the cycle).
- Re-added `ferro-mcp = { path = "../ferro-mcp" }` to `ferro-cli/Cargo.toml`.
- Rewrote `ferro-cli/src/commands/mcp.rs`: removed `Command::new("ferro-mcp")` subprocess plumbing; now `set_current_dir` to project root then call `ferro_mcp::run()` on a fresh tokio runtime.

## Verification

- `cargo fmt --all -- --check` clean
- `cargo clippy --all --all-targets --no-deps -- -D warnings` clean
- `cargo test --all-features` — 0 failures
- `cargo build --workspace` — success, no circular deps

## Deviations from Plan

None — plan executed as written. The CLI passes project root to ferro-mcp via `set_current_dir` rather than threading it through the function signature, since `ferro_mcp::run()` already resolves CWD.
