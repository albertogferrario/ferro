# Phase 122.2 Plan 08: Doctor Check List Revision Summary

Replaced the Phase 124 doctor check set with the 9-check list mandated by
SCOPE §12, deleting the workspace cargo-chef and path-deps "warn for prod"
heuristics that became obsolete after the cargo-chef rewrite (Plan 06) and
the introduction of `Cargo.docker.toml` (Plan 02 §2).

## What changed

Registry order (SCOPE §12):
1. `toolchain_match` — rustc vs `rust-toolchain.toml` channel.
2. `db_connection` — DATABASE_URL probe via `db:status` subprocess.
3. `migrations_pending` — applied vs pending count.
4. `local_env_parity` — `.env.example` keys vs `.env` keys.
5. `deploy_env_parity` — `.env.production` keys vs commented scaffold in
   `.do/app.yaml`. Skipped when either file absent.
6. `cargo_docker_toml_staleness` — ferro* version deps in `Cargo.docker.toml`
   vs current workspace path-dep versions in `Cargo.toml`. Warn on drift,
   skip when file absent or wildcard.
7. `generated_artifacts` — Dockerfile / .dockerignore / .do/app.yaml presence
   (warn-level).
8. `database_url_sqlite_in_prod` — hard-error if `.env.production` declares
   `DATABASE_URL=sqlite:...`.
9. `git_clean_and_pushed` — `git status --porcelain` + `git log @{upstream}..HEAD`.

The Check trait, `Report`/`CheckResult` types, JSON output, and exit-code
contract (non-zero only on Error) are unchanged.
