# Phase 122.2 Plan 04: Stub legacy docker_init/do_init and templates Summary

**Stripped the Phase 122 docker_init/do_init commands, their renderers, and Dockerfile/app.yaml templates down to compile-only stubs so Plans 06 and 07 can rewrite them against the new SCOPE design from a clean slate.**

## Performance

- **Duration:** ~5 min
- **Tasks:** 2
- **Files modified:** 9

## Accomplishments

- `commands/docker_init::run` is now a single `_force` no-op stub; `DockerInitArgs` clap surface reduced from `force/ferro_ref/runtime_deps` to just `force`.
- `commands/do_init::run` is now a single `_force` no-op stub; `DoInitArgs` clap surface reduced from `repo/region/force/ferro_ref` to just `force`.
- `templates/docker.rs` no longer contains `DockerfileContext`, `render_dockerfile`, or any of its helper functions/tests. Only the static `dockerignore_template()` and `docker_compose_template(...)` survive (still consumed by `commands/docker_compose.rs` and the project scaffold).

- `main.rs` clap variants and dispatch arms updated accordingly.

Kept `EnvEntry`, `parse_env_entries`, and `find_ferro_path_deps` for `doctor/checks/env_completeness.rs` and `doctor/checks/path_deps.rs`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Updated main.rs clap variants and dispatch arms**

- **Found during:** Task 1
- **Issue:** Plan tasks describe reducing the args structs in `commands/docker_init.rs` and `commands/do_init.rs` to `pub force: bool`, but those crates do not declare clap-derive arg structs — the variants live in `ferro-cli/src/main.rs` and the run functions take positional args. Leaving main.rs unchanged would break compilation.
- **Fix:** Reduced `Commands::DockerInit` to `{ force: bool }` and `Commands::DoInit` to `{ force: bool }` in main.rs, and updated the dispatch arms to call `commands::docker_init::run(force)` and `commands::do_init::run(force)` respectively.
- **Files modified:** `ferro-cli/src/main.rs`
- **Verification:** `cargo check -p ferro-cli` clean
- **Committed in:** `a154f789`

**2. [Rule 3 - Blocking] Trimmed deploy/mod.rs transitional helpers**

- **Found during:** Task 2
- **Issue:** Plan 03 left four transitional helpers in `deploy/mod.rs` (`EnvEntry`/`parse_env_entries`, `is_secret`, `find_ferro_path_deps`, `render_rewrite_script`) to keep unmigrated consumers compiling. After this plan, `is_secret` had no callers (was used only by the deleted `templates/do.rs` renderer) and `render_rewrite_script` had no callers (was used only by the old `docker_init.rs`). The execution prompt explicitly invites simplifying these stubs once unconsumed.
- **Fix:** Removed `is_secret` and `render_rewrite_script` (and the latter's `FERRO_REPO` constant + `fs/io/Path` imports). Kept `EnvEntry`, `parse_env_entries`, and `find_ferro_path_deps` because `doctor/checks/env_completeness.rs` and `doctor/checks/path_deps.rs` still consume them (slated for rewrite in plan 12).
- **Files modified:** `ferro-cli/src/deploy/mod.rs`
- **Verification:** `cargo check -p ferro-cli` + `cargo test -p ferro-cli` clean
- **Committed in:** `a154f789`

**3. [Rule 3 - Blocking] Unwired `templates::do_spec` module**

- **Found during:** Task 2
- **Issue:** `templates/mod.rs` declared `pub mod do_spec` (path-aliased to `do.rs`). After truncating `do.rs` to a placeholder comment, the path alias still pulled in an empty module — harmless, but cleaner to drop the wiring entirely so Plan 07 starts from a known-empty slate.
- **Fix:** Removed `#[path = "do.rs"] pub mod do_spec;` from `templates/mod.rs`. The orphaned `do.rs` file remains in place (per the plan's literal "replace contents") and Plan 07 will re-mod it.
- **Files modified:** `ferro-cli/src/templates/mod.rs`
- **Verification:** `cargo check -p ferro-cli` clean
- **Committed in:** `a154f789`
