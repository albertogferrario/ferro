<task type="auto">
  <name>Task 1: Create layout module with Layout trait, LayoutContext, LayoutRegistry, and DefaultLayout</name>
  <files>ferro-json-ui/src/layout.rs, ferro-json-ui/src/lib.rs</files>
  <action>
Create `ferro-json-ui/src/layout.rs` with:

1. **LayoutContext struct** — passed to layout functions:
   ```
   pub struct LayoutContext<'a> {
       pub title: &'a str,
       pub content: &'a str,        // Rendered component HTML fragment
       pub head: &'a str,           // Additional <head> content (Tailwind CDN, custom styles)
       pub body_class: &'a str,     // CSS classes for <body>
       pub view_json: &'a str,      // Serialized view JSON (for data-view attr)
       pub data_json: &'a str,      // Serialized data JSON (for data-props attr)
   }
   ```

2. **Layout trait** — `Send + Sync` for thread safety:
   ```
   pub trait Layout: Send + Sync {
       fn render(&self, ctx: &LayoutContext) -> String;
   }
   ```

3. **DefaultLayout struct** — minimal but functional HTML page:
   - `<!DOCTYPE html>` with lang="en"
   - Standard meta charset + viewport tags
   - Title from ctx.title
   - Head content from ctx.head
   - Body with ctx.body_class
   - `<div id="ferro-json-ui" data-view="..." data-props="...">` wrapper containing ctx.content
   - This mirrors the existing HTML shell in framework/src/json_ui/mod.rs

4. **AppLayout struct** — dashboard-style layout with nav + sidebar + main content:
   - Reuses the `base_document` helper (see below)
   - Includes navigation partial at top
   - Flex layout with sidebar on left, main content area on right
   - Content wrapped in `<main class="flex-1 p-6">`
   - The ferro-json-ui wrapper div goes inside main

5. **AuthLayout struct** — centered card layout for login/register pages:
   - Centered vertically and horizontally
   - Max-width container with card styling
   - No navigation or sidebar

6. **base_document helper** — private function to avoid duplicating the HTML/head/body boilerplate:
   ```
   fn base_document(title: &str, head: &str, body_class: &str, body_content: &str) -> String
   ```
   All three layouts call this instead of duplicating `<!DOCTYPE html>...`.

7. **LayoutRegistry struct**:
   - `layouts: HashMap<String, Box<dyn Layout>>`
   - `default: String` (name of the default layout, initially "default")
   - `new()` — creates registry with DefaultLayout pre-registered as "default", AppLayout as "app", AuthLayout as "auth"
   - `register(&mut self, name: impl Into<String>, layout: impl Layout + 'static)` — add/replace layout
   - `render(&self, name: Option<&str>, ctx: &LayoutContext) -> String` — look up by name (None → default), fall back to default if name not found
   - `has(&self, name: &str) -> bool` — check if layout exists

8. **Global registry** via `std::sync::OnceLock<std::sync::RwLock<LayoutRegistry>>`:
   - `pub fn global_registry() -> &'static RwLock<LayoutRegistry>` — lazy init
   - `pub fn register_layout(name: impl Into<String>, layout: impl Layout + 'static)` — convenience
   - `pub fn render_layout(name: Option<&str>, ctx: &LayoutContext) -> String` — convenience

Use `OnceLock` (stable since Rust 1.70), NOT `once_cell` external crate. The pattern matches how route names are registered globally in the framework.

Add `pub mod layout;` to `ferro-json-ui/src/lib.rs` and re-export key types:
```
pub use layout::{Layout, LayoutContext, LayoutRegistry, DefaultLayout, AppLayout, AuthLayout};
pub use layout::{global_registry, register_layout, render_layout};
```

Include unit tests in `layout.rs`:
- DefaultLayout produces valid HTML with all LayoutContext fields interpolated
- AppLayout includes navigation and sidebar sections
- AuthLayout centers content
- LayoutRegistry returns default for None name
- LayoutRegistry returns default for unknown name
- LayoutRegistry renders registered layout by name
- register_layout/render_layout global functions work
- base_document helper produces valid HTML structure

**Important:** Use the existing `render.rs::html_escape()` pattern for escaping title and body_class in layout output. Import it as `crate::render::html_escape` or duplicate the 5-line function locally if render's html_escape is not pub. Check render.rs — if html_escape is `fn` (private), make it `pub(crate)` so layout.rs can use it.

<task type="auto">
  <name>Task 2: Add reusable partial functions for navigation, sidebar, and footer</name>
  <files>ferro-json-ui/src/layout.rs</files>
  <action>
Add partial helper types and functions to `layout.rs` (same file, below the layout implementations):

1. **NavItem struct**:
   ```
   pub struct NavItem {
       pub label: String,
       pub url: String,
       pub active: bool,
   }
   ```
   With `NavItem::new(label, url) -> Self` (active defaults to false) and `NavItem::active(mut self) -> Self`.

2. **SidebarSection struct**:
   ```
   pub struct SidebarSection {
       pub title: String,
       pub items: Vec<NavItem>,
   }
   ```
   With `SidebarSection::new(title, items) -> Self`.

3. **navigation(items: &[NavItem]) -> String** — renders a `<nav>` with Tailwind classes:
   - `<nav class="bg-white border-b border-gray-200 px-4 py-3">`
   - `<div class="flex items-center space-x-6">` containing links
   - Active items get `text-blue-600 font-medium`, inactive get `text-gray-600 hover:text-gray-900`
   - Each item is an `<a href="..." class="...">label</a>`

4. **sidebar(sections: &[SidebarSection]) -> String** — renders an `<aside>`:
   - `<aside class="w-64 bg-gray-50 border-r border-gray-200 p-4 min-h-screen">`
   - Each section: `<div class="mb-6">` with `<h3 class="text-xs font-semibold text-gray-500 uppercase tracking-wider mb-2">title</h3>`
   - Items as `<a>` links in a `<ul>` with same active/inactive styling

5. **footer(text: &str) -> String** — renders a simple `<footer>`:
   - `<footer class="border-t border-gray-200 px-4 py-3 text-center text-sm text-gray-500">`
   - Text content inside

All partial functions escape user-provided strings (labels, URLs, text) with html_escape.

Update AppLayout to use these partials internally with placeholder items to demonstrate the pattern. AppLayout can use `navigation(&[])` and `sidebar(&[])` by default (empty nav/sidebar) — users customize by creating their own Layout impl that calls these partials with real data.

Add tests:
- navigation renders empty nav gracefully
- navigation renders items with correct classes
- navigation marks active item
- sidebar renders sections with headers
- footer renders text
- html_escape is applied to all user strings
