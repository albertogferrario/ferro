<task type="auto">
  <name>Task 1: Replace hardcoded HTML shell in framework render methods with layout registry calls</name>
  <files>framework/src/json_ui/mod.rs</files>
  <action>
Refactor `JsonUi::render_with_config` and `JsonUi::render_with_errors_config` in `framework/src/json_ui/mod.rs`:

1. **Extract shared logic into a private helper** — both methods do the same work (resolve → serialize → build head → render components → build HTML). Create:
   ```
   fn build_response(view: &JsonUiView, data: &serde_json::Value, config: &JsonUiConfig) -> Response
   ```
   that both `render_with_config` and `render_with_errors_config` delegate to after their respective resolve steps.

2. **Replace the hardcoded HTML format! block** with:
   ```rust
   let ctx = ferro_json_ui::LayoutContext {
       title: html_escape(title),     // escaped title
       content: &rendered,             // component HTML fragment
       head: &head,                    // built from config
       body_class: &html_escape(&config.body_class),
       view_json: &html_escape_attr(&view_json),
       data_json: &html_escape_attr(&data_json),
   };

   let layout_name = view.layout.as_deref();
   let html = ferro_json_ui::render_layout(layout_name, &ctx);
   ```

3. **Remove the duplicated HTML template** — the `format!(r#"<!DOCTYPE html>..."#)` blocks in both methods are completely replaced by the layout call. This is the key deduplication win.

4. **LayoutContext escaping contract:** The framework is responsible for escaping values BEFORE putting them into LayoutContext. The layout implementations receive pre-escaped values and interpolate them directly. This keeps layouts simple (just format!()) and security centralized in the framework. Make the LayoutContext fields contain already-escaped strings:
   - `title` → html_escape applied
   - `body_class` → html_escape applied
   - `view_json` → html_escape_attr applied
   - `data_json` → html_escape_attr applied
   - `content` → already HTML (from render_to_html)
   - `head` → already HTML (built by framework)

5. **The head building logic stays in framework** — it reads JsonUiConfig and produces the head string. This is passed to LayoutContext.head.

6. **Ensure all existing tests still pass.** The output HTML structure should be identical to before for the default layout — same DOCTYPE, same meta tags, same div#ferro-json-ui wrapper. Tests that check for these strings should continue to pass.

Do NOT touch render_json methods — they return JSON, not HTML, so layouts don't apply.
