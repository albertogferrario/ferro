<task type="auto">
  <name>Task 1: Add x-mcp extension extraction to spec parser</name>
  <files>ferro-api-mcp/src/types.rs, ferro-api-mcp/src/spec.rs</files>
  <action>
**types.rs changes:**
1. Add `pub hint: Option<String>` field to `ApiOperation` struct (after `input_schema`)
2. Update `ApiOperation::new()` to set `hint: None`

**spec.rs changes in `parse_spec()` — inside the `for &(method, op_opt) in methods` loop, after `if let Some(operation) = op_opt`:**

1. Before extracting tool_name and description, check for x-mcp-hidden:
   ```
   let hidden = operation.extensions
       .get("x-mcp-hidden")
       .and_then(|v| v.as_bool())
       .unwrap_or(false);
   if hidden { continue; }
   ```

2. Extract x-mcp overrides:
   ```
   let mcp_tool_name = operation.extensions
       .get("x-mcp-tool-name")
       .and_then(|v| v.as_str())
       .map(String::from);
   let mcp_description = operation.extensions
       .get("x-mcp-description")
       .and_then(|v| v.as_str())
       .map(String::from);
   let mcp_hint = operation.extensions
       .get("x-mcp-hint")
       .and_then(|v| v.as_str())
       .map(String::from);
   ```

3. Use x-mcp values as overrides with existing behavior as fallback:
   ```
   let tool_name = mcp_tool_name
       .unwrap_or_else(|| generate_tool_name(operation.operation_id.as_deref(), method, path));
   let description = mcp_description
       .unwrap_or_else(|| build_description(operation, &tool_name));
   ```

4. Set hint on the operation:
   ```
   op.hint = mcp_hint;
   ```

**Add tests (in spec.rs tests module):**
- `x_mcp_tool_name_overrides_operation_id`: Spec with both operationId and x-mcp-tool-name → tool_name uses x-mcp value
- `x_mcp_description_overrides_summary`: Spec with summary and x-mcp-description → description uses x-mcp value
- `x_mcp_hidden_excludes_operation`: Spec with x-mcp-hidden: true → operation not in results
- `x_mcp_hint_extracted`: Spec with x-mcp-hint → hint field populated on ApiOperation
- `x_mcp_fallback_without_extensions`: Spec without any x-mcp extensions → existing behavior unchanged (tool_name from operationId, description from summary)
- `x_mcp_partial_extensions`: Spec with only x-mcp-tool-name (no description/hint) → tool_name overridden, description falls back to summary

Use the existing `spec_shell` helper. Add x-mcp extensions directly in the operation JSON objects — openapiv3 preserves all `x-*` keys in `operation.extensions: IndexMap<String, Value>`.

This keeps the hint visible to AI agents consuming the tool list without requiring any MCP protocol changes.
