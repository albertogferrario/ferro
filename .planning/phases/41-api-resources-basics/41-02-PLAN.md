<task type="auto">
  <name>Task 1: Implement ApiResource derive macro</name>
  <files>ferro-macros/src/resource.rs, ferro-macros/src/lib.rs</files>
  <action>
Create `ferro-macros/src/resource.rs` implementing the `ApiResource` derive macro.

**Struct-level attributes** parsed from `#[resource(...)]`:
- `model = "path::to::Model"` — generates `From<Model>` impl alongside `Resource` impl. The path is parsed as a Rust type path. Optional — if omitted, only `Resource` impl is generated.

**Field-level attributes** parsed from `#[resource(...)]`:
- `rename = "new_name"` — use different key name in JSON output. Default: field name as-is.
- `skip` — exclude this field from the resource output entirely.

**Generated code for a struct like:**
```rust
#[derive(ApiResource)]
#[resource(model = "entities::users::Model")]
pub struct UserResource {
    pub id: i32,
    pub name: String,
    #[resource(rename = "member_since")]
    pub created_at: String,
    #[resource(skip)]
    pub password_hash: String,
}
```

**Generates:**
```rust
impl ferro::Resource for UserResource {
    fn to_resource(&self, _req: &ferro::Request) -> ferro::serde_json::Value {
        ferro::ResourceMap::new()
            .field("id", ferro::serde_json::json!(self.id))
            .field("name", ferro::serde_json::json!(self.name))
            .field("member_since", ferro::serde_json::json!(self.created_at))
            .build()
    }
}

impl From<entities::users::Model> for UserResource {
    fn from(model: entities::users::Model) -> Self {
        Self {
            id: model.id,
            name: model.name,
            created_at: model.created_at,
            password_hash: model.password_hash,
        }
    }
}
```

**Implementation approach:**
- Parse struct with `syn::DeriveInput`
- Extract struct-level `#[resource(model = "...")]` by iterating `input.attrs` and parsing meta lists
- For each field in `syn::Fields::Named`, check for `#[resource(skip)]` and `#[resource(rename = "...")]`
- Generate `ResourceMap::new()` chain with `.field()` calls for non-skipped fields, using rename if present
- If `model` attribute present, parse the path as `syn::Path` and generate `From<ModelPath>` impl mapping all fields (including skipped ones — `From` copies all fields, `to_resource` selects which to expose)
- Use `ferro::` prefix for all framework types in generated code (matches existing macro patterns in handler.rs, model.rs)
- Use `ferro::serde_json::json!()` for value serialization (serde_json is re-exported as `#[doc(hidden)]` from framework)

**Error handling:**
- If `#[resource(model = "...")]` value is not a valid Rust path, emit compile error
- If `#[resource(...)]` contains unknown attribute, emit compile error
- If applied to non-struct or tuple struct, emit compile error

Register in `ferro-macros/src/lib.rs`:
- Add `mod resource;`
- Add derive macro function:
```rust
#[proc_macro_derive(ApiResource, attributes(resource))]
pub fn derive_api_resource(input: TokenStream) -> TokenStream {
    resource::api_resource_impl(input)
}
```

Check `ferro-macros/Cargo.toml` — ensure `syn` has `full` feature (should already be present for existing macros). No new dependencies needed.
  </action>
  <verify>cargo build -p ferro-macros 2>&1 | tail -5</verify>
  <done>ApiResource derive macro compiles. Registered in lib.rs with `attributes(resource)`.</done>
