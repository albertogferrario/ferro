```rust
pub struct StripeChargeRefunded {
    pub event_id: String,
    pub charge_id: String,
    pub payment_intent_id: Option<String>,
    pub amount_refunded_cents: i64,
    pub metadata: HashMap<String, String>,
}

impl StripeEvent for StripeChargeRefunded {
    fn from_raw(event: &stripe::Event) -> Option<Self> {
        if event.type_ != stripe::EventType::ChargeRefunded {
            return None;
        }
        match &event.data.object {
            stripe::EventObject::Charge(charge) => Some(Self {
                event_id: event.id.to_string(),
                charge_id: charge.id.to_string(),
                payment_intent_id: charge.payment_intent.as_ref().map(|e| e.id().to_string()),
                amount_refunded_cents: charge.amount_refunded,
                metadata: charge.metadata.clone(),
            }),
            _ => None,
        }
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe webhook -> ferro-stripe parser | Untrusted JSON crosses here. Signature verification happens upstream of `from_raw` (HMAC at the dispatcher); `from_raw` operates on an already-signature-verified, serde-deserialized `stripe::Event`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-193-01 | Tampering | `StripeChargeRefunded::from_raw` reading `charge.refunds` | mitigate | The new field is read from an already serde-deserialized, signature-verified `stripe::Event`. No new input parsing surface, no string interpolation, no injection sink — `refund_id` is an inert `Option<String>` the consumer treats as an opaque lookup key. |
| T-193-02 | Denial of Service | empty/missing refunds list panicking the parser | mitigate | The accessor uses `.as_ref().and_then(|l| l.data.first()).map(...)` — total over a missing/empty list, returning `None` instead of indexing. The `behavior` block tests the empty-list path explicitly. |
| T-193-03 | Information Disclosure | refund_id surfaced to the consumer | accept | `refund_id` is a Stripe object identifier (`re_...`), not PII or a secret; it is already present in the webhook payload the consumer is authorized to receive. No new disclosure. |
| T-193-04 | Spoofing | forged charge.refunded event injecting a refund_id | accept | Out of scope for this change — webhook authenticity is enforced by the existing upstream HMAC signature check before `from_raw` runs. This phase adds no new ingress path. |
</threat_model>
