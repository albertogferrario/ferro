    .title("Users")

Rules for the port:

1. `JsonUiView::new().title(...).component(ComponentNode { key, component: Component::X(XProps { fields }), action, visibility })` becomes `Spec::builder().title(...).element(key, Element::new("X").prop(field_name, field_value).prop(...).action(a).visible(v)).build().unwrap()`.
2. For each Props struct, translate its named fields into `.prop(field_name_as_str, value)` calls. Use snake_case string keys (matches serde rename_all convention).
3. `ButtonVariant::Primary` and similar enums serialize to snake_case strings (`"primary"`) — use the string directly in `.prop("variant", "primary")`.
4. `Option::None` fields are simply omitted (the builder does not set what you do not call).
5. For tests that call `.render(&view, ...)` or `.render_with_errors(&view, ...)`, replace `&view` with `&spec`.
6. The `sample_view() -> JsonUiView` helper at line 268 becomes `sample_spec() -> Spec`. Rename callers correspondingly. Same for `form_view_with_inputs` at line 539.
7. Tests asserting on the rendered HTML must relax assertions where the placeholder renderer behaves differently from v1's tree walker. Specifically:

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| handler -> `JsonUi::render(&Spec, ...)` | Spec originates from handler code — typically trusted, but eventually (Phase 119) loaded from JSON files or produced by AI. The framework MUST NOT panic on any Spec value that `Spec::from_json` or `SpecBuilder::build` produced. |

## Threats

| ID | Severity | Asset | Attack | Mitigation |
|----|----------|-------|--------|------------|
| T-115-09 | low | `JsonUi::render` | Handler passes a Spec containing untrusted user data in props (e.g., `content: "<script>"`) | Placeholder renderer escapes all HTML in the pretty-JSON output (T-115-06 from Plan 02). Test `test_title_xss_escapes` at line ~389 asserts this via the layout-level escape of `spec.title`. |
| T-115-10 | low | `JsonUi::render_json_with_errors` | Caller passes a large errors HashMap | `resolve_errors` walks `spec.elements` linearly. No exponential blowup. Errors field on Spec is gone (D-06), so no JSON payload bloat from `resolved.errors`. |

Security enforcement: Framework-layer threats at this plan are limited to surface reshape; no new attack surface introduced.
