<task type="auto">
  <name>Task 1: Add MailDriver enum and driver-specific config structs</name>
  <files>ferro-notifications/src/dispatcher.rs</files>
  <action>
  Add the following types to dispatcher.rs:

  1. `MailDriver` enum with `Smtp` (default) and `Resend` variants. Derive Debug, Clone, Default. Add `#[default]` on Smtp.

  2. `SmtpConfig` struct with fields: host (String), port (u16), username (Option<String>), password (Option<String>), tls (bool). Derive Clone.

  3. `ResendConfig` struct with field: api_key (String). Derive Clone.

  4. Refactor `MailConfig` to:
     - driver: MailDriver
     - from: String
     - from_name: Option<String>
     - smtp: Option<SmtpConfig>
     - resend: Option<ResendConfig>
     Derive Clone.

  5. Update `MailConfig::new()` to create an SMTP config (backwards compat):
     ```
     pub fn new(host, port, from) -> Self {
         Self {
             driver: MailDriver::Smtp,
             from: from.into(),
             from_name: None,
             smtp: Some(SmtpConfig { host: host.into(), port, username: None, password: None, tls: true }),
             resend: None,
         }
     }
     ```

  6. Add `MailConfig::resend(api_key, from)` constructor for Resend driver.

  7. Update builder methods:
     - `credentials()` → modifies `self.smtp` inner config (create SmtpConfig if None)
     - `from_name()` → stays on MailConfig (shared field)
     - `no_tls()` → modifies `self.smtp` inner config

  8. Update `send_mail()` to access config fields through the new structure. The SMTP sending code accesses `config.smtp.as_ref().unwrap()` for SMTP-specific fields and `config.from`/`config.from_name` for shared fields. Keep the existing SMTP logic working — no Resend dispatch yet (that's Plan 02).

  9. Update existing tests in `mod tests` to work with new struct layout.
  </action>

<task type="auto">

  <files>ferro-notifications/src/dispatcher.rs, ferro-notifications/src/lib.rs, framework/src/lib.rs</files>
  <action>
  1. Rewrite `MailConfig::from_env()` to support driver selection:
     - Read `MAIL_DRIVER` env var, default to "smtp" if unset or empty
     - Read shared vars: `MAIL_FROM_ADDRESS` (required for both), `MAIL_FROM_NAME` (optional)
     - Branch on driver:
       - "smtp" (default): Read MAIL_HOST (required), MAIL_PORT (default 587), MAIL_USERNAME, MAIL_PASSWORD, MAIL_ENCRYPTION. Return None if MAIL_HOST missing.
       - "resend": Read RESEND_API_KEY (required). Return None if RESEND_API_KEY missing.
     - Return None if MAIL_FROM_ADDRESS is missing (required for all drivers)

     Key: When MAIL_DRIVER is unset, behavior MUST match current behavior (defaults to SMTP, requires MAIL_HOST). Existing apps with no MAIL_DRIVER env var must not break.

  2. Update `NotificationConfig::from_env()` docstring to mention MAIL_DRIVER and RESEND_API_KEY.

  3. In `ferro-notifications/src/lib.rs`: Add `MailDriver` to the pub use exports (alongside existing MailConfig).

  4. In `framework/src/lib.rs`: Add `MailDriver` to the ferro-notifications re-export line.
  </action>
