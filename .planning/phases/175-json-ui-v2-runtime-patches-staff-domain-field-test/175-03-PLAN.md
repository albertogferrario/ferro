to also resolve `{row.X}` against the same row object. Today the consumer authors

add `{row.X}` as an alias.

load-bearing case.

fn template_url(template: &str, row: &Value, row_key_value: &str) -> String {
    let mut url = template.to_string();
    if let Some(obj) = row.as_object() {
        for (col_key, col_val) in obj {
            let placeholder = format!("{{{col_key}}}");
            let val_str = match col_val {
                Value::String(s) => s.clone(),
                Value::Number(n) => n.to_string(),
                _ => continue,
            };
            url = url.replace(&placeholder, &val_str);
        }
    }
    url = url.replace("{row_key}", row_key_value);
    // ... `{id}` substitution
    url
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| handler data → DataTable row values | Row values come from handler-provided JSON; they are the data the operator is allowed to see. |
| DataTable row value → HTML attribute (`<form action="…">`, `<a href="…">`) | The substituted value is interpolated into an HTML attribute; existing `html_escape` pass downstream must continue to apply. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-175-03-01 | I (Information disclosure) / S (Spoofing) | `template_actions` / `template_url` substituting `{row.X}` into action URLs | mitigate | The substituted value is consistent with the column-cell substitution that already exists. Both feed into the same row-action emission, which already passes the final URL through `html_escape` before writing it into the HTML attribute. The F6 change extends the substitution path; it does NOT bypass any escape. Verify by grepping the row-action emission to confirm `html_escape` still wraps the final URL in `<a href="…">` / `<form action="…">`. |
| T-175-03-02 | T (Tampering) | `{row.X}` with a row value containing `..` or other path-traversal tokens | accept | The substituted value becomes a URL fragment; path-traversal interpretation happens at the server's routing layer, not at the DataTable. If a handler stores `../admin/elimina` in a row's `delete_url`, the handler has already trusted that value (it came from the handler's own data emission). DataTable is a faithful presentation layer; it is not the security boundary for the URL contents. (CLAUDE.md "validate-all-inputs in form handlers" applies.) |
| T-175-03-03 | T (Tampering) | A row key literally named `row` would create `{row}` and `{row.row}` substitution overlap | accept | `{row}` substitutes against the row's `row` field value (if present); `{row.row}` would substitute against the SAME field (`row.row` → row[`row`]). The two forms resolve to the same string; no inconsistency. Documented in RESEARCH.md Assumption A2. |
</threat_model>
