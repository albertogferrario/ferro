```rust
/// Returns `true` if this field should receive `__gt/__gte/__lt/__lte` range params.
///
/// Gate 5 is DataType-based (Integer/Float/DateTime/Date), NOT meaning-based, so
/// Money/Quantity/Percentage fields — excluded by `is_filter_field`'s meaning gate —
/// still get range params.
pub fn is_range_filter_field(field: &FieldDef) -> bool {
    if !field.readable { return false; }
    if field.is_list { return false; }
    if matches!(field.meaning, FieldMeaning::Sensitive) { return false; }
    if matches!(field.data_type, DataType::Json | DataType::Binary) { return false; }
    matches!(
        field.data_type,
        DataType::Integer | DataType::Float | DataType::DateTime | DataType::Date
    )
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → write inputSchema | The create/update schemas define exactly which declared fields the agent may supply. A Sensitive or server-injected field leaking into a schema is an information-disclosure / tampering surface. |
| agent → list_ filter params | New `__op` and `sort` params widen the advertised filter surface. The schema must not advertise filtering on fields that read execution would reject, but advertising is non-load-bearing — enforcement is Plan 04's allowlist. |

No new authorization or runtime execution here — this plan only emits JSON Schema. Write
authorization, tenant injection, and the non-disclosure envelope are Phase 242.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-240-04 | Information Disclosure | create/update schema builders | mitigate | Both builders gate every data field through `is_write_excluded_field`, so Sensitive/server-injected/UpdatedAt/list/SM-Status fields never appear in a write schema; covered by `test_create_schema_exclusions` + `test_create_schema_status_sm`. |
| T-240-05 | Tampering | update builder identifier handling | mitigate | The identifier is injected as the sole required field and data fields stay optional, so an agent cannot omit the target id nor be required to send server-managed columns; covered by `test_update_schema_patch_semantics`. |
| T-240-06 | Information Disclosure | extended `build_input_schema` (range/sort advertising) | accept | The schema only advertises params; actual SQL-level allowlisting of `__op` base fields and `sort` happens in Plan 04 dispatch. Advertising a param that dispatch later rejects is a non-disclosing 400-style error, not a leak. Equality `is_filter_field` allowlist is unchanged, preserving the existing read surface. |
</threat_model>
