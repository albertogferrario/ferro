The 7 Intent variants (ferro-projections/src/derive.rs intent_priority, ~lines 550-560):
  Browse, Focus, Collect, Process, Summarize, Analyze, Track  (plus Custom(String))

derive signals cheat-sheet (RESEARCH §derive signals — calibrate corpus tasks to these):
  - Browse: EntityName/Category fields, OneToMany/ManyToMany rels, simple CRUD. Baseline +0.1.
  - Focus: FreeText/ImageUrl/Url fields, OneToOne-inline / ManyToOne rels, more-readable-than-writable. Baseline +0.1.
  - Collect: >50% writable ratio, write-only fields, actions with >2 inputs.
  - Process: state machine WITH guards + branching; actions with transition_trigger + preconditions.
  - Track: state machine LINEAR (>2 non-final states, no branching), Status field, unguarded progression, final states.
  - Summarize: Money/Percentage/Quantity fields, mostly-read-only (>70% non-writable).
  - Analyze: DateTime + numeric co-occurrence (flat 0.35).
  Tie-break (lower wins): Process(0) > Track(1) > Collect(2) > Browse(3) > Focus(4) > Summarize(5) > Analyze(6).

CRITICAL Analyze↔Summarize margin (RESEARCH / COMP-02 catalog.rs lines 12-19): Analyze's
datetime_numeric_cooccurrence is a flat 0.35 that does NOT scale; each Money/Percentage/Quantity
field adds 0.30 to Summarize. So an Analyze corpus task must describe EXACTLY ONE numeric-aggregate
field + a DateTime field — two numeric fields flip the derived winner to Summarize and break T2.
