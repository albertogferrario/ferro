  <action>
    Create `ferro-whatsapp/src/client.rs` implementing the OnceLock facade pattern (matching ferro-stripe/src/client.rs):

    1. Two `OnceLock` statics: `WA_CLIENT: OnceLock<reqwest::Client>` and `WA_CONFIG: OnceLock<WhatsAppConfig>`

    2. `pub struct WhatsApp;` with:
       - `pub fn init(config: WhatsAppConfig)` — sets both OnceLocks (`.set().ok()` pattern)
       - `pub fn config() -> &'static WhatsAppConfig` — `.get().expect("WhatsApp::init() not called")`
       - `pub async fn send(to: &str, message: Message) -> Result<SendResult, Error>` — calls internal `send_message()`

    3. Internal `async fn send_message(client: &reqwest::Client, config: &WhatsAppConfig, to: &str, message: Message) -> Result<SendResult, Error>`:
       - Builds payload via `message.to_api_payload(to)`
       - POSTs to `config.api_url()` with `.bearer_auth(&config.access_token).json(&payload)`
       - On success (200): parses JSON response, extracts `messages[0].id` as wamid
       - On error: maps HTTP status to Error variants:
         - 429 -> Error::RateLimit
         - 401 -> Error::AuthError
         - 400 with body containing "invalid" -> Error::InvalidNumber (simplified heuristic)
         - Other 4xx/5xx -> Error::ApiError { status, message: body }
       - reqwest::Error -> Error::NetworkError(e.to_string())

    4. Internal helper `fn parse_wamid(body: &serde_json::Value) -> Result<String, Error>` extracting from `body["messages"][0]["id"]`

    5. Test helper `pub(crate) fn build_api_payload(to: &str, message: &Message, phone_number_id: &str) -> (String, serde_json::Value)` returning (url, json) for testing without HTTP calls

    Tests verify the payload construction and response parsing logic without making real HTTP calls. The `send_message` function's internal helpers are testable independently.
