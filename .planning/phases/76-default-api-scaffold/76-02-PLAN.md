  <name>Task 1: Create CRUD operations module with model-aware SQL builders</name>
  <files>ferro-mcp/src/tools/crud_operations.rs, ferro-mcp/src/tools/mod.rs</files>
  <action>
1. Create `ferro-mcp/src/tools/crud_operations.rs` with four public functions:

   **Shared helpers:**
   - `get_model_metadata(project_root: &Path, model_name: &str) -> Result<ModelMeta>` — reuse list_models logic to parse model struct, extract table name and field info (name, type, nullable, primary_key)
   - `get_database_url(project_root: &Path) -> Result<String>` — same as database_query.rs helper
   - `connect_db(project_root: &Path) -> Result<DatabaseConnection>` — connect via SeaORM
   - `rust_type_to_sql_cast(field_type: &str) -> &str` — map Rust types to expected SQL value handling (String→text, i32→integer, bool→boolean, DateTime→timestamp, Option<T>→nullable T)

   **crud_create:**
   ```rust
   pub async fn create(project_root: &Path, model: &str, data: &serde_json::Value) -> Result<CrudResult>
   ```
   - Parse model metadata to get table name and fields
   - Validate that all required (non-nullable, non-PK, non-default) fields are provided in `data`
   - Build parameterized INSERT using `Statement::from_sql_and_values()`:
     ```sql
     INSERT INTO {table} (field1, field2, ...) VALUES ($1, $2, ...) RETURNING *
     ```
   - For SQLite (no RETURNING), use INSERT then SELECT by last_insert_rowid()
   - Return inserted row as JSON

   **crud_list:**
   ```rust
   pub async fn list(project_root: &Path, model: &str, filters: Option<&serde_json::Value>, page: Option<u64>, per_page: Option<u64>) -> Result<CrudListResult>
   ```
   - Parse model metadata for table and fields
   - Build SELECT with optional WHERE clauses from `filters` JSON object (field=value pairs, simple equality)
   - Add `LIMIT` and `OFFSET` for pagination (default page=1, per_page=25)
   - Return rows + total count + pagination info

   **crud_update:**
   ```rust
   pub async fn update(project_root: &Path, model: &str, id: &serde_json::Value, data: &serde_json::Value) -> Result<CrudResult>
   ```
   - Parse model metadata for table, PK field, and fields
   - Validate provided fields exist in model
   - Build parameterized UPDATE:
     ```sql
     UPDATE {table} SET field1 = $1, field2 = $2 WHERE {pk} = $N RETURNING *
     ```
   - Return updated row as JSON

   **crud_delete:**
   ```rust
   pub async fn delete(project_root: &Path, model: &str, id: &serde_json::Value) -> Result<CrudResult>
   ```
   - Parse model metadata for table and PK
   - Build parameterized DELETE:
     ```sql
     DELETE FROM {table} WHERE {pk} = $1
     ```
   - Return `{"deleted": true, "id": ...}`

   **Result types:**
   ```rust
   #[derive(Debug, Serialize)]
   pub struct CrudResult {
       pub success: bool,
       pub data: Option<serde_json::Value>,
       pub message: String,
   }

   #[derive(Debug, Serialize)]
   pub struct CrudListResult {
       pub data: Vec<serde_json::Value>,
       pub total: u64,
       pub page: u64,
       pub per_page: u64,
   }
   ```

   **ModelMeta struct:**
   ```rust
   struct ModelMeta {
       table_name: String,
       primary_key: String,
       fields: Vec<FieldMeta>,
   }
   struct FieldMeta {
       name: String,
       column_name: String,
       field_type: String,
       is_nullable: bool,
       is_primary_key: bool,
   }
   ```

   **SQL injection prevention:** ALL queries use parameterized statements via SeaORM's `Statement::from_sql_and_values()`. Table and column names are validated against model metadata — only names that exist in the parsed model struct are allowed. Never interpolate user values into SQL strings.

   **Database backend detection:** Use `db.get_database_backend()` to detect Postgres vs SQLite and adjust SQL syntax (RETURNING clause, parameter placeholders $1 vs ?).

2. Add `pub mod crud_operations;` to `ferro-mcp/src/tools/mod.rs`.
