<objective>
Retire the `Cargo.docker.toml` dual-manifest pattern in ferro's scaffolding and doctor surface. Docker builds read `Cargo.toml` directly; local ferro development against an unpublished checkout happens through a hand-written, uncommitted `[patch.crates-io]` block. This plan is pure deletion plus narrow template edits — no new CLI verbs, no replacement doctor check, no hooks installer.

Purpose: Downstream projects scaffolded by `ferro new` no longer need two parallel manifests to reconcile local path deps with published versions. Clone-and-build works from the canonical `Cargo.toml`; ferro developers opt into a local patch block by hand when needed. The staleness-reconciliation surface (two doctor checks plus the rewriter) exists only to keep the dual manifest honest, so it all goes.

Output: Smaller ferro-cli deploy/doctor/templates surface; cleaner scaffolded Dockerfile and Cargo.toml; doctor registry with two fewer checks; docs updated to match.
</objective>
