**Helper function:**
```rust
fn assert_primary_intent(service: &ServiceDef, expected: Intent) {
    let scores = derive_intents(service);
    assert!(!scores.is_empty(), "derive_intents returned empty for '{}'", service.name);
    assert_eq!(
        scores[0].intent, expected,
        "Expected primary intent {:?} for '{}', got {:?} (confidence: {:.2}). Signals: {:?}",
        expected, service.name, scores[0].intent,
        scores[0].confidence, scores[0].matching_signals
    );
}
```

**12 validation fixtures (one test each):**

1. **Order Management → Process**: State machine with draft→submitted→approved→completed. Guards on submit (has_items) and approve (is_manager). Actions with transition_trigger. Money field (total), Status field.

2. **Product Catalog → Browse**: EntityName (name), Money (price), Category (category). has_many("reviews", "review"). No state machine.

3. **Blog Post → Focus**: FreeText (body), ImageUrl (featured_image), Url (canonical_url). belongs_to("author", "user"). Mostly readable fields.

4. **User Registration → Collect**: Many writable fields: EntityName (full_name), Email (email), write-only Sensitive (password), Phone (phone), FreeText (bio). >50% writable non-system fields.

5. **Revenue Report → Summarize**: Money (total_revenue), Percentage (margin), Quantity (units_sold). read_only_field for growth_rate (Percentage). No state machine, no actions with inputs.

6. **Sales Analytics → Analyze**: DateTime (order_date), Money (revenue), Quantity (units), Category (region). read_only_field (computed metrics). Multiple date + numeric signals.

7. **Shipment Tracking → Track**: Status (status), DateTime fields (shipped_at, delivered_at). Linear state machine: pending→shipped→in_transit→delivered (no guards, no branching). No actions with transition triggers.

8. **Comment Thread → Browse**: FreeText (content), has_many("replies", "comment"), belongs_to("author", "user"). EntityName absent but has_many relationship signals Browse.

9. **Support Ticket → Process**: State machine with open→in_progress→waiting→resolved→closed. Guards (is_assigned, customer_responded). Actions with transition_trigger (assign, resolve, close). Status + FreeText fields.

10. **User Profile → Focus**: ImageUrl (avatar), FreeText (bio), Url (website). one_to_one with inline navigation (address). Mostly readable.

11. **Survey Form → Collect**: All writable fields: multiple FreeText inputs, Boolean (consent), Email (contact_email). Actions with >2 inputs (submit_survey). No state machine.

12. **Activity Log → Track**: Status (event_type), CreatedAt (logged_at), read-only fields. No writable non-system fields. No state machine (Track derives from Status + temporal fields + read-only pattern).

Each test should call `assert_primary_intent(service, expected_intent)`.

<task type="auto">
  <name>Task 2: Edge cases and weight tuning</name>

  <action>
Add edge case tests to the tests module in derive.rs:

**Edge case tests:**
1. **Empty ServiceDef** — `ServiceDef::new("empty")` with no fields, no actions, no relationships, no state machine → returns Focus with ~0.5 confidence and "no_structural_signals" or baseline signals
2. **Minimal ServiceDef** — single Identifier field only → returns Focus or Browse with low confidence (baseline scores dominate)
3. **Maximal ServiceDef** — service with fields from every FieldMeaning category, state machine, relationships, actions → returns highest-confidence intent based on dominant signals
4. **Ambiguous ServiceDef** — service with roughly equal signals for two intents (e.g., Money + Status + has_many could be Browse or Summarize or Track) → returns a valid result (does not panic), top-2 within reasonable range
5. **IntentHint Primary override** — service that structurally derives Browse, but has IntentHint::Primary(Process) → returns Process as primary with confidence 1.0
6. **IntentHint Exclude** — service that structurally derives Process, but has IntentHint::Exclude(Process) → Process NOT in results, second-highest intent becomes primary
7. **Multiple IntentHints** — Primary(Collect) + Exclude(Browse) → Collect at top, Browse absent
8. **All confidences in valid range** — for every validation fixture, assert all IntentScore confidences are in [0.0, 1.0]

**Weight tuning (if needed):**
If any of the 12 validation fixtures fail assert_primary_intent, analyze the confusion pattern:
- What intent was derived instead? Check matching_signals for the wrong intent.
- Is the wrong intent getting a stronger signal from a specific analyzer?
- Adjust the relevant weight constant(s) at the top of derive.rs.
- Re-run ALL tests after each adjustment (prevent fixing one and breaking another).
- Document any weight changes as comments next to the constants.
