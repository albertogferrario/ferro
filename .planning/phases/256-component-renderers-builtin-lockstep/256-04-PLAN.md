<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser DOM → attribute selector | field names from data-selection-*/data-qty-* are concatenated into querySelector attribute selectors. |
| client running total → server | the displayed total is client-computed; only quantities are POSTed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-256-12 | Tampering | selection.rs querySelector construction | mitigate | Sanitize every field before building an attribute selector: `field = field.replace(/["\\\]]/g, '')` (copied from tiles.rs/numpad.rs) — prevents querySelector SyntaxError / selector injection. |
| T-256-13 | Tampering | line name/qty rendered into the DOM | mitigate | Line name/qty/total are written via `textContent` (never innerHTML) — no HTML parsing of tile-derived strings, so a hostile data-filter-text cannot inject markup client-side. |
| T-256-14 | Spoofing | client running total | mitigate | Total is display-only; the confirm POST carries only hidden-input quantities; the server re-derives the authoritative total from products × quantities. State this in the selection.rs header comment. |
| T-256-15 | Tampering | integer-cents money math | mitigate | All arithmetic is `parseInt`-based integer cents; the only float appears in the presentational `(n/100).toFixed(2)` display string, never in a stored/POSTed value (PITFALLS integer-cents rule). |
</threat_model>
