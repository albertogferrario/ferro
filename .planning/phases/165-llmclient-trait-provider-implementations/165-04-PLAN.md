## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env → AiConfig | `FERRO_AI_PROVIDER/MODEL/API_KEY/BASE_URL` (operator-configured). Unknown provider rejected at startup. |
| ferro-ai → Anthropic HTTPS (via classifier) | API key crosses in headers only; classifier delegates to AnthropicClient. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-165-01 | Information Disclosure | Error::Provider in classifier retry path | mitigate | Retry guard matches on `is_retryable()` / status, never reconstructs or logs the API key. Provider message text only. |
| T-165-02 | Information Disclosure | AiConfig reading FERRO_AI_API_KEY | mitigate | Key is moved directly into the provider constructor; never logged, never placed in `Error::Config` messages (Config messages name the missing var, not its value). |
| T-165-03 | Tampering / SSRF | FERRO_AI_BASE_URL passed to OpenAiClient/OllamaClient | accept | base_url is operator-configured server-side env, not end-user input. Documented assumption per security_context. |
| T-165-07 | Spoofing / Config error | unknown FERRO_AI_PROVIDER | mitigate | Construction-time `Error::Config` (not first-call) — fail fast on misconfiguration; no silent fallthrough to a wrong provider. |
</threat_model>
