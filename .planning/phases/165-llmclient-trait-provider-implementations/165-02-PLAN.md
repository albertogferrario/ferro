<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ferro-ai → Anthropic/OpenAI HTTPS | API key crosses in headers (x-api-key / Authorization: Bearer) only. |
| operator env → base_url | `FERRO_AI_BASE_URL` (Groq) is operator-configured (Plan 03 reads it), not end-user-supplied. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-165-02 | Information Disclosure | API key in request headers / error paths | mitigate | Key lives in `x-api-key` / `bearer_auth` headers only; never logged; error mapping uses `e.to_string()` (reqwest error) and provider `resp.text()`, neither of which echoes the request auth header. No `tracing` span includes the key. |
| T-165-03 | Tampering / SSRF | base_url-derived URLs in OpenAiClient | accept | base_url is operator-configured via `FERRO_AI_BASE_URL` (server-side env), not user-controlled at request time. No SSRF surface from end-user input. Documented assumption per security_context. |
| T-165-04 | Denial of Service | Streaming + non-streaming HTTP reads | mitigate | reqwest client retains the analog's 60s timeout on both constructors; bounds both `complete` and `complete_stream` connection time. |
| T-165-05 | Information Disclosure | reqwest-eventsource as public surface | mitigate | reqwest-eventsource imported only inside provider modules; never `pub use`d. Public-surface enforcement (grep) lands in Plan 04 (SC#6/D-09). |
</threat_model>
