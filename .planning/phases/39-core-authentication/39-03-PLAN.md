<task type="auto">
  <name>Task 1: Create make:auth command with scaffolding templates</name>
  <files>ferro-cli/src/commands/make_auth.rs, ferro-cli/src/templates/mod.rs</files>
  <action>
Create `ferro-cli/src/commands/make_auth.rs` that generates auth scaffolding.

The command should generate these files (skip if they already exist, with a message):

1. **Migration:** `src/migrations/mYYYYMMDD_HHMMSS_add_auth_fields_to_users.rs`
   - Adds name, email (unique), password, remember_token to users table
   - Uses `ALTER TABLE` approach (not recreate) since users table likely exists
   - Also registers the migration in `src/migrations/mod.rs`

2. **Auth controller:** `src/controllers/auth_controller.rs`
   - register, login, logout handlers (same pattern as Plan 02)
   - Add `pub mod auth_controller;` to `src/controllers/mod.rs`

3. **Update auth provider:** Print instructions to update `src/providers/auth_provider.rs`
   - Show the `retrieve_by_credentials` and `validate_credentials` implementations
   - Don't auto-modify the file (risky — user may have custom code)

4. **Route snippet:** Print route registration snippet to stdout
   - Show the guest-guarded and auth-guarded route groups
   - Don't auto-modify routes.rs (user may have custom structure)

Use the `confirm_overwrite` pattern from existing make commands. Use timestamp-based migration naming (like make_migration.rs does).

Add template strings as constants in `ferro-cli/src/templates/mod.rs` following existing patterns. Use `AUTH_CONTROLLER_TEMPLATE`, `AUTH_MIGRATION_TEMPLATE` naming.

Output format:
```
Created: src/migrations/m20260209_120000_add_auth_fields_to_users.rs
Created: src/controllers/auth_controller.rs
Updated: src/controllers/mod.rs

Next steps:
  1. Update src/providers/auth_provider.rs:
     [show code snippet]

  2. Add routes to src/routes.rs:
     [show route snippet]

  3. Run migration:
     ferro db:migrate
```
  </action>
