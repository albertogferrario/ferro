<objective>
Rewire `ferro make:json-view` from a direct NL->spec two-pass LLM flow into a
two-stage **projection** flow: NL description -> `ServiceDef` (via the Phase 171
`scaffold_core` logic) -> deterministic `Spec::from_service_def` render -> catalog
write-gate validation. Also accept an already-serialized `ServiceDef`
(`--from-service-json <path>`) and render it with no LLM call. Delete the
superseded direct-to-spec two-pass per the feature-branch convention (D-03).

Purpose: This makes `make:json-view` the first concrete `Renderer` over a
`ServiceDef` produced by `ai:make` (AICLI-04 / ROADMAP SC1-SC4), wiring the AI
pipeline through the projection/intent core instead of running a parallel
direct-to-spec scaffolding path.

Output: A `make:json-view` command whose only spec source is a `ServiceDef`,
rendered by the shipped deterministic renderer; the old direct-to-spec functions
removed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI invoker -> scaffold_core (NL description) | The `description` string is untrusted free text destined for an LLM prompt. |
| filesystem -> --from-service-json | A serialized ServiceDef JSON file supplied by the local invoker. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-173-01 | Tampering (prompt injection) | `description` -> `scaffold_core` | mitigate (inherited) | `scaffold_core` already applies `sanitize_description` (Phase 171, ferro-mcp/src/tools/ai_scaffold.rs:205) before assembling the prompt; make:json-view reuses scaffold_core unchanged — no new prompt surface added. |
| T-173-02 | Tampering | `--from-service-json` deserialization | accept | Input is a local-developer-supplied file on the dev machine (same trust level as the source tree being scaffolded); `serde_json::from_str::<ServiceDef>` is non-executing and a malformed file fails closed with a printed error + exit(1). No privilege boundary crossed (CLI runs as the invoking developer). |
| T-173-03 | Information disclosure | rendered spec written to src/views/{name}.json | accept | Output is deterministic from the ServiceDef and contains no secrets; the existing already-exists guard prevents overwrite. |
</threat_model>
