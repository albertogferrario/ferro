Output: `make:api` generates resources that auto-exclude sensitive fields. `--exclude` flag for manual control.

<task type="auto">
  <name>Task 1: Add field exclusion to make:api resource generation</name>
  <files>ferro-cli/src/commands/make_api.rs, ferro-cli/src/main.rs</files>
  <action>
  1. Add `--exclude` flag to the `MakeApi` variant in `ferro-cli/src/main.rs`:
     ```rust
     MakeApi {
         models: Vec<String>,
         #[arg(long)]
         all: bool,
         #[arg(long, short = 'y')]
         yes: bool,
         /// Fields to exclude from API resources (comma-separated, e.g., password_hash,secret_token)
         #[arg(long, value_delimiter = ',')]
         exclude: Vec<String>,
     }
     ```
     Pass `exclude` to `commands::make_api::run()`.

  2. Define a constant list of auto-excluded field name patterns in `make_api.rs`:
     ```rust
     const SENSITIVE_FIELD_PATTERNS: &[&str] = &[
         "password",
         "password_hash",
         "hashed_password",
         "secret",
         "token",
         "api_key",
         "hashed_key",
         "remember_token",
     ];
     ```
     These fields are excluded from the **API resource** (response serialization) by default. They are NOT excluded from the **request types** for create/update (since update password is a valid operation — but the request type already handles this via dedicated fields).

  3. Modify the resource template generation to filter out excluded fields:
     - When generating the resource struct fields, skip any field whose name matches `SENSITIVE_FIELD_PATTERNS` or the user's `--exclude` list.
     - When generating the `From<Model>` impl, skip the same fields.
     - Print a note during generation: "Auto-excluded sensitive fields from {Model}Resource: password_hash, hashed_key" (only if fields were actually excluded).

  4. Fields are matched case-insensitively. Exact match only (not substring) — `"token"` excludes `token` but not `created_at_token_time`.

  5. Add `--include-all` flag as escape hatch to disable auto-exclusion:
     ```rust
     /// Include all fields in API resources (disable auto-exclusion of sensitive fields)
     #[arg(long)]
     include_all: bool,
     ```

  Do NOT modify the controller/handler templates — they should still accept all fields for create/update operations. Only the resource (response) template is filtered.
  </action>
  <verify>Run `cargo build -p ferro-cli` — compiles. Create a test model with password_hash field, run make:api, verify resource excludes password_hash.</verify>
  <done>`make:api` auto-excludes sensitive fields from resources. `--exclude` adds custom exclusions. `--include-all` disables auto-exclusion. Console output shows which fields were excluded.</done>
</task>
