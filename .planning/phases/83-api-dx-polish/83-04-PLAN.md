  <files>ferro-cli/src/commands/api_check.rs, ferro-cli/src/commands/mod.rs, ferro-cli/src/main.rs</files>
  <action>
  Create a new `api_check` command that verifies the local API is ready for MCP integration.

  1. Register in `ferro-cli/src/main.rs`:
     ```rust
     /// Check local API readiness for MCP integration
     #[command(name = "api:check")]
     ApiCheck {
         /// Base URL of the running API server (default: http://localhost:8080)
         #[arg(long, default_value = "http://localhost:8080")]
         url: String,
         /// API key to test authentication (optional)
         #[arg(long)]
         api_key: Option<String>,
         /// Path to the OpenAPI spec endpoint (default: /api/openapi.json)
         #[arg(long, default_value = "/api/openapi.json")]
         spec_path: String,
     }
     ```

  2. Add `pub mod api_check;` to `ferro-cli/src/commands/mod.rs`.

  3. Create `ferro-cli/src/commands/api_check.rs` with `run(url, api_key, spec_path)`:

     The command runs 4 sequential checks, each with pass/fail output:

     **Check 1: Server connectivity**
     - HTTP GET to `{url}/` (or `{url}{spec_path}`)
     - Pass: Got HTTP response (any status)
     - Fail: Connection refused / timeout → "Server not running. Start with: cargo run"

     **Check 2: OpenAPI spec available**
     - HTTP GET to `{url}{spec_path}`
     - Pass: 200 OK with JSON body
     - Fail: 404 → "OpenAPI spec not found. Did you register docs_routes()?"
     - Fail: Non-JSON → "OpenAPI spec endpoint returned non-JSON response"

     **Check 3: OpenAPI spec valid**
     - Parse the JSON response
     - Check for `openapi` field starting with "3."
     - Check for `paths` object with at least one path
     - Count operations and report: "Found {N} API operations across {M} paths"
     - Fail: Missing required fields → "OpenAPI spec is malformed: missing {field}"

     **Check 4: API key authentication (if --api-key provided)**
     - Pick the first API endpoint from the spec (prefer GET)
     - Send request WITH X-API-Key header
     - Pass: Not 401 → "API key accepted"
     - Fail: 401 → "API key rejected. Check if the key is valid and not expired."
     - Skip if no --api-key provided: "Skipped — provide --api-key to test authentication"

     **Output format:**
     ```
     Checking API at http://localhost:8080...

     ✓ Server is running
     ✓ OpenAPI spec available at /api/openapi.json
     ✓ Valid OpenAPI 3.1.0 spec — 10 operations across 5 paths
     ✓ API key authentication working

     Ready for MCP! Configure ferro-api-mcp:
       ferro-api-mcp --spec-url http://localhost:8080/api/openapi.json --api-key {key}
     ```

     Or on failure:
     ```
     Checking API at http://localhost:8080...

     ✗ Server not reachable
       → Start your server with: cargo run

     Stopped — fix the above issues and try again.
     ```

     Use `reqwest::blocking::Client` with a 5-second timeout for all requests. Use `console` crate for colored output (green ✓, red ✗).

  4. Stop on first failure — don't continue checks if the server isn't reachable.
