    ## 3. Intentional gaps

    Features explicitly not shipped, with rationale.

    - **`Fragment` / `Group` borderless container** — Phase 162 D-06 rejected. Rationale: v2's flat ID-reference model means a container with no chrome and no semantic role does not earn its place in the catalog. Consumers wanting "no wrapper" use the existing `children` slot directly on the parent.
    - **`#[handler(name = "...")]` attribute** — Phase 162 D-10 rejected. Rationale: handler-name convention is already established (module path + function name); a renaming attribute introduces a second name that drifts.
    - **`$template` separate element** — Phase 163 D-05 rejected. Rationale: `$each` covers the templated-element-tree case; a second mechanism would fragment the directive surface.
    - **Codemod directory-recursive mode** — Phase 163 D-10 rejected. Rationale: file-at-a-time keeps the codemod's failure mode explicit; a recursive mode invites silent partial migration.
    - **Modal chrome variant sweep** — V7-RUNTIME §F10 question 2 answered "probably no action". Rationale: `Modal` already uses `shadow-lg` (closer to Elevated); no friction surfaced.
    - **Granular `padding` / `elevation` props on `CardProps`** — V7-RUNTIME §F10 question 3 answered "ship variant only". Rationale: 2×2 prop matrix would be more surface area than the `variant` enum; revisit if real demand surfaces.
    - **`Component::Plugin` generic dispatch reintroduction** — Phase 115 D-01 killed it; Phase 164 D-17a (`RawHtml`) is the narrow replacement, NOT a re-introduction. Plugin widgets continue to use first-class type names via `JsonUiPlugin`.
    - **`ammonia` HTML sanitiser as a workspace dep** — RESEARCH §Don't Hand-Roll row 3. Rationale: discipline-by-doc (RawHtml + RichTextEditor) over renderer-side sanitisation; pushing sanitisation to the consumer's handler keeps the renderer simple and the trust boundary explicit.
