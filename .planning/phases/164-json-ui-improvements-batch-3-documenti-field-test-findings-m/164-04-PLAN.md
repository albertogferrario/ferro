<objective>
Allow `Spec.title` to accept either a string literal or a `{"$data": "/path"}` binding object. Closes V7-RUNTIME-FRICTION F1 / CONTEXT D-12.

Purpose: 23 gestiscilo specs had to strip `$data` bindings from titles via `sed`. The fix introduces a typed `TitleBinding` enum with the same `#[serde(untagged)]` shape used by `Visibility`. The renderer (in `framework`) resolves the binding against `spec.data` at response-build time using `serde_json::Value::pointer` (already imported) — no new public API on `ferro-json-ui::data`.

This plan depends on:
- Plan 01 (raises MAX_NESTING_DEPTH in spec.rs — must land first to avoid spec.rs merge conflicts)
- Plan 03 (adds re-exports to lib.rs — must land first to keep lib.rs edits sequential)

Per CONTEXT D-12 + RESEARCH Pitfall 5: define `DataRef` as a distinct typed struct (not raw `serde_json::Value`) so round-trip serialisation preserves the binding shape.

Output: One new enum + one new struct in spec.rs; two new re-exports in lib.rs; one renderer branch update in framework/src/json_ui/mod.rs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spec author → loader | JSON title field is parsed by serde; untagged enum dispatch chooses literal vs binding. DataRef.data is a JSONPointer string — pointer-traversal is constrained to in-tree lookups. |
| handler data → renderer | `spec.data.pointer(path)` returns Option<&Value>; .as_str() narrows to string types only. Missing or non-string → fallback to "Ferro". |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-164-04-01 | T (Tampering) | DataRef.data path-traversal | mitigate | `serde_json::Value::pointer` accepts only JSONPointer syntax (`/foo/bar`); no `..` semantic, no out-of-tree dereferencing. The path resolves within `spec.data` which is the handler-provided struct — bounded by serialization shape. |
| T-164-04-02 | I (Information disclosure) | Binding title resolves to arbitrary string content | mitigate | The resolved title is emitted in `<title>...</title>` which html_escape is applied by the existing build_response. Even if `data` contains malicious content, it cannot break out of the `<title>` element. Audit: confirm `build_response` already HTML-escapes its title argument; if not, escape here before emission. |
| T-164-04-03 | D (DoS) | unbounded title length | accept | spec.data is bounded by the handler — same threat surface as any other prop binding. No new DoS vector introduced. |
