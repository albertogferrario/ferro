<objective>
Reorder the spec validation pipeline so per-component enum-shape validation runs AFTER `expand_directives` (and after visibility-based element removal). Closes V7-RUNTIME-FRICTION F8 / CONTEXT D-16.

Purpose: Today `loader::load_cached` calls `Spec::from_json` (structural) then `global_catalog().validate` (catalog/enum) — both fail at server startup. This rejects specs with `Alert.variant=""` gated by `visible: { exists: /flash_message }` even though the alert is going to be removed before render. The architectural fix: keep structural validation at load time but move enum-shape validation to per-request, AFTER `expand_directives` (which runs `$if` removal + `$each` cloning).

Per RESEARCH Pitfall 1 Recommended Option A — TWO-STAGE: startup runs catalog validation as `tracing::warn` (preserves visibility into structural fragility without failing); per-request `JsonUi::resolve` enforces. Structural errors (footer IDs, element refs, depth) remain hard-fails at load time via `Spec::from_json`.

This plan depends on Plan 04 (Plan 04 already touches `framework/src/json_ui/mod.rs` for D-12; this plan touches the same file for D-16; sequential to avoid merge conflicts).

Output: Loader's call to `Catalog::validate` becomes warn-only; JsonUi::resolve and resolve_with_errors gain a catalog validation call after `expand_directives`; new integration test proves the gated bad-variant case renders cleanly.
</objective>
