<objective>
Convert the sample app login from password to magic-link as the golden-path exemplar that proves the Plan 01 resume contract works across separate requests. `POST /auth/login` becomes a request-link handler that issues a single-use, TTL-bounded `ferro-cache` token; a new `GET /auth/verify?token=...` handler consumes the token, establishes the session, and resumes the OAuth flow via `oauth_resume_redirect`. The old password path is deleted.

Purpose: SC-2 — the magic-link exemplar; mitigates T-202-01/02/03 (replay, stale link, token entropy).
Output: app deps, two handlers, the verify route, the deleted password path, and single-use/expiry/dev-surface unit tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| email link click → session establishment | `GET /auth/verify?token=` is an unauthenticated request that, with a valid token, grants a session. The token is the credential. |
| request body email → token issuance | `POST /auth/login` accepts an arbitrary email; reveals account existence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-202-01 | Elevation / replay | `verify_magic_link` token consumption | mitigate | `Cache::forget` is called BEFORE `Auth::login` (forget-before-validate, mirrors token.rs 62-64). Proven by `magic_link_single_use` unit test (second get → None). |
| T-202-02 | DoS / stale credential | magic-link token TTL | mitigate | `Cache::put` with `Some(Duration::from_secs(15*60))`; absent/expired token → 422 re-render with the UI-SPEC error. Proven by `magic_link_expired`. |
| T-202-03 | Spoofing / token guessing | `generate_magic_link_token` | mitigate | 256-bit crypto token via `rand::thread_rng().gen::<[u8;32]>()` + `URL_SAFE_NO_PAD`, replicating the proven pkce generator. |
| T-202-04 | Information disclosure / email enumeration | `request_link` unknown-email path | accept (FLAG) | "No account found for this email." reveals registration status. Acceptable for the sample exemplar; noted in SUMMARY as a hardening item (a generic "if an account exists, a link was sent" message for production consumers). |
| T-202-MAIL | DoS / CI dependency | non-dev `Channel::Mail` send | accept | Best-effort, guarded by `!is_development()`, errors are `tracing::warn!`, never a hard failure; never exercised in CI. |
</threat_model>
