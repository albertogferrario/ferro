<objective>
Consolidate the duplicated `oauth_return_to` session round-trip into a single crate-owned helper set in `ferro-mcp-oauth`. The `/authorize` handler stores the in-flight authorize URL; any login handler (password, magic-link, future SSO/device-grant) calls one helper post-auth to resume the OAuth flow or fall back to a default. This is the load-bearing, reusable deliverable of Phase 202 — everything downstream depends on it.

Purpose: SC-1 — give login-resume one source of truth so a separate-request login method (magic-link `verify`) can resume the OAuth flow with a one-line call.
Output: `ferro-mcp-oauth/src/resume.rs` (helpers + key constant + unit tests), refactored `authorize.rs`/`consent.rs` with no inline `"oauth_return_to"` literal, `lib.rs` re-exports, and a documented contract.

    Three `///`-documented public functions (exact signatures):
    ```rust
    /// Store the in-flight authorize URL so a later login handler can resume it.
    /// Called by the `/authorize` handler when redirecting an unauthenticated user to login.
    pub fn store_oauth_return_to(url: String) {
        session_mut(|s| {
            s.put(OAUTH_RETURN_TO_KEY, url);
        });
    }

    /// Take the stored return URL, clearing it from the session (consume-on-read).
    /// Returns `None` when no authorize flow is in progress.
    pub fn take_oauth_return_to() -> Option<String> {
        let url: Option<String> = session().and_then(|s| s.get(OAUTH_RETURN_TO_KEY));
        if url.is_some() {
            session_mut(|s| {
                s.forget(OAUTH_RETURN_TO_KEY);
            });
        }
        url
    }

    /// 302-redirect to the stored OAuth return URL, or to `default` when no
    /// authorize flow is in progress. Consumes the stored key. Returns the success
    /// path of `ferro::Response` — callers use `return oauth_resume_redirect("/")`,
    /// NOT `oauth_resume_redirect("/")?`.
    ///
    /// Open-redirect invariant: the stored value originates ONLY from the `/authorize`
    /// handler (a validated, internal `/authorize?...` URL it constructs itself), never
    /// from user input. `default` is a static internal path supplied by the caller. The
    /// helper therefore never redirects to an attacker-controlled URL. (Mitigates the
    /// carry-forward of T-199-04.)
    pub fn oauth_resume_redirect(default: &str) -> ferro::Response {
        let dest = take_oauth_return_to().unwrap_or_else(|| default.to_string());
        Ok(ferro::HttpResponse::new()
            .status(302)
            .header("Location", dest))
    }
    ```
    Note `oauth_resume_redirect` returns the `Ok` branch (mirrors auth_controller `login_form` line 184) so callers' `?` propagation behaves correctly — do NOT use the `Err`-302 form here (that form is only for the `/authorize` pre-login redirect).
