//! Conversational-text renderer for Ferro service projections.
//!
//! `TextRenderer` projects a [`ServiceDef`] to deterministic plain text for the
//! cleanly-mapping intents (Browse, Collect, Process, Summarize, Track), guard-filtered
//! and verbosity-aware, with a defined fallback for Focus and Analyze.

use std::collections::HashMap;

use ferro_projections::render::{field_display_name, is_system_field, BaseContext, Renderer, Verbosity};
use ferro_projections::{ActionDef, Error, FieldDef, FieldMeaning, IntentScore, RenderHint, ServiceDef};

/// Renders a service projection to conversational plain text.
pub struct TextRenderer;

impl Renderer for TextRenderer {
    type Output = String;
    type Context = BaseContext;

    fn render(&self, service: &ServiceDef, intents: &[IntentScore], ctx: &BaseContext)
        -> Result<String, Error> {
        let score = intents.get(ctx.intent_index).ok_or(Error::NoIntents)?;
        let out = match score.intent.label() {
            "browse" => render_browse(service, ctx),
            "collect" => render_collect(service, ctx),
            "process" => render_process(service, ctx),
            "summarize" => render_summarize(service, ctx),
            "track" => render_track(service, ctx),
            "focus" => render_focus(service, ctx),
            "analyze" => render_analyze(service, ctx),
            _ => render_browse(service, ctx), // Custom intents: best-effort
        };
        Ok(out)
    }
}
```

fn render_field_value(f: &FieldDef) -> Option<String> {
    match &f.render_hint {
        Some(RenderHint::Skip) => None,
        Some(RenderHint::AltText(s)) => Some(s.clone()),
        None => {
            let label = field_display_name(&f.name);
            match &f.meaning {
                FieldMeaning::ImageUrl => Some(format!("{label} (image)")),
                FieldMeaning::Url => Some(format!("{label} (link)")),
                _ => Some(label),
            }
        }
    }
}
```

Per-intent (D-05 / D-08 verbosity shapes; exact wording is your discretion under "reads naturally"):
- **render_browse**: entity (`service.display_name`/`service.name`) + domain fields (`!is_system_field(&f.meaning)`). Full: entity + all domain field labels. Brief: entity + primary EntityName field only.
- **render_collect**: writable domain fields (`f.writable && !is_system_field(&f.meaning)`) framed as "fields to provide", with required markers from `f.required`. Full: labeled list with required markers. Brief: count ("3 fields to fill in").
- **render_process**: current state from `ctx.current_state`, falling back to `service.state_machine.as_ref().map(|sm| &sm.initial_state)`. Then the guard-PASSING actions only (`service.actions` filtered by `action_passes_guards(a, &ctx.evaluated_guards)`), labeled by `action.display_name`/`action.name`. Full: "Currently *{state}*." + field listing + guard-passing action list. Brief: "Currently *{state}*. You can: {verb1}, {verb2}.".
- **render_summarize**: entity + headline metric/status fields (`Money | Percentage | Quantity | Status`). Full: compact sentence enumerating key metric fields. Brief: entity + first metric field.
- **render_track**: current state (or `sm.initial_state` fallback); look up the `StateDef` to read `is_final` for "completed" language. Full: state + terminal? + possible transitions (unguarded — Track is linear). Brief: "Currently *{state}*.".
- **render_focus** (fallback, D-13): render domain fields applying `render_field_value` (D-12), dropping `Skip` fields, then a one-line note: "This is a media/navigational view; full text representation is limited."
- **render_analyze** (fallback, D-13): entity + domain field set (names only — NO fabricated statistics; ServiceDef has no computed values), then a one-line note: "Time-series and trend data has no full text representation in this channel."

Rustdoc every public item (only `TextRenderer` is public; the `render_*` fns stay private). Keep `lib.rs` under ~400 lines; if it grows past that, split strategies into a `strategies` submodule. `cargo build -p ferro-text` + `cargo clippy -p ferro-text --all-targets -- -D warnings` must be clean.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| (none new — network/auth/parsing) | `TextRenderer` consumes a trusted, developer-authored, in-process `ServiceDef` and `BaseContext` and returns a `String`. No network, no deserialization of untrusted input, no auth decision, no injection sink. |
| guard → rendered-action visibility | The one real correctness/safety seam: an action whose guard evaluates `false` must be OMITTED so the rendered text never tells a caller they can perform an action they cannot. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-216-03 | Information Disclosure | `render_process` guard filtering | mitigate | `action_passes_guards` omits any action with a precondition mapping to explicit `false` (D-09). Test `process_filtered_hides_approve_reject` asserts approve/reject are ABSENT when `{"is_approver": false}`, proving a guard-false action cannot leak into output. This is a behavior verified by a test, not a CVE class. |
| T-216-04 | Tampering / Spoofing | Analyze fallback | mitigate | Analyze renders only field names present in `ServiceDef`; the implementation fabricates NO statistics (D-13). Test `analyze_fallback_present` confirms no fabricated numbers — the channel never presents invented data as real. |
| T-216-05 | Denial of Service | empty / malformed intent slice | accept | Empty intents return `Error::NoIntents` (no panic, no unbounded work); `render` is O(fields + actions) over a bounded in-process struct. Test `empty_intents_returns_no_intents` pins the no-panic path. |
