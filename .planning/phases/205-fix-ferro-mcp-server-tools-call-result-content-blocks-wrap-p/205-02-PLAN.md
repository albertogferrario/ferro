<objective>
Update the two existing tenant-isolation integration tests in `app/src/tests/mcp_tenant_isolation.rs`
that currently iterate `result["result"]["content"]` as bare row objects and read `row["tenant_id"]`.
After Plan 01's fix, `content[0]` is a `{"type":"text",...}` block and the rows now live under
`structuredContent.rows` — so these tests will PANIC ("each row must have a tenant_id field") unless
re-pointed.

Per PATTERNS.md Pattern 3 and RESEARCH.md §5, re-point both tests to
`result["result"]["structuredContent"]["rows"]`, and add an assertion that
`result["result"]["content"][0]["type"] == "text"` to lock the valid-content-block shape (so the
original bug cannot silently return). The tenant-isolation **behavior** asserted (tenant A sees only
tenant 1, tenant B only tenant 2, no cross-tenant leak) is unchanged — only the navigation path moves.

This is the regression-proofing wave and the tenant non-regression evidence for the security gate.

Purpose: keep the cross-tenant isolation guarantee under test after the envelope change.
Output: updated `tenant_a_isolation` and `tenant_b_isolation`.
</objective>
