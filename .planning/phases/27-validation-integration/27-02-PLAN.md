Add convenience methods to the `JsonUi` struct that accept validation errors and wire them into the render pipeline. Follow the clone-resolve-serialize pattern from Phase 26.

**Add a `resolve_with_errors` private helper:**
```rust
fn resolve_with_errors(
    view: &JsonUiView,
    errors: &std::collections::HashMap<String, Vec<String>>,
) -> JsonUiView {
    let mut resolved = view.clone();
    resolve_actions(&mut resolved, |handler| crate::routing::route(handler, &[]));
    ferro_json_ui::resolve_errors(&mut resolved, errors);
    // Also set errors on the view for JSON consumers
    resolved.errors = Some(errors.clone());
    resolved
}
```

**Add public methods:**

1. `render_with_errors(view, data, errors) -> Response`:
   - Same as render() but uses resolve_with_errors() instead of resolve()
   - Accepts `&HashMap<String, Vec<String>>` for the errors map
   - Returns HTML with errors embedded in component props AND in view.errors

2. `render_json_with_errors(view, data, errors) -> Response`:
   - Same as render_json() but uses resolve_with_errors()
   - Returns JSON with errors populated in form fields AND in view.errors

3. `render_validation_error(view, data, validation_error) -> Response`:
   - Takes `&crate::validation::ValidationError` directly (the framework type)
   - Calls `.all()` to get the HashMap, delegates to render_with_errors()
   - This is the primary convenience method handlers will use

4. `render_json_validation_error(view, data, validation_error) -> Response`:
   - JSON variant of render_validation_error()

Import `ferro_json_ui::resolve_errors` at the top of the file.

**Tests to write:**

1. `render_with_errors_populates_form_fields` — View with Form containing Input fields, pass errors map → serialized JSON contains error messages on the correct fields
2. `render_json_with_errors_includes_errors_in_response` — render_json_with_errors → JSON response body contains both field-level errors and view.errors
3. `render_with_errors_empty_map_produces_no_errors` — Empty errors → same as regular render
4. `render_validation_error_accepts_framework_type` — Create ValidationError, add field errors, pass to render_validation_error → errors populated
5. `render_with_errors_preserves_action_resolution` — View with both actions and form fields → both actions resolved AND errors populated
