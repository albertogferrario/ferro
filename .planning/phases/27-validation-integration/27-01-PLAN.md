**1. Add `errors` field to `JsonUiView` (view.rs):**

Add an `errors` field to `JsonUiView`:
```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub errors: Option<HashMap<String, Vec<String>>>,
```

Place it after the `data` field, before `components`. Initialize to `None` in `new()` and `Default`.

Add builder method:
```rust
pub fn errors(mut self, errors: HashMap<String, Vec<String>>) -> Self {
    self.errors = Some(errors);
    self
}
```

Import `std::collections::HashMap` at the top of view.rs.

**2. Build `resolve_errors()` in resolve.rs:**

Add two public functions following the resolve_actions pattern:

`resolve_errors(view: &mut JsonUiView, errors: &HashMap<String, Vec<String>>)`:
- Walks the component tree recursively
- For each form field component (Input, Select, Checkbox, Switch), checks if `errors` contains the field name
- If yes, sets the component's `error` to `Some(first_error_message)` (first message only — single string field)
- Must recurse into Card children/footer, Form fields, Modal children/footer, Tabs tab children (same nesting as resolve_actions)
- Does NOT overwrite an existing error already set on a component (explicit error takes priority)

`resolve_errors_all(view: &mut JsonUiView, errors: &HashMap<String, Vec<String>>)`:
- Same tree walk but concatenates ALL error messages for a field, separated by ". " (useful when displaying all validation messages)
- Same "do not overwrite existing" rule

Helper function `resolve_errors_node(node: &mut ComponentNode, errors: &HashMap<String, Vec<String>>, all: bool)`:
- Match on Component variants:
  - Input(props) → if props.error.is_none() && errors has props.field: set error
  - Select(props) → same
  - Checkbox(props) → same
  - Switch(props) → same
  - Card(props) → recurse children + footer
  - Form(props) → recurse fields
  - Modal(props) → recurse children + footer
  - Tabs(props) → recurse tab children
  - Table, Button, Alert, Badge, Text, Separator, DescriptionList, Breadcrumb, Pagination, Progress, Avatar, Skeleton → leaf, no-op

**3. Update lib.rs exports:**

Add `resolve_errors` and `resolve_errors_all` to the public re-exports from `resolve` module.
