```rust
use sea_orm::DatabaseBackend;
let db = manager.get_connection();
match manager.get_database_backend() {
    DatabaseBackend::Postgres | DatabaseBackend::Sqlite => {
        db.execute_unprepared(
            "CREATE UNIQUE INDEX uq_payment_intents_active \
             ON payment_intents (billable_kind, billable_id) \
             WHERE status IN ('reserved','paid')",
        ).await?;
    }
    DatabaseBackend::MySql => {
        db.execute_unprepared(
            "ALTER TABLE payment_intents \
             ADD COLUMN active_billable_key VARCHAR(600) \
             AS (CASE WHEN status IN ('reserved','paid') \
                      THEN CONCAT(billable_kind, '|', CAST(billable_id AS CHAR)) \
                      ELSE NULL END) STORED",
        ).await?;
        db.execute_unprepared(
            "CREATE UNIQUE INDEX uq_payment_intents_active_mysql \
             ON payment_intents (active_billable_key)",
        ).await?;
    }
}
```
The MySQL `CAST(billable_id AS CHAR)` is explicit per Pitfall 4. The raw DDL strings are static literals with NO interpolated user values (security: SQL-injection-safe by construction — see threat model).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-233-03 | Tampering / Injection | `execute_unprepared` partial-index + MySQL generated-column DDL | mitigate | The raw DDL strings are static migration literals with NO interpolated user-supplied values — SQL injection is impossible by construction. Documented inline in the migration. All non-DDL access goes through SeaORM's parameterized builder. |
| T-233-04 | Tampering (data integrity) | partial unique index `(billable_kind, billable_id) WHERE status IN ('reserved','paid')` | mitigate | This index is the financial-integrity invariant preventing two simultaneously-active payment intents for one billable (double-charge surface in later phases). It is enforced at the DB, not in application logic, and unit-tested (`partial_unique_rejects_second_active_row` / `..._allows_new_active_after_release`). Not an external attack surface — a correctness control. |
| T-233-05 | Information disclosure | `metadata` JSON column | accept | Free-form JSON, documented "no PII" convention (D-07). No column-level enforcement in this phase; the convention is the control and there is no external writer in 233. |
