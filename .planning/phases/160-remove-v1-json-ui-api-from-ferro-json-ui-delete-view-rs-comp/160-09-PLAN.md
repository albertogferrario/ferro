**Step 2 — Classify each match.**

For each line in `/tmp/d08-sweep-raw.txt`, classify into one of these categories:

  - **api-versioning-example** — match is in a docs file showing `/api/v1/...` URL design (the substring `v1` is part of a path example, not a JSON-UI version reference). Acceptable.
  - **arbitrary-fixture** — match is in a test file using `"v1"` / `"v2"` as arbitrary string identifiers (e.g. `expression.rs:253-256`, `plugin.rs:381-401`). Acceptable.
  - **legitimate-historical** — match is in a context where historical reference is required for clarity AND was not removed by Plans 01-08. Rare. Acceptable with rationale.
  - **FAIL** — match is v1-JSON-UI narrative framing that should have been rewritten by Plans 01-08 but was missed. Requires escalation.

Note on `legacy` and other generic terms: `legacy` may appear in middleware code or framework code unrelated to JSON-UI v1 (e.g. "legacy browser compatibility shim"). Read the surrounding context — if the term is not about JSON-UI v1, classify as `legitimate-historical` (acceptable; out of scope).
