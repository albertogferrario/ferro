<task type="auto">
  <name>Task 2: Implement LangMiddleware with Accept-Language detection</name>
  <files>framework/src/lang/middleware.rs</files>
  <action>
**Create framework/src/lang/middleware.rs** following SessionMiddleware pattern:

```
pub struct LangMiddleware;
```

No constructor parameters needed — reads LangConfig from Config registry at request time.

**Implement Middleware trait:**
1. Read `Config::get::<LangConfig>()` — if missing, use hardcoded defaults ("en" locale, "en" fallback).
2. Determine request locale with priority:
   a. `?locale=xx` query parameter (explicit override, useful for API clients)
   b. `Accept-Language` header — parse the first language tag only (e.g., `en-US,en;q=0.9` → `en-us`). Use simple split on ',' then trim the first entry, strip quality suffix (split on ';' take first). Normalize via `ferro_lang::normalize_locale()`.
   c. LangConfig.locale as default.
3. Create task-local context via the mod.rs helper, store the determined locale string.
4. Call `LOCALE_CONTEXT.scope(ctx, async { next(request).await }).await` — same pattern as SessionMiddleware.
5. Return the response unchanged (no post-processing needed unlike session which saves data).

**Accept-Language parsing:** Keep it simple — take the first (highest priority) language. No need for full RFC 2616 quality-value parsing. The normalize_locale() call handles en_US → en-us conversion.

**Do NOT:**
- Load translations here — Translator initialization happens in framework integration (Phase 63).
- Add complex Accept-Language negotiation with quality values — first match is sufficient.
- Store anything on the response — locale is read-only per-request context.
  </action>
  <verify>cargo check -p ferro-rs && cargo clippy -p ferro-rs -- -D warnings</verify>
  <done>LangMiddleware compiles, implements Middleware trait, detects locale from Accept-Language header with query param override, scopes task-local context</done>
</task>
