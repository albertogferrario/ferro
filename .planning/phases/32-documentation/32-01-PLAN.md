Page structure:
1. **H1: JSON-UI** — One-sentence description: server-driven UI rendering that outputs Tailwind-styled HTML from Rust data structures, no frontend build step required.

2. **How It Works** — Brief conceptual overview:
   - Define UI as Rust structs (ComponentNode tree)
   - Attach data, actions, and visibility rules
   - Framework renders to HTML with Tailwind classes
   - Alternative to Inertia.js — no React/Vite/Node needed
   - Same handler pattern, different output format

3. **When to Use JSON-UI vs Inertia** — Decision guide:
   - JSON-UI: Admin panels, CRUD apps, rapid prototyping, server-rendered pages
   - Inertia: Rich interactive UIs, complex client state, SPA behavior
   - Can coexist in same app (different routes)

4. **Quick Example** — Minimal working handler:
   - Show a handler returning `JsonUi::render()` with a Card + Table
   - Show the import: `use ferro::{handler, JsonUi, JsonUiView, ComponentNode, Component, CardProps, Response}`
   - Keep it under 25 lines of Rust

5. **Key Concepts** — Brief list pointing to dedicated pages:
   - **Components**: 20 built-in types (link to components.md)
   - **Actions**: Route-based navigation and form submission (link to actions.md)
   - **Data Binding & Visibility**: Pre-fill forms and conditional rendering (link to data-binding.md)
   - **Layouts**: Page structure with navigation (link to layouts.md)

6. **CLI Support** — Mention `ferro make:json-view` for scaffolding (link to CLI reference)

Target length: ~80-120 lines. Follow the established tone: concise, code-focused, no marketing.
