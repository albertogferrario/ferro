`extract_service_impl_name` (`:263-273`, WR-01, already shipped). This closes WR-02 only.

```rust
/// Join any multi-line `#[service(...)]` attribute into a single logical line.
///
/// Keys on the `#[service(` prefix ONLY. Walks physical lines; when a `#[service(`
/// line's parens are not balanced on that line, accumulates subsequent trimmed lines
/// (joined by a single space) until paren depth returns to <= 0, then emits the joined
/// text as one logical line. All other lines — including `fn` signatures and other
/// attributes — pass through unchanged. Counts only `(` / `)` (never `[` / `]`), so the
/// `)]` close and `<...>` generics inside an impl type are handled correctly. Mirrors the
/// paren-depth balancing in `extract_inner_params`.
fn normalize_service_lines(content: &str) -> Vec<String> { ... }
```

Algorithm (mirror RESEARCH.md §"Pattern 2"):
- Iterate `content.lines()`. Keep `accumulating: Option<String>` and `paren_depth: i32`.
- If `accumulating` is `Some`: push a `' '` separator (unless empty) then the trimmed line; add
  `+1` per `(` and `-1` per `)` in the trimmed line; when `paren_depth <= 0`, `result.push` the
  taken accumulator and reset `paren_depth = 0`.
- Else if `trimmed.starts_with("#[service(")`: compute the line's own net `(`/`)` depth. If
  `<= 0` the attribute closed on this line — `result.push(line.to_string())` UNCHANGED
  (preserve original indentation for the pass-through case). If `> 0`, start accumulation with
  `accumulating = Some(trimmed.to_string())` and `paren_depth = depth`.
- Else `result.push(line.to_string())` unchanged.
- After the loop, if `accumulating` is still `Some` (malformed / EOF mid-attribute), flush it so
  no content is lost.

Count ONLY `(` and `)` — never `[`/`]` (RESEARCH Pitfall 1: `[` would keep depth positive so a
single-line `#[service(Type)]` would be misread as multi-line). Do NOT key on any prefix other
than `#[service(` (RESEARCH anti-pattern: joining `#[offload(...)]` or `fn` lines corrupts the
`FnCollecting` buffer).

Then add the unit test in `#[cfg(test)] mod tests`, name it exactly `normalize_service_lines`
(matches VALIDATION.md's `cargo test -p ferro-mcp normalize_service_lines` command). Assert:
