# Phase 249.3 Plan 01: Sync-Mode Terminal State Completeness — Summary

**One-liner:** `dispatch_immediately()` now calls `handle_with_value()` and routes both success and failure outcomes through `persist_offload_outcome`, so an `OffloadHandle` held by a sync-mode caller always resolves to `Completed` or `Failed` rather than returning `Ok(None)` forever (246 WR-01).

---

## What Was Built

### Task 1 — RED: SC#1 integration test

`framework/tests/sync_mode_terminal_state.rs` establishes the failing baseline. Two scenarios run under a single `#[tokio::test] #[serial]` entry (one `Queue::init` site per process, per the OnceLock constraint):

- **SC#1-success:** dispatches `SyncSuccessJob { expected_value: 42 }` with a handle key via `PendingDispatch::new(job).with_handle_key(key).dispatch()` under `QUEUE_CONNECTION=sync`; asserts `read_result::<i32>` returns `Some(Completed { value: 42 })`.
- **SC#1-failure:** dispatches `SyncFailingJob`; asserts `dispatch()` returns `Err` (D-03) and `read_result::<()>` returns `Some(Failed { .. })`.

The test uses `PendingDispatch` directly rather than `enqueue_and_mark_pending` to avoid the sync-mode pending-overwrite ordering hazard (RESEARCH.md RF-2 / Pitfall 2). An `EnvGuard` RAII helper removes `QUEUE_CONNECTION` on drop even on panic.

**Commit:** `4a303e3e` — fails RED against the unmodified dispatcher (success assertion hits `None` because `dispatch_immediately` writes no snapshot).

### Task 2 — GREEN: rework `dispatch_immediately()`

`ferro-queue/src/dispatcher.rs:dispatch_immediately()` is replaced with the verified target body from PATTERNS.md:

- Switches from `self.job.handle()` to `self.job.handle_with_value()`.
- Fetches `Queue::connection()` behind an `is_initialized()` guard (Pitfall 1: no panic in non-boot unit tests).
- On `Ok(Some(val))`: calls `persist_offload_outcome(self.handle_key.as_deref(), Ok(val), conn)`.
- On `Ok(None)` with `handle_key.is_some()`: persists `Ok(Value::Null)` so unit-return jobs with a handle always resolve terminally (Pitfall 4).
- On `Err(e)`: calls `persist_offload_outcome(self.handle_key.as_deref(), Err(e.to_string()), conn)`, then `self.job.failed(&e).await`, then returns `Err(e)` (D-03 dual signal).
- No new crate dependency: persistence reaches only through the already-registered hook (D-11 preserved).

**Commits:** `1e0bace3` (implementation), `c54dd8b1` (rustfmt formatting).
