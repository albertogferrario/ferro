# Phase 249.3 Plan 02: Reaper terminal envelope — Summary

Closes the reaper edge (edge b) of OFFLOAD-03: a reaper-parked visibility-timeout-exhausted job that carries a handle key now writes a terminal `failed` envelope under that handle, and a subscribed caller observes the failure delta rather than waiting to its own timeout (SC#2).

## What Was Built

### Task 1 + Task 2 (coupled — same commit `71986158`)

`ferro-queue/src/db.rs` — `reaper()` signature changed from `Result<(), Error>` to `Result<Vec<(i64, String)>, Error>`. Between the requeue UPDATE (Step 1) and the park UPDATE (Step 2), a SELECT-before-park step queries `id, handle_key WHERE status='claimed' AND claimed_at < cutoff AND attempts + 1 >= max_retries AND queue = ? AND handle_key IS NOT NULL` inside the same transaction. The collected pairs are returned after `txn.commit()`. The park UPDATE and its `"visibility timeout exceeded"` error string are unchanged (D-06). Four existing unit-test call-sites updated to bind `_parked`. New `insert_job_with_handle` helper added alongside `insert_job` (existing call-sites unchanged, OQ2). New unit test `reaper_returns_parked_handle_key_rows` asserts a non-empty return for a handle-key row.

`ferro-queue/src/worker.rs` — both reaper call-sites updated:
- Main run loop: `Ok(()) => {}` replaced with `Ok(parked) => { for (_, handle_key) in parked { persist_offload_outcome(Some(&handle_key), Err("visibility timeout exceeded"...), conn).await; } }`
- `drain_for_test`: `.ok()` replaced with `if let Ok(parked) = ... { for loop }` (same persistence pattern)

Both call-sites: persistence after `reaper()` returns (txn committed), never inside the txn (D-07); error literal exact match with `db.rs` (D-06); no raw error broadcast — hook applies D-05 redaction.

### Task 3 — SC#2 integration test (`3c2dbb26`)

`framework/tests/reaper_terminal_envelope.rs` — single `#[tokio::test] #[serial]` entry with two sub-scenarios:

- **Signal A** (`reaper_parks_write_failed_envelope`): inserts a claimed handle-key row, calls `ferro_queue::reaper` + `ferro_queue::persist_offload_outcome` directly, asserts `read_result` returns `Some(Failed { error })` with `error.contains("visibility timeout exceeded")`.
- **Signal B** (`subscriber_observes_reaper_failure`): subscribes before triggering the reaper, asserts `ServerMessage::Event` arrives within 5s with `data["status"] == "failed"` AND `data.get("error").is_none()` (D-05 redaction).

`ferro_queue::dispatcher::persist_offload_outcome` promoted to `pub` and re-exported from `lib.rs` to enable direct integration-test access without going through `drain_for_test` (which calls `reap_startup_claims` first and would park the test row before the reaper).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `drain_for_test` calls `reap_startup_claims` before the reaper**

- **Found during:** Task 3 — first test run: Signal A panic `SC#2-A: failed envelope must exist` because `reap_startup_claims` (called inside `drain_for_test`) parks the test row with a different error before the targeted `reaper()` has a chance to process it.
- **Issue:** The plan proposed driving the reaper through `drain_for_test`, but `drain_for_test` calls `reap_startup_claims` at startup, which parks any `claimed` row in the monitored queues immediately — with error `'reaped on worker startup (orphan claim from previous worker)'` rather than `'visibility timeout exceeded'` — so the subsequent reaper call finds no eligible rows and `persist_offload_outcome` is never called.
- **Fix:** Drive the reaper directly via the now-public `ferro_queue::reaper` + `ferro_queue::persist_offload_outcome` instead of `drain_for_test`. Promoted `persist_offload_outcome` from `pub(crate)` to `pub` and re-exported from `lib.rs`.
- **Files modified:** `ferro-queue/src/dispatcher.rs`, `ferro-queue/src/lib.rs`, `framework/tests/reaper_terminal_envelope.rs`
- **Commit:** `3c2dbb26`

**2. [Rule 2 - Clippy] `too_many_arguments` on `insert_job_with_handle` in test**

- **Found during:** Task 4 clippy gate.
- **Fix:** Added `#[allow(clippy::too_many_arguments)]` — matches the same attribute already on `insert_job` in `db.rs`.
- **Files modified:** `framework/tests/reaper_terminal_envelope.rs`
- **Commit:** `8fb525da`
