<objective>
Close silent-drop edge (b): reaper-parked jobs. Today `db::reaper()`
(`ferro-queue/src/db.rs:486`) bulk-`UPDATE`s timed-out `claimed` rows to `status='failed'`
but never persists a terminal-error envelope under the handle key, so a subscribed caller
waits to its own timeout instead of observing the failure (246 WR-02).

This plan changes `reaper()` to surface the parked handle-key rows (SELECT-before-park inside
the same transaction, returning `Vec<(i64, String)>`), updates BOTH worker reaper call-sites
(`worker.rs:348`, `worker.rs:405`) to persist a terminal-error envelope per parked row through
the existing `persist_offload_outcome` hook — best-effort, after the txn commits — and adds the
SC#2 integration test plus the `insert_job_with_handle` test helper.

Purpose: guarantee a reaper-parked offload handle resolves to a terminal `failed` state AND that
a subscribed caller observes the failure delta.
Output: reworked `reaper()` + `insert_job_with_handle` helper + updated worker call-sites +
`framework/tests/reaper_terminal_envelope.rs`.

Scope guardrail: surgical. No new envelope shape, no new transport, no `ferro-queue → ferro-projection`
dependency. The `reaper()` signature change and the worker call-site update are COUPLED — they ship
together in this plan (a signature change with a stale call-site would not compile).
</objective>
