**In the "Development Commands" section (after `ferro generate-types`, before `## Code Generators`):**

1. **`ferro clean`** — Remove build artifacts. Flags: `--sweep <days>` (optional, requires cargo-sweep). Document that without --sweep it runs `cargo clean`, with --sweep it removes artifacts older than N days.

2. **`ferro generate-routes`** — Document as an internal utility, NOT a standalone subcommand. It is called automatically by `ferro generate-types` and `ferro serve`. The module generates TypeScript route helpers from Rust route definitions. Do NOT claim it can be invoked as `ferro generate-routes` (it cannot — there is no Commands enum variant). Instead, document it under generate-types as a note: "This also runs `generate-routes` internally to produce TypeScript route helpers."

   Since generate-routes is not independently invocable, add a brief note under the existing `ferro generate-types` section rather than creating a standalone `### ferro generate-routes` heading. Something like:

   > **Includes route generation:** `generate-types` also runs route generation internally, producing TypeScript route helpers alongside the type definitions.

**In the "Code Generators" section (after the last existing `make:*` entry, which is `make:scaffold`, before `## Database Commands`):**

3. **`ferro make:api`** — Generate REST API endpoints for models. Flags: positional `models` (Vec), `--all`, `--yes`/`-y`, `--exclude` (comma-delimited), `--include-all`. Document the auto-exclusion of 8 sensitive field patterns (password, secret, token, etc.) and that --exclude uses comma-delimited values.

4. **`ferro make:api-key`** — Generate an API key with SHA-256 hashing. Flags: positional `name` (required), `--env` (default: live, accepts live/test). Document that it outputs the key once (not stored in plaintext) and prints the SQL insert + Rust verification snippet.

5. **`ferro make:lang`** — Create translation files for a locale. Flags: positional `name` (required, e.g., fr, pt-br). Generated files: `lang/<locale>/validation.json`, `lang/<locale>/app.json`.

6. **`ferro make:policy`** — Create an authorization policy. Flags: positional `name` (required), `--model`/`-m` (optional, defaults to name without "Policy" suffix). Generated file: `src/policies/<name>_policy.rs`. NOTE: make:policy already has a row in the Command Summary table (line ~1021) — do NOT add another row in Task 2.

7. **`ferro make:projection`** — Create a service projection definition. Flags: positional `name` (required), `--from-model` (populate fields from matching SeaORM model). Generated file: `src/projections/<name>.rs`.

8. **`ferro make:stripe`** — Scaffold Stripe billing integration. Flags: `--connect` (include Stripe Connect scaffolding). Generated files: `src/stripe/mod.rs`, `src/stripe/webhook.rs`, `src/stripe/listeners.rs`, plus `src/stripe/connect_webhook.rs` and a billing migration when `--connect` is used.

9. **`ferro make:theme`** — Create a JSON-UI theme with Tailwind v4 semantic tokens. Flags: positional `name` (required). Generated files: `themes/<name>/tokens.css` (Tailwind v4 `@theme` block with 23 semantic token slots), `themes/<name>/theme.json` (empty JSON for intent template overrides).

10. **`ferro make:whatsapp`** — Scaffold WhatsApp Cloud API integration. No flags. Generated files: `src/whatsapp/mod.rs`, `src/whatsapp/webhook.rs`, `src/whatsapp/listeners.rs`.

**Create a new `## Validation & Diagnostics` section (insert it between `## Storage Commands` and `## AI-Assisted Development`):**

11. **`ferro api:check`** — Verify local API server is running and MCP-compatible. Flags: `--url` (default: http://localhost:8080), `--api-key` (optional), `--spec-path` (default: /api/openapi.json). Document that it checks server reachability, fetches the OpenAPI spec, validates the spec structure, tests API key auth if provided, and prints ferro-api-mcp configuration.

12. **`ferro projection:check`** — Validate service projection definitions. Flags: `--name` (optional, check a single projection). Note prominently: "Requires the `projections` feature. Build with `cargo build --features projections` or add `projections` to default features in `Cargo.toml`."

13. **`ferro validate:contracts`** — Validate Inertia TypeScript contracts against Rust handler props. Flags: `--filter`/`-f` (optional route filter), `--json` (JSON output for CI). Document that it compares Rust InertiaProps structs with generated TypeScript types and reports mismatches.

- Keep descriptions concise and factual — no marketing language
- Source all flag names and defaults from the research file's "Flags from main.rs" sections
