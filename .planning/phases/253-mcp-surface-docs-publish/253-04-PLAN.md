human-readable output can tell "nothing found" apart from "found and clean":

   a file is read successfully and BEFORE/at the `lint_content` call, increment when the file carries
   the schema marker (so only real specs count). Concretely, replace the read-then-lint tail:
```rust
let content = match std::fs::read_to_string(file_path) { /* unchanged Err arm */ };
if content.contains(ferro_json_ui::spec::SCHEMA_VERSION) {
    files_linted += 1;
}
all.extend(lint_content(&label, &content));
```
   (Import or fully-qualify `SCHEMA_VERSION` consistent with the existing `use` block, which already
   imports `ferro_json_ui::spec::{Spec, SCHEMA_VERSION}`.)

2. Change the human-output path so the zero-files case is explicit. In the `else { print_human(&all) }`
   branch of `run()`, gate the message:
```rust
} else if all.is_empty() && files_linted == 0 {
    println!("{}", console::style("No JSON-UI spec files found.").yellow());
} else {
    print_human(&all);
}
```
   Leave `print_human`'s existing "No findings — all specs are clean." for the `all.is_empty()` case
   where `files_linted > 0` (files were checked and are clean). Do not change the `--json` output path
   or the `--deny` exit logic.

3. If a CLI test asserts the exact "No findings — all specs are clean." string on an empty-dir case,
