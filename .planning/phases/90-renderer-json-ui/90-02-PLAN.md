Create `ferro-projections/src/render/json_ui.rs`:

1. **JsonUiRenderer struct:** Unit struct implementing the `Renderer` trait. The `render()` method:
   - Gets the IntentScore at `ctx.intent_index`, returns `Error::Render` if index out of bounds
   - Matches on `intent.intent` to dispatch to private layout methods
   - Wraps result in JSON conforming to ferro-json-ui/v1 schema:
     ```json
     {
       "$schema": "ferro-json-ui/v1",
       "title": service.display_name or service.name,
       "components": [...]
     }
     ```
   - `Intent::Custom(_)` falls back to `render_focus` (detail view is safest default)
   - Process/Summarize/Analyze/Track call `todo!("implemented in Plan 03")` temporarily — they'll be filled in 90-03

2. **render_browse (Display mode):** List view with filterable table.
   Components produced:
   - **Table:** columns from `field_to_column()` for readable, non-system fields. `data_path: "/data/items"`. `sortable: true`.
   - **Pagination:** below table. `current_page: 1`, `per_page: 25`, `total: 0`, `base_url: format!("/{}", service.name)`.

   In Input mode: render_collect (redirect to form view for Browse doesn't make sense, but handle gracefully).

3. **render_focus (Display mode):** Detail view with field descriptions and relationship sections.
   Components produced:
   - **Card** with title = service display_name or name:
     - **DescriptionList** child: items from readable fields via `field_to_display()`. Each item: `{"term": label, "detail_data_path": "/data/{field_name}"}`. Skip fields where `field_to_display` returns Null (ForeignKey, Sensitive).
   - **Relationship sections:** For each relationship with NavigationHint != Hidden:
     - Tab hint → collect into Tabs component
     - Nested hint → Table component below Card
     - Inline/Link → included in Card as additional children

   In Input mode: render_collect (detail editing).

Update `render/mod.rs`:

- render_focus excludes Sensitive and ForeignKey fields
- render_focus includes relationship components based on NavigationHint

Add two intent layout methods to JsonUiRenderer:

1. **render_collect:** Data entry form.
   Components produced:
   - **Form** component wrapping input fields:
     - `action_handler: format!("{}.store", service.name)` (convention: service_name.action_name)
     - `method: "POST"`
     - Children: one input component per writable field via `field_to_input()`. Skip fields where field_to_input returns Null.
     - **Button** (submit): `{"type": "Button", "label": "Save", "variant": "default"}` with action handler
   - Skip system fields that are auto-generated (Identifier with writable=false, CreatedAt, UpdatedAt)

   In Display mode: still render the form but with fields pre-filled via data_path bindings (edit mode).

2. **render_summarize:** Dashboard metrics overview.
   Components produced:
   - **Card grid:** One Card per readable numeric/monetary/percentage field:
     - Money fields → Card with title = field display name, child Text with data_path
     - Percentage fields → Card with title = field display name, child Progress with data_path
     - Quantity fields → Card with title = field display name, child Text with data_path
   - If no numeric fields exist, fall back to a DescriptionList of all readable non-system fields (graceful degradation)
   - **Status fields:** Render as Badge in a summary Card

   In Input mode: redirect to render_collect (editing a summary service).

Remove the `todo!()` calls for Summarize and Collect in the render() dispatch.

- render_summarize produces Card per metric field (Money, Percentage, Quantity)
- render_summarize falls back to DescriptionList when no numeric fields
- render_summarize shows Status as Badge
