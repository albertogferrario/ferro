<task type="auto">
  <name>Task 2: Build resolve_actions tree walker</name>
  <files>ferro-json-ui/src/resolve.rs, ferro-json-ui/src/lib.rs</files>
  <action>
Create `ferro-json-ui/src/resolve.rs` with a `resolve_actions` function that:

1. Takes a mutable `JsonUiView` and a resolver callback `Fn(&str) -> Option<String>` (maps handler name to URL).
2. Walks the entire component tree recursively:
   - `view.components` — check each ComponentNode's `action` field
   - Recurse into nested children: CardProps.children, CardProps.footer, FormProps.fields, ModalProps.children, ModalProps.footer, TabsProps.tabs[].children
   - For FormProps.action — this is a required (non-Option) Action, resolve it too
   - For TableProps.row_actions — resolve each Action in the Vec
3. For each Action found, call the resolver with `action.handler` as input.
4. If resolver returns `Some(url)`, set `action.url = Some(url)`.
5. If resolver returns `None`, leave `action.url` as None (caller handles missing routes).

The resolver callback approach keeps ferro-json-ui decoupled from the framework — it doesn't know about `route()` or the route registry. The framework bridge (Plan 02) provides the concrete resolver.

Also add `resolve_actions_strict` that returns `Result<(), Vec<String>>` — collects all unresolvable handler names and returns them as errors. This is useful for development-time validation.

Helper: create a private `resolve_action` function that resolves a single `&mut Action` with the callback, and a private `resolve_component_node` that handles recursion through a `&mut ComponentNode`.

Export `resolve_actions` and `resolve_actions_strict` from `ferro-json-ui/src/lib.rs`.

Tests in the same file:
- `resolve_actions` with a view containing a button with action → url gets populated
- `resolve_actions` with nested components (Card > Button with action) → all actions resolved
- `resolve_actions` with Form (required action) → form action resolved
- `resolve_actions` with Table row_actions → all row actions resolved
- `resolve_actions` with Tabs containing actions → actions in tab children resolved
- Unresolvable handler → url stays None
- `resolve_actions_strict` with missing handler → returns error with handler name
- `resolve_actions_strict` with all resolved → returns Ok(())
  </action>
  <verify>cargo test -p ferro-json-ui -- resolve::tests</verify>
  <done>resolve_actions and resolve_actions_strict work for all component types with nested children. All resolver tests pass.</done>
