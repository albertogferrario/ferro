<task type="auto">
  <name>Task 1: Integrate resolve_actions into render pipeline</name>
  <files>framework/src/json_ui/mod.rs</files>
  <action>
Modify `JsonUi::render()` and `JsonUi::render_json()` to resolve actions before output:

1. In both `render` and `render_json`, clone the view to avoid mutating the caller's data: `let mut resolved_view = view.clone();`
2. Call `ferro_json_ui::resolve_actions(&mut resolved_view, |handler| { crate::routing::route(handler, &[]) });`
3. Use `resolved_view` for serialization instead of the original `view`.

The resolver callback uses Ferro's `route()` function which resolves named routes to URL patterns. For routes without parameters, this produces the final URL (e.g., `"users.index"` → `"/users"`). For parameterized routes, it produces the URL template with `{param}` placeholders (e.g., `"users.show"` → `"/users/{id}"`). This is correct — table row actions use these templates with per-row data substitution (Phase 28 concern).

Do NOT use `resolve_actions_strict` in the render pipeline — that would make missing routes a hard error at render time. Missing routes produce `url: None` in the JSON, which downstream consumers (Phase 28 renderer) handle gracefully.

Update existing render tests to verify:
- Views with actions get `url` populated in the output JSON
- Views without actions still render correctly (no regression)
- The original view passed to render is not mutated (clone semantics)

Add a new test `render_resolves_action_urls` that:
- Registers a test route name → path mapping using `register_route_name`
- Creates a view with a button action referencing that route
- Renders to JSON
- Verifies the output contains the resolved URL
  </action>

  <done>Both render() and render_json() automatically resolve action URLs. Tests verify resolution occurs and original view is not mutated.</done>

<task type="auto">
  <name>Task 2: Add Action builder methods and update re-exports</name>
  <files>ferro-json-ui/src/action.rs, framework/src/lib.rs</files>
  <action>
Add builder/convenience methods to the `Action` struct in `ferro-json-ui/src/action.rs`:

1. `Action::new(handler: impl Into<String>)` — creates an action with Post method, no confirm, no outcomes, no url. This is the minimum viable action.

2. `Action::get(handler: impl Into<String>)` — creates with Get method (for navigation actions).

3. `Action::delete(handler: impl Into<String>)` — creates with Delete method.

4. Builder methods (take self, return Self):
   - `.method(method: HttpMethod)` — override the HTTP method
   - `.confirm(title: impl Into<String>)` — add a default confirmation dialog
   - `.confirm_danger(title: impl Into<String>)` — add a danger confirmation dialog
   - `.on_success(outcome: ActionOutcome)` — set success outcome
   - `.on_error(outcome: ActionOutcome)` — set error outcome

These replace verbose struct construction. Example before:
```rust
Action { handler: "users.store".to_string(), method: HttpMethod::Post, confirm: None, on_success: None, on_error: None }
```
Example after:
```rust
Action::new("users.store")
Action::delete("users.destroy").confirm_danger("Delete user?").on_success(ActionOutcome::Refresh)
```

Update re-exports in `framework/src/lib.rs`:
- Add `resolve_actions` and `resolve_actions_strict` to the ferro_json_ui re-export block.

Tests for builder methods:
- `Action::new` creates Post action with given handler
- `Action::get` creates Get action
- `Action::delete` creates Delete action
- `.confirm()` adds Default variant dialog
- `.confirm_danger()` adds Danger variant dialog
- `.on_success()` and `.on_error()` set outcomes
- Builder chain produces expected serialized JSON
