In `docs/src/features/projections.md`, add a section "Rendering a projection inside an app shell" documenting the composition pattern (D-05a). Neutral architectural voice (no internal-strategy language). Content:
- A projection `Spec` is a standalone spec rooted at the content component (DataTable, KanbanBoard, StatCard). Surrounding dashboard chrome (sidebar, nav, PageHeader) is the consumer's responsibility.
- Two documented composition options: (a) merge the projection root element into an existing layout spec's main-content children; (b) return the projection spec at a known key in the handler response and have the dashboard layout template embed it. Use the RESEARCH §"Gap E" code sketches as the example.
- State explicitly that a first-class `VisualContext.layout` field is intentionally not provided in this release — composition is the supported pattern.

In the same file (or a "Projection content binding" subsection), document the conventions this phase introduced so a migrator without source access knows the contract:
- **Action routes:** projection actions emit a URL `/{service.name}/{action.name}` (page-level) and `/{service.name}/{row_key}/{action.name}` (DataTable row actions). `ActionDef` has no route field; the consumer's route table must match this convention.
- **Kanban data:** the handler merges the column array at `/data/{service.name}/columns` (array of `{id, title, count, children}`); static columns derive from the state machine as the fallback schema.
- **StatCard value:** bound via `value_path` to `/data/{service.name}/{field.name}` (the primary Money/Quantity field).
- **DataTable rows:** rows merged at `/data/{service.name}` (existing convention, restated for completeness).

In `docs/src/json-ui/data-binding.md`, add the kanban `/columns` suffix convention and the StatCard `value_path` field to the data_path reference (so all three bindings — DataTable array, Kanban columns, StatCard scalar — are documented in one place).

Keep the prose minimal and scientific (per project doc conventions). Do not add marketing language or "v2/legacy" framing.
