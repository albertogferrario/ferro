# Phase 243.1 Plan 01: Projection Computed/Derived Fields Summary

Gate F in `is_write_excluded_field` + `order.total` derived from `line_items.amount` via post-persist recompute hook, with full CRUD projection and in-process e2e CI gate.

## What Was Built

**Part A — Framework (ferro-projections):** Added Gate F to `ServiceDef::is_write_excluded_field` — a field with `writable: false` (e.g. declared via `.read_only_field()`) is now excluded from create/update input schemas. This is the single source of truth for write eligibility; no special handling needed at dispatch time. Gate F is validated by a new unit test and a regression guard in ferro-mcp-server.

**Part C — Sample App:** End-to-end demonstration that projection declarations drive runtime correctness:
- `orders.total` redeclared as `.read_only_field()` — excluded from `create_order`/`update_order` input schemas automatically via Gate F
- `orders.total` defaults to `0` in the DB migration, so INSERT without `total` succeeds
- New `line_items` table + SeaORM entity + `line_item` CRUD projection (creatable/updatable/deletable, tenant-scoped, soft-deletable)
- `recompute_order_total_hook` registered via `WriteDispatcher::with_override` for `create_line_item`, `update_line_item`, `delete_line_item` — after each write, `orders.total` is set to `COALESCE(SUM(amount), 0)` over non-deleted line items, tenant-scoped
- In-process e2e test `computed_total_e2e.rs` proves all four truths as a CI gate

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `ActiveModelBehavior` conflict in `line_items.rs` entity**
- **Found during:** Task 5 — build failed with E0119
- **Issue:** Plan's `line_items.rs` snippet included `impl ActiveModelBehavior for ActiveModel {}`. The `FerroModel` derive macro already derives `ActiveModelBehavior`, so the explicit impl causes a conflicting implementation error.
- **Fix:** Removed the `impl ActiveModelBehavior for ActiveModel {}` block to match the pattern used by `orders.rs` and all other generated entities.
- **Files modified:** `app/src/models/entities/line_items.rs`
- **Commit:** d1df9e3a

**2. [Rule 1 - Bug] Missing `created_at` column in `line_items` table**
- **Found during:** Task 8 — `order_total_is_derived_from_line_items` test failed with total remaining 0.0 after line-item creates (the `create_line_item` CRUD call was silently failing)
- **Issue:** `execute_crud_plan` (CrudPlan::Create) always appends `created_at` to the INSERT column list and injects `datetime('now')` as a literal value. The `line_items` migration had no `created_at` column, causing the `INSERT … RETURNING *` to fail at the DB level.
- **Fix:** Added `created_at TIMESTAMP NOT NULL DEFAULT current_timestamp` to the migration, `CreatedAt` to the `DeriveIden` enum, `created_at: String` field to the SeaORM entity, and `.read_only_field("created_at", DataType::DateTime, FieldMeaning::CreatedAt)` to the `line_item` projection.
- **Files modified:** `app/src/migrations/m20260624_create_line_items_table.rs`, `app/src/models/entities/line_items.rs`, `app/src/projections/line_item.rs`
- **Commit:** 70e90a47

**3. [Rule 1 - Bug] Response path in `order_total_is_derived_from_line_items` test**
- **Found during:** Task 8 — test panicked at `expect("order id")`
- **Issue:** Plan spec used `created["structuredContent"]["result"]["id"]` but `handle_tools_call` wraps results under an outer `"result"` key: `created["result"]["structuredContent"]["result"]["id"]`.
- **Fix:** Updated all response access paths in the test to include the outer `"result"` key, matching the envelope shape confirmed by `crud_e2e.rs`.
- **Files modified:** `app/src/tests/computed_total_e2e.rs`
- **Commit:** 70e90a47
