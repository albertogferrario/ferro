**Part B — Update all rules in `framework/src/validation/rules.rs`:**

For each rule's `validate()` method, change the error `Err(format!(...))` to first try translation, then fall back to the existing hardcoded string.

The pattern for simple rules (no type-specific messages):

```rust
// Before:
Err(format!("The {} field is required.", field))

// After:
Err(translate_validation(
    "validation.required",
    &[("attribute", field)],
).unwrap_or_else(|| format!("The {} field is required.", field)))
```

Add `use crate::validation::translate_validation;` at the top of rules.rs (it's already pub(crate) from bridge.rs).

For **size rules** (min, max, between), use type-specific translation keys:

```rust
// In Min::validate(), after computing size and unit:
let type_key = match value {
    Value::String(_) => "validation.min.string",
    Value::Array(_) | Value::Object(_) => "validation.min.array",
    _ => "validation.min.numeric",
};
Err(translate_validation(
    type_key,
    &[("attribute", field), ("min", &format!("{}", self.min as i64))],
).unwrap_or_else(|| format!(
    "The {} field must be at least {} {}.",
    field, self.min as i64, unit
)))
```

Same pattern for Max (validation.max.string/array/numeric with "max" param) and Between (validation.between.string/array/numeric with "min" and "max" params).

For **comparison rules** (different, same), include the `:other` param:

```rust
Err(translate_validation(
    "validation.different",
    &[("attribute", field), ("other", &self.other)],
).unwrap_or_else(|| format!(
    "The {} and {} fields must be different.",
    field, self.other
)))
```

  <action>
Add a test module section in `rules.rs` (inside the existing `#[cfg(test)] mod tests`) that verifies the translate_validation bridge is actually called by rules when a translator is registered.

Add a test that:
1. Registers a mock translator via `register_validation_translator` that returns `Some("TRANSLATED: {key}")` for any key
2. Runs a rule that should fail (e.g., `required().validate("name", &json!(null), &json!({}))`)
3. Asserts the error message starts with "TRANSLATED:" (proving the bridge was called)

**Important caveat:** `register_validation_translator` uses OnceLock, so it can only be set once per process. Since tests run in the same process, this test must be aware that another test may have already set it. Use `#[ignore]` attribute with a comment explaining it should be run in isolation (`cargo test test_translation_bridge_integration -- --ignored`) OR check if the result contains "TRANSLATED:" only if registration succeeded.

Recommended approach — check registration success:

```rust
#[test]
fn test_rules_call_translate_validation() {
    fn mock(key: &str, params: &[(&str, &str)]) -> Option<String> {
        let attr = params.iter().find(|(k, _)| *k == "attribute").map(|(_, v)| *v).unwrap_or("?");
        Some(format!("[translated] {}: attr={}", key, attr))
    }

    // OnceLock: if already set by another test, skip gracefully
    let was_set = crate::validation::bridge::VALIDATION_TRANSLATOR.set(mock as crate::validation::TranslatorFn).is_ok();

    let result = required().validate("email", &json!(null), &json!({}));
    assert!(result.is_err());

    if was_set {
        let msg = result.unwrap_err();
        assert!(msg.contains("[translated]"), "Expected translated message, got: {}", msg);
        assert!(msg.contains("validation.required"), "Expected key in message, got: {}", msg);
    }
    // If not set (another test beat us), we just verify the rule still errors — which the assert above covers
}
```

**Note:** This requires making VALIDATION_TRANSLATOR `pub(crate)` in bridge.rs (it's currently private to the module). Change `static VALIDATION_TRANSLATOR` to `pub(crate) static VALIDATION_TRANSLATOR` in bridge.rs to allow test access within the crate.

Also add tests for type-specific translation keys in size rules:
- Test that min/max/between pick correct subkey based on value type (string vs number vs array)
