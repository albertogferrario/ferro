## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-authored spec → catalog | `json_ui_catalog` surfaces `LiveFragment` for composition; malformed props are the input-validation surface |
| delta snapshot → broadcast HTML | The app hook re-renders snapshot data into HTML pushed on the public channel |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-260-09 | Tampering (XSS) | delta re-render HTML | mitigate | The delta re-render uses the IDENTICAL `render_spec_to_html` path as first paint (proven equal in Task 3), so all snapshot values pass through the same ferro-json-ui escaping. There is no second, less-safe render path for deltas. |
| T-260-10 | Information Disclosure | channel name derivation | mitigate | The channel `projection.{name}.{key}` is derived from the fragment's OWN `projection`/`key` props (Plan 02, html-escaped) — a fragment cannot subscribe to or emit another key's channel. Cross-key leakage is structurally prevented; broadcast auth remains `ferro-broadcast`'s subscribe check. |
| T-260-11 | Tampering | catalog drift guard | mitigate | The lockstep (BUILTIN_TYPES + dispatch + BUILTIN_SPECS + pinned count 53 + relational guard) is enforced by `dispatch_match_covers_every_builtin`, the count assertion, and `BUILTIN_SPECS.len() == BUILTIN_TYPES.len()` — a half-added builtin fails the build, so the catalog cannot silently drift. |
</threat_model>
