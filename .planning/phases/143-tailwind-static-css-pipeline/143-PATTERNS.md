### `ferro-json-ui/assets/ferro-base.css` (static asset, build-time generated)

**Analog:** `ferro-theme/assets/default.css`

This file is generated by the Tailwind v4 standalone CLI and checked into git — it is not hand-authored. The `ferro-theme/assets/default.css` file demonstrates the checked-in pattern: it is the upstream source for `include_str!` and lives adjacent to the code that depends on it.

The Tailwind CLI input file that generates `ferro-base.css` should be co-located:

```
ferro-json-ui/assets/
├── input.css          # Tailwind CLI entry (not embedded; used only at build time)
└── ferro-base.css     # Generated output (embedded via include_str! in assets.rs)
```

**`input.css` content pattern** (synthesised from RESEARCH.md Pattern 6):
```css
@import "tailwindcss";

/* Scan Rust source files for all utility class literals */
@source "../../ferro-json-ui/src";
@source "../../framework/src";
```

**Shell script pattern** (mirrors CI convention for documented manual steps):
```bash
#!/usr/bin/env bash
# scripts/gen-ferro-base-css.sh
# Run from repo root. Requires tailwindcss binary on PATH.
set -euo pipefail
tailwindcss \
  -i ferro-json-ui/assets/input.css \
  -o ferro-json-ui/assets/ferro-base.css \
  --minify
echo "ferro-base.css regenerated."
```

**Add one match arm before the wildcard `_`** (D-04):


**Handler function pattern** — follows `framework/src/static_files.rs` response builder (lines 61-67) with `Bytes::from_static` for zero-copy `'static` content:
```rust
fn serve_ferro_base_css() -> hyper::Response<Full<Bytes>> {
    let css = ferro_json_ui::FERRO_BASE_CSS;
    hyper::Response::builder()
        .status(200)
        .header("Content-Type", "text/css; charset=utf-8")
        .header("Content-Length", css.len().to_string())
        .header("Cache-Control", "public, max-age=86400")
        .body(Full::new(Bytes::from_static(css.as_bytes())))
        .unwrap()
}
```

Notes:
- `Bytes::from_static(css.as_bytes())` is zero-copy; `css` is `&'static str` so `.as_bytes()` returns `&'static [u8]`. Do not use `Bytes::from(css.as_bytes().to_vec())` — unnecessary allocation.
- Cache-Control is `max-age=86400` (24h) rather than `immutable`, matching the RESEARCH.md recommendation for the initial setting (revisit when version-stamped URLs are implemented).
- The handler is synchronous — no `.await`. The existing non-async arms (`handle_routes`, `handle_middleware`, etc.) confirm this is the correct convention.
- The match arm is an exact string match, not a path prefix — no traversal risk.
- Imports already available in `server.rs`: `bytes::Bytes`, `http_body_util::Full`.

### `ferro-theme/src/loader.rs` (utility, update)

**Analog:** `ferro-theme/src/loader.rs` itself

The `DEFAULT_THEME_CSS` constant (line 6) references `assets/default.css`, which currently contains `@import "tailwindcss"` and `@theme { ... }` directives. After this phase, `theme.css` injected into `<head>` must contain plain CSS variables — not Tailwind-specific at-rules.

Two options; choose based on implementation approach:

**Option A — Convert `default.css` to plain CSS vars (simplest):**

Replace `ferro-theme/assets/default.css` content: remove `@import "tailwindcss"`, convert `@theme { ... }` to `:root { ... }`, convert `@media (prefers-color-scheme: dark) { @theme { ... } }` to `@media (prefers-color-scheme: dark) { :root { ... } }`.

The loader.rs `include_str!` line is unchanged. The file it embeds changes format.

**Current `default.css` format** (lines 1-36):
```css
@import "tailwindcss";

@theme {
  --color-background: oklch(100% 0 0);
  /* ... all 23 tokens ... */
}

@media (prefers-color-scheme: dark) {
  @theme { ... }
}

[data-theme="dark"] { ... }
```

**Target plain-CSS format** (injectable as-is into `<style>` without Tailwind CDN):
```css
:root {
  --color-background: oklch(100% 0 0);
  /* ... all 23 tokens ... */
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-background: oklch(12% 0 0);
    /* ... dark values ... */
  }
}

[data-theme="dark"] {
  --color-background: oklch(12% 0 0);
  /* ... dark values ... */
}
```

**Existing test to update** (`ferro-theme/src/loader.rs` line 91):

The test `from_path_loads_tokens_css_and_theme_json` uses `"@theme { --color-primary: oklch(55% 0.2 250); }"` as fixture CSS. This test checks `theme.css == css_content` (round-trip read), so the fixture format does not need to change — the test does not assert on `@theme` syntax being correct, just that the file is read back identically.

The test at line 70 (`default_theme_returns_non_empty_css_with_color_primary`) asserts `theme.css.contains("--color-primary")`. This remains valid regardless of `@theme` vs `:root` format.

**Option B — Strip `@import` and `@theme` wrappers at load time in loader.rs:**

More complex, not recommended. CONTEXT.md decision D-10 says conversion happens before injection. Option A (convert the file) is the simpler path.

## Shared Patterns

### `include_str!` for compile-time asset embedding
**Source:** `ferro-theme/src/loader.rs` line 6
**Apply to:** `ferro-json-ui/src/assets.rs`
```rust
const DEFAULT_THEME_CSS: &str = include_str!("../assets/default.css");
```
The pattern: module-level `const` (not `static`, not a function), `&'static str` type, relative path from the `.rs` file to the asset file. This is the only pattern used for embedded assets in this codebase.

### hyper response builder for embedded static content
**Source:** `framework/src/static_files.rs` lines 61-67
**Apply to:** `serve_ferro_base_css()` in `framework/src/server.rs`
```rust
let response = hyper::Response::builder()
    .status(200)
    .header("Content-Type", &content_type)
    .header("Content-Length", bytes.len().to_string())
    .header("Cache-Control", cache_control)
    .body(Full::new(Bytes::from(bytes)))
    .unwrap();
```
Deviation: use `Bytes::from_static(css.as_bytes())` instead of `Bytes::from(bytes)` — the CSS is `'static`, allocation is unnecessary.

### Consuming builder methods on config structs
**Source:** `ferro-json-ui/src/config.rs` lines 44-59
**Apply to:** new `stylesheet_urls` builder method in same file
```rust

```
Pattern: `pub fn {name}(mut self, {param}) -> Self { self.{field} = {param}; self }`. No `with_` prefix in this file — match the existing convention exactly.

### `/_ferro/*` synchronous match arm
**Source:** `framework/src/server.rs` lines 214-224
**Apply to:** new `"/_ferro/ferro-base.css"` arm

Non-async arms return `hyper::Response<Full<Bytes>>` directly (no `.await`). The new CSS handler follows the same pattern. The function it calls must return `hyper::Response<Full<Bytes>>` (same type as the match expression).
