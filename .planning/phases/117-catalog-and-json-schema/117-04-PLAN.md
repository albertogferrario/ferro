<objective>
Implement the two-stage validation pipeline: `catalog.validate(&spec) ->
Result<(), Vec<CatalogError>>`. This satisfies CAT-03 (typed errors, pre-dispatch
short-circuit) and completes SCHEMA-03 (validator reused, not recompiled).

Pipeline (CONTEXT D-10):
1. **Stage 1 — type_name whitelist.** Iterate `spec.elements`; every
   `element.type_name` must resolve to a built-in OR plugin. Unknown type_names
   become `CatalogError::UnknownType`. If Stage 1 finds ANY error, return
   immediately — do NOT run Stage 2 or 3 (avoids noisy `oneOf-no-match` errors).
2. **Stage 2 — per-element Props validation.** For each element, look up
   `per_component_schemas[type_name]` and validate `element.props` against it
   using on-demand `jsonschema::validator_for`. Errors become
   `CatalogError::PropsInvalid`. Plugin schemas are opaque (D-20) — skip per-
   element validation when the type is a plugin unless the plugin provided a
   meta-valid schema (Plan 02 guaranteed this).
3. **Stage 3 — envelope check.** Serialize the full `Spec` and run it through
   `self.validator` (the cached full-spec validator from Plan 03). Any errors
   become `CatalogError::SpecInvalid`.

Errors accumulate into `Vec<CatalogError>` so a caller sees every issue at
once, not just the first.

Purpose: CAT-03 is the contract Phase 119 (Page Loader) depends on. Getting
errors structured and distinguishable here means downstream tooling can act
on them (not just print opaque strings).

Output: Callable `catalog.validate(&spec)` with 6 negative + 2 positive tests
proving every branch.
</objective>

    ```rust
    impl Catalog {
        // ... existing build(), json_schema() ...

        /// Validate a Spec against the catalog.
        ///
        /// Pipeline (CONTEXT D-10):
        /// 1. Type-name whitelist (O(n), O(1) per element). Unknown type_names return `UnknownType`
        ///    and SHORT-CIRCUIT the rest of the pipeline (avoids noisy oneOf errors downstream).
        /// 2. Per-element Props validation against the component's schema. Errors become
        ///    `PropsInvalid`. Plugin types (where per-component schema was accepted by
        ///    meta-validation in build) ARE validated — plugin authors are responsible for
        ///    accurate schemas, but we still enforce what they declared (CONTEXT D-20).
        /// 3. Full-spec envelope validation using the cached `self.validator` (SCHEMA-03 —
        ///    NEVER recompiled).
        ///
        /// Errors accumulate across Stages 2 and 3 so a caller sees every issue at once.
        /// Stage 1 short-circuits because downstream stages would explode into noise if
        /// type_name is unknown.
        pub fn validate(&self, spec: &crate::spec::Spec) -> Result<(), Vec<CatalogError>> {
            let mut errors: Vec<CatalogError> = Vec::new();

            // === Stage 1: type_name whitelist (O(1) per element) ===
            for (id, el) in &spec.elements {
                let known = self.components.contains_key(&el.type_name)
                    || self.plugin_components.contains_key(&el.type_name);
                if !known {
                    errors.push(CatalogError::UnknownType {
                        element_id: id.clone(),
                        type_name: el.type_name.clone(),
                    });
                }
            }
            // SHORT-CIRCUIT: if any type is unknown, skip Stages 2 & 3.
            // Rationale: Stage 3's full-spec oneOf would emit dozens of
            // noisy "no variant matched" errors for unknown types, drowning
            // the signal. Stage 2 would skip unknowns anyway.
            if !errors.is_empty() {
                return Err(errors);
            }

            // === Stage 2: per-element Props validation ===
            for (id, el) in &spec.elements {
                if let Some(schema) = self.per_component_schemas.get(&el.type_name) {
                    // On-demand compile (CONTEXT D-12). Escape hatch documented for
                    // future precompilation HashMap<String, Validator> if profiling
                    // demands. Since schemas are small (~50–200 LOC JSON), compile
                    // cost is < 1 ms per component.
                    let v = match jsonschema::validator_for(schema) {
                        Ok(v) => v,
                        Err(e) => {
                            errors.push(CatalogError::BuildFailed(format!(
                                "compiling per-component schema for '{}': {e}",
                                el.type_name
                            )));
                            continue;
                        }
                    };
                    let mut per_elem_errs: Vec<String> = Vec::new();
                    for err in v.iter_errors(&el.props) {
                        per_elem_errs.push(format!("{}: {}", err.instance_path, err));
                    }
                    if !per_elem_errs.is_empty() {
                        errors.push(CatalogError::PropsInvalid {
                            element_id: id.clone(),
                            type_name: el.type_name.clone(),
                            errors: per_elem_errs,
                        });
                    }
                }
            }

            // === Stage 3: full-spec envelope validation (uses cached validator) ===
            let spec_value = match serde_json::to_value(spec) {
                Ok(v) => v,
                Err(e) => {
                    errors.push(CatalogError::SchemaSerialization(e));
                    return Err(errors);
                }
            };
            let mut envelope_errs: Vec<String> = Vec::new();
            for err in self.validator.iter_errors(&spec_value) {
                envelope_errs.push(format!("{}: {}", err.instance_path, err));
            }
            if !envelope_errs.is_empty() {
                errors.push(CatalogError::SpecInvalid {
                    errors: envelope_errs,
                });
            }

            if errors.is_empty() { Ok(()) } else { Err(errors) }
        }
    }
    ```

    Note on `err.instance_path` in jsonschema 0.46: the error type exposes
    `instance_path` as a `Display`-friendly field (not a method). If the
    compile fails with "no method named `instance_path`", use
    `err.instance_path.to_string()` instead. Verify against jsonschema 0.46
    docs at edit time.
