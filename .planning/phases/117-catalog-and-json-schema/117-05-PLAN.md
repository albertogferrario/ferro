Add the zero-copy per-component schema accessor (`Catalog::component_schema`)
that closes CAT-04 ("`catalog.component_schema("Card")` returns the JSON Schema
for a single component's props — for targeted AI structured output generation"
— ROADMAP success criterion 5). Also add the two sorted-iteration helpers

`json_ui_catalog.rs` consumer rewrite (RESEARCH §9).

The per-component schema is the bridge between Plan 02's `per_component_schemas`
map (populated once at `Catalog::build` time, already sanitized, already meta-
validated for plugins) and downstream consumers:

- Phase 120 AI structured-output generation passes a single-component schema
  to Anthropic / OpenAI as the response schema — the Element / Spec envelope
  would confuse the model (CONTEXT D-19).
- `ferro json-ui:schema --component Card` CLI (Plan 07) prints this exact
  schema. Zero-copy reference → CLI clones once at serialization site.
- Phase 117.1 `Spec::from_service_def` inspects component Props shapes to map
  `DataType` → component; `component_schema` is the query path.

Scope is deliberately narrow: three public methods, no recomputation, no
re-materialization of the maps. Every test asserts on the live Plan 02
artifacts.

Purpose: CAT-04 is the public API every downstream AI/projection generator
depends on; getting the accessor shape right (return `Option<&Value>`, not
`Option<Value>`) saves a clone per generation call.

Output: A `catalog.rs` that exposes `component_schema` + two sorted-iterator
helpers, with four unit tests proving built-in lookup, plugin lookup, unknown
→ None, and Props-only shape.
</objective>

Target public surface this plan adds:

```rust
impl Catalog {
    /// Zero-copy accessor for a single component's Props JSON Schema.
    ///
    /// Returns the Props-only schema (NOT wrapped in the Element envelope
    /// that `json_schema()` uses for the full spec). Used by Phase 120 AI
    /// structured-output generation and by `ferro json-ui:schema --component`.
    ///
    /// Looks up both built-in and plugin components.
    ///
    /// Returns `None` for unknown component type names.
    pub fn component_schema(&self, type_name: &str) -> Option<&serde_json::Value> {
        self.per_component_schemas.get(type_name)
    }

    /// Iterate built-in `ComponentSpec` entries sorted by name (ascending).
    ///
    /// Used by `prompt()` (Plan 06) for deterministic output and by ferro-mcp
    /// `json_ui_catalog.rs` (Plan 06 consumer migration) for stable output.
    pub fn components_sorted(&self) -> impl Iterator<Item = &ComponentSpec> {
        let mut entries: Vec<&ComponentSpec> = self.components.values().collect();
        entries.sort_by(|a, b| a.name.cmp(&b.name));
        entries.into_iter()
    }

    /// Iterate plugin `ComponentSpec` entries sorted by name (ascending).
    pub fn plugin_components_sorted(&self) -> impl Iterator<Item = &ComponentSpec> {
        let mut entries: Vec<&ComponentSpec> = self.plugin_components.values().collect();
        entries.sort_by(|a, b| a.name.cmp(&b.name));
        entries.into_iter()
    }
}
```

    ```rust
    #[test]
    fn component_schema_returns_props_only() {
        // ROADMAP SC-5 canonical example: catalog.component_schema("Card") must
        // return the CardProps schema (NOT the Element wrapper from
        // $defs/Element.properties.props in the full schema).
        let cat = Catalog::build().expect("build");
        let schema = cat
            .component_schema("Card")
            .expect("Card is a built-in component");

        // A Props schema is an object with a `properties` map. The Element
        // envelope would have a `type` + `props` + `children` layout — we
        // assert the Props-only shape by checking for CardProps fields.
        let obj = schema.as_object().expect("Card props schema is a JSON object");

        // Expect "type": "object" or equivalent (schemars uses `type` or `oneOf`).
        assert!(
            obj.contains_key("type") || obj.contains_key("oneOf") || obj.contains_key("anyOf"),
            "CardProps schema should be a structural object schema; got {obj:?}"
        );

        // Expect CardProps-specific field "title" exists in `properties`.
        // If schemars emits the schema without a `properties` map, this plan's
        // Props-only assumption is wrong — surface that immediately.
        if let Some(props) = obj.get("properties").and_then(|v| v.as_object()) {
            assert!(
                props.contains_key("title"),
                "CardProps schema.properties should include 'title'; got keys: {:?}",
                props.keys().collect::<Vec<_>>()
            );
        } else {
            // schemars sometimes wraps via allOf/$ref — still fail loudly so
            // we revisit the sanitizer if this path triggers.
            panic!(
                "CardProps schema missing top-level 'properties' map — \
                 sanitizer or Plan 02 may be wrong. Got: {}",
                serde_json::to_string_pretty(schema).unwrap_or_default()
            );
        }

        // Must NOT be the Element envelope (defensive — would mean we accidentally
        // returned full_schema["$defs"]["Element"] or similar).
        let is_element_wrapper = obj.get("properties")
            .and_then(|v| v.as_object())
            .map(|p| p.contains_key("children") && p.contains_key("props"))
            .unwrap_or(false);
        assert!(
            !is_element_wrapper,
            "component_schema('Card') returned an Element wrapper; must be Props-only (CONTEXT D-19)"
        );
    }

    #[test]
    fn component_schema_none_for_unknown() {
        let cat = Catalog::build().expect("build");
        assert!(
            cat.component_schema("NotARealComponent_117_05").is_none(),
            "unknown component must return None"
        );
        // Empty string is also "unknown"
        assert!(cat.component_schema("").is_none());
    }

    #[test]
    fn component_schema_resolves_every_builtin() {
        // Parallel safety net for SC-5: every name in BUILTIN_TYPES must have a
        // per-component schema. If any is missing, Plan 02's BUILTIN_SPECS table
        // or the build loop dropped an entry.
        let cat = Catalog::build().expect("build");
        for name in crate::render::BUILTIN_TYPES.iter() {
            assert!(
                cat.component_schema(name).is_some(),
                "built-in '{name}' has no per-component schema"
            );
        }
    }

    #[test]
    fn components_sorted_yields_ascending_by_name() {
        let cat = Catalog::build().expect("build");
        let names: Vec<String> = cat
            .components_sorted()
            .map(|spec| spec.name.clone())
            .collect();
        assert_eq!(names.len(), crate::render::BUILTIN_TYPES.len());
        let mut sorted = names.clone();
        sorted.sort();
        assert_eq!(names, sorted, "components_sorted must yield ascending order");

        // plugin_components_sorted returns the plugin side; may be empty.
        let plugin_names: Vec<String> = cat
            .plugin_components_sorted()
            .map(|spec| spec.name.clone())
            .collect();
        let mut plugin_sorted = plugin_names.clone();
        plugin_sorted.sort();
        assert_eq!(
            plugin_names, plugin_sorted,
            "plugin_components_sorted must yield ascending order"
        );
    }
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Caller-provided `type_name: &str` → HashMap lookup | Untrusted input; HashMap lookup is O(1) and safe. No interpolation into queries or format strings beyond the assertion messages. |
| Returned `&Value` → downstream serializer (CLI stdout, AI SDK) | Reference lifetime bounded by `&self`; downstream clones at serialization boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-117-05-01 | I (Information Disclosure) | `component_schema(name)` for plugin components | accept | Plugin schemas are already public via the full `json_schema()` oneOf (Plan 03). Exposing individual plugin schemas adds no new surface. |
| T-117-05-02 | D (Denial of Service) | `components_sorted` / `plugin_components_sorted` allocating a Vec per call | accept | Vec holds 39 references for built-ins, typically <10 for plugins. O(n log n) sort is dominated by the 39 element count. If profiling shows this as hot, cache inside `Catalog` — deferred to follow-up per CONTEXT D-12 escape-hatch pattern. |
| T-117-05-03 | T (Tampering) | Returning `&Value` that points into `Catalog.per_component_schemas` | accept | The `Catalog` is held inside a `OnceLock<Catalog>` (Plan 01 `global_catalog`) — it never mutates after build, so borrow aliasing is sound. Rust's borrow checker enforces the `&self` lifetime. |
</threat_model>
