<objective>
Ship the `ferro json-ui:schema` CLI command that closes SCHEMA-02 ("`ferro
json-ui:schema` CLI command exports the spec schema to stdout or file —
consumable by external tools and IDEs" — ROADMAP success criterion 6).

Architecture (verified in RESEARCH §8):

1. **Binary-side dispatch** in `framework/src/app.rs` — the unified `ferro`
   binary's clap `Commands` enum receives a new `JsonUiSchema` variant. The
   handler calls `ferro_json_ui::Catalog::build()` directly (NOT
   `global_catalog()`, so build failures surface as non-zero exit, not
   panics). Serializes via `serde_json::to_string_pretty` / `to_string` and
   writes to stdout or the path given by `--output`.

2. **ferro-cli shell-out** in `ferro-cli/src/commands/json_ui_schema.rs` —
   mirrors `db_status.rs`: verifies the caller is in a Ferro project, then
   spawns `cargo run --quiet -- json-ui:schema [args]`. This lets developers
   invoke the command from the `ferro` binary in the workspace root without
   requiring the framework binary to be on PATH.

3. **ferro-cli main dispatch** in `ferro-cli/src/main.rs` — clap variant
   `JsonUiSchema { output, pretty, component }` + match arm calling
   `commands::json_ui_schema::run(output, pretty, component)`.

4. **Module declaration** in `ferro-cli/src/commands/mod.rs` — `pub mod json_ui_schema;`.

Three flags (CONTEXT D-21):
- `--output <path>` (short `-o`) → write to file; default stdout
- `--pretty` → pretty-print (default behavior per RESEARCH §8 handler is
  already pretty-printed; `--pretty` stays explicit for back-compat with
  external tools expecting the flag)
- `--component <name>` → emit only that component's Props schema (via
  `Catalog::component_schema(name)` from Plan 05); unknown name is an error

No CLI output has been promised for Phase 117 beyond this command. Phase 119
(Page Loader) and Phase 120 (Two-tier AI) build on `json_schema()` /
`component_schema()` library access, NOT on CLI.

Purpose: SCHEMA-02 is the first external-tooling surface of the catalog.
Getting the shell-out + binary dispatch right here sets the pattern for
future `ferro json-ui:*` subcommands (view render preview, component lint,
etc.) without re-deciding the architecture each time.

Output: Two new files, two modified dispatch files, smoke-tested command
that pipes valid JSON to `jq .` in both the full-schema and per-component
modes.

    async fn run_json_ui_schema(
        output: Option<String>,
        pretty: bool,
        component: Option<String>,
    ) {
        // Build a local Catalog so BuildFailed surfaces as non-zero exit
        // (NOT a panic via global_catalog's `expect`). RESEARCH §8 L-1 pattern.
        let catalog = match ferro_json_ui::Catalog::build() {
            Ok(c) => c,
            Err(e) => {
                eprintln!("error building catalog: {e}");
                std::process::exit(1);
            }
        };

        let value: &serde_json::Value = match &component {
            Some(name) => match catalog.component_schema(name) {
                Some(v) => v,
                None => {
                    eprintln!("error: unknown component '{name}'");
                    std::process::exit(1);
                }
            },
            None => catalog.json_schema(),
        };

        // CONTEXT D-21: default output is pretty-printed (RESEARCH §8 handler).
        // The --pretty flag stays as an explicit opt-in for back-compat with
        // tooling that passes it; compact is NOT reachable via any flag in
        // Phase 117. If a future plan wants compact output, add --compact.
        let _ = pretty;
        let serialized = serde_json::to_string_pretty(value)
            .expect("schema serializes");

        match output {
            Some(path) => {
                if let Err(e) = std::fs::write(&path, serialized) {
                    eprintln!("error writing to {path}: {e}");
                    std::process::exit(1);
                }
            }
            None => println!("{serialized}"),
        }
    }
    ```

    use console::style;
    use std::path::Path;
    use std::process::Command;

    /// Invoke the unified `ferro` binary's `json-ui:schema` subcommand from
    /// the workspace root via `cargo run --quiet`.
    ///
    /// Mirrors the `db_status.rs` shell-out pattern. Requires a `Cargo.toml`
    /// at the current directory to prove we are inside a Ferro project.
    pub fn run(output: Option<String>, pretty: bool, component: Option<String>) {
        if !Path::new("Cargo.toml").exists() {
            eprintln!(
                "{} This command must be run from a Ferro project root",
                style("Error:").red().bold()
            );
            std::process::exit(1);
        }

        let mut args: Vec<String> = vec![
            "run".into(),
            "--quiet".into(),
            "--".into(),
            "json-ui:schema".into(),
        ];
        if let Some(o) = output.as_deref() {
            args.push("--output".into());
            args.push(o.to_string());
        }
        if pretty {
            args.push("--pretty".into());
        }
        if let Some(c) = component.as_deref() {
            args.push("--component".into());
            args.push(c.to_string());
        }

        let status = Command::new("cargo")
            .args(&args)
            .status()
            .expect("Failed to execute cargo command");

        if !status.success() {
            eprintln!(
                "{} Schema export failed",
                style("Error:").red().bold()
            );
            std::process::exit(1);
        }
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI caller → `--output <path>` filesystem write | Moderate risk — `--output` accepts an arbitrary path string; `std::fs::write` will overwrite. Accepting: this is a local developer CLI; path traversal is caller's responsibility. |
