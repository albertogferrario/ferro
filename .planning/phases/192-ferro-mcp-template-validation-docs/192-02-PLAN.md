ConstraintMap (framework/src/validation/constraint_map.rs):
```rust
let map = ConstraintMap::new()
    .on("pages_slug_unique", "slug", "has already been taken")  // Postgres constraint name
    .sqlite("pages.slug");                                       // SQLite table.column discriminator
// try_map(err: DbErr) -> Result<ValidationError, DbErr>  (non-match returned unchanged)
// MapConstraintExt on Result<T, DbErr>:
new_page.insert(db).await
    .map_constraint(&map, &data, "/pages/new")?;   // match -> field error + redirect; else From<DbErr> for ActionError
```

Postgres vs SQLite identity (constraint_map.rs module doc):
- Postgres: matched by constraint NAME via DatabaseError::constraint() — no message parsing.
- SQLite: matched by `table.column` parsed from "UNIQUE constraint failed: table.column".
- One registration covers both by chaining `.sqlite("t.c")` after `.on(...)`.

    **Section A — `## Async Rules (DB-backed)`** (D-04). Content:
    - One-sentence intro: some rules must hit the database (e.g. "is this slug
      already taken?"); these run through `AsyncValidator` / `validate_async`,
      a parallel path that leaves the synchronous `Validator` API unchanged.
    - Code block, create form (no exclude-self):
      ```rust
      use ferro::{AsyncValidator, AsyncValidationError, unique, rules, required, string};

      let data = req.input::<serde_json::Value>().await?;

      match AsyncValidator::new(&data)
          .rules("slug", rules![required(), string()])
          .async_rule("slug", unique("pages", "slug"))
          .validate_async()
          .await
      {
          Ok(()) => { /* proceed to insert */ }
          Err(AsyncValidationError::Validation(e)) => {
              return Err(e.with_old_input(&data).into_action_error("/pages/new"));
          }
          Err(AsyncValidationError::Infra(fe)) => return Err(fe.into()),
      }
      ```
    - Prose: sync rules run first and async rules are skipped on a field that
      already failed sync (fail-fast — no needless DB query). A `Validation` error
      surfaces under the field with old input preserved (303 redirect-back); an
      `Infra` error is a 500, never a silent validation pass.
    - Subsection on exclude-self (`### Exclude-Self on Edit Forms`). Prose: on edit
      forms the record would fail its own current value; `.ignore(id)` excludes it.
      Code block:
      ```rust
      // Edit form: allow record #42 to keep its current slug.
      .async_rule("slug", unique("pages", "slug").ignore(record_id))
      ```
      Note `.ignore_on("uuid", id)` for non-`id` primary keys.
    - Closing cross-link sentence (REQUIRED, SC3):
      "The async rule is the proactive layer. It cannot eliminate the
      check-then-write race under concurrency — pair it with the defensive
      [Constraint Mapping](#constraint-mapping) layer at the write site."

    **Section B — `## Constraint Mapping`** (D-05). Content:
    - Intro: even with the proactive rule, two requests can both pass the check and
      one loses the INSERT race (TOCTOU). `ConstraintMap` maps the DB UNIQUE
      violation to the SAME field-level error instead of leaking a raw SQL error.
    - Code block:
      ```rust
      use ferro::{ConstraintMap, MapConstraintExt};

      let map = ConstraintMap::new()
          .on("pages_slug_unique", "slug", "has already been taken")
          .sqlite("pages.slug");

      let page = new_page
          .insert(db)
          .await
          .map_constraint(&map, &data, "/pages/new")?;
      ```
    - Prose two-layer rationale (REQUIRED): the proactive `unique` rule catches the
      common case before the write (good UX — inline error, no wasted INSERT); the
      defensive `ConstraintMap` closes the TOCTOU race at the write (concurrency
      safety net). A non-matching `DbErr` falls through `map_constraint` unchanged
      to the existing `From<DbErr> for ActionError` passthrough — never swallowed.
    - Brief Postgres-vs-SQLite identity note (REQUIRED): Postgres matches by the
      structured constraint NAME (the `.on("pages_slug_unique", ...)` key); SQLite
      matches by `table.column` from the error message (the `.sqlite("pages.slug")`
      discriminator). One registration covers both by chaining both.
    - Opening cross-link sentence (REQUIRED, SC3):
      "This is the defensive complement to the proactive
      [Async Rules](#async-rules-db-backed) layer — use both together."
