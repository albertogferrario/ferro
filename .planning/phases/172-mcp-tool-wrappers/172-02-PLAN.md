<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → LLM (ai_scaffold) | The `description` argument is concatenated into the LLM prompt inside a `<description>...</description>` block. Untrusted free text crosses into the model context here. |
| caller → LLM (ai_explain prose) | The `target` argument selects a route/model whose introspected facts are placed into the prose prompt. Target reaches resolution logic and (indirectly, via the resolved artifact) the prompt. |
| caller → introspection (ai_explain structured) | `target` reaches `inspect_projection::execute`; the structured branch makes NO LLM call (no injection surface to the model). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-172-PI | Tampering / Elevation (prompt injection) | `scaffold_core` `description` → LLM prompt | mitigate | Relocate `sanitize_description` INTACT from Phase 171 (IN-01) and apply it to `description` before embedding in the `<description>` block — replaces `</description>`/`<description>` so a crafted payload cannot close the delimiter and inject out-of-band instructions. Asserted by the `sanitize_description_strips_xml_delimiters` test (Task 1). Re-implementation is prohibited; copy the verified body. |
| T-172-PI-EXPLAIN | Tampering (prompt injection via target) | `explain_core` `target` → prose prompt | mitigate | The prose prompt is built from INTROSPECTED artifact facts (RouteExplanation/ModelExplanation), not from the raw `target` string interpolated freely — `target` is used as a lookup key, and resolution returns NotFound (an `Err`, no LLM call) for unmatched input. The structured branch makes zero LLM calls. Document this in the explain_core doc comment. Disposition: low residual risk; the route/model fact content is project-owned, not attacker-controlled. |
| T-172-DISK | Tampering (unexpected disk mutation) | `scaffold_core` | mitigate | `scaffold_core` returns the `ServiceDef` value and performs NO file write (D-02). Acceptance criteria forbid `render_output`/file-write symbols in ai_scaffold.rs (the emitter stays CLI-side, Plan 04). No path-traversal surface exists in the core. |
| T-172-CRASH | Denial of Service (server crash on tool error) | both cores | mitigate | Cores return `Result<_, String>`; acceptance criteria forbid `process::exit`/`panic`/`eprintln!`. `AiConfig::from_env` and LLM failures map to `Err(String)`. The MCP server process cannot be terminated by a tool-level error. |
</threat_model>
