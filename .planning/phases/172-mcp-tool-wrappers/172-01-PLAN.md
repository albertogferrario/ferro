<objective>
Relocate the lexical relevance filter from `ferro-cli/src/relevance.rs` into
`ferro-mcp/src/tools/relevance.rs` verbatim, with visibility raised from
`pub(crate)` to `pub` so both the relocated cores (Plan 02) and the CLI thin
wrapper (Plan 04) can consume it. Add a test-only `ENV_LOCK` to `ferro-mcp` so
env-touching tests for the relocated cores (later plans) do not race.

This is the foundation wave: it establishes the shared utility surface the cores
depend on, with zero dependency on any other plan.

Purpose: SC#3 (no duplicate implementation) requires the relevance filter to have
exactly one definition site in the crate both the CLI and MCP tool depend on
(`ferro-mcp`). This plan creates that single site.

Output: `ferro-mcp/src/tools/relevance.rs` (with all tests), `pub mod relevance`
in tools/mod.rs, and a `#[cfg(test)] ENV_LOCK` static in ferro-mcp.
</objective>
