## Decisions Made

- The fix is surgical: only the one `#job_ident_str` inside `fn name()` is replaced. The `job_ident_str` local variable is preserved (still used in `Error::job_failed` diagnostics and `JobRegistrarEntry.name` diagnostic field). Zero API surface change.
- The test binary uses a temp-file SQLite (not in-memory) to ensure all pool connections share the same database. `Queue::init` is called once per binary (OnceLock constraint). `ferro::container::provider::bootstrap()` is called before the `WorkerLoop` drain to activate the `#[service]` binding so the derived `handle()` can resolve `dyn Reports`.
- Test lives in `framework/tests/` not `ferro-queue/tests/`: a real derived job emits `::ferro::*` paths and `ferro-rs` → `ferro-queue` creates a dependency cycle in the other direction. This was the `<planner_correction>` carried into the plan; the RESEARCH.md sketch used a hand-written `impl Job` which would not have discriminated against the unfixed macro.

## Planner Correction: Test Location

The original RESEARCH.md placed the test at `ferro-queue/tests/dispatch_key_derived_job.rs` with a hand-written `impl Job`. The plan carried a `<planner_correction>` explaining both defects:
1. A real derived job cannot compile in `ferro-queue/tests/` because `#[offload]`/`#[service]` emit `::ferro::*` paths and `ferro-rs` depends on `ferro-queue` (dependency cycle).
2. A hand-written `impl Job` already uses the default `name()` = `type_name` and would pass against the unfixed macro, proving nothing about DISPATCH-KEY-01.

The test was placed at `framework/tests/dispatch_key_derived_job.rs` (the `ferro-rs` crate), which already hosts real offload integration tests (`offload_result_round_trip.rs`, `offload_delta_broadcast.rs`, `worker_boot.rs`).
