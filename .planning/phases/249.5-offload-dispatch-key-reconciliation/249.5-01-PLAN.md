<objective>
Reconcile the two ends of the offload dispatch handshake so that an `#[offload]`-derived
job enqueued on the `QUEUE_CONNECTION=db` path is actually claimed and executed by the
worker (DISPATCH-KEY-01, GAP CLOSURE). Today the derived `Job::name()` returns the **bare
struct ident** (e.g. `"ReportsBuildMonthlyJob"`), which enqueue writes to the DB `job_type`
column; the worker registers and looks up handlers by fully-qualified
`std::any::type_name::<J>()` (e.g. `"…::reports::ReportsBuildMonthlyJob"`). The lookup in
`spawn_job` always misses → "No handler registered — releasing job for retry" → the job
release-loops until its retries are exhausted and never produces a snapshot or delta.

The fix is one expression in `ferro-macros/src/offload.rs`: emit
`::std::any::type_name::<Self>()` from the derived `fn name()` instead of the bare-ident
literal. That makes ONE canonical dispatch key on both sides. Hand-written jobs already use
the default `name()` = `type_name` and are unaffected.

Purpose: Restore OFFLOAD-01 db-path dispatch; unblock OFFLOAD-04 (delta fires) and
OFFLOAD-05 (worker dispatches offloaded work) at runtime. This repairs the primary offload
E2E flow.

Output:
- A new discriminating integration test that enqueues a REAL derived job on the db path and
  proves claim + exactly-once dispatch.
- The one-line macro fix + doc-comment reconciliation.

   is exactly the silent degradation this creates — and a hand-written job already uses the
   default `name()` = `type_name`, so it would PASS against the UNFIXED macro and prove
   nothing about DISPATCH-KEY-01.

2. Correct home: `framework/tests/` — the `ferro-rs` crate depends on the facade (as
   `ferro_rs`) and already hosts real offload integration tests
   (`offload_result_round_trip.rs`, `offload_delta_broadcast.rs`, `worker_boot.rs`). A real

   macro→enqueue→worker path. File: `framework/tests/dispatch_key_derived_job.rs`; the test

3. Additional step RESEARCH omitted: the derived `handle()` calls
