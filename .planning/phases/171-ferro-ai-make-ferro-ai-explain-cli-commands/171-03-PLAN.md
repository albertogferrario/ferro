<objective>
Ship `ferro ai:explain <target>` (AICLI-03): resolve a target in service → route → model order
(projection-framed is the PRIMARY path, prose is the fallback), assemble a projection-framed
prompt from `inspect_projection`'s parsed vocabulary when a `ServiceDef` exists, and produce a
prose explanation via a raw `client.complete()` call with `schema: None`. `--dry-run` prints the
assembled prompt and makes no LLM call.

Purpose: This is the consume half of the milestone killer feature — an existing service explained
in projection terms (Intent / FieldMeaning / ActionDef+GuardDef / StateMachine, SC#4), grounded
only in what introspection reports (SC#6). It reuses the AI-required fail-fast + tokio-bridge
patterns established in Plan 02.
Output: `ferro-cli/src/commands/ai_explain.rs` + clap registration in main.rs.

Note (research correction): `inspect_projection::execute` returns a `ProjectionDetail` of PARSED
STRINGS (`meaning: String`, `actions: Vec<String>`, `relationships: Vec<String>`,
`intent_hints: Vec<String>`), NOT a live typed `ServiceDef`. The projection framing is built by
the LLM from this string vocabulary — `derive_intents` is NOT called (it needs a live ServiceDef
value, which the CLI does not have for an existing service). Prose output uses a RAW
`CompletionRequest { schema: None, .. }` (the make_json_view pass-1 pattern), NOT
`complete_with::<String>()` (which would force a JSON-quoted-string response).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user CLI arg → LLM prompt | `target` and the introspected facts are interpolated into the prompt |
| CLI → LLM provider | request max_tokens crosses to a paid external API (cost surface) |
| introspection → prompt | only ferro-mcp-reported facts feed the prompt (no source-tree write — ai:explain is read-only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-171-EX-DoS | Denial of Service | token/cost exhaustion | mitigate | `FERRO_AI_MAX_TOKENS_PER_COMMAND` caps response tokens (default 2048); the prompt is bounded by a single resolved target's introspection (no whole-project context). |
| T-171-EX-INFO | Information Disclosure | prompt grounding | mitigate | The prompt is assembled only from ferro-mcp introspection facts for the resolved target (SC#6); no filesystem read beyond what the mcp tools expose. ai:explain writes nothing to disk — read-only command, so the Tampering/path-traversal surface of ai:make does not apply. |
| T-171-EX-PI | Elevation of Privilege | target arg in prompt | accept | `target` is a route/model/service name used for lookup; if no match it is NotFound (never reaches the LLM as free instruction). Injected text in a target name only affects prose output, not control flow; low value, no structured-write side effect. |
</threat_model>
