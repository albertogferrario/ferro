<objective>
Close the loop by default (CHK-07): after generation, both `generate_projection` and `json_ui_generate`
embed a compact checkpoint `VerdictSummary` in their response so the agent receives verification
without a separate call. The dependency is strictly one-way — generators call the checkpoint, never
the reverse. `json_ui_generate` uses a speculative model-derived anchor and embeds nothing (None,
field omitted) when no model is named or the anchor does not resolve, avoiding the SC-1 vacuous
all-`not_checked` summary.

Purpose: This is the "by default" half of "close the loop by default". An agent that generates a
projection immediately sees whether the field→column seam and the four delegated seams are clean.
Output: Two generators with async `execute` embedding `checkpoint: Option<VerdictSummary>`; the two
service.rs handlers awaiting them; updated MCP tool descriptions.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-195-07 | Tampering | speculative anchor → run_for | mitigate | The derived anchor passes through `validate_name` inside `run_for`; a model name with illegal chars yields `Err` → `.ok()` → `None` (field omitted). No path-traversal reaches the cache write. |
| T-195-08 | Information Disclosure | embedded VerdictSummary | accept | Summary contains only seam names + next_steps strings about the agent's own project. Read-only; no secrets. SC-1 keeps it compact (no raw seam dump). |
| T-195-09 | Spoofing | one-way dependency | mitigate | Generators import checkpoint; checkpoint never imports generators — verified by the absence of generator references in checkpoint_projection.rs (no reverse edge to exploit). |
</threat_model>
