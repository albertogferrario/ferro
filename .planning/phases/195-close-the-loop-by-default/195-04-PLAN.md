## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ferro-mcp → filesystem (cache read) | Both ambient tools read `.ferro/checkpoints/{projection_name}.json` via `read_ambient_status`; the key is a scanned projection function name, not raw user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-195-10 | Tampering | ambient cache key (`proj.name`) | mitigate | The key originates from the trusted projection scan (`list_projections` / `ModelCoverage.projection_name`), not user input. `read_ambient_status` is tolerant (any IO/parse error → `"unverified"`), so a hand-edited or poisoned cache file degrades to honest `"unverified"` rather than a false `clean`. |
| T-195-11 | Repudiation/Integrity | stale cache reported as fresh | accept | D-11 is an explicit stale-ok decision: ambient status is a cached last-run result, not a live recompute. The inline hook (Plan 03) refreshes on every generation. Reporting stale status is the intended, documented behavior — not a defect. |
| T-195-12 | Information Disclosure | rollup counts in application_info | accept | Counts only (clean/failing/unverified) about the project's own projections. Read-only, no secrets, low value. |
</threat_model>
