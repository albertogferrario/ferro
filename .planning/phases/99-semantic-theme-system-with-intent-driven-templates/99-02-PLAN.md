  <action>
    1. Add ferro-theme as optional dependency in `framework/Cargo.toml`:
       ```toml
       ferro-theme = { path = "../ferro-theme", version = "0.1", optional = true }
       ```
       Add `theme = ["dep:ferro-theme"]` to `[features]` section.

    2. Create `framework/src/theme/context.rs` — mirrors `tenant/context.rs`:
       - Task-local `CURRENT_THEME: Arc<RwLock<Option<Arc<Theme>>>>` using `tokio::task_local!`
       - `pub fn current_theme() -> Option<Arc<Theme>>` — reads from task-local, returns clone of Arc
       - `pub(crate) fn theme_scope() -> Arc<RwLock<Option<Arc<Theme>>>>` — creates empty scope
       - `pub(crate) async fn with_theme_scope<F, R>(ctx: Arc<RwLock<Option<Arc<Theme>>>>, f: F) -> R` — scoped execution
       - Note: Theme is wrapped in Arc because it can be large (CSS string). TenantContext is Clone-cheap; Theme is not.

    3. Create `framework/src/theme/resolver.rs`:
       - `ThemeResolver` trait: `async fn resolve(&self, req: &Request) -> Option<Arc<Theme>>`
       - Use `#[async_trait]` for trait object compatibility
       - No concrete resolvers in this plan — users and future plans provide implementations. The trait is enough for ThemeMiddleware to work with mock resolvers in tests.

    4. Create `framework/src/theme/middleware.rs` — mirrors `tenant/middleware.rs`:
       - `ThemeMiddleware` struct with `resolvers: Vec<Box<dyn ThemeResolver>>` and `default: Arc<Theme>`
       - `ThemeMiddleware::new() -> Self` — empty resolvers, default = `Arc::new(Theme::default_theme())`
       - `.resolver(impl ThemeResolver + 'static) -> Self` — consuming builder, adds to vec
       - `.default_theme(theme: Theme) -> Self` — consuming builder, sets custom default
       - `impl Middleware for ThemeMiddleware` — iterates resolvers, first Some wins, falls back to self.default
       - Stores resolved theme in task-local via `with_theme_scope`
       - No failure modes needed (unlike TenantMiddleware) — default theme always available

    5. Create `framework/src/theme/mod.rs`:
       ```rust
       pub(crate) mod context;
       mod middleware;
       mod resolver;

       pub use context::current_theme;
       pub use middleware::ThemeMiddleware;
       pub use resolver::ThemeResolver;
       ```

    6. Add to `framework/src/lib.rs`:
       - `#[cfg(feature = "theme")] pub mod theme;` module declaration (near tenant module)
       - Feature-gated re-exports:
         ```rust
         #[cfg(feature = "theme")]
         pub use ferro_theme::{Theme, ThemeError, ThemeTemplates, IntentModeTemplates, IntentSlotTemplate};
         #[cfg(feature = "theme")]
         pub use theme::{current_theme, ThemeMiddleware, ThemeResolver};
         ```

    Tests use the same TCP loopback pattern as tenant/middleware.rs tests — `make_request()` via `tokio::net::TcpListener` since `Request::new()` takes `hyper::body::Incoming` with no default constructor.

    Use mock `AlwaysThemeResolver` and `NeverThemeResolver` (same pattern as `AlwaysResolver`/`NeverResolver` in tenant tests).
