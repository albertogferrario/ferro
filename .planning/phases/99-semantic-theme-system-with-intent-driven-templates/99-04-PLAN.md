Update JsonUiRenderer to consume intent templates from ferro-theme instead of using hardcoded layout decisions.

Purpose: Intent templates allow theme creators to override how each intent renders (slot arrangement, layout strategy) without writing Rust. This makes the ServiceDef -> Intent -> Renderer pipeline fully customizable through the theme system.

Output: JsonUiRenderer that checks for intent template overrides before falling back to built-in layouts. RenderContext extended with optional ThemeTemplates. Existing tests updated, new template-consumption tests added.

        let intent_score = intents.get(ctx.intent_index)...;
        let components = match &intent_score.intent {
            Intent::Browse => match ctx.mode {

    4. Implement template-driven rendering:
       Create a private method `render_from_template(&self, service: &ServiceDef, template: &IntentSlotTemplate, ctx: &RenderContext) -> Vec<Value>`:
       - Iterate over `template.slots`
       - For each slot name, produce the corresponding component(s):
         - `"title"` → Text component with service display_name (element: h1)
         - `"body"` → depends on layout hint: "table" -> Table component, "detail" -> DescriptionList, "form" -> Form fields

         - `"actions"` → Button components from service.actions (using existing action mapping)
         - `"relationships"` → relationship_to_component for each service.relationships (skip if empty)
         - `"pagination"` → Pagination component
         - `"metadata"` → system field display (created_at, updated_at)
         - `"stats"` → StatCard/summary components for numeric fields
       - Skip slots that produce empty component lists (no empty containers)

    5. Template lookup helper:
       ```rust
       fn get_template_for_intent(
           templates: &ThemeTemplates,
           intent: &Intent,
           mode: &RenderMode,
       ) -> Option<&IntentSlotTemplate> {
           let mode_templates = match intent {
               Intent::Browse => templates.browse.as_ref()?,
               Intent::Focus => templates.focus.as_ref()?,
               // ... all 7 intents
               Intent::Custom(_) => return None, // Custom intents don't have template overrides
           };
           let slot_template = match mode {
               RenderMode::Display => &mode_templates.display,
               RenderMode::Input => &mode_templates.input,
           };
           if slot_template.slots.is_empty() {
               None  // Empty slots = no override, use built-in
           } else {
               Some(slot_template)
           }
       }
       ```

    IMPORTANT: The render_from_template method reuses the SAME field_map functions (field_to_column, field_to_display, field_to_input) and relationship_to_component that the built-in render methods use. Templates control slot ARRANGEMENT only; component generation logic stays unchanged.
