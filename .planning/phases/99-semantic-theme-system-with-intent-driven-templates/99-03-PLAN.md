<task type="auto">
  <name>Task 1: Migrate render.rs -- replace all hardcoded Tailwind classes with semantic tokens</name>
  <files>ferro-json-ui/src/render.rs</files>
  <action>
    Perform a systematic, one-pass replacement of ALL hardcoded Tailwind color, rounded, and shadow classes in render.rs (~189 occurrences across 4530 lines). This is a single-pass, exhaustive migration.

    **Approach:** Search-and-replace across the entire file using the mapping table in the interfaces block above. Process function by function through all 26+ component render functions.

    **Tailwind v4 semantic utility class format:** Use `bg-primary`, `text-surface`, `border-border`, etc. -- these are standard Tailwind v4 utility classes generated from the `@theme` block's custom properties. Per the locked decision in CONTEXT.md: "components use `bg-primary`, `text-surface`, etc. as Tailwind utility classes mapped to CSS custom properties via Tailwind v4 `@theme` block."

    **Key rules:**
    1. Replace ALL `bg-gray-*`, `bg-white` with semantic equivalents (`bg-background`, `bg-surface`, `bg-card`)
    2. Replace ALL `text-gray-*` with `text-text` or `text-text-muted`
    3. Replace ALL `bg-blue-*`, `text-blue-*` with `bg-primary`, `text-primary`
    4. Replace ALL `bg-red-*`, `text-red-*` with `bg-destructive`, `text-destructive`
    5. Replace ALL `bg-green-*`, `text-green-*` with `bg-success`, `text-success`
    6. Replace ALL `bg-yellow-*`, `text-yellow-*` with `bg-warning`, `text-warning`
    7. Replace ALL `border-gray-*` with `border-border`
    8. Replace ALL `rounded-md`, `rounded-lg`, `rounded-full` with `rounded-radius-md`, `rounded-radius-lg`, `rounded-radius-full`
    9. Replace ALL `shadow-sm`, `shadow-md`, `shadow-lg` with `shadow-shadow-sm`, `shadow-shadow-md`, `shadow-shadow-lg`
    10. Replace ALL `ring-blue-*` with `ring-primary`
    11. Replace ALL `divide-gray-*` with `divide-border`
    12. `hover:bg-blue-700` -> `hover:bg-primary/90` (opacity modifier for hover)
    13. `focus:ring-blue-*` -> `focus:ring-primary`
    14. `text-white` on colored backgrounds -> `text-primary-foreground`
    15. Keep all sizing classes (text-sm, p-4, w-full, etc.) unchanged
    16. Keep all layout classes (flex, grid, gap-*, etc.) unchanged

    **Variant-specific mappings in render functions:**
    - `ButtonVariant::Primary` -- bg-primary text-primary-foreground
    - `ButtonVariant::Secondary` -- bg-secondary text-secondary-foreground
    - `ButtonVariant::Danger` -- bg-destructive text-primary-foreground
    - `ButtonVariant::Outline` -- border-border text-text
    - `ButtonVariant::Ghost` -- text-text hover:bg-surface
    - `AlertVariant::Info` -- bg-primary/10 text-primary border-primary
    - `AlertVariant::Success` -- bg-success/10 text-success border-success
    - `AlertVariant::Warning` -- bg-warning/10 text-warning border-warning
    - `AlertVariant::Error` -- bg-destructive/10 text-destructive border-destructive
    - `BadgeVariant` -- same pattern as AlertVariant colors
    - `ToastVariant` -- same pattern as AlertVariant colors

    **Update ALL tests in the same pass.** render.rs has test modules that assert specific CSS class names. Every assertion containing a hardcoded class must be updated to the semantic equivalent. Example:
    - `assert!(html.contains("text-gray-900"))` -> `assert!(html.contains("text-text"))`
    - `assert!(html.contains("bg-blue-600"))` -> `assert!(html.contains("bg-primary"))`
    - `assert!(html.contains("rounded-md"))` -> `assert!(html.contains("rounded-radius-md"))`

    After migration, verify with: `grep -c 'bg-gray\|bg-white\|text-gray\|border-gray\|bg-blue\|text-blue\|bg-red\|text-red\|bg-green\|text-green\|bg-yellow\|text-yellow' ferro-json-ui/src/render.rs` -- should return 0.
