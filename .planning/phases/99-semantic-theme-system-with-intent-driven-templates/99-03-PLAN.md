<task type="auto">
  <name>Task 1: Migrate render.rs — replace all hardcoded Tailwind classes with semantic tokens</name>
  <files>ferro-json-ui/src/render.rs</files>
  <action>
    Perform a systematic, one-pass replacement of ALL hardcoded Tailwind color, rounded, and shadow classes in render.rs (~189 occurrences across 4530 lines). This is a single-pass, exhaustive migration.

    **Approach:** Search-and-replace across the entire file using the mapping table in the interfaces block above. Process function by function through all 26+ component render functions.

    **Tailwind v4 arbitrary value syntax:** Use `bg-[--color-primary]` (NOT `bg-[var(--color-primary)]`). Tailwind v4 resolves `--custom-property` references in arbitrary values directly.

    **Key rules:**
    1. Replace ALL `bg-gray-*`, `bg-white`, `bg-blue-*`, `bg-red-*`, `bg-green-*`, `bg-yellow-*` with semantic equivalents
    2. Replace ALL `text-gray-*`, `text-blue-*`, `text-red-*`, `text-green-*`, `text-yellow-*` with semantic equivalents
    3. Replace ALL `border-gray-*`, `border-blue-*` with `border-[--color-border]` or role-specific
    4. Replace ALL `rounded-md`, `rounded-lg`, `rounded-full` with `rounded-[--radius-*]`
    5. Replace ALL `shadow-sm`, `shadow-md`, `shadow-lg` with `shadow-[--shadow-*]`
    6. Replace ALL `ring-blue-*` with `ring-[--color-primary]`
    7. Replace ALL `divide-gray-*` with `divide-[--color-border]`
    8. `hover:bg-blue-700` → `hover:bg-[--color-primary]/90` (opacity modifier for hover)
    9. `focus:ring-blue-*` → `focus:ring-[--color-primary]`
    10. Keep all sizing classes (text-sm, p-4, w-full, etc.) unchanged
    11. Keep all layout classes (flex, grid, gap-*, etc.) unchanged

    **Variant-specific mappings in render functions:**
    - `ButtonVariant::Primary` — bg-[--color-primary] text-[--color-primary-foreground]
    - `ButtonVariant::Secondary` — bg-[--color-secondary] text-[--color-secondary-foreground]
    - `ButtonVariant::Danger` — bg-[--color-destructive] text-[--color-primary-foreground]
    - `ButtonVariant::Outline` — border-[--color-border] text-[--color-text]
    - `ButtonVariant::Ghost` — text-[--color-text] hover:bg-[--color-surface]
    - `AlertVariant::Info` — bg-[--color-primary]/10 text-[--color-primary] border-[--color-primary]
    - `AlertVariant::Success` — bg-[--color-success]/10 text-[--color-success] border-[--color-success]
    - `AlertVariant::Warning` — bg-[--color-warning]/10 text-[--color-warning] border-[--color-warning]
    - `AlertVariant::Error` — bg-[--color-destructive]/10 text-[--color-destructive] border-[--color-destructive]
    - `BadgeVariant` — same pattern as AlertVariant colors
    - `ToastVariant` — same pattern as AlertVariant colors

    **Update ALL tests in the same pass.** render.rs has test modules that assert specific CSS class names. Every assertion containing a hardcoded class must be updated to the semantic equivalent. Example:
    - `assert!(html.contains("text-gray-900"))` → `assert!(html.contains("text-[--color-text]"))`
    - `assert!(html.contains("bg-blue-600"))` → `assert!(html.contains("bg-[--color-primary]"))`

    After migration, verify with: `grep -c 'bg-gray\|bg-white\|text-gray\|border-gray\|bg-blue\|text-blue\|bg-red\|text-red\|bg-green\|text-green\|bg-yellow\|text-yellow' ferro-json-ui/src/render.rs` — should return 0 (excluding "bg-white" in specific edge cases like contrast text, which should have been migrated to primary-foreground).
