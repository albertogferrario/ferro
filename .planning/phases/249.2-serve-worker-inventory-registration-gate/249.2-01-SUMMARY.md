# Phase 249.2 Plan 01: Serve Worker Inventory Registration Gate Summary

One-liner: `has_registered_jobs()` extended to OR-in the `JobRegistrarEntry` compile-time inventory, closing the silent serve-path integration seam for pure-`#[offload]` apps.

## What Was Built

### Task 1 — Fix `has_registered_jobs()` (ferro-queue/src/db.rs)

The predicate at `db.rs:75-78` previously inspected only `JOB_REGISTRARS` (the runtime `Queue::register` Vec). Jobs registered exclusively through `#[offload]`-derived `inventory::submit!` never touched `JOB_REGISTRARS`, so `has_registered_jobs()` returned `false` for a pure-offload app — and the serve boot gate at `framework/src/app.rs:488` (`!no_worker && has_registered_jobs()`) skipped spawning the in-process worker entirely, silently dropping background jobs.

The fix extends the predicate with:

```rust
|| inventory::iter::<JobRegistrarEntry>
    .into_iter()
    .next()
    .is_some()
```

This short-circuits after the first inventory entry and mirrors `registered_queue_names()` (db.rs:92), which already consulted `inventory::iter::<JobRegistrarEntry>`. The docstring was updated to document both the runtime and compile-time paths and to note the consistency with `registered_queue_names()`.

Commits: `87dc2075` (predicate + docstring), `efd350fe` (cargo fmt reformatting of the method chain, no semantic change).

### Task 2 — Regression test binary (ferro-queue/tests/serve_worker_inventory_gate.rs)

A new integration test binary that:

1. Registers `ServeGateInventoryJob` via `inventory::submit!` only — no `Queue::register` call anywhere.
2. Asserts `Queue::has_registered_jobs()` is `true` from inventory alone (Criterion 1).
3. Reproduces the exact serve-gate boolean `!no_worker && has` for both `no_worker` states (Criterion 2/3).

The test uses plain `#[test]` (synchronous) for two reasons: (a) no async runtime is needed for a predicate and boolean check, and (b) this sidesteps the ferro test-suite-collapse false-green trap — a filtered `#[tokio::test]` run can match 0 tests and exit 0; a plain `#[test]` binary cannot be collapsed.

The binary is a standalone file because `inventory::submit!` is per-binary global: once the entry is submitted, `has_registered_jobs()` returns `true` for the entire binary permanently. An empty-inventory assertion (`== false`) cannot coexist in the same binary.

Run result: `test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out`.

Commit: `84109016`.

**Tradeoff noted in plan:** The test asserts the predicate and gate boolean, not a full `WorkerLoop` boot. A full-boot end-to-end test for the `run_worker` path already exists in `offload_round_trip.rs`; this test's regression surface is specifically the serve gate seam, not the dispatch pipeline.

### Task 3 — Read-verification of framework/src/app.rs + pre-commit gate

`framework/src/app.rs` was confirmed unchanged (`git diff --name-only framework/src/app.rs` produced no output throughout). The relevant code was read-verified:

- **app.rs:488** — `if !no_worker && ferro_queue::Queue::has_registered_jobs()` is the sole serve-path spawn gate. Fixing the predicate (Task 1) fixes the serve path without any edit to app.rs.
- **app.rs:488 `!no_worker` term** — when `--no-worker` is passed (`no_worker = true`), the gate short-circuits to `false` regardless of the predicate, so `serve --no-worker` still skips the worker.
- **app.rs:532-535** — `run_worker` calls `run_common_boot(.., /*no_worker=*/ true)` (skipping the serve gate entirely) and computes its queue list from `registered_queue_names()`, not `has_registered_jobs()`. The fix does not affect `run_worker`.

- **Fix:** Added `#[derive(Serialize, Deserialize)]` and `use serde::{Deserialize, Serialize}`. No semantic change — the test never dispatches the job; the derives satisfy the bound.
- **Files modified:** `ferro-queue/tests/serve_worker_inventory_gate.rs`
- **Commit:** `84109016`

**2. [Rule 1 — Clippy] Extracted nonminimal bool into named variable with allow attribute**

- **Files modified:** `ferro-queue/tests/serve_worker_inventory_gate.rs`
- **Commit:** `84109016`
