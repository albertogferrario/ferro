## Summary

Phase 249.2 extends `Queue::has_registered_jobs()` in `ferro-queue/src/db.rs` to
consult the compile-time `JobRegistrarEntry` inventory in addition to the runtime
`JOB_REGISTRARS` Vec, and adds a new inventory-only regression test binary
(`ferro-queue/tests/serve_worker_inventory_gate.rs`) guarding the serve-boot spawn
gate at `framework/src/app.rs:488`.

The change is small, correct, and well-contained. The predicate now matches the
semantics already used by `Queue::registered_queue_names` (db.rs:99) and by
`WorkerLoop::from_registry` (worker.rs:220) — both of which already drain both the
runtime Vec and the inventory. The predicate change closes a real seam: an
`#[offload]`-only app registered jobs solely through the inventory, so the prior
`JOB_REGISTRARS`-only predicate returned `false` and serve spawned no worker.

Verification performed:

- **Predicate correctness.** `!JOB_REGISTRARS.lock().unwrap().is_empty() || inventory::iter::<JobRegistrarEntry>.into_iter().next().is_some()`
  short-circuits correctly on the manual path and reads the inventory only when
  needed. `inventory::iter::<T>` is a zero-sized value implementing `IntoIterator`,
  so `.into_iter().next().is_some()` is the correct presence check and will not
  trip clippy's `-D warnings` gate (no `into_iter_on_ref` or `iter_next_slice`
  applies).
- **Consistency.** The docstring's claim of parity with `registered_queue_names`
  is accurate — both consult `inventory::iter::<JobRegistrarEntry>`.
- **Test correctness.** `ServeGateInventoryJob` derives `Serialize, Deserialize`
  and implements `Job`, satisfying the `J: Job + DeserializeOwned + 'static` bound
  reached through the `register` closure. All symbols the test imports
  (`Error`, `Job`, `JobRegistrarEntry`, `Queue`, `WorkerLoop`) are public exports
  in `ferro-queue/src/lib.rs`; `async-trait`, `serde`, and `inventory` are regular
  dependencies, so the integration test compiles as its own binary.
- **Gate fidelity.** The test reproduces the exact serve-boot expression
  (`!no_worker && has`) and asserts both `no_worker` branches. The
  `framework/src/app.rs:488` reference is current.
- **Global-inventory hazard.** The file header correctly documents that
  `inventory::submit!` is global to the test binary and therefore the file asserts
  only the positive (inventory-present) case; a false/empty-inventory assertion
  cannot hold in the same binary. This is the right call and avoids a flaky test.

No source files were modified during this review.

## Info

### IN-01: Docstring line reference to `app.rs:488` will drift as the file changes

**File:** `ferro-queue/tests/serve_worker_inventory_gate.rs:4,57`
**Issue:** The test doc comments cite the serve gate by absolute line number
(`framework/src/app.rs:488`). The reference is accurate today, but line-number
citations across crates go stale silently on any edit to `app.rs` above that line
and give a future reader a false anchor. This is documentation drift, not a
correctness issue — the test's behavior does not depend on the cited line.
**Fix:** Cite the gate by a stable identifier rather than a line number, e.g.
reference the `spawn_in_process_worker` call site or the `!no_worker && Queue::has_registered_jobs()`
expression in `App`'s serve boot path, dropping the `:488`. Example:
`framework/src/app.rs, serve boot gate: !no_worker && Queue::has_registered_jobs()`.
