## Decisions Made

- **Test-friendly `from_service_def_with_catalog` variant.** Tests that call `Spec::from_service_def` would panic inside `global_catalog()` when the `BadPlugin_117` plugin test runs first in the same process, because `global_catalog()` is a `OnceLock` initialized once and `BadPlugin_117` is registered into the global plugin registry before first access. Instead of forcing a test-specific execution order or sanitizing the global registry, this plan adds a `pub(crate) from_service_def_with_catalog` that accepts an explicit `&Catalog`; the public entry point passes `global_catalog()`, tests pass `Catalog::build_builtins_only()`. This is the same isolation pattern `catalog.rs` itself documents at line 1117 and the same pattern Plan 01 adopted for its drift guards.
- **Form display short-circuit.** `Intent::Collect` with `RenderMode::Display` is rendered by `build_input_spec`, not a separate Form emitter. The reason is `FormProps.action: Action` is required (Pitfall 1); the only well-tested code path that emits a valid placeholder Action is `build_input_spec`. Keeping Collect's Display and Input modes in the same code path ensures they validate identically and that Phase 118+ only has one site to upgrade when real action routing lands.
- **StatCard orphan-metadata policy.** `emit_statcard_root` walks the `slots` list and will invoke `emit_metadata` when the theme asks for it, but StatCard has no child-element slot in `component.rs` — so the resulting `DescriptionList` element is dropped rather than appended to the root's children. The test `template_override` verifies that the root element's `type_name` is `StatCard`; it does NOT assert sibling-element presence. When themes eventually need a sibling-container layout (Grid, Card wrapping StatCard), that is a theme-file change, not a projector change.
- **Clippy `ptr_arg` allow on placeholders.** Two no-op emit functions keep `&mut Vec<..>` parameters for signature parity with the live emitters (so Plan 03 / Phase 118 don't have to flip their signatures back when they gain bodies). `#[allow(clippy::ptr_arg)]` on those two functions is more honest than a cosmetic slice swap that would obscure intent.
- **Placeholder "reserved" functions.** `_plan_02_reserved(&Element)` and `_reserved_props_noop()` silence "unused import" warnings on the Plan-01 helpers (`build_badge_props`, `build_progress_props`, `build_text_props`, `Element`) that this plan doesn't call but Plan 03 will wire in via the field-level slot walk. They compile to nothing and document the hand-off.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] `global_catalog()` OnceLock poisoning panics test runs when `BadPlugin_117` plugin test registers a bad schema first**

- **Found during:** Task 1 verification. The 7 new tests passed when run in isolation (`cargo test -- from_service_def_validates from_service_def_browse_display ...`) but 5 of them panicked with `catalog build failed — see CatalogError for details: BuildFailed("plugin 'BadPlugin_117' returned an invalid JSON Schema")` when the full ferro-json-ui lib suite ran (`cargo test -p ferro-json-ui --features projections --lib`).
- **Root cause:** `global_catalog()` (catalog.rs:950-954) is a `OnceLock` — it builds the catalog on first call using the plugin registry state at that moment. The sibling test `catalog::tests::build_discovers_plugins_and_rejects_invalid_schema` registers a `BadPlugin_117` that returns a malformed JSON Schema; when that test runs before any `Spec::from_service_def` test, the OnceLock initializer panics at `Catalog::build().expect(...)`. This is the same class of pollution Plan 01 worked around in its drift guard tests.
- **Fix:** Extracted a `pub(crate) Spec::from_service_def_with_catalog(..., catalog: &Catalog)` that mirrors the public `Spec::from_service_def` code path one-for-one but validates against an injected catalog instead of `global_catalog()`. The public entry point wraps the helper, calling it with `global_catalog()`. All 7 tests now call the helper with `Catalog::build_builtins_only()`.
- **Files modified:** `ferro-json-ui/src/projection/builder.rs`.
- **Verification:** `cargo test -p ferro-json-ui --features projections --lib` reports 399 passed / 0 failed. Full suite (399 + 11 + 8 + 5) also green. Clippy `--all-targets -D warnings` clean.
- **Committed in:** `28c0e253` (Task 1 — the only commit; the fix was applied before the first successful commit).

**2. [Rule 3 — Blocking] Clippy `ptr_arg` errors on two no-op slot emit placeholders (`&mut Vec<..>` parameters)**

- **Found during:** Task 1 verification, same clippy pass that exposed deviation #1.
- **Root cause:** `emit_actions_placeholder` and `emit_body_placeholder` take `&mut Vec<ElementBuilder>` / `&mut Vec<String>` parameters but never push to them (they are no-op placeholders documenting future wiring points). Clippy's `ptr_arg` lint prefers `&mut [..]` when the body doesn't grow the Vec.
- **Fix:** Applied `#[allow(clippy::ptr_arg)]` to both functions with a comment explaining the intent: signature parity with real emitters is preferable to flipping the signatures back to `&mut Vec<..>` when these placeholders gain bodies in a later phase.
- **Files modified:** `ferro-json-ui/src/projection/builder.rs`.
- **Verification:** Clippy `--all-targets -D warnings` clean at workspace level.
- **Committed in:** `28c0e253` (Task 1).

## Pitfalls Resolved

- **Pitfall 1 — FormProps.action is required.** Resolved: `build_input_spec` always constructs `Action::new(format!("/{}", service.name))` before `serde_json::to_value(FormProps { action, ... })`. The resulting Form passes catalog Stage 2 validation in every one of the 7 tests. Phase 118+ will resolve this placeholder into a real route.
- **Pitfall 3 — Spec nesting depth limit (MAX_NESTING_DEPTH = 3).** Resolved: every root container uses typed Props fields (`DataTable.columns: Vec<Column>`, `KanbanBoard.columns: Vec<KanbanColumnProps>`, `StatCard` no-children) rather than child-element IDs. The only child-of-root wiring is Card's aux elements (DescriptionList, relationship elements, Tabs container), and those are always leaf elements (depth 2). `SpecBuilder::build()`'s `DepthExceeded` check is not triggered in any of the 7 tests.
- **Pitfall 7 — Relationship slot uses `NavigationHint::Tab`, no `Tab` leaf component.** Resolved: `emit_relationships` pre-scans `service.relationships` for `Tab` hints and emits a single `Tabs` element wrapping a `Vec<Tab>` derived from those relationships. Non-Tab relationships still emit one element per `RelationshipDef` using the Plan 01 dispatch.
