### 2. `Spec::from_service_def` (D-08, D-06, D-11)
```rust
impl Spec {
    /// Generate a v2 `Spec` from a `ServiceDef` and its ranked intents.
    ///
    /// Consumes the intent at `ctx.intent_index`, resolves an `IntentSlotTemplate`
    /// (theme override or built-in default), then emits one `Element` per slot
    /// into the flat `Spec.elements` map. `ctx.mode == RenderMode::Input`
    /// collapses the pipeline to a fixed Form layout per D-11.
    ///
    /// Every returned `Spec` has been validated by `global_catalog().validate`.
    /// In `cfg(debug_assertions)` builds, validation failure also panics.
    pub fn from_service_def(
        service: &ServiceDef,
        intents: &[IntentScore],
        ctx: &VisualContext,
    ) -> Result<Spec, ProjectionError> {
        if intents.is_empty() {
            return Err(ProjectionError::EmptyIntents);
        }
        let intent_score = intents.get(ctx.intent_index).ok_or(
            ProjectionError::IntentIndexOutOfBounds {
                requested: ctx.intent_index,
                available: intents.len(),
            },
        )?;

        let spec = if ctx.mode == RenderMode::Input {
            build_input_spec(service)?
        } else {
            let template = ctx
                .templates
                .as_ref()
                .and_then(|t| pick_intent_template(t, &intent_score.intent))
                .cloned()
                .unwrap_or_else(|| default_template(&intent_score.intent));
            build_display_spec(service, &intent_score.intent, &template.display, ctx)?
        };

        match global_catalog().validate(&spec) {
            Ok(()) => Ok(spec),
            Err(errors) => {
                #[cfg(debug_assertions)]
                panic!("Projector emitted invalid spec: {:?}", errors);
                #[allow(unreachable_code)]
                Err(ProjectionError::CatalogValidation(errors))
            }
        }
    }
}
```

### 4. Element construction helpers + `build_input_spec` — Input-mode Form (D-11, Pitfall 1 action placeholder)

**Important implementation note:** `SpecBuilder::element` does not currently expose a way to bulk-set props from a `Value`; the `Element` API is `Element::new(type_name)` + `.prop(key, value)` one-at-a-time. Typed Props structs (`FormProps`, `DataTableProps`, etc.) serialize to a `serde_json::Value::Object`, so we need two small helpers that lift an object into an `Element` by iterating its keys.

Write these helpers once; use them EVERYWHERE in this file in place of any `.set_props` / `.children` shorthand. `Element` does not expose `.set_props` or `.children` methods — do not invent them. The child-append method on `Element` is `.child(id)`; verify the exact name in `spec.rs` before finalizing. If the real name is `.add_child` or `.with_child`, use that instead per-call.

```rust
/// Build an `Element` with the given type_name and all properties from a
/// typed Props-serialized `serde_json::Value` object. Panics if `props` is
/// not an object — the typed Props approach guarantees it always is.
fn element_with_props(type_name: &str, props: serde_json::Value) -> Element {
    let obj = props
        .as_object()
        .expect("typed Props must serialize to a JSON object");
    let mut el = Element::new(type_name);
    for (k, v) in obj {
        el = el.prop(k.clone(), v.clone());
    }
    el
}

/// Build an `Element` with props and a list of child element IDs.
fn element_with_props_and_children(
    type_name: &str,
    props: serde_json::Value,
    children: Vec<String>,
) -> Element {
    let mut el = element_with_props(type_name, props);
    for child in children {
        el = el.child(child);
    }
    el
}
```

Now implement `build_input_spec`. D-11: Input mode collapses every intent to a Form regardless of intent. The Form action defaults to `POST /{service_name}` per Pitfall 1; callers mutate the returned Spec to override. Only writable, non-system fields are emitted as Input children; `lookup_meaning` picks the concrete input component per `FieldMeaning`; `input_props_for` dispatches to the typed Props builder for that component.

```rust
fn build_input_spec(service: &ServiceDef) -> Result<Spec, ProjectionError> {
    let action = Action::new(format!("/{}", service.name));
    // FormProps.action is required (no default). Set method: None to inherit Action's default POST.
    let form_props = serde_json::to_value(FormProps {
        action,
        method: None,
        guard: None,
        max_width: None,
    })
    .expect("FormProps serialization cannot fail");

    let mut children_ids: Vec<String> = Vec::new();
    let mut field_elements: Vec<(String, Element)> = Vec::new();

    for field in service
        .fields
        .iter()
        .filter(|f| f.writable && !is_system_field(&f.meaning))
    {
        let choice = lookup_meaning(&field.meaning);
        let Some(type_name) = choice.input else {
            continue;
        };
        let props = input_props_for(type_name, field);
        let id = format!("field-{}", field.name);
        field_elements.push((id.clone(), element_with_props(type_name, props)));
        children_ids.push(id);
    }

    let root = element_with_props_and_children("Form", form_props, children_ids);

    let mut builder = Spec::builder()
        .title(resolve_title(service))
        .element("root", root);
    for (id, el) in field_elements {
        builder = builder.element(id, el);
    }
    builder.build().map_err(ProjectionError::SpecBuild)
}

fn input_props_for(type_name: &str, field: &FieldDef) -> serde_json::Value {
    match type_name {
        "Input" => build_input_props(field),
        "Select" => build_select_props(field),
        "Switch" => build_switch_props(field),
        _ => build_input_props(field),
    }
}
```

### 5. `build_display_spec` — slot orchestration (D-05, D-10)

Dispatch on `template.layout` (outer container) and walk `template.slots`. Each slot name routes to an emit helper. The outer container determines how `fields` is rendered:
- `DataTable` → `fields` slot is a `Vec<Column>` inside `DataTableProps.columns`, not child elements
- `Card` → `fields` slot emits a `DescriptionList` child element holding `Vec<DescriptionItem>`
- `Form` → `fields` slot emits child Input elements (reuses `build_input_spec` logic conceptually)
- `KanbanBoard` → `body` slot is synthesized from `service.intent_hints` state machine (or a placeholder single column if none)
- `StatCard` → `stats` slot fills `label`/`value`; `metadata` slot may add a DescriptionList child

```rust
fn build_display_spec(
    service: &ServiceDef,
    intent: &Intent,
    template: &IntentSlotTemplate,
    _ctx: &VisualContext,
) -> Result<Spec, ProjectionError> {
    let layout = template
        .layout
        .as_deref()
        .unwrap_or("Card"); // sensible fallback if a theme omits layout

    // Collect auxiliary child elements emitted by slots (e.g., DescriptionList for fields in Card).
    let mut aux_elements: Vec<(String, Element)> = Vec::new();
    let mut root_children: Vec<String> = Vec::new();

    // Build root props per layout component. Each branch consumes whichever slots apply.
    let root = match layout {
        "DataTable" => emit_datatable_root(service),
        "Card" => emit_card_root(service, &template.slots, &mut aux_elements, &mut root_children),
        "Form" => {
            // Display-mode Form (Collect intent). Treat like Input pipeline but with display-friendly children.
            return build_input_spec(service);
        }
        "KanbanBoard" => emit_kanban_root(service),
        "StatCard" => emit_statcard_root(service),
        other => {
            return Err(ProjectionError::UnknownComponent {
                type_name: other.to_string(),
            });
        }
    };

    // `intent` currently only informs layout selection via the template passed in;
    // we keep the parameter to document the dispatch path for future per-intent tweaks.
    let _ = intent;

    let mut builder = Spec::builder()
        .title(resolve_title(service))
        .element("root", root);
    for (id, el) in aux_elements {
        builder = builder.element(id, el);
    }
    builder.build().map_err(ProjectionError::SpecBuild)
}
```

fn emit_card_root(
    service: &ServiceDef,
    slots: &[String],
    aux: &mut Vec<(String, Element)>,
    children_out: &mut Vec<String>,
) -> Element {
    let title = resolve_title(service);

    // Slot walk — emit child elements for each configured slot.
    for slot in slots {
        match slot.as_str() {
            "title" => { /* already captured on Card title */ }
            "fields" => {
                let items: Vec<DescriptionItem> = service
                    .fields
                    .iter()
                    .filter(|f| f.readable && !is_system_field(&f.meaning))
                    .map(build_description_item)
                    .collect();
                let props = serde_json::to_value(DescriptionListProps { items })
                    .expect("DescriptionListProps serialization cannot fail");
                let id = "fields-list".to_string();
                aux.push((id.clone(), element_with_props("DescriptionList", props)));
                children_out.push(id);
            }
            "relationships" => emit_relationships(service, aux, children_out),
            "actions" => emit_actions_placeholder(service, aux, children_out),
            "metadata" => emit_metadata(service, aux, children_out),
            "body" | "stats" | "pagination" => {
                // Non-applicable to Card layout; skip silently. The intent_layout
                // defaults align slots to layouts, so mismatches only happen with
                // theme-override templates — a warning-free skip is correct.
            }
            _ => {}
        }
    }

    let props = serde_json::to_value(crate::component::CardProps {
        title,
        // If CardProps has more required fields, initialize them here; otherwise
        // all remaining fields are Option<T> set to None through explicit literal.
        // Read the actual struct in component.rs before finalizing the literal.
        ..CardProps::default_literal() // placeholder — see note below

    .expect("CardProps serialization cannot fail");
    let mut el = element_with_props("Card", props);
    for id in children_out.iter() {
        el = el.child(id.clone());
    }
    el
}

            .expect("TabsProps serialization cannot fail");

        children_out.push(id);

    for rel in service.relationships.iter() {
        let Some(component) = lookup_relationship(rel.navigation) else {
            continue; // Hidden → skip
        };
        if matches!(rel.navigation, NavigationHint::Tab) {
            continue; // already grouped above
        }
        let props = match rel.navigation {
            NavigationHint::Inline => build_relationship_text_props(rel),
            NavigationHint::Link => build_relationship_button_props(rel),
            NavigationHint::Nested => {
                // Nested → Table with a single "name" column, data_path = /data/{rel.name}
                let col = Column {
                    key: "name".to_string(),
                    label: "Name".to_string(),
                    format: None,
                };
                serde_json::to_value(crate::component::TableProps {
                    columns: vec![col],
                    data_path: Some(format!("/data/{}", rel.name)),
                    ..TableProps::default_literal()
                })
                .expect("TableProps serialization cannot fail")
            }
            _ => continue,
        };
        let id = format!("rel-{}", rel.name);
        aux.push((id.clone(), element_with_props(component, props)));
        children_out.push(id);
    }
}
