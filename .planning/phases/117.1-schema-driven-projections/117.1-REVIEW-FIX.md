## Fixed Issues

### WR-01: `choice.display` and `choice.column` are never consulted — Sensitive fields can leak

**Files modified:** `ferro-json-ui/src/projection/builder.rs`
**Commit:** c0ecf2c1
**Applied fix:** Gated `emit_datatable_root` on `lookup_meaning(&f.meaning).column.is_some()` and `emit_fields_as_description_list` on `lookup_meaning(&f.meaning).display.is_some()`. Meanings with opt-out (Sensitive/ForeignKey for display; Identifier/ForeignKey/ImageUrl/Sensitive for column) are now excluded even when the underlying `FieldDef` is `readable = true`. Added regression test `sensitive_field_never_appears_in_display_or_column` which constructs a `User` service with a readable `password_hash` field and asserts the Sensitive field is absent from both the Browse DataTable columns and the Focus DescriptionList items.

### WR-02: `root_children` allocated in `build_display_spec` but never wired into the Spec

**Files modified:** `ferro-json-ui/src/projection/builder.rs`
**Commit:** 21652b21
**Applied fix:** Removed the `root_children: Vec<String>` allocation from `build_display_spec` and the `&mut root_children` parameter from `emit_card_root`'s signature. Card children are now tracked in a local `children` vec inside `emit_card_root`, which attaches them to the returned `ElementBuilder` via `el.child(..)` before returning. The outer function owns only `aux_elements`. Applied option 1 from the review (minimal fix matching actual dataflow).

### WR-03: `emit_statcard_root` drops metadata into `aux` orphans

**Files modified:** `ferro-json-ui/src/projection/builder.rs`
**Commit:** 9e771d7b
**Applied fix:** Applied option 3 from the review (pin the contract with a test). Sharpened the doc comment on `emit_statcard_root` to state the orphan contract explicitly: StatCard's catalog shape forbids children, so the `metadata` slot emits a DescriptionList as a sibling in `spec.elements` that is intentionally not reachable from the root. Added `statcard_metadata_is_orphan_element` regression test which asserts both (a) `metadata_list` is present in `spec.elements` and (b) it is absent from `root.children`. Any future change (stop emitting, or wire into a wrapper) will fail the test and force an explicit decision.

### WR-04: `input_props_for` silently masks schema drift on unknown type names

**Files modified:** `ferro-json-ui/src/projection/builder.rs`
**Commit:** ffa37b08
**Applied fix:** Changed `input_props_for` to return `Result<serde_json::Value, ProjectionError>` instead of silently coercing unknown type names to `InputProps`. Unrecognized names now surface as `ProjectionError::UnknownComponent { type_name }`. Propagated the `Result` through `build_input_spec` via `?`. Added regression test `input_props_for_unknown_type_returns_unknown_component_error` that passes `"DatePicker"` and asserts the `UnknownComponent` variant.
