**Rejected:** Shape A — insert a new Wave 2.5 block between Wave 2 and Wave 3. Rejected because (a) larger diff, (b) overloads the wave numbering, (c) `ferro-cli` and `ferro-bundle` share the same dep relationship to ferro-rs and belong in the same wave.

**Correction from CONTEXT.md D-09/D-11:** CONTEXT.md assigned ferro-bundle to Wave 1B; RESEARCH §critical finding identified that ferro-rs itself publishes in Wave 2 (line 274), so any ferro-rs consumer must publish AFTER Wave 2. The plan honored RESEARCH's correction over CONTEXT.md.

## Decisions Made

1. **Wave 3 = framework-consumers (not Wave 1B).** RESEARCH's critical finding overrode CONTEXT.md D-09/D-11. ferro-rs publishes in Wave 2; consumers must follow.
2. **For-loop Wave 3 (Shape B).** Smaller diff than Wave 2.5 insertion; matches Wave 2's structure verbatim for consistency.
3. **`ferro-rs = { path = "../framework", version = "0.2" }` (not version-omitted).** This is a non-dev dep; crates.io publish-time resolution requires `version`. ferro-macros omits version only because its `ferro-rs` dep is a dev-dep — different rule.
4. **No `pub` items yet.** lib.rs is `//!`-docs-only at scaffold stage; Plan 02 lands the `Bundle` type, registries, `Error` enum, and tests.
5. **README explicitly states "do not fold these"** twice (capitalized in headline, lowercase in tail clause). Load-bearing per D-10 — protects the architectural split from future tidying instincts.
