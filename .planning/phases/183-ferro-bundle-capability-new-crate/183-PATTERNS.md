**HTTP response shaping pattern** (RESEARCH.md §Framework HTTP Types Reference — verified against `framework/src/http/response.rs` lines 18-24, 48-54, 117-136):
```rust
// 200 with bytes + cache headers + ETag (Bundle::serve cold path)
use ferro_rs::HttpResponse;
use bytes::Bytes;

let resp = HttpResponse::bytes(Bytes::from_static(entry.bytes))
    .header("Content-Type", &entry.content_type)
    .header("Cache-Control", "public, max-age=31536000, immutable")
    .header("ETag", format!("\"{}\"", entry.sha256_full_hex));

// 304 Not Modified (Bundle::serve If-None-Match match)
let resp = HttpResponse::new()
    .status(304)
    .header("ETag", format!("\"{}\"", entry.sha256_full_hex))
    .header("Cache-Control", "public, max-age=31536000, immutable");

// 301 Moved Permanently (Bundle::serve alias path)
let resp = HttpResponse::new()
    .status(301)
    .header("Location", target.value().clone());
```

**Notes for the planner:**
- `HttpResponse::bytes` (response.rs lines 48-54) sets NO default headers — caller MUST add Content-Type explicitly.
- `.header()` uses case-insensitive **replace** semantics. Use `.append_header()` only for multi-value headers like `Set-Cookie`; ferro-bundle uses `.header()` exclusively.
- ETag MUST be quoted per RFC 7232 §2.3 (Pitfall 3 in RESEARCH.md). `format!("\"{}\"", hex)` not `.header("ETag", hex)`.
- 304 MUST include `Cache-Control` (RFC 7232 §4.1; Pitfall 4 in RESEARCH.md) — without it, browsers re-revalidate immediately.
- `Bytes::from_static(&'static [u8])` is zero-copy (Pitfall 7). Do NOT use `Bytes::from(vec.clone())`.

```yaml
                echo "Failed to publish $crate"
                echo "$OUTPUT"
                exit 1

            sleep 5
```

## Shared Patterns

### Workspace inheritance (`version.workspace = true`)

**Source:** every `ferro-*/Cargo.toml` (e.g., `ferro-storage/Cargo.toml` lines 3-5, `ferro-ai/Cargo.toml` lines 3-5, `ferro-wallet/Cargo.toml` lines 3-5).

**Apply to:** `ferro-bundle/Cargo.toml`

```toml
[package]
name = "ferro-bundle"
version.workspace = true
edition.workspace = true
license.workspace = true
description = "..."
repository = "https://github.com/albertogferrario/ferro"

categories = ["web-programming"]
readme = "README.md"
```

The only workspace fields a crate manifest CANNOT inherit (they have no workspace defaults in `Cargo.toml`): `description`, `repository`, `keywords`, `categories`, `readme`. These are crate-specific. Every other `[package]` field uses `.workspace = true`.

### `thiserror` error pattern (one Error enum per crate)

**Source:** `ferro-wallet/src/error.rs` (canonical), also used by every `ferro-*` crate.

**Apply to:** `ferro-bundle/src/lib.rs` (or `ferro-bundle/src/error.rs` if planner splits).

```rust
#[derive(Debug, thiserror::Error)]
pub enum Error {
    #[error("bundle not found at path: {0}")]
    NotFound(String),
    #[error("duplicate bundle name: {0} already registered")]
    DuplicateName(String),
}

pub type Result<T> = std::result::Result<T, Error>;
```

**Convention notes:**
- `Display` strings prefix the variant role (`"bundle not found:"`, `"duplicate bundle name:"`) so production log greps stay surgical.
- Tests live in `#[cfg(test)] mod tests` colocated with the enum, one test per variant verifying `to_string()`.
- Newer crates use `thiserror = "2"` (ferro-ai, ferro-wallet); older crates still on `"1.0"` (ferro-storage, ferro-cache). ferro-bundle uses `"2"`.

### `OnceLock`-based global registry

**Source:** `ferro-json-ui/src/plugin.rs` lines 14, 145-159 (only existing in-repo example of an `OnceLock<…>`-backed process-global registry).

**Apply to:** ferro-bundle's `BUNDLE_REGISTRY` and `ALIAS_REGISTRY`.

```rust
use std::sync::OnceLock;
use dashmap::DashMap;

static BUNDLE_REGISTRY: OnceLock<DashMap<String, BundleEntry>> = OnceLock::new();

fn bundle_registry() -> &'static DashMap<String, BundleEntry> {
    BUNDLE_REGISTRY.get_or_init(DashMap::new)
}
```

**Key swap from ferro-json-ui:** RwLock → DashMap. ferro-json-ui uses `RwLock<PluginRegistry>` because the registry stores boxed trait objects with built-in registrations at init time. ferro-bundle's hot path is `Bundle::serve` reading per-request; DashMap's bucket-level locking gives finer concurrency for read-mostly workloads.

### `framework::HttpResponse` builder

**Source:** `framework/src/http/response.rs` lines 48-54 (`bytes`), 18-24 (`new`), 87-97 (`status`), 117-136 (`header`).

**Apply to:** every response constructed in `Bundle::serve`.

```rust
use ferro_rs::HttpResponse;

// 200 with bytes
HttpResponse::bytes(Bytes::from_static(static_bytes))
    .header("Content-Type", "application/javascript")
    .header("Cache-Control", "public, max-age=31536000, immutable")
    .header("ETag", format!("\"{}\"", full_sha256_hex));

// 304
HttpResponse::new()
    .status(304)
    .header("ETag", format!("\"{}\"", full_sha256_hex))
    .header("Cache-Control", "public, max-age=31536000, immutable");

// 301
HttpResponse::new()
    .status(301)
    .header("Location", target_url);
```

**Notes:**
- `HttpResponse::bytes` sets NO default headers. Caller MUST add Content-Type.
- `.header()` uses case-insensitive **replace** semantics (not append). Setting `Content-Type` twice yields one header.
- ETag MUST be quoted: `format!("\"{}\"", hash)`.
- 304 MUST include `Cache-Control` (RFC 7232 §4.1).

### `framework::Request` accessors

**Source:** `framework/src/http/request.rs` lines 121-123 (`path`), 309-311 (`header`).

**Apply to:** `Bundle::serve(req)` for path-dispatch and `If-None-Match` lookup.

```rust
use ferro_rs::Request;

let path = req.path();                          // -> &str (no query, no fragment)
let if_none_match = req.header("if-none-match"); // Option<&str>, case-insensitive lookup
```

**Notes:**
- `req.path()` returns only the path component. Matches the registry key shape (e.g., `/bundles/embed-v1.a4b8c2d1.js`).
- Header name lookup is case-insensitive via `HeaderMap` semantics; lowercased is conventional in ferro code.

### `extern crate ferro_rs as ferro` in integration tests

**Source:** `framework/tests/routing_group_trailing_slash.rs` line 15 — only existing in-repo example of an integration test that imports from `ferro-rs`.

**Apply to:** every `ferro-bundle/tests/*.rs` integration test.


Or, since ferro-bundle is a separate crate from framework (unlike the framework's own tests), the simpler import without `extern crate` works:
```rust

```

The planner verifies which form is needed during the implement phase (depends on `framework::testing` visibility — RESEARCH.md Open Question §3).
