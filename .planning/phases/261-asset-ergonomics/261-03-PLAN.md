2. Name validation (SECURITY — SSRF + path traversal, T-261-05/06). A single guard applied to every set/family/icon segment BEFORE it is interpolated into a URL or a filesystem path:
```rust
/// Reject any name segment that could escape the fixed API host or the output
/// directory. Allowed: ASCII lowercase alphanumerics and `-` (matches Iconify
/// prefixes and Fontsource family ids). One `/` separator is allowed ONLY for
/// the `prefix/icon` Iconify form and is validated per-segment.
fn validate_segment(seg: &str) -> anyhow::Result<()> {
    if seg.is_empty() {
        anyhow::bail!("empty name segment");
    }
    if !seg.chars().all(|c| c.is_ascii_lowercase() || c.is_ascii_digit() || c == '-') {
        anyhow::bail!(
            "invalid name segment {seg:?}: only lowercase ascii letters, digits, and '-' are allowed"
        );
    }
    Ok(())
}
```
For Iconify `set` that may contain one `/`: `split('/')`, require 1 or 2 parts, `validate_segment` each part, reject any additional `/` (3+ parts) or leading/trailing `/`. This makes `../`, absolute paths, `%2e`, and alternate-host injection (`evil.com/x`) structurally impossible because `.`, `:`, `%`, and extra `/` are all rejected.

3. `fetch_iconify(client, set, out_dir)`:
   - Validate `set` per rule 2.
   - If `set` contains a `/` (`prefix/icon`): GET `https://api.iconify.design/{prefix}/{icon}.svg`, `.error_for_status()?`, write the returned SVG text to `{out_dir}/{prefix}/{icon}.svg` (create parent dir).
   - Else (bare `prefix`): GET `https://api.iconify.design/{prefix}.json`, parse `icons` object; for each `(name, def)` wrap the body: `format!("<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 {w} {h}\">{body}</svg>")` where `w`/`h` fall back to the top-level `width`/`height` (default 24). Write each to `{out_dir}/{prefix}/{name}.svg`.
   - Icon names from the JSON keys must ALSO pass `validate_segment` before being used in a path (defense-in-depth — a malicious API response cannot write outside the dir).
   - Print a one-line summary (`wrote N icons to {out_dir}/{prefix}/`).

4. `fetch_fontsource(client, family, weights, subsets, out_dir)`:
   - Validate `family` per `validate_segment`.
   - GET `https://api.fontsource.org/v1/fonts/{family}`, `.error_for_status()?.json::<Value>()?`.
   - Read `variants[weight][style="normal"][subset].url.woff2` for each requested weight×subset (RESEARCH Pattern 6 code example). Download each woff2 (`.bytes()?`), write to `{out_dir}/{family}/{subset}-{weight}-normal.woff2` (create parent dir). Validate each `subset` string with `validate_segment` before path use.
   - Skip (with a warning, do not error) weight/subset combinations absent from the API response.
   - Print a summary of files written.

5. `run` / `run_inner` (matches the json_ui_migrate_v1 error-wrapper pattern):
```rust
pub fn run(subcommand: AssetsCommand) {
    if let Err(e) = run_inner(subcommand) {
        eprintln!("error: {e}");
        std::process::exit(1);
    }
}

fn run_inner(subcommand: AssetsCommand) -> anyhow::Result<()> {
    let client = Client::new();
    match subcommand {
        AssetsCommand::Fetch { source } => match source {
            FetchSource::Iconify { set, out } => fetch_iconify(&client, &set, Path::new(&out)),
            FetchSource::Fontsource { family, weights, subsets, out } => {
                let subset_refs: Vec<&str> = subsets.iter().map(|s| s.as_str()).collect();
                fetch_fontsource(&client, &family, &weights, &subset_refs, Path::new(&out))
            }
        },
    }
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arg (set/family/icon name) → outbound URL | The user-supplied name becomes part of an Iconify/Fontsource URL. |
| CLI arg / API response → filesystem path | The name and (for sets) the API-returned icon keys become path components under the output dir. |
| Network → local filesystem | Downloaded bytes are written to disk under `--out`/`assets/`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-261-05 | Spoofing / SSRF | `fetch_iconify` / `fetch_fontsource` URL construction | mitigate | `validate_segment` rejects `.`, `:`, `%`, and extra `/`, so a name can never inject an alternate host, port, credentials, or path outside the fixed `https://api.iconify.design` / `https://api.fontsource.org` prefixes. URLs are built by interpolating validated segments into hardcoded HTTPS host literals — the host is never user-controlled. TLS is rustls (no cert-validation bypass). |
| T-261-06 | Tampering (path traversal) | `write_icon` / woff2 write path | mitigate | Every path segment (prefix, family, icon name from API response, subset) passes `validate_segment` (lowercase-alnum + `-` only) before being joined onto the output dir, so `..`, absolute paths, and separators cannot escape `--out`. Parent dirs are created with `create_dir_all` under the validated join only. |
| T-261-07 | Elevation / Injection (build-time) | opt-in fetch | accept | The fetch is only reachable through the author-run `ferro assets fetch` binary; it is not a library API and is absent from any `cargo build` of a consumer app (SC-3). No default feature pulls a network call into a build. |
| T-261-08 | Information Disclosure | outbound HTTPS only | accept | Requests go only to the two fixed public asset APIs over HTTPS/rustls; no credentials, cookies, or local files are transmitted. |
</threat_model>
