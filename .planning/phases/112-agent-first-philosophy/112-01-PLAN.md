**Create docs/src/getting-started/working-with-agents.md** with the following structure:

1. **Opening (1-2 sentences):** Why Ferro is agent-first — agents get the same structural understanding of your application that developers do, via MCP.

2. **## Setting Up ferro-mcp:** Brief explanation that Ferro's CLI binary doubles as an MCP server.

3. **### MCP Configuration** with three subsections:
   - **#### Claude Desktop** — copy-paste JSON config. File location: `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS). Command: path to ferro binary, args: `["mcp"]`, type: `"stdio"`.
   - **#### Claude Code (.claude.json)** — copy-paste JSON config. Place at project root (project-scope) or `~/.claude.json` (user-scope). Same command/args pattern.
   - **#### Generic stdio** — minimal JSON config for any MCP-compatible host (Cursor, Windsurf, etc.).

   Use the exact config snippets from the research (112-RESEARCH.md Code Examples section). The command path should use a placeholder like `/path/to/your/app/target/debug/ferro` for development and note that `target/release/ferro` works for production builds.

4. **## The Discovery Loop:** Document the core agent workflow: `application_info` (understand the project) -> feature-specific tools (explore routes, models, etc.) -> `code_templates` / `generation_context` (generate code). This is the fundamental loop agents use.

5. **## Common Workflows:** Document 3-4 concrete workflows. Choose from these (at discretion, but aim for the ones that best demonstrate agent-first value):
   - Discovery loop: agent calls `application_info` to understand the project, then drills into specific areas
   - Error diagnosis: agent encounters build error, calls `last_error` or `diagnose_error`
   - Model exploration: agent calls `list_models` -> `explain_model` -> `model_usages` to understand data layer
   - Code generation: agent reads `code_templates` hints, selects appropriate CLI command, scaffolds code

   Format at discretion — prose narrative, step-by-step lists, or pseudo-conversation are all acceptable. No visual diagrams.

6. **## Agent-to-CLI Workflow (PHIL-04):** Document the specific pipeline: Agent calls MCP tool (e.g., `code_templates`) -> reads `generation_hints` in the response -> identifies the right CLI command (e.g., `ferro make:model`) -> executes CLI command to scaffold code. This is the bridge between introspection and action. Show at least one concrete end-to-end example.

7. **## Troubleshooting:** Common setup issues:
   - "command not found" — binary path wrong; must point to `ferro` binary, not `ferro-mcp`
   - "No tools available" — MCP host not configured correctly; check JSON syntax
   - Tool returns stale data — rebuild the project (`cargo build`) so ferro reads current source

8. **## See Also:** Link to [MCP Bridge](../features/api-mcp.md) for ferro-api-mcp (the consumer-facing API MCP server, separate from the framework introspection covered here).
