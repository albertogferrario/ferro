///

/// ```

macro_rules! error_response {
    ($status:expr, $msg:expr) => {

    };
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scaffold template string → generated user project source | The CLI emits Rust source from format strings; the generated source is compiled and run by the developer |
| error_response! macro expansion → HTTP response body | A status code + message string the developer passes becomes an HTTP JSON response body |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-214-01 | Information disclosure | `error_response!` macro — `$msg` often carries `e.to_string()` (a DB/driver error) into the JSON `message` field | accept | The macro is a developer-facing ergonomic for handler error arms; the developer chooses what to pass. The generated templates pass static strings ("Not found", "Failed to fetch X"), not raw error internals, in the public-facing arms. Leaking internal errors is the developer's choice at hand-written call sites — out of scope for a scaffold-parity fix. Documented in the macro doc-comment example (uses both a static string and `e.to_string()`). |
| T-214-02 | Tampering / Injection | Template format strings emitting Rust source (`{name}`, `{form_fields}`) | accept | Inputs are model/field names from the developer's own `make:scaffold` invocation, not untrusted network input; the CLI runs locally under the developer's own privileges. Field-name validation already exists in `make_scaffold.rs` ("Invalid field name"). No new injection surface is introduced — this plan only changes which already-trusted symbols are emitted. |
| T-214-03 | Elevation of privilege | `#[macro_export] error_response!` added to the framework crate root | mitigate | The macro expands only to a public `HttpResponse` builder chain already reachable by any consumer; it grants no new capability. Scoped to two expression positions (`$status`, `$msg`). No `unsafe`, no environment/filesystem access in expansion. |

All threats are low severity (local CLI surface, developer-controlled inputs). No high-severity
threat blocks this plan.
</threat_model>
