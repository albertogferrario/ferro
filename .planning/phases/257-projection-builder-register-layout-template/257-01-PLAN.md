<objective>
Add the two builder setters (`ElementBuilder.each`, `SpecBuilder.fill_viewport`)
and fix the pre-existing `Catalog::validate` limitation that rejects `$each`
template elements whose data-bound props are non-String (e.g. `TileProps.price_cents:
Option<u64>`). These are the self-contained ferro-json-ui primitives that Plan 02's
`emit_register_root` depends on.

Purpose: Without `ElementBuilder.each` the projector cannot attach the Tile `$each`
directive from Rust (D-12). Without `SpecBuilder.fill_viewport` the Register arm
cannot emit `fill_viewport: true` (D-13). Without the catalog `$each` guard, a Tile
template with a `$data`-bound `price_cents` fails catalog validation because
`strip_expr_objects` turns `{"$data":..}` into `""` which fails the `anyOf[integer,null]`
schema (the RESEARCH "Critical Finding"). All three are prerequisites for SC-1/SC-4.

Output: two public consuming setters on the spec builders + a targeted catalog
validation fix, each with tests.
</objective>

///

}

The fix is two localized guards so that `$each` template elements (whose props are
data-bound and cannot be type-checked before expansion) are not schema-validated by
`Catalog::validate`. Root cause: `strip_expr_objects` replaces `{"$data":..}` with `""`,
which passes String schemas but fails `anyOf[integer,null]` for `TileProps.price_cents`.

1. **Stage 2** — in the `for (id, el) in &spec.elements` loop, immediately AFTER the
   existing `if el.props.is_null() { continue; }` guard (catalog.rs :750-752), add:
```rust
                // Template elements ($each) carry data-bound props of arbitrary
                // type; the concrete type is only known after $each expansion at
                // render time. strip_expr_objects turns `{"$data":..}` into `""`,
                // which fails non-String schemas (e.g. TileProps.price_cents:
                // Option<u64>). Skip per-element Props validation for template
                // elements — validate_directives (spec.rs) enforces the $each
                // structural rules, and resolve_expressions enforces types at
                // render time against real row data.
                if el.each.is_some() {
                    continue;
                }
```

2. **Stage 3** — the envelope validator (catalog.rs :816-834) validates the whole
   serialized spec, so a per-element `continue` is not available. Instead null-out the
   props of template elements in the envelope-validation copy (props is optional in the
   envelope schema). Change `let spec_value = match serde_json::to_value(spec) { .. }`
   to `let mut spec_value = ...` and, immediately BEFORE the `strip_expr_objects(&spec_value)`
   call, insert:
```rust
        // Template elements ($each) carry data-bound props that cannot be schema
        // -validated before expansion. Null their props in the envelope copy so
        // the whole-spec validator does not reject them (see Stage 2 rationale).
        if let Some(elements) = spec_value.get_mut("elements").and_then(|e| e.as_object_mut()) {
            for (id, el_val) in elements.iter_mut() {
                let is_template = spec
                    .elements
                    .get(id)
                    .map(|e| e.each.is_some())
                    .unwrap_or(false);
                if is_template {
                    if let Some(obj) = el_val.as_object_mut() {
                        obj.insert("props".to_string(), serde_json::Value::Null);
                    }
                }
            }
        }
```
   (Add `use serde_json::Value;` if not already imported, or fully-qualify as shown.)

Do NOT alter `strip_expr_objects` itself, and do NOT weaken validation for
non-template (`each.is_none()`) elements — the guards are strictly scoped to
`each.is_some()`.
