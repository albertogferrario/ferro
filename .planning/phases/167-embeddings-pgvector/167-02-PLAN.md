```rust
pub struct Neighbor { pub id: i64, pub score: f32 }   // score = 1 - cosine_distance, in [-1,1]
pub struct PgVectorStore { table: String, column: String }
impl PgVectorStore {
    pub fn new(table: &str, column: &str) -> Self;
    pub async fn store(&self, pool: &sqlx::PgPool, id: i64, embedding: &[f32]) -> Result<(), Error>;

```

is an UPSERT via `ON CONFLICT (id) DO UPDATE` (locked, OQ-3).

- `store(&self, pool: &PgPool, id: i64, embedding: &[f32]) -> Result<(), Error>`:
  ```rust
  let vec = Vector::from(embedding.to_vec());
  let sql = format!(
      "INSERT INTO {} (id, {}) VALUES ($1, $2) ON CONFLICT (id) DO UPDATE SET {} = $2",
      self.table, self.column, self.column
  );
  sqlx::query(&sql).bind(id).bind(vec).execute(pool).await
      .map_err(|e| Error::Sqlx(e.to_string()))?;
  Ok(())
  ```
- `nearest(&self, pool: &PgPool, query: &[f32], k: i64) -> Result<Vec<Neighbor>, Error>`:
  ```rust
  let vec = Vector::from(query.to_vec());
  let sql = format!(
      "SELECT id, (1.0 - ({} <=> $1))::float4 AS score FROM {} ORDER BY {} <=> $1 LIMIT $2",
      self.column, self.table, self.column
  );
  sqlx::query_as::<_, Neighbor>(&sql).bind(vec).bind(k).fetch_all(pool).await
      .map_err(|e| Error::Sqlx(e.to_string()))
  ```
**Security (T-167-04):** the `<=>` value (id, embedding, k) is bound via `$1`/`$2` parameters —
never string-interpolated. `table`/`column` come ONLY from the `new()` constructor (trusted app
code), never from request input; document this constraint in the `PgVectorStore` rustdoc. Use
`sqlx::query`/`query_as` (runtime) — NOT the `query_as!` macro (it needs a compile-time DB).

Do NOT add `error.rs` edits (Plan 01 added `Error::Sqlx`). Do NOT add DDL helpers (D-09).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ferro-ai → Postgres (sqlx) | `PgVectorStore` issues SQL against the caller's Postgres. Embedding values (`Vec<f32>`), `id`, and `k` cross this boundary as parameters. |
| caller(app code) → PgVectorStore::new | `table` and `column` names are configuration supplied by trusted application code at construction — they are NOT request/user input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-167-04 | Tampering (SQL injection) | PgVectorStore::store / nearest | mitigate | All dynamic values (id, embedding, k) bound via `$1`/`$2` parameterized `sqlx::query`/`query_as` — never string-interpolated. `table`/`column` are interpolated but sourced only from the trusted `new()` constructor; documented as not-attacker-controlled in the struct rustdoc. |
| T-167-05 | Information Disclosure | Error::Sqlx(e.to_string()) message | accept | sqlx error string does not include bound parameters (embedding f32 arrays); table/column names are low-risk. Mirrors the existing `Error::Provider { message }` convention. |
| T-167-06 | Denial of Service | Unbounded `k` or very large embedding vector | accept | Leaf-crate primitive; `k` is `i64` bound into `LIMIT $2` (server enforces). ASVS L1 does not require a hard cap; caller controls inputs. Noted, not enforced. |
</threat_model>
