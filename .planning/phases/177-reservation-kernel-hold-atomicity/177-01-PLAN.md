<objective>
Land the kernel atomicity fix and add the load-bearing SQLite concurrency tests.

Purpose: `ReservationKernel::hold` performs check-then-act (capacity SELECT + held SELECT + INSERT) with no transaction. Two concurrent `tokio::spawn` tasks racing identical `(key, window)` both pass the capacity check and both INSERT — violating `held ≤ capacity`. This plan wraps the entire `hold` body in a `SERIALIZABLE` transaction (D-06) so the database serializes the conflict, translates Postgres SQLSTATE `40001` to `ReservationError::Insufficient` (D-07), and replaces the existing `tokio::Mutex` workaround test with bare `tokio::spawn` tests that prove the kernel is intrinsically race-free.

Output:
- `ferro-reservation/src/kernel.rs` — `hold` body wrapped in `begin_with_config(Some(IsolationLevel::Serializable), Some(AccessMode::ReadWrite))`; private `is_serialization_failure` helper (cfg-gated dual stub).
- `ferro-reservation/tests/concurrent_hold.rs` — rewritten to remove `tokio::Mutex`; adds SC-1 (capacity=1, ≥50 iters), SC-1 extended (capacity=N), SC-2 (non-overlapping keys), SC-5 (audit-row count after race).
</objective>
