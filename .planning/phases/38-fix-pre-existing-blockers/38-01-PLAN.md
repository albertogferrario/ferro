<task type="auto">
  <name>Task 2: Fix queue tests env var safety</name>
  <files>ferro-queue/src/dispatcher.rs, ferro-queue/src/config.rs</files>
  <action>
The queue tests in `dispatcher.rs` (4 tests) and `config.rs` (4 tests) use `env::set_var()` and `env::remove_var()` which are unsafe in multi-threaded contexts (deprecated as unsafe in Rust 2024). They already use `#[serial]` which mitigates race conditions, but if a test panics before cleanup, env vars leak.

Fix approach for both files: Wrap each test's env var manipulation in a guard pattern that cleans up on drop. Create a simple helper struct within the test module:

```rust
struct EnvGuard {
    vars: Vec<String>,
}

impl EnvGuard {
    fn set(key: &str, value: &str) -> Self {
        unsafe { env::set_var(key, value); }
        Self { vars: vec![key.to_string()] }
    }

    fn also_set(&mut self, key: &str, value: &str) {
        unsafe { env::set_var(key, value); }
        self.vars.push(key.to_string());
    }
}

impl Drop for EnvGuard {
    fn drop(&mut self) {
        for var in &self.vars {
            unsafe { env::remove_var(var); }
        }
    }
}
```

Note: In Rust 2021 edition (which this project uses), `env::set_var` and `env::remove_var` are safe. No `unsafe` blocks needed. Only in 2024 edition do they become unsafe. So just implement the guard pattern without `unsafe` wrappers — the safety improvement is the automatic cleanup on panic.

Replace manual `env::set_var`/`env::remove_var` calls in all 8 tests with the EnvGuard pattern. Remove manual cleanup lines at end of tests.

In `dispatcher.rs`, the timing assertion in `test_sync_mode_ignores_delay` (line 254) uses `Duration::from_secs(1)` which may be tight on slow CI. Increase to `Duration::from_secs(5)` for reliability.
