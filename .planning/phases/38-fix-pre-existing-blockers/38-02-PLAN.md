<task type="auto">
  <name>Task 2: Remove hardcoded Tailwind CDN from Inertia dev template</name>
  <files>ferro-inertia/src/response.rs</files>
  <action>
The Inertia dev-mode HTML template (`ferro-inertia/src/response.rs:410`) hardcodes:
```html
<script src="https://cdn.tailwindcss.com"></script>
```

This assumes all Ferro apps use Tailwind CSS and requires CDN access in development. This is problematic for:
- Apps not using Tailwind
- Offline development
- Security-conscious environments blocking external CDN

Fix approach: Remove the hardcoded Tailwind CDN script from the dev template. The Inertia template should be minimal — it provides the shell for Vite to inject assets. Tailwind compilation is handled by the project's Vite/PostCSS pipeline, not by a CDN script tag.

In the development template (around line 410), remove the line:
```html
<script src="https://cdn.tailwindcss.com"></script>
```

The Vite dev server (already configured in the template via `@vite/client` and entry point script tags) handles CSS hot-reload including Tailwind. The CDN script is redundant when Vite is running and incorrect when Tailwind isn't used.

Check if there are any tests that assert on the CDN URL being present in dev mode HTML. If so, update them to assert it's NOT present.
  </action>
  <verify>cargo test -p ferro-inertia 2>&1 | grep "test result" — passes. grep -r "cdn.tailwindcss.com" ferro-inertia/ — returns no results.</verify>
  <done>No hardcoded Tailwind CDN reference in ferro-inertia. Existing tests pass. Dev template still includes Vite dev server integration.</done>
</task>
