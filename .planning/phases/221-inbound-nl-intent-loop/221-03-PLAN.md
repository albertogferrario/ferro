<objective>
Wire the consumer-facing entry point: a thin `POST /mcp/chat` endpoint in the sample `app` that authenticates, resolves `tenant_id` from the principal, instantiates the live `AnthropicProvider` (behind `ai-live`), and calls `process_nl_turn`. Then add the `#[ignore]`-gated live-eval test (SC#4) that makes a real classification call, matches/updates the fixture, and announces estimated cost before the first call.

Purpose: D-01 puts the loop's HTTP wiring in the app (ferro-mcp-server provides the pieces). App-level identity (app_name/app_url) belongs here via `McpServerConfig::from_env()`, never hardcoded (CLAUDE.md project-agnostic rule). The live path is opt-in and cost-announced (isolate-before-spend discipline); CI never sets the env var.

Output: `app/src/controllers/mcp_chat.rs` + route registration + the `ai-live` feature enabled in `app/Cargo.toml`, and the gated live-eval test in `ferro-mcp-server/tests/intent_loop.rs`.
</objective>

|----------|-------------|
| HTTP client -> /mcp/chat | Untrusted bearer-authenticated request; principal-derived tenant only, NL message is untrusted free text |
| live LLM provider -> cost | Real API spend; must be opt-in (`FERRO_AI_LIVE_EVAL=1`) and cost-announced, never reachable from CI |
| app config -> ferro-* crates | App identity (app_url/app_name) must originate from env via `McpServerConfig::from_env()`, never hardcoded in code |
