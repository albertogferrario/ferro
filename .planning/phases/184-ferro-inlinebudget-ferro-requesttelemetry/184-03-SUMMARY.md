## Decisions Made

- **Integration test uses `Request::new(req)` synchronously.** Verified at `framework/src/http/request.rs:55-65` (the only constructor on `Request`; no `from_hyper(...).await` or `Default` impl exists in this codebase). The TCP-loopback `make_request()` helper from `framework/tests/action_handler.rs:47-94` is the canonical analog and was copied verbatim. `grep -F 'Request::from_hyper' framework/tests/telemetry_smoke.rs` returns zero; same for `Request::default`. Honors the plan's anti-pattern guard.
- **Single `#[tokio::test]` function covers all four required scenarios.** All four scenarios (Inline-below, Preload-above, unscoped record/snapshot, scoped record/snapshot + isolation) fit naturally in one round-trip on the same `Request`. Test isolation is handled by `RequestTelemetry::clear()` at the top of the function; because the integration-test binary contains exactly one test function that touches the global telemetry store, `#[serial_test::serial]` was unnecessary. `clear()` is `pub`; `reset()` is `pub(crate)` and not reachable from the integration-test binary, so `clear()` is the correct choice here.
- **`cargo publish --dry-run --allow-dirty` used during the ship-gate.** The workspace bump + dry-run + cargo doc are an atomic gate per the plan (the dry-run validates the bumped manifest before the commit; the commit then captures `Cargo.toml` + `Cargo.lock` together). `--allow-dirty` was the correct switch here because the dirty file is exactly the version edit the dry-run is meant to validate. No other uncommitted changes went into the dry-run.
- **Docs page voice matches `action-handlers.md`.** Scientific, neutral, no marketing language (per CLAUDE.md). The "Key cardinality" section explicitly closes the T-184-01 / T-184-05 / T-184-07 documentation gap by warning that callers MUST NOT derive `key`/`scope` from user input.
