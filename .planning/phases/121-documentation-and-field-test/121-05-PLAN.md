Two expression types, no others:
1. $data: `{ "$data": "/json/pointer/path" }` — type-preserving

Create `docs/src/json-ui/expressions.md` as a new file. Content:

1. **Title and intro:** `# Expressions` — Explain that expressions are JSON objects placed as prop values that are resolved at render time by the framework. Two types only: `$data` and `$template`.

2. **$data — Type-preserving extraction:**
   - Format: `{ "$data": "/json/pointer/path" }` using RFC 6901 JSON Pointer syntax
   - The entire object is replaced by the resolved value, preserving its type
   - Show examples:
     ```json
     { "$data": "/user/name" }      // "Alice" (string preserved)
     { "$data": "/order/total" }    // 99.50 (number preserved)
     { "$data": "/flags/active" }   // true (boolean preserved)
     { "$data": "/items" }          // [...] (array preserved)
     { "$data": "/missing" }        // null (missing path)
     ```
   - In a complete element:
     ```json
     "total_card": {
       "type": "StatCard",
       "props": {
         "label": "Total Revenue",
         "value": { "$data": "/stats/revenue" }
       }
     }
     ```

3. **$template — String interpolation:**
   - Format: `{ "$template": "text {/path} more text" }`
   - Always produces a string result
   - Placeholders use `{/json/pointer}` syntax
   - Missing paths produce `""` in the placeholder slot
   - Escape literal braces: `\{` and `\}`
   - Show examples:
     ```json
     { "$template": "Hello, {/user/name}!" }          // "Hello, Alice!"
     { "$template": "Order #{/order/id}" }             // "Order #1042"
     { "$template": "Items: {/cart/count} in cart" }   // "Items: 3 in cart"
     ```

4. **Where expressions apply (scope):**
   - Resolved in `element.props` values only
   - NOT resolved in: `spec.title`, `element.action`, `element.visible`, `element.children`
   - Show a props object using both expression types:
     ```json
     "greeting": {
       "type": "Text",
       "props": {
         "content": { "$template": "Welcome, {/user/name}!" },
         "element": "h1"
       }
     }
     ```

5. **Single-pass guarantee:** If a `$data` path resolves to a string like `{"$data":"/other"}`, that inner expression is NOT re-resolved. This prevents unexpected evaluation and injection.

6. **Hard cap — what does not exist:**
   Explicitly list: `$if`, `$for`, `$state`, `$bind`, `$map`, `$reduce` — these are not implemented and are not planned. Conditional rendering uses the `"visible"` field on elements (field/op/value condition). Data transformation belongs in the handler before calling `render_file`.

7. **Infallible semantics:** Malformed expressions degrade to literal JSON values — the framework never panics on invalid expressions. This is intentional for rendering reliability.

**Create docs/src/json-ui/json-schema.md:**

1. **Title and intro:** `# JSON Schema Export` — Ferro can export a JSON Schema document describing the full v2 spec format, including all built-in components and any registered custom plugins. Use it for IDE validation of spec files.

2. **Generate the schema:**
   ```bash
   # Export full schema (all components + custom plugins)
   ferro json-ui:schema --output schema.json --pretty

   # Export schema for a single component
   ferro json-ui:schema --component DataTable --pretty
   ```
   Note: The command requires a compiled Ferro project (it runs your app binary to include custom plugins). First run may be slow due to compilation.

3. **VS Code integration:** Add to `.vscode/settings.json`:
   ```jsonc
   {
     "json.schemas": [
       {
         "fileMatch": ["src/views/*.json"],
         "url": "./schema.json"
       }
     ]
   }
   ```
   After setup, VS Code validates spec files and provides autocompletion for component types and props.

4. **Other editors:** The generated `schema.json` is standard JSON Schema draft-07 — compatible with any editor that supports JSON Schema validation (IntelliJ, Neovim with LSP, etc.).

5. **What the schema covers:**
   - Full `Spec` object shape (`$schema`, `title`, `layout`, `root`, `elements`)
   - All element fields (`type`, `props`, `children`, `action`, `visible`)
   - Per-component props definitions (required vs optional fields, allowed values)
   - Expression objects (`$data` and `$template` shapes)
   - Custom plugin components (if registered in the app)

6. **Trimmed example output snippet** (show ~15 lines of schema JSON to illustrate the structure, not the full output):
   ```json
   {
     "$schema": "http://json-schema.org/draft-07/schema#",
     "title": "Ferro JSON-UI Spec",
     "type": "object",
     "required": ["root", "elements"],
     "properties": {
       "$schema": { "type": "string" },
       "title": { "type": "string" },
       "layout": { "type": "string" },
       "root": { "type": "string" },
       "elements": { "type": "object", "additionalProperties": { "$ref": "#/definitions/Element" } }
     }
   }
   ```

7. **Keeping the schema up to date:** Re-run `ferro json-ui:schema --output schema.json --pretty` when you add new custom plugins or after upgrading Ferro.
