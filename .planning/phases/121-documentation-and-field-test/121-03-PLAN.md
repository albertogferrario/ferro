  <action>
Rewrite `docs/src/json-ui/data-binding.md` for v2. Content must include:

1. **Overview:** In v2, data binding uses expressions — JSON objects with a single `$data` or `$template` key — placed as prop values in elements. Data flows from the handler (via `JsonUi::render_file`) into expressions.

2. **Handler data shape:** Show that the handler passes `serde_json::json!({...})` as the second argument to `render_file`. This JSON object is the root data context for all expressions.

3. **$data expression:** Type-preserving field extraction using JSON Pointer syntax.
   - Format: `{ "$data": "/json/pointer/path" }`
   - Resolves to the value at that path (preserves type: string stays string, number stays number, boolean stays boolean, array stays array)
   - Missing paths resolve to `null`
   - Example: `"value": { "$data": "/order/total" }` → resolves to `99.50` (number)

4. **$template expression:** String interpolation, always produces a string.
   - Format: `{ "$template": "Hello, {/user/name}!" }`
   - Placeholders `{/path}` use JSON Pointer syntax
   - Missing paths produce empty string `""` in the placeholder
   - Escape literal `{` and `}` with `\{` and `\}`
   - Example: `"label": { "$template": "Order #{/order/id}" }` → `"Order #1042"`

5. **Where expressions apply:** Props values only. Expressions in `spec.title`, element `action`, `visible` conditions, or `children` arrays are NOT resolved — they are literal strings.

6. **Hard cap — what does NOT exist:** `$if`, `$for`, `$state`, `$bind`, `$map` — these are not implemented and will not be added. Keep spec files declarative; conditional logic belongs in the handler (Rust).

7. **Single-pass guarantee:** If a `$data` expression resolves to a string that looks like `{"$data": "/another"}`, the inner expression is NOT re-resolved. This is intentional — prevents injection.

8. **Complete example:** A handler + spec file showing multiple expressions:
   - A StatCard with `"value": { "$data": "/stats/total" }`
   - A Text with `"content": { "$template": "Welcome, {/user/name}!" }`
   - A DataTable with `"data_path": "/orders"` (plain string, not expression)

9. Do NOT reference `data_path` as a Rust field. The prop `data_path` is a plain string value in JSON props (a JSON Pointer path for the component to read rows/items from), distinct from the `$data` expression which resolves at render time.
