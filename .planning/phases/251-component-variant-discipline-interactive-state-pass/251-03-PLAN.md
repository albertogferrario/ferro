- `$defs/Tone`.enum    == `["neutral", "success", "warning", "destructive"]`
- `$defs/Size`.enum    == `["sm", "md", "lg"]`

Schemars 1.x enum schema shapes the walker must handle (RESEARCH §Enforcement Mechanics):
1. Struct field of enum type → `{"$ref": "#/$defs/EnumName"}`.
2. `Option<Enum>` → `{"anyOf": [{"$ref": ...}, {"type": "null"}]}` (Avatar's `Option<Size>`).
3. Plain enum → `$defs` entry `{"type": "string", "enum": [...]}` (canonical enums have
   container-level docs only → this shape).
4. Per-variant-doc enum → `anyOf` of `{"type":"string","const":"x"}` (avoid on the canonical enums;
   handle defensively anyway so the guard cannot be silently defeated).

Catalog build in tests: `Catalog::build_builtins_only().expect("build succeeds")` (avoids plugin
pollution — catalog.rs :1122). The assembled schema shape: `$defs/Element/oneOf[]`, each entry
`allOf: [ {properties.type.const}, {properties: {props: <schema>, children, action: $ref #/$defs/Action,
visible: $ref #/$defs/Visibility}} ]`; component-local `$defs` are hoisted to the root (catalog.rs
:500-521), so all `$ref`s resolve against the root `$defs` map.
</interfaces>

   the NEW part is the `$ref` resolution + recursion (no in-tree analog — RESEARCH "No Analog Found").
