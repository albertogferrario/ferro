2. In field.rs:
   - Add `use schemars::JsonSchema;` import.
   - Add `JsonSchema` to DataType derive list (after existing derives).
   - Add `JsonSchema` to FieldMeaning derive list. Add `#[schemars(description = "Semantic field meaning. Known variants: identifier, foreign_key, entity_name, email, phone, url, image_url, money, percentage, quantity, status, category, boolean, free_text, created_at, updated_at, date_time, sensitive. Any other string is a custom domain-specific meaning.")]` on the FieldMeaning enum. This mitigates the anyOf schema problem where the Custom(String) catch-all shadows named variants — the description tells agents what the known values are.
   - Add `JsonSchema` to FieldDef derive list.

3. In service.rs:
   - Add `use schemars::JsonSchema;` import.
   - Add `JsonSchema` to ServiceDef derive list.

4. In state.rs:
   - Add `use schemars::JsonSchema;` import.
   - Add `JsonSchema` to StateMachine derive list.
   - Add `JsonSchema` to StateDef derive list.
   - Add `JsonSchema` to Transition derive list.

Do NOT add JsonSchema to Error or Warning (internal types, not part of protocol contract). Do NOT change any existing behavior or API signatures.
  </action>
