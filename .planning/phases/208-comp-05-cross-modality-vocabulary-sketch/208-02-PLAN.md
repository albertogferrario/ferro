<!-- The seven-intent structural definitions to analyze (from 208-RESEARCH.md, VERIFIED against intent.rs/derive.rs). READ-ONLY context — do NOT modify these files. -->

| Intent | Structural Signals | Non-Visual Concern (starting point — refine from sketch evidence) |
|--------|-------------------|----------------------------|
| Browse | has_many relationships, EntityName fields, category fields, baseline | Table has no clear voice equivalent; CLI lists names |
| Focus | FreeText/ImageUrl/Url fields, inline relationships, parent refs | Image/URL fields meaningless without a screen; voice must narrate or skip |
| Collect | High writable ratio (>50%), write_only fields, complex-input actions | Form → voice dialog or CLI prompt sequence; step count unclear |
| Process | Guarded branching transitions, transition-trigger actions, workflow/guarded actions | Richest structure — maps most naturally to multi-step flows in all modalities (the anchor) |
| Summarize | Read-only Money/Percentage/Quantity, mostly read-only ratio | Dashboard numbers → verbal summary or compact stats card |
| Analyze | DateTime + numeric co-occurrence | Time-series exploration needs chart/graph; awkward for voice |
| Track | Linear (non-branching) states, Status field, has_final_states, unguarded progression | Timeline/audit → voice status narration or CLI progress bar |

Derivation facts (frozen): tie-break priority Process(0) > Track(1) > Collect(2) > Browse(3) > Focus(4) > Summarize(5) > Analyze(6). Browse+Focus get a +0.1 baseline. Primary = intents[0].

BaseContext fields today: intent_index, current_state. D-05: any modality-specific need (device_class, voice verbosity, max-card-count) is a v14.0 implication to RECORD here, never to implement.
