Update `ferro-mcp/src/tools/stripe.rs` so that `stripe_webhook_events` discovers the
SyncDispatcher closure handler form introduced in Phase 141, and so that
`stripe_config_status` reports the capability-axis module layout
(`checkout.rs`, `refund.rs`, `account.rs`, `webhook/`).

Purpose: After Phase 141 rewrote ferro-stripe to use anonymous closures registered
via `SyncDispatcher::on(|event: EventType| ...)` and a capability-axis module tree,
the ferro-mcp introspection tools scan for the obsolete `impl Listener<EventType> for Struct`
pattern and the obsolete file layout, making them blind to the current architecture.
ferro-mcp is the surface AI agents read to author Ferro applications, so a stale
introspection layer contradicts the framework's core proposition.

Output: Updated `WebhookEventInfo` struct (drops `listener`, adds `line: u32`),
extended `StripeConfigStatus` struct (adds four boolean fields), rewritten
`stripe_webhook_events` body using `walkdir::WalkDir` and two regex patterns,
extended `stripe_config_status` body with four `Path::is_file()/is_dir()` checks,
and updated/added tests covering the new behavior (D-16, D-17, D-18, D-19).
</objective>

       ```rust
       pub fn stripe_webhook_events(project_root: &Path) -> StripeWebhookEvents {
           let src_dir = project_root.join("src");
           if !src_dir.is_dir() {
               return StripeWebhookEvents { events: Vec::new() };
           }

           // Primary: closure form  .on(|ident: EventType| ...)
           let re_closure = Regex::new(r"\.on\(\s*\|[a-zA-Z_]+:\s*(\w+)\s*\|").unwrap();
           // Secondary: turbofish form  .on::<EventType
           let re_turbofish = Regex::new(r"\.on::<(\w+)").unwrap();

           let mut events = Vec::new();

           for entry in WalkDir::new(&src_dir)
               .into_iter()
               .filter_map(|e| e.ok())
               .filter(|e| e.path().extension().map(|ext| ext == "rs").unwrap_or(false))
           {
               let content = match fs::read_to_string(entry.path()) {
                   Ok(c) => c,
                   Err(_) => continue,
               };
               let relative = entry
                   .path()
                   .strip_prefix(project_root)
                   .unwrap_or(entry.path())
                   .to_string_lossy()
                   .to_string();

               for cap in re_closure.captures_iter(&content) {
                   let byte_offset = cap.get(0).unwrap().start();
                   let line = (content[..byte_offset].lines().count() + 1) as u32;
                   events.push(WebhookEventInfo {
                       event_type: cap[1].to_string(),
                       file: relative.clone(),
                       line,
                   });
               }

               for cap in re_turbofish.captures_iter(&content) {
                   let byte_offset = cap.get(0).unwrap().start();
                   let line = (content[..byte_offset].lines().count() + 1) as u32;
                   events.push(WebhookEventInfo {
                       event_type: cap[1].to_string(),
                       file: relative.clone(),
                       line,
                   });
               }
           }

           StripeWebhookEvents { events }
       }
       ```
       The line-number formula `(content[..byte_offset].lines().count() + 1) as u32` produces 1-based line numbers. The `+ 1` is REQUIRED — see Pitfall 4 in 142-RESEARCH.md.
