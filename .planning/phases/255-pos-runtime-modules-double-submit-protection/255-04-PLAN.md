<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spec author -> render (server) | props.name flows into the data-filter-text HTML attribute at render time. |
| server-rendered DOM -> client runtime | filters.rs reads data-filter-* attributes and toggles visibility client-side; it never fetches or authorizes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-255-07 | Information disclosure / Tampering (XSS) | render_tile data-filter-text emission (atoms.rs) | mitigate | Emit via html_escape(&props.name); add the tile_escapes_filter_text test asserting quote/angle-bracket escaping. Attribute value is never interpolated raw. |
| T-255-08 | Elevation of privilege | filters.rs client-side visibility toggle | accept | Client-side filtering is a UX affordance, NOT an authorization boundary. Hidden tiles remain in the DOM but were already server-rendered from data the user is authorized to see; the server never trusts filter state. Documented as presentational; no data exposure beyond what was already sent. |
| T-255-09 | Tampering (money) | numpad price mode | mitigate | Hidden field carries raw integer-cents string; all arithmetic is integer, never float (PITFALLS.md). Display formatting is presentational only; the server re-validates the submitted cents value. |
</threat_model>
