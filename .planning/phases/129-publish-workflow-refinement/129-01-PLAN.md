  <action>
In `.github/workflows/publish.yml`, extend the existing `check-version` job. Do NOT create a new job.

Step A — Add a new step BEFORE the existing `Check if version is tagged` step, named `Check for library crate changes`, with `id: gate`. Its script must:

1. Resolve the last `v*` tag:
   ```bash
   LAST_TAG=$(git describe --tags --abbrev=0 --match 'v*' 2>/dev/null || echo "")
   ```
2. If `LAST_TAG` is empty, log `No prior v* tag — first publish, treating as library change` and set `LIB_CHANGED=1`.
3. Otherwise, compute `CHANGED=$(git diff --name-only "$LAST_TAG"..HEAD)`, log it, and iterate the paths through the following `case` statement (exclusion list). A changed path is a LIBRARY change only if it matches NONE of these excluded globs:
   ```bash
   case "$path" in
     ferro-cli/*|app/*) continue ;;
     docs/*|.github/*|.planning/*|scripts/*) continue ;;
     *.md|LICENSE|.gitignore|.editorconfig|rustfmt.toml) continue ;;
     bacon.toml|deny.toml|dev.sh|llms.txt|rust-toolchain.toml) continue ;;
     Cargo.lock) continue ;;
     "") continue ;;
     *) LIB_CHANGED=1; echo "Library change detected: $path"; break ;;
   esac
   ```
   Start with `LIB_CHANGED=0` before the loop.
4. Emit `echo "lib_changed=$LIB_CHANGED" >> $GITHUB_OUTPUT`.

Precede the step with a comment block explaining the rule verbatim:
```yaml
# Library-change gate (Phase 129, REPORT §8).
#
# A push only triggers a patch bump + crates.io release if at least one file
# under a library crate path changed since the last v* tag. Paths under
# ferro-cli/, app/, docs/, .github/, .planning/, scripts/, top-level *.md,
# LICENSE, Cargo.lock, and top-level config files (.gitignore, .editorconfig,
# rustfmt.toml, bacon.toml, deny.toml, dev.sh, llms.txt, rust-toolchain.toml)
# are NOT library changes. Workspace-root Cargo.toml IS a library change
# (workspace version / dep updates).
#
# First-run edge case: no v* tag yet → treat as library change (publish).
```

Step B — Modify the existing `Check if version is tagged` step to run only when a library change was detected, by wrapping its logic so that when `steps.gate.outputs.lib_changed == '0'` it instead emits:
```bash
echo "Skipping publish: no library crate changed since $LAST_TAG"
echo "version=$VERSION" >> $GITHUB_OUTPUT
echo "new_version=$VERSION" >> $GITHUB_OUTPUT
echo "should_publish=none" >> $GITHUB_OUTPUT
```
and otherwise runs the existing tag/bump logic unchanged (still emitting `should_publish=bump` or `should_publish=yes`). The cleanest form: keep `id: check`, add an `if: steps.gate.outputs.lib_changed == '0'` early-exit step emitting `should_publish=none`, and add `if: steps.gate.outputs.lib_changed == '1'` to the existing step. Both branches must set all three outputs (`version`, `new_version`, `should_publish`).

Step C — Downstream guards. Replace every `if:` that currently uses `needs.check-version.outputs.should_publish != ''` with explicit equality on the allow-list:
- `bump-version`: keep `if: needs.check-version.outputs.should_publish == 'bump'` (unchanged).
- `test`: change to `if: always() && (needs.check-version.outputs.should_publish == 'bump' || needs.check-version.outputs.should_publish == 'yes')`.
- `publish`: change to `if: always() && needs.test.result == 'success' && (needs.check-version.outputs.should_publish == 'bump' || needs.check-version.outputs.should_publish == 'yes')`.

Delete the old `!= ''` form. Do not leave commented-out code. Do not rename jobs.

Do NOT use the string `no` anywhere — use `none` exclusively (YAML 1.1 coerces `no` to `false`).
