Create `ferro-api-mcp/src/schema.rs`:

Main function: `pub fn build_input_schema(params: &[ApiParam], request_body_schema: Option<&serde_json::Value>) -> serde_json::Value`

Logic:
1. Create a JSON Schema object: `{"type": "object", "properties": {}, "required": []}`
2. For each ApiParam:
   - Add to "properties" with param.name as key
   - Value is param.schema with description injected if present
   - If param.required, add name to "required" array
3. For request_body_schema (POST/PUT/PATCH operations):
   - Add under "body" key in properties (prevents name collisions with path/query params)
   - Set description: "Request body (JSON)"
   - If the body schema has "properties", nest them under body
   - If the body has "required" fields, note in body's description but don't make "body" itself required (let the AI decide what to send)
4. Return the complete JSON Schema Value

Helper: `pub fn inject_description(schema: &mut serde_json::Value, description: &str)` — adds "description" key to a schema object

Write unit tests:
- `build_input_schema` with path params only → properties have id, required has id
- `build_input_schema` with query params → properties have page, required is empty
- `build_input_schema` with body → properties has "body" object
- `build_input_schema` with no params → empty properties, empty required
- `build_input_schema` with mixed path + query + body → all three present, only path params required
- `inject_description` adds description to schema object

Add `pub mod schema;` to lib.rs.

<task type="auto">
  <name>Task 2: Build HTTP client for API call execution</name>
  <files>ferro-api-mcp/src/http.rs, ferro-api-mcp/src/lib.rs</files>
  <action>
Create `ferro-api-mcp/src/http.rs`:

Define `pub struct HttpClient`:
- Fields: client (reqwest::Client), base_url (url::Url), api_key (Option<String>)
- Constructor: `pub fn new(base_url: url::Url, api_key: Option<String>) -> Self` — create reqwest::Client with reasonable timeout (30s)

Main method: `pub async fn execute(&self, op: &ApiOperation, args: &serde_json::Map<String, serde_json::Value>) -> Result<serde_json::Value, Error>`

Logic:
1. **Path interpolation:** Clone op.path, for each param where location == Path, replace `{param_name}` with the value from args. Convert non-string values via `.to_string()` (strip quotes for strings).
2. **Build URL:** Join base_url with interpolated path via `self.base_url.join(&path)`
3. **Create request:** `self.client.request(method.parse()?, url)`
4. **Add auth header:** If api_key is Some, add `Authorization: Bearer {key}` header
5. **Add query params:** For each param where location == Query, if present in args, add to query string. For string values use the string directly; for numbers/bools use to_string().
6. **Add body:** If args contains "body" key and method is POST/PUT/PATCH, send as JSON body via `.json(body_value)`
7. **Send and handle response:**
   - Success (2xx): Parse response body as JSON. If not valid JSON, wrap as `Value::String(body)`
   - Error (4xx/5xx): Return `Error::ApiError { status, body }`

Write a helper: `pub fn interpolate_path(path: &str, params: &[ApiParam], args: &serde_json::Map<String, serde_json::Value>) -> String` — pure function for path interpolation, easy to test.

Write a helper: `pub fn build_query_params(params: &[ApiParam], args: &serde_json::Map<String, serde_json::Value>) -> Vec<(String, String)>` — pure function for query param extraction.

Write unit tests for the pure functions:
- `interpolate_path` with single param: "/users/{id}" + {"id": "123"} → "/users/123"
- `interpolate_path` with multiple params: "/users/{user_id}/posts/{post_id}" + values → correct
- `interpolate_path` with numeric value: "/users/{id}" + {"id": 42} → "/users/42"
- `interpolate_path` with missing param: "/users/{id}" + {} → "/users/{id}" (unchanged)
- `build_query_params` extracts only Query-location params present in args
- `build_query_params` with no query params → empty vec

Add `pub mod http;` to lib.rs.
