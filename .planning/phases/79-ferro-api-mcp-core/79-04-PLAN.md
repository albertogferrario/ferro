  <action>
Create `ferro-api-mcp/src/service.rs`:

Define `pub struct ApiMcpService`:
- Fields: api_name (String), tool_router (ToolRouter<Self>), tool_count (usize)

Constructor: `pub fn new(api_name: String, operations: Vec<ApiOperation>, http_client: Arc<HttpClient>) -> Self`
- Build ToolRouter from operations:
  1. For each ApiOperation, create an rmcp Tool using `Tool::new(op.tool_name, op.description, input_schema_as_arc_map)`
     - Convert op.input_schema (serde_json::Value) to `Arc<serde_json::Map<String, serde_json::Value>>` — extract the object map from the Value
  2. Create ToolRoute::new_dyn(tool, closure) where the closure:
     - Clones the http_client Arc and ApiOperation
     - Extracts arguments from ToolCallContext: `ctx.request().arguments.clone().unwrap_or_default()`
     - Calls `http_client.execute(&op, &args).await`
     - On success: return `CallToolResult::success(vec![Content::text(serde_json::to_string_pretty(&response))])`
     - On error: return `CallToolResult::error(vec![Content::text(format!("API call failed: {err}"))])`
  3. Add each ToolRoute to the ToolRouter
- Store tool count for server info

Implement `ServerHandler for ApiMcpService`:
- `fn get_info(&self) -> ServerInfo`:
  - server_name: "ferro-api-mcp"
  - version: env!("CARGO_PKG_VERSION")
  - instructions: "API tools for {api_name}. {tool_count} tools available. Use these tools to interact with the API."
  - capabilities: enable_tools()
- `async fn list_tools(...)`: Return `ListToolsResult::with_all_items(self.tool_router.list_all())`
- `async fn call_tool(...)`: Create ToolCallContext, delegate to `self.tool_router.call(tcc).await`

Set tool annotations based on HTTP method for each tool:
- GET: readOnlyHint = true, idempotentHint = true
- POST: readOnlyHint = false
- PUT/PATCH: readOnlyHint = false, idempotentHint = true
- DELETE: destructiveHint = true

Note: Check rmcp 0.12 Tool struct for annotation support. If Tool::new doesn't accept annotations directly, check if there's a builder or setter. If not available in 0.12, skip annotations (add as Phase 81 enhancement) — don't block on this.

Add `pub mod service;` to lib.rs.

Define `pub struct McpServer`:
- Fields: service (ApiMcpService)
- Constructor: `pub fn new(service: ApiMcpService) -> Self`
- Method: `pub async fn run(self) -> Result<(), Error>`:
  - Create stdin/stdout handles: `tokio::io::stdin()`, `tokio::io::stdout()`
  - Start MCP server: `self.service.serve((stdin, stdout)).await?`
  - Wait: `server.waiting().await?`
  - Pattern matches ferro-mcp/src/server.rs for consistency

Add `pub mod server;` to lib.rs.

Update `ferro-api-mcp/src/main.rs` to wire the full pipeline:

```
#[tokio::main]
async fn main() {
    1. Parse CLI args (already done)
    2. Initialize tracing

    3. Fetch spec:
       let spec_json = spec::fetch_spec(&cli.spec_url).await?
       - On error: print clear message "Failed to fetch OpenAPI spec from {url}: {err}" and exit(1)

    4. Parse spec:
       let operations = spec::parse_spec(&spec_json)?
       - On error: print clear message "Failed to parse OpenAPI spec: {err}" and exit(1)
       - Log: "Parsed {n} API operations from spec"

    5. Determine base URL:
       - If cli.base_url provided, use it
       - Else if spec has servers[0].url, use that
       - Else extract origin from spec_url (scheme + host + port)
       - Parse into url::Url
       - Log: "Base URL: {base_url}"

    6. Build input schemas for each operation:
       For each operation, call schema::build_input_schema(&op.parameters, op.request_body_schema.as_ref())
       and set op.input_schema to the result

    7. Create HTTP client:
       let http_client = Arc::new(HttpClient::new(base_url, cli.api_key))

    8. Create service:
       let service = ApiMcpService::new(api_name, operations, http_client)
       - api_name: extract from spec's info.title, or "API" if missing

    9. Start server:
       let server = McpServer::new(service)
       server.run().await?
}
```

For base URL extraction from spec: Parse the spec JSON again with serde_json to get `spec["servers"][0]["url"]`. Or pass the parsed openapiv3::OpenAPI from parse_spec. Consider making parse_spec return both the operations Vec AND the spec title + server URL. Alternative: add a `pub fn extract_metadata(json: &str) -> Result<SpecMetadata, Error>` that returns title and server_url alongside parse_spec.

Error handling: Use a helper function or match blocks. Don't use `.unwrap()`. Print user-friendly errors to stderr and exit with code 1.

Logging: Use `eprintln!` for startup messages (not stdout — stdout is the MCP transport). Use tracing for structured logs that go to stderr via tracing-subscriber.
