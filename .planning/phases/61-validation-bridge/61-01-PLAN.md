<task type="auto">
  <name>Task 1: Create validation bridge module</name>
  <files>framework/src/validation/bridge.rs, framework/src/validation/mod.rs, framework/src/lib.rs</files>
  <action>
Create `framework/src/validation/bridge.rs` with:

1. **Type alias:** `pub type TranslatorFn = fn(&str, &[(&str, &str)]) -> Option<String>;`
   - First param: translation key (e.g., "validation.required")
   - Second param: interpolation parameters (e.g., [("attribute", "email"), ("min", "8")])
   - Returns: translated message or None (caller falls back to English)

2. **Static OnceLock:** `static VALIDATION_TRANSLATOR: OnceLock<TranslatorFn> = OnceLock::new();`
   - Follows established pattern from config/repository.rs, container/mod.rs, etc.
   - No RwLock needed — the translator is set once at boot, never changes.

3. **Registration function:**
   ```rust
   pub fn register_validation_translator(f: TranslatorFn) {
       let _ = VALIDATION_TRANSLATOR.set(f);
   }
   ```
   - Silently ignores double-registration (OnceLock::set returns Err if already set).

4. **Lookup helper:**
   ```rust
   pub(crate) fn translate_validation(key: &str, params: &[(&str, &str)]) -> Option<String> {
       VALIDATION_TRANSLATOR.get().and_then(|f| f(key, params))
   }
   ```
   - `pub(crate)` — only rules within the validation module call this.
   - Returns None if no translator registered (rules fall back to hardcoded English).

Then wire into the module:
- In `framework/src/validation/mod.rs`: add `mod bridge;` and `pub use bridge::register_validation_translator;`. Also `pub use bridge::TranslatorFn;`.
- In `framework/src/lib.rs`: add `register_validation_translator` and `TranslatorFn` to the validation re-exports block.

Do NOT modify any existing rules — that is Phase 62 work.
Do NOT add ferro-lang as a dependency — the entire point is decoupling.
