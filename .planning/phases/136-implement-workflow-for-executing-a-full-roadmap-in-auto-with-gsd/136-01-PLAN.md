  <action>
Create `~/.claude/get-shit-done/bin/gsd-roadmap-run.sh` — a bash script implementing the outer orchestrator per decisions D-01 through D-07.

**Script structure:**

1. **Argument parsing** (per D-03):
   - Required first argument: milestone name (e.g., "v11.5")
   - Optional `--from N` flag to start from a specific phase number
   - Optional `--dry-run` flag that prints what would be done without invoking claude
   - Print usage and exit 1 if no milestone argument provided

2. **Milestone validation:**
   - Run `node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" init milestone-op` and parse JSON
   - Verify `roadmap_exists` and `state_exists` are true; exit 1 with error if not
   - Extract `milestone_version`, `milestone_name`, `phase_count`, `completed_phases`

3. **Phase discovery** (per D-04 — no new state file, use `roadmap analyze`):
   - Run `node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" roadmap analyze` and parse JSON
   - Filter to phases where `disk_status != "complete"` OR `roadmap_complete == false`
   - If `--from N` provided, additionally filter phases where number < N (numeric comparison)
   - Sort by phase number ascending
   - If no incomplete phases remain, print "All phases complete" and exit 0

4. **Phase loop** (per D-02 — one fresh invocation per phase):
   - For each incomplete phase:
     a. Print progress banner: `[N/T] Phase {number}: {name}`
     b. **Re-read roadmap state** before each phase (per D-04): re-run `roadmap analyze`, re-filter incomplete phases, check if current phase is still incomplete (skip if already complete)
     c. Invoke claude CLI: `claude -p "/gsd:autonomous --from ${PHASE_NUM}" --permission-mode auto --verbose --model opus 2>&1 | tee "/tmp/gsd-roadmap-${PHASE_NUM}.log"`
     d. Capture exit code from `${PIPESTATUS[0]}`
     e. On success (exit 0): print checkmark, continue to next phase
     f. On failure (non-zero exit): execute failure handler

5. **Failure handler** (per D-05, D-06):
   - Extract last 50 lines from the log file
   - Create GitHub issue via `gh issue create`:
     - Title: `"Phase ${PHASE_NUM} failed: ${PHASE_NAME}"`
     - Body: exit code, last 50 lines of output, path to phase directory
     - Labels: `"gsd-failure"` (if label exists, otherwise omit `--label`)
   - Print failure message with issue URL
   - Exit 1 immediately (per D-05 — stop on failure)

6. **Completion banner:**
   - After all phases succeed, print summary: phases completed count, total time elapsed

**Key implementation details:**
- Use `set -euo pipefail` at top
- Use `jq` for JSON parsing (check `jq` availability at script start, print helpful error if missing)
- Also check `node`, `claude`, and `gh` availability at start
- Log each phase output to `/tmp/gsd-roadmap-{phase_num}.log`
- Track elapsed time using `$SECONDS`
- The `/gsd:autonomous --from N` prompt tells the autonomous workflow to start from a specific phase, which handles the discuss/plan/execute/verify cycle internally
- Make the script executable: `chmod +x`

**Claude CLI invocation rationale:**
- `--print` (`-p`): non-interactive mode, prints response and exits
- `--permission-mode auto`: allows autonomous tool execution without prompts
- `--verbose`: shows progress during execution
- `--model opus`: use the strongest model for reliable autonomous execution
- The prompt is `/gsd:autonomous --from ${PHASE_NUM}` — this triggers the existing autonomous workflow which handles smart discuss, plan, execute, and verification for one phase, then returns
- Note: `/gsd:autonomous` processes multiple phases within one session. Since we want one phase per session, we use `--from N` and rely on context exhaustion or phase completion to end the session. An alternative is to invoke the individual steps directly: `/gsd:discuss-phase ${N} --auto && /gsd:plan-phase ${N} && /gsd:execute-phase ${N} --no-transition`. Use the individual steps approach — it gives cleaner exit code handling per operation.

**Revised invocation strategy:**
Instead of `/gsd:autonomous --from N`, invoke individual GSD steps sequentially within one claude session using a combined prompt:
```
claude -p "Run these GSD commands in sequence for phase ${PHASE_NUM}: 1) /gsd:discuss-phase ${PHASE_NUM} --auto  2) /gsd:plan-phase ${PHASE_NUM}  3) /gsd:execute-phase ${PHASE_NUM} --no-transition" --permission-mode auto --verbose --model opus
```

This keeps one claude invocation per phase (per D-02) while making the prompt explicit about what operations to run.
