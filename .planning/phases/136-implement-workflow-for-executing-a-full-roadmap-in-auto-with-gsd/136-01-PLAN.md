  <action>
Create `.github/workflows/gsd-roadmap.yml` with the following structure:

**Trigger:** `workflow_dispatch` with two inputs per D-03:
  1. `roadmap_path` (string, required, default: `.planning/ROADMAP.md`) — path to the roadmap file
  2. `milestone` (string, required) — milestone name within that roadmap (e.g. "v11.5")

**Runner:** `ubuntu-latest` (GitHub-hosted). Per D-01, runs entirely on GitHub infrastructure.

**Environment setup step:**
  - `actions/checkout@v4` with `fetch-depth: 0` and `token: ${{ secrets.GITHUB_TOKEN }}`
  - Configure git identity as `github-actions[bot]` (the workflow commits plan/summary docs)
  - Install Node.js via `actions/setup-node@v4` (Node 20)
  - Install `gsd-tools.cjs` — copy from the repo's vendored path or install globally. The file lives at `$HOME/.claude/get-shit-done/bin/gsd-tools.cjs` on the developer machine; for CI, the workflow should expect it at a known path. Use an environment variable `GSD_TOOLS` pointing to the script path. For now, assume the runner has access to the GSD tools via the repo or a setup step that installs them. Add a placeholder step `# TODO: Install GSD tools — requires packaging decision` with a comment explaining this needs the tools available on the runner.
  - Install `claude` CLI — use `npm install -g @anthropic-ai/claude-code` (the official npm package). Requires `ANTHROPIC_API_KEY` secret.
  - Set env vars: `ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}`

**Phase discovery step (bash):**
  - Run `node "$GSD_TOOLS" roadmap analyze --file "${{ inputs.roadmap_path }}"` (or pass the roadmap path if the tool supports it; if not, the tool reads `.planning/ROADMAP.md` by default which matches the default input)
  - Parse the JSON output to extract incomplete phases for the specified milestone
  - Filter phases where `disk_status !== "complete"` AND belonging to the milestone matching `${{ inputs.milestone }}`
  - Sort by phase number ascending
  - Store the phase list as a newline-separated list in `$GITHUB_OUTPUT`
  - If no incomplete phases found, log "All phases complete for milestone {name}" and exit 0

**Phase execution loop step (bash):**
  - Loop over each incomplete phase number from the discovery step
  - Per D-02: one fresh `claude` CLI invocation per phase. Use `claude -p --dangerously-skip-permissions --model opus` with the prompt:
    ```
    /gsd:autonomous --from {PHASE_NUM}
    ```
    The `--dangerously-skip-permissions` flag is required for non-interactive CI execution. The `-p` (print) flag makes it non-interactive.
  - Capture output: pipe claude stdout+stderr through `tee` to a log file (`/tmp/claude-phase-{N}.log`), AND capture the exit code separately using `set +e` / `EXIT_CODE=$?` pattern
  - Per D-04: Before each phase, re-run `roadmap analyze` to re-read state and catch dynamically inserted phases. If the current phase is now complete (appeared in a prior run's commits), skip it.
  - Per D-05/D-06 (with checker feedback fix): On non-zero exit code, STOP the loop and create a GitHub issue via:
    ```bash
    TAIL_OUTPUT=$(tail -50 /tmp/claude-phase-${PHASE_NUM}.log)
    gh issue create \
      --title "GSD: Phase ${PHASE_NUM} failed — ${PHASE_NAME}" \
      --body "$(cat <<ISSUEEOF
    ## Phase ${PHASE_NUM} Failed

    **Milestone:** ${{ inputs.milestone }}
    **Roadmap:** ${{ inputs.roadmap_path }}
    **Exit code:** ${EXIT_CODE}

    ### Last 50 lines of output

    \`\`\`
    ${TAIL_OUTPUT}
    \`\`\`

    ### Phase directory

    \`.planning/phases/${PHASE_DIR_NAME}/\`

    ### Workflow run

    ${GITHUB_SERVER_URL}/${GITHUB_REPOSITORY}/actions/runs/${GITHUB_RUN_ID}
    ISSUEEOF
    )" \
      --label "gsd-failure"
    ```
    Then `exit 1` to fail the workflow.
  - On success (exit code 0): log completion, continue to next phase
  - After all phases complete: log "Milestone {name} complete"

**Permissions block:** `permissions: contents: write, issues: write` (needs to commit docs and create issues).

**Key details:**
- Do NOT use `--bare` flag — CLAUDE.md auto-discovery is needed for project context
- Use `set +e` before claude invocation to capture exit code without failing the step immediately
- The `gh` CLI is pre-installed on GitHub-hosted runners, no installation needed
- `GITHUB_TOKEN` is auto-provided, used by `gh` for issue creation
- Add `concurrency: group: gsd-roadmap, cancel-in-progress: false` to prevent parallel runs but not cancel running ones
