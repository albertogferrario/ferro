Create `.github/workflows/gsd-roadmap.yml` with the following structure:

**Trigger:** `workflow_dispatch` with one required input `milestone` (string, description: "Milestone name to execute, e.g. v11.5"). Per D-01 and D-07.

**Runner:** `ubuntu-latest` (GitHub-hosted). Per Claude's discretion on runner choice.

**Permissions:** `contents: write` (for git commits from gsd-tools), `issues: write` (for gh issue create on failure).

**Environment variables:**
- `ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}` — required for claude CLI
- `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` — for gh issue create

**Job: `run-roadmap`**

Steps:

1. **Checkout** — `actions/checkout@v4` with `fetch-depth: 0` and `token: ${{ secrets.GITHUB_TOKEN }}`.

2. **Configure Git** — Set git user to `github-actions[bot]` (same pattern as publish.yml).

3. **Setup Node.js** — `actions/setup-node@v4` with `node-version: '20'`. Required for `gsd-tools.cjs`.

4. **Install Claude CLI** — Run: `npm install -g @anthropic-ai/claude-code`. This installs the `claude` command globally on the runner.

5. **Copy GSD tools to runner** — The workflow needs `~/.claude/get-shit-done/` on the runner. Since gsd-tools and workflows live in the user's home directory (not in the repo), the workflow must bootstrap them. Add a step that clones or copies the GSD toolkit. Use a repository secret `GSD_TOOLS_REPO` for the git URL, or if not set, skip and assume tools are pre-installed. For the initial version, use an environment variable `GSD_TOOLS_PATH` that defaults to `$HOME/.claude/get-shit-done` and document that the runner needs GSD tools pre-installed OR the user sets up a self-hosted runner. Add a validation step that checks `node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" --help` succeeds.

   Actually, simplify: use a dedicated step that clones from a secret `GSD_REPO_URL` if set, otherwise errors with a clear message. The step:
   ```
   - name: Setup GSD tools
     run: |
       if [ -n "${{ secrets.GSD_REPO_URL }}" ]; then
         git clone "${{ secrets.GSD_REPO_URL }}" "$HOME/.claude/get-shit-done"
       fi
       # Validate GSD tools are available
       if [ ! -f "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" ]; then
         echo "::error::GSD tools not found. Set GSD_REPO_URL secret or use a self-hosted runner with GSD pre-installed."
         exit 1
       fi
   ```

6. **Discover incomplete phases** — Run a shell script block that:
   - Calls `node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" roadmap analyze` and captures JSON
   - Filters phases where `disk_status` is not `"complete"` (use `jq`)
   - Filters to phases belonging to the input milestone (match milestone from ROADMAP heading context — or simpler: just run all incomplete phases, since gsd-tools already knows milestone context)
   - Sorts by phase number ascending
   - Outputs a space-separated list of phase numbers to `$GITHUB_OUTPUT` as `phases`
   - If no incomplete phases, outputs empty string and logs "All phases complete"

   Install `jq` if needed (ubuntu-latest has it pre-installed).

7. **Execute phases loop** — A step with a bash loop over the phase numbers from step 6. Per D-02, one fresh `claude` invocation per phase. Per D-04, re-read roadmap state before each phase.

   For each phase number `$PHASE`:
   ```bash
   echo "::group::Phase $PHASE"

   # Re-read roadmap state before each phase (per D-04)
   PHASE_STATE=$(node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" init phase-op "$PHASE" 2>/dev/null || echo "{}")
   HAS_CONTEXT=$(echo "$PHASE_STATE" | jq -r '.has_context // false')
   HAS_PLANS=$(echo "$PHASE_STATE" | jq -r '.has_plans // false')
   PHASE_NAME=$(echo "$PHASE_STATE" | jq -r '.phase_name // "unknown"')

   echo "Phase $PHASE ($PHASE_NAME): context=$HAS_CONTEXT plans=$HAS_PLANS"

   # Step A: Discuss (if no context yet)
   if [ "$HAS_CONTEXT" != "true" ]; then
     echo "Running discuss for phase $PHASE..."
     claude -p --permission-mode auto --model sonnet \
       "Run /gsd:discuss-phase $PHASE --auto" \
       || { echo "Discuss failed for phase $PHASE"; exit 1; }
   fi

   # Step B: Plan (if no plans yet)
   PHASE_STATE=$(node "$HOME/.claude/get-shit-done/bin/gsd-tools.cjs" init phase-op "$PHASE" 2>/dev/null || echo "{}")
   HAS_PLANS=$(echo "$PHASE_STATE" | jq -r '.has_plans // false')
   if [ "$HAS_PLANS" != "true" ]; then
     echo "Running plan for phase $PHASE..."
     claude -p --permission-mode auto --model opus \
       "Run /gsd:plan-phase $PHASE" \
       || { echo "Plan failed for phase $PHASE"; exit 1; }
   fi

   # Step C: Execute
   echo "Running execute for phase $PHASE..."
   claude -p --permission-mode auto --model sonnet \
     "Run /gsd:execute-phase $PHASE --no-transition" \
     || { echo "Execute failed for phase $PHASE"; exit 1; }

   # Commit any uncommitted changes from this phase
   git add -A .planning/
   git diff --cached --quiet || git commit -m "docs($PHASE): autonomous execution artifacts"
   git push origin HEAD

   echo "::endgroup::"
   ```

   The `exit 1` inside the loop will trigger the failure handler.

8. **Failure handler** — Use an `if: failure()` step at the end of the job. Per D-05 and D-06:
   ```yaml
   - name: Create failure issue
     if: failure()
     run: |
       PHASE="${{ env.FAILED_PHASE || 'unknown' }}"
       gh issue create \
         --title "GSD Roadmap: Phase $PHASE failed" \
         --body "$(cat <<'ISSUE_EOF'
   ## Phase Failure

   **Milestone:** ${{ inputs.milestone }}
   **Phase:** $PHASE
   **Run:** ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}

   Check the workflow logs for details.
   ISSUE_EOF
   )"
     env:
       GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
   ```

   To capture which phase failed, set `FAILED_PHASE` env var before each phase execution in the loop:
   ```bash
   echo "FAILED_PHASE=$PHASE" >> $GITHUB_ENV
   ```

**Important implementation details:**
- Use `--bare` flag on claude CLI to skip hooks/LSP/MCP that won't be available on the runner. The full flag set per phase: `claude -p --permission-mode auto --bare --model <model>`
- The `--print` (`-p`) flag makes claude non-interactive and exit after completion
- Each `claude` call gets a fresh context window (per D-02) because `-p` mode creates a new session each time
- The workflow pushes commits after each phase so progress is saved even if a later phase fails
- Use `--max-budget-usd 5` as a safety cap per claude invocation to prevent runaway costs (Claude's discretion)
