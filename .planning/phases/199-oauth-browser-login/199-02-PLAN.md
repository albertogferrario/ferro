<objective>
Implement OAuth discovery metadata (RFC 8414 / RFC 9728) and Dynamic Client Registration
(RFC 7591) — the AMCP-07 surface. Two GET discovery handlers serve spec-compliant JSON derived
from `OAuthConfig.app_url`; `POST /register` validates `redirect_uris` (scheme allowlist),
persists a UUIDv4-keyed client to `oauth_clients`, and returns the `client_id`.

Purpose: SC-1 (discovery docs advertise authorization-code + PKCE S256) and SC-2 (DCR returns a
client_id). This is the entry point an MCP client hits before any browser flow.
Output: discovery.rs + register.rs handler bodies + store.rs OAuthClient model.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → /register | untrusted JSON (redirect_uris, client_name) crosses into DB persistence |
| MCP client → /.well-known/* | public unauthenticated reads; must not leak config-secret presence |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-199-05 | Tampering (T) | register.rs redirect_uri scheme | mitigate (HIGH) | Scheme allowlist at DCR: accept only `http://localhost*` or `https://*`; reject `javascript:`/`data:`/custom → 400 (Task 2). |
| T-199-DCR | Spoofing (S) | register.rs client_id generation | mitigate (LOW) | `client_id` = UUIDv4 or 16-byte URL-safe base64 (high entropy), never a sequential integer → no enumeration (Task 2). |
| T-199-04a | Tampering (T) | register.rs redirect_uris storage | mitigate (HIGH) | Store the exact registered `redirect_uris`; Plan 04 /authorize + /token exact-string-match against this stored list (no prefix match). store.rs persists verbatim (Task 2). |
| T-199-DISC | Information disclosure (I) | discovery.rs | accept (LOW) | Discovery docs are public by RFC design; they expose only endpoint URLs derived from APP_URL, no secret. Discovery does not require MCP_TOKEN_SECRET (reads app_url only) so it cannot leak secret-presence (Task 1). |
</threat_model>
