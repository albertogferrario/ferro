<objective>
Implement the browser authorization-code + PKCE flow (AMCP-08): `GET /authorize` reuses the
app's existing session login and renders a server-rendered consent page; `POST /authorize`
validates CSRF and mints a single-use auth code into `ferro::Cache`; `POST /token` redeems the
code (forget-before-validate), verifies PKCE S256, and mints the `(user, tenant)`-bound JWT.
The end-to-end integration test proves the whole chain in-process with the app as its own IdP.

Purpose: SC-3 (login redirect → consent → code) and SC-4 (code → audience-bound token), and the
mandatory full PKCE integration test (RESEARCH §9). This plan owns the consent CSRF, open-redirect,
PKCE-downgrade, and code-replay threats.
Output: authorize.rs + consent.rs + token.rs bodies + the full flow_integration.rs e2e test.
</objective>

**consent.rs `authorize_post` `#[handler]`** (RESEARCH §2 lines 290-309):
1. `req.form::<ConsentForm>()` (urlencoded; fields: `_token`, `action`, `client_id`,
   `redirect_uri`, `code_challenge`, `code_challenge_method`, `state`, `response_type`).
2. **CSRF (T-10/T-12, MEDIUM):** `let session_csrf = get_csrf_token().ok_or(400)?;`
   constant-time compare `form._token.as_bytes().ct_eq(session_csrf.as_bytes())` — mismatch → 400.
3. **Deny path:** if `action == "deny"` → `302` to `{redirect_uri}?error=access_denied&state={state}`.
4. **Approve path:** re-validate client_id + redirect_uri exact-match (T-16). Re-confirm
   `code_challenge_method == "S256"`. Capture `user_id = Auth::id()`, `tenant_id = current_tenant().map(|t| t.id)`.
5. `let code = pkce::generate_auth_code();` build `OAuthCode { client_id, redirect_uri,
   code_challenge, user_id, tenant_id, created_at: now }` and
   `Cache::put(&format!("mcp:code:{code}"), &record, Some(Duration::from_secs(60))).await`.
6. `302` redirect to `{redirect_uri}?code={code}&state={state}`.

**token.rs `token_exchange` `#[handler]`** (RESEARCH §2 lines 310-346):
1. `req.form::<TokenRequest>()` (urlencoded: `grant_type`, `code`, `redirect_uri`, `client_id`,
   `code_verifier`).
2. `grant_type != "authorization_code"` → `400 {"error":"unsupported_grant_type"}`.
3. **Single-use (T-02, HIGH):** retrieve then forget BEFORE any validation:
```rust
let record: Option<OAuthCode> = Cache::get(&format!("mcp:code:{code}")).await.ok().flatten();
Cache::forget(&format!("mcp:code:{code}")).await.ok();
let record = record.ok_or(/* 400 invalid_grant */)?;
```
   So a replay or any-failure path cannot reuse the code.
4. Validate `record.client_id == client_id` (else `invalid_client`), `record.redirect_uri ==
   redirect_uri` exact-match (else `invalid_grant`, T-16).
5. **PKCE verify (T-01):** `pkce::verify_s256(&code_verifier, &record.code_challenge)` — false →
   `400 {"error":"invalid_grant"}`.
6. Mint: `let claims = jwt::build_claims(record.user_id, record.tenant_id, &config.app_url, 3600);`
   `let token = jwt::mint_token(&claims, &config.token_secret)?;`
7. Return `200 {"access_token": token, "token_type": "Bearer", "expires_in": 3600}` (RFC 6749 §5.1;
   no refresh_token, no scope).
All error bodies follow RFC 6749 §5.2 (`{"error":..,"error_description":..}`, status 400).
`OAuthConfig::from_env()` provides app_url + token_secret in token_exchange (fail-closed → 500 if unset).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /authorize | untrusted query params (client_id, redirect_uri, code_challenge) |
| browser → POST /authorize | consent form submission (CSRF surface) |
| MCP client → /token | code + code_verifier exchange (replay + PKCE surface) |
| /authorize → ferro::Cache | server-minted single-use code crosses into the TTL store |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-199-01 | Spoofing (S) | authorize.rs + consent.rs | mitigate (HIGH) | Reject `code_challenge_method != "S256"` and absent `code_challenge` at GET /authorize (error page) and re-confirm at POST /authorize (Task 1,2). |
| T-199-02 | Repudiation (R) | token.rs | mitigate (HIGH) | `Cache::forget("mcp:code:{code}")` called BEFORE any validation on first retrieval; absent code → invalid_grant. Single-use even on failure (Task 2). |
| T-199-03 | Elevation (E) | consent.rs Cache::put | mitigate (MEDIUM) | 60s TTL on the auth code via `Some(Duration::from_secs(60))`; `created_at` recorded for audit (Task 2). |
| T-199-04 | Tampering (T) | authorize.rs + token.rs redirect_uri | mitigate (HIGH) | Exact-string match of `redirect_uri` against the registered client's list at /authorize AND /token; mismatch at /authorize → error PAGE (never redirect to unvalidated URI) (Tasks 1,2). |
| T-199-10 | Spoofing (S) | consent.rs authorize_post | mitigate (MEDIUM) | `_token` hidden field validated against session `get_csrf_token()` via constant-time `ct_eq` before processing approve/deny (Task 2). |
| T-199-12 | Information disclosure (I) | consent.rs CSRF compare | mitigate (MEDIUM) | Same `subtle::ConstantTimeEq` for the CSRF compare — no timing oracle (Task 2). |
| T-199-16 | Tampering (T) | token.rs | mitigate (HIGH) | Code record carries client_id + redirect_uri; both re-validated at exchange against the request, preventing code substitution/injection (Task 2). |
| T-199-XSS | Tampering (T) | consent.rs render | mitigate (MEDIUM) | HTML-escape `client_name` (attacker-controlled at DCR) before embedding in the consent page (Task 1). |
</threat_model>
