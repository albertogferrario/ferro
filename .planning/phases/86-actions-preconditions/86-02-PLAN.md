**ServiceDef struct changes (service.rs):**
Add two new fields to ServiceDef:
- `actions: Vec<ActionDef>` — `#[serde(default, skip_serializing_if = "Vec::is_empty")]`
- `guards: Vec<GuardDef>` — `#[serde(default, skip_serializing_if = "Vec::is_empty")]`

Initialize both to `Vec::new()` in `ServiceDef::new()`.

**ServiceDef builder methods:**
- `action(mut self, action: ActionDef) -> Self` — pushes to actions vec
- `guard(mut self, guard: GuardDef) -> Self` — pushes to guards vec

Import ActionDef, GuardDef from `crate::action`.

**Warning enum extension (state.rs):**
Add two new variants to the existing Warning enum:
- `UnusedGuard(String)` — guard declared but never referenced by any transition or action precondition
- `TransitionTriggerWithoutStateMachine(String)` — action has transition_trigger but service has no state machine

**ServiceDef::validate() method (service.rs):**
New method: `pub fn validate(&self) -> Result<Vec<Warning>, crate::Error>`

Validation logic (in order):
1. If state machine exists, delegate to `state_machine.validate()` and collect its warnings
2. Collect all guard names from `self.guards` into a HashSet
3. Check action preconditions reference declared guards — return Err if undefined
4. Check transition guards reference declared guards (if state machine exists) — return Err if undefined
5. Check action transition_triggers match state machine event names (if state machine exists) — return Err if undefined
6. Warn about declared guards never referenced by any transition guard or action precondition
7. Warn about actions with transition_trigger when no state machine exists

Import `std::collections::HashSet` in service.rs.

**Key design:** ServiceDef::validate() is the single validation entry point that subsumes StateMachine::validate(). Guard names are a shared pool referenced from two places: Transition.guard (Phase 85) and ActionDef.preconditions (Phase 86).
