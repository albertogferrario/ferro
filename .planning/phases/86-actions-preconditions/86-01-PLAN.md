Create `ferro-projections/src/action.rs` with three types following existing crate conventions:

**ActionDef** — business operation schema:
- Fields: name (String), display_name (Option<String>), description (Option<String>), inputs (Vec<InputDef>), preconditions (Vec<String>), effects (Vec<String>), transition_trigger (Option<String>)
- Derive: Debug, Clone, Serialize, Deserialize, PartialEq, Eq, JsonSchema
- Serde: skip_serializing_if for Option fields, skip_serializing_if Vec::is_empty for Vec fields, default for Vec fields
- Builder: consuming pattern (mut self -> Self) — new(), display_name(), description(), input(), precondition(), effect(), transition_trigger()

**InputDef** — action parameter:
- Fields: name (String), data_type (DataType), meaning (FieldMeaning), required (bool, default true via serde), description (Option<String>)
- Derive: Debug, Clone, Serialize, Deserialize, PartialEq, Eq, JsonSchema
- Builder: new(name, data_type, meaning), required(bool), description()
- Reuses DataType and FieldMeaning from field.rs — do NOT create parallel type systems

**GuardDef** — named boolean condition:
- Fields: name (String), display_name (Option<String>), description (Option<String>)
- Derive: Debug, Clone, Serialize, Deserialize, PartialEq, Eq, JsonSchema
- Builder: new(name), display_name(), description()

Update `lib.rs` to add `mod action;` and re-export: ActionDef, InputDef, GuardDef.

All builder methods use `impl Into<String>` for string parameters, matching existing crate pattern.
No runtime logic — these are schema-only definitions.

  <action>
**FieldDef changes (field.rs):**
Add two boolean fields to FieldDef struct:
- `readable: bool` — default true via `#[serde(default = "default_true")]`
- `writable: bool` — default true via `#[serde(default = "default_true")]`

The `default_true()` helper already exists in field.rs. Both fields default to true (read-write) for backward compatibility — existing JSON without these fields deserializes correctly.

**ServiceDef convenience builders (service.rs):**
Add two new builder methods on ServiceDef:

`read_only_field(name, data_type, meaning)` — creates FieldDef with readable=true, writable=false, required=true, is_list=false. For system-assigned/computed fields (id, created_at, total).

`write_only_field(name, data_type, meaning)` — creates FieldDef with readable=false, writable=true, required=true, is_list=false. For sensitive inputs (password, api_key).

Existing `field()`, `optional_field()`, `list_field()` methods remain unchanged — they default to readable=true, writable=true.

Do NOT break existing serde compatibility — the `default_true` serde defaults ensure all existing Phase 84/85 JSON deserializes to read-write fields.
  </action>
