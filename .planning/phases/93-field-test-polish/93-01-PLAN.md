Create 5 hand-crafted projections designed to derive specific intents. Each must follow the builder chain pattern parseable by the MCP regex scanner. Use `ferro::{ServiceDef, DataType, FieldMeaning, ...}` imports.

**order.rs — Target: Process**
ServiceDef for an order fulfillment workflow with:
- Fields: id (Integer/Identifier), customer_name (String/EntityName), total (Float/Money), status (String/Status), created_at (DateTime/CreatedAt)
- State machine: "order_lifecycle" with states: draft, submitted, approved, shipped, delivered (final), cancelled (final). Initial: draft.
- Transitions: draft→submit→submitted, submitted→approve→approved (guard "is_manager"), submitted→reject→cancelled, approved→ship→shipped, shipped→deliver→delivered, draft→cancel→cancelled
- Guards: GuardDef::new("is_manager").display_name("Manager Approval Required")
- Actions: submit (transition_trigger "submit"), approve (transition_trigger "approve", precondition "is_manager"), ship (transition_trigger "ship")
- Relationships: belongs_to("customer", "user"), has_many("line_items", "line_item")
Process signals: guarded transitions, branching states, transition triggers on actions.

**product.rs — Target: Browse**
ServiceDef for a product catalog with:
- Fields: id (Integer/Identifier), name (String/EntityName), price (Float/Money), category (String/Category), image_url (String/ImageUrl), created_at (DateTime/CreatedAt)
- Relationships: has_many("reviews", "review"), has_many("variants", "product_variant"), belongs_to("brand", "brand")
- No state machine, no complex actions.
Browse signals: EntityName + Category + OneToMany relationships.

**revenue_dashboard.rs — Target: Summarize**
ServiceDef for a read-only financial dashboard with:
- Fields: id (Integer/Identifier), total_revenue (Float/Money, read_only_field), profit_margin (Float/Percentage, read_only_field), order_count (Integer/Quantity, read_only_field), avg_order_value (Float/Money, read_only_field), return_rate (Float/Percentage, read_only_field)
- No relationships, no state machine, no actions.
- All domain fields are read_only_field — critical for Summarize signal.
Summarize signals: >70% non-writable + Money/Percentage/Quantity meanings.

**sales_analytics.rs — Target: Analyze**
ServiceDef for time-series sales data with:
- Fields: id (Integer/Identifier), sale_date (DateTime/DateTime, read_only_field), amount (Float/Money, read_only_field), units_sold (Integer/Quantity, read_only_field), discount_applied (Float/Percentage, read_only_field), region (String/Category, read_only_field)
- Use read_only_field for all domain fields.
- DO NOT use CreatedAt/UpdatedAt (system fields excluded from analysis). Use DateTime meaning for temporal fields.
Analyze signals: DateTime + numeric field co-occurrence, read-only.

**feedback_form.rs — Target: Collect**
ServiceDef for a data collection form with:
- Fields: id (Integer/Identifier), subject (String/EntityName), rating (Integer/Custom("rating")), comment (String/Custom("answer"), write_only_field), contact_email (String/Email, write_only_field), category (String/Category)
- Use write_only_field for submission-only fields. Use Custom("answer")/Custom("rating") instead of FreeText to avoid amplifying Focus.
- Actions: ActionDef::new("submit_feedback") with 3+ inputs (InputDef::new for subject, rating, comment)
Collect signals: >50% writable, write_only fields, action with multiple inputs.
