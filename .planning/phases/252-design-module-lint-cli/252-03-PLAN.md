// types.rs
pub struct DesignRule { pub id: &'static str, pub title: &'static str,
    pub rationale: &'static str, pub intents: &'static [&'static str],
    pub check: fn(&Spec, Option<&str>) -> Vec<Finding> }
pub struct Finding { pub rule: &'static str, pub element_id: Option<String>,
    pub severity: Severity, pub message: String, pub suggestion: String }
pub enum Severity { Info, Warning }
// rules.rs (currently): pub(super) static RULE_REGISTRY: &[DesignRule] = &[];
```
`lint()` runs `rule.check(spec, resolved_intent)` only when `rule.intents` is empty
(all intents) or contains the resolved intent, then suppresses findings whose `rule`
is in `spec.design.allow`. Rules must be defensive: `el.props.get(k)` / `.and_then()`,
never `.unwrap()`.

Spec/Element shape (ferro-json-ui/src/spec.rs): `spec.layout: Option<String>`,
`spec.elements: IndexMap<String, Element>` (iterate `.values()` / `.iter()`),
`Element { type_name: String, props: Value, children: Vec<String>, action: Option<Action> }`.
Element `type_name` is the JSON `"type"` key.

DesignRule {
    id: "page-header",
    title: "Dashboard pages start with a PageHeader",
    rationale: "A PageHeader gives every app page a consistent title, breadcrumb, and action-button slot.",
    intents: &[],                       // all intents; the layout gate is inside check
    check: check_page_header,
},
DesignRule {
    id: "prefer-data-table",
    title: "Prefer DataTable over raw Table",
    rationale: "DataTable adds responsive mobile cards and DropdownMenu row actions the raw Table lacks.",
    intents: &["browse"],
    check: check_prefer_data_table,
},
DesignRule {
    id: "list-empty-state",
    title: "List pages define an empty state",
    rationale: "An empty state with a create CTA turns a blank list into a first-run affordance.",
    intents: &["browse"],
    check: check_list_empty_state,
},
```

Check logic:
- `check_page_header`: `if !is_app_shell_layout(spec) { return vec![] }`. Find any element with `type_name == "PageHeader"`. If none → Warning `{ rule: "page-header", element_id: None, severity: Warning, message: "Dashboard-family layout has no PageHeader element.", suggestion: "Add a PageHeader element (with a `title` prop) as the first child of root." }`. If a PageHeader exists but its `props.get("title")` is `None`/`Value::Null` → Warning `{ ..., element_id: Some(id), message: "PageHeader is missing a title.", suggestion: "Set the PageHeader `title` prop." }`. Otherwise `vec![]`.
- `check_prefer_data_table`: for each `(id, el)` where `el.type_name == "Table"`, push Warning `{ rule: "prefer-data-table", element_id: Some(id.clone()), severity: Warning, message: "Raw Table used for an entity list.", suggestion: "Replace with a DataTable (responsive mobile cards, DropdownMenu row actions)." }`.
- `check_list_empty_state`: `let has_empty_state = spec.elements.values().any(|e| e.type_name == "EmptyState");` then for each `(id, el)` where `el.type_name == "DataTable"` (also `"MediaCardGrid"`): if `el.props.get("empty_message").and_then(Value::as_str).is_none()` AND `!has_empty_state` → Warning `{ rule: "list-empty-state", element_id: Some(id.clone()), severity: Warning, message: "List component has no empty-state config.", suggestion: "Add an `empty_message` to the DataTable or include an EmptyState element with a create CTA." }`.

    id: "row-actions-grouped",
    title: "Group row/card actions in an ActionGroup",
    rationale: "Loose inline buttons per row are inconsistent and crowd small screens; an ActionGroup/DropdownMenu keeps them tidy.",
    intents: &["browse", "process"],
    check: check_row_actions_grouped,
},
DesignRule {
    id: "breadcrumb-on-subpages",
    title: "Create/edit/detail pages carry a Breadcrumb",

Check logic:
- `check_row_actions_grouped`: for each `(id, el)`, count children whose resolved element `type_name == "Button"`: `let btn = el.children.iter().filter(|c| spec.elements.get(*c).map(|e| e.type_name == "Button").unwrap_or(false)).count();` if `btn >= 2` → Warning `{ rule: "row-actions-grouped", element_id: Some(id.clone()), severity: Warning, message: format!("Element `{id}` has {btn} loose Button children."), suggestion: "Group these row/card actions in an ActionGroup (DropdownMenu) instead of loose inline Buttons." }`.

If neither → 1 Warning `{ rule: "breadcrumb-on-subpages", element_id: None, severity: Warning, message: "App-shell subpage has no Breadcrumb.", suggestion: "Add a Breadcrumb (or a PageHeader with a non-empty `breadcrumb`) linking back to the list page." }`.

Add the violating + conforming tests from the behavior block (row-actions: 2 cases; breadcrumb: 4 cases incl. the auth-exempt path). The auth-exempt breadcrumb case is a regression guard for the Plan 05 app-views gate.
