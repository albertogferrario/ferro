<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent/caller → tools/call (dispatch_write) | An agent may skip tools/list and call tools/call directly; guards must be re-evaluated live |
| override hook → audited write envelope | An override runs post-persist inside the audited window; it must not be able to suppress the base guard/transition |
| app executor → transition target | The to-state must come only from declared `Transition.to`, never a re-introduced hand-written map |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-231-04 | Elevation of Privilege | dispatch_write guard loop (transition guard) | mitigate | Transition.guard is added to the LIVE guard set and re-evaluated at execution via the existing GuardEvaluatorFn; ctx.evaluated_guards is never read (Task 1) |
| T-231-05 | Elevation of Privilege | override hook timing | mitigate | Override runs AFTER the guarded base persist, inside the same audited envelope (Task 2); it cannot bypass the base guard or transition |
| T-231-06 | Tampering | app executor to_state source | mitigate | new_status is sourced only from derive_transition_plan().to_state; the hand-written match is deleted and grep-asserted absent (Task 3) |
| T-231-07 | Information Disclosure | cross-tenant write via derived path | accept | Tenant scoping stays in the executor's find_for_tenant/Column::TenantId.eq predicate (mcp.rs:84-95), unchanged; the plan is tenant-agnostic data |
</threat_model>
