The WR-03 conversion is applied symmetrically at both `handle()` and `handle_with_value()`, producing `::ferro::queue::Error::job_failed` on a missing service registration, with no residual `.expect()` at those sites.

One warning is raised: the error message emitted by the WR-01 guard names `&Ref<'a>` as a rejected form, but the guard (`matches!(other, Type::Reference(_))`) only fires when the inner element is itself a `syn::Type::Reference` — which is the `&&T` case. A parameter typed `&Ref<'a, T>` (a shared reference to a named wrapper type) has `r.elem = Type::Path`, so it silently passes the guard and emits the inner `Type::Path` token as the owned field type. No data-corruption outcome results because such a field type will fail the `OffloadSerializable` bound at the use site, but the user receives a serde/bound error rather than the clear spanned message the error text promises.

## Warnings

### WR-01: `owned_type` guard rejects `&&T` but not the `&Ref<'a>` case named in its error message

**File:** `ferro-macros/src/offload.rs:97-104`

**Issue:** The guard `matches!(other, Type::Reference(_))` fires only when the inner `r.elem` is `syn::Type::Reference` — that is, the `&&T` (double-reference) case. A parameter typed `&Ref<'a, T>` where `Ref<'a, T>` is a named generic struct has `r.elem = Type::Path`, so it passes the guard and falls through to `Ok(quote! { #other })`, emitting the inner path as an owned field type. The error message names both `&&T` and `&Ref<'a>` as rejected, creating a false promise: users who write `&std::cell::Ref<'a, Val>` receive a serde/`OffloadSerializable`-bound error from a different location rather than the intended spanned diagnostic here.

**Fix:** Widen the guard to cover the `Type::Path` inner-element case, or tighten the error message to name only the case the guard actually handles (`&&T`). The minimal-change option:

```rust
other => {
    // Reject &&T (inner is a reference) and plain &T falling through this arm
    // (which would silently emit a non-owned type).
    // Note: &str and &[T] are handled by the arms above.
    if matches!(other, Type::Reference(_)) {
        return Err(syn::Error::new_spanned(
            ty,
            "#[offload] parameters must be fully owned — \
             double references (&&T) are not supported as job payload fields",
        ));
    }
    Ok(quote! { #other })
}
```

The scoped message is accurate. If explicit rejection of `&Ref<'a, T>` with a better diagnostic is also desired, it requires a separate arm that checks whether the inner `Type::Path` resolves to a reference-holding wrapper — which is not resolvable at `syn` parse time without name resolution. Tightening the message is the correct move now; explicit `&Ref<'a>` rejection can be a follow-up if a concrete case surfaces.
