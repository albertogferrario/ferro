### `ferro-macros/tests/ui/offload/pass/offload_handle.rs` (extend, 245-WR-01)

```rust
//! Compile-pass: .offload() on a derived Job returns OffloadHandle<Output> (OFFLOAD-02a).
#![allow(unused_imports, dead_code)]

extern crate ferro_rs as ferro;
extern crate serde;

use ferro::queue::{OffloadHandle, Offloadable};
use ferro::{async_trait, service};
use serde::{Deserialize, Serialize};

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Report {
    pub total: i64,
}

#[derive(Default)]
pub struct Reports;

#[service(Reports)]
#[async_trait]
pub trait ReportsService {
    #[offload]
    async fn build_monthly(&self, tenant_id: i64) -> Report;
}

#[async_trait]
impl ReportsService for Reports {
    async fn build_monthly(&self, _tenant_id: i64) -> Report {
        Report { total: 0 }
    }
}

fn main() {
    // Structural proof: the derived Job implements Offloadable with Output = Report,
    // so `.offload()` returns OffloadHandle<Report>. Verified at compile time —
    // no runtime dispatch (no App/DB needed).
    fn assert_output_is_report<J: Offloadable<Output = Report>>() {}
    assert_output_is_report::<ReportsServiceBuildMonthlyJob>();

    // And the handle type is what .offload() yields:
    fn _handle_ty(h: OffloadHandle<Report>) -> OffloadHandle<Report> {
        h
    }
}
```

### SC#2 double-registration test (new runtime test, WR-02)

**Analog:** `ferro-queue/tests/offload_round_trip.rs` — Test C (lines 94-129)

**Harness setup pattern** (from existing Test C):
```rust
use ferro_queue::{async_trait, dispatch, Error, Job, JobRegistrarEntry, WorkerConfig, WorkerLoop};
use serde::{Deserialize, Serialize};

inventory::submit! {
    JobRegistrarEntry {
        register: |w: &mut WorkerLoop| { w.register::<InventoryJob>(); },
        name: "InventoryJob",
        queue: None,
    }
}

#[tokio::test]
#[serial_test::serial]
async fn offload_job_auto_registers_via_inventory() {
    let worker = WorkerLoop::from_registry(WorkerConfig::default());
    assert!(
        worker.registered_job_count() >= 1,
        "InventoryJob must be auto-registered by from_registry via the inventory path"
    );
}
```

**Key accessor** — `WorkerLoop::registered_job_count()` is at `ferro-queue/src/worker.rs:232-234`, marked `#[doc(hidden)]`, already public. No new accessor needed.

**New test shape** (can be appended to `offload_round_trip.rs` or placed in a new `registration_idempotency.rs`):
```rust
#[tokio::test]
#[serial_test::serial]
async fn double_from_registry_does_not_double_register() {
    // InventoryJob is already submitted to inventory (Test C in this file).
    // Two WorkerLoop instances each start with a fresh HashMap; HashMap::insert
    // is per-key idempotent so re-running the same registrar overwrites with an
    // identical handler, leaving count unchanged.
    let w1 = WorkerLoop::from_registry(WorkerConfig::default());
    let count1 = w1.registered_job_count();

    let w2 = WorkerLoop::from_registry(WorkerConfig::default());
    let count2 = w2.registered_job_count();

    assert_eq!(
        count1, count2,
        "second from_registry must not double-register: expected {count1}, got {count2}"
    );
    assert!(count1 >= 1, "at least InventoryJob must be registered");
}
```

**Placement decision:** appending to `offload_round_trip.rs` is simplest (same `InventoryJob` submission is already there; no duplicate `inventory::submit!` needed). A separate `registration_idempotency.rs` is acceptable but requires re-declaring `InventoryJob` and its `inventory::submit!` — prefer the append.

### SC#3 missing-binding Err test (new runtime test, WR-03)

**Dependency constraint — verified from `ferro-queue/Cargo.toml`:**

`ferro-queue` dev-dependencies are:
```toml
[dev-dependencies]
tokio = { version = "1", features = ["full", "test-util"] }
serial_test = "3"
tempfile = "3"
```

`framework` (the crate that provides `ferro::App`) is **absent** from `ferro-queue` dev-dependencies. Adding it is likely circular (queue is a dependency of framework). Therefore: **the SC#3 behavioral runtime test must live in `framework/tests/` rather than `ferro-queue/tests/`.**

**Analog in `ferro-queue/tests/offload_round_trip.rs`** — Test B (lines 59-91) shows the existing pattern for asserting dispatch `Err`:
```rust
#[tokio::test]
#[serial_test::serial]
async fn offload_result_err_maps_to_job_failure() {
    std::env::set_var("QUEUE_CONNECTION", "sync");
    let res = dispatch(FailingJob).await;
    assert!(
        res.is_err(),
        "Err(e) from handle() must surface as a dispatch failure in sync mode"
    );
    assert!(
        format!("{}", res.unwrap_err()).contains("boom"),
        "Error message must contain the original failure reason"
    );
}
```

**Difference for SC#3:** instead of a `FailingJob` whose `handle()` explicitly returns `Err`, the fixture dispatches a derived `#[offload]` job with no concrete service registered in `ferro::App` — so `App::make` returns `None`, the `.ok_or_else(...)` fires, and `handle()` returns `Err` rather than panicking.

**Location decision:** check whether `framework/tests/` already has an offload integration test file. If not, create one. The `#[offload]` macro is reachable from `framework` (framework re-exports `ferro-macros`). The test needs `ferro::App::singleton` to be callable from the test body.

**Simpler acceptable alternative:** if the planner judges a full behavioral test adds disproportionate setup cost relative to the property being asserted (a `?` operator cannot panic), a unit-level confirmation is acceptable: add a short `// SC#3: the ? operator guarantees Err, not panic` comment at both fix sites in `ferro-macros/src/offload.rs` and verify the property by inspection + the CI gate. The trybuild pass fixture already exercises the generated code path with a bound service (Test A of `offload_round_trip.rs`).

## Shared Patterns

### Trybuild compile-fail fixture structure

**Source:** `ferro-macros/tests/ui/offload/fail/mut_ref_param.rs` + `mut_ref_param.stderr`
**Apply to:** `double_ref_param.rs` + `double_ref_param.stderr` (new, WR-01)

Invariants that all fail fixtures observe:
- `extern crate ferro_rs as ferro;` — the published crate name alias
- `extern crate serde;` — if serde types appear in the fixture
- No concrete `impl` of the service trait needed (compilation fails earlier)
- `fn main() {}` as the entry point (required by trybuild crate format)
- `#![allow(unused_imports, dead_code)]` — suppresses noise unrelated to the tested error
- `.stderr` is generated by `TRYBUILD=overwrite`, never hand-written

### Trybuild compile-pass fixture structure

**Source:** `ferro-macros/tests/ui/offload/pass/offload_handle.rs`
**Apply to:** the `SerdeOnly` extension of the same file (245-WR-01)

Invariants:
- Structural proof lives inside `fn main()` as inner functions (no `#[tokio::test]`, no `App`)
- `fn assert_*<J: Trait>()` pattern for compile-time trait-bound verification
- No database, no `App::singleton`, no environment variables

### Runtime test harness for ferro-queue

**Source:** `ferro-queue/tests/offload_round_trip.rs`
**Apply to:** SC#2 double-registration test

Invariants:
- `#[tokio::test]` + `#[serial_test::serial]` on every async test (env mutation)
- `std::env::set_var("QUEUE_CONNECTION", "sync")` at the top of any sync-mode test
- `WorkerLoop::from_registry(WorkerConfig::default())` — the standard loop construction
- `worker.registered_job_count()` — the existing `#[doc(hidden)]` accessor; no new accessor needed
- `inventory::submit!` is static and cumulative per binary — do not re-submit the same job type in a sibling test file if the round_trip tests already submit it

### `::ferro::*` path convention (macro emission)

**Source:** `ferro-macros/src/offload.rs` throughout
**Apply to:** both `.expect(...)` replacement sites (WR-03)

All generated code uses fully-qualified `::ferro::*` paths (e.g. `::ferro::App::make`, `::ferro::queue::Error::job_failed`). Do not use bare `App::make` or import-relative paths. This is enforced by D-14 and the macro gate blindspot note.
