## What Was Built

### Task 1 — 245-WR-01 (SC#4, code side)

`OffloadHandle<T>`'s `#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]` was
injecting `T: Clone + Debug + PartialEq + Eq` bounds beyond the `OffloadSerializable` contract
(`Serialize + DeserializeOwned`). These bounds silently rejected result types that satisfy the
serializable contract but do not derive the standard trait set.

The fix removes `Debug, Clone, PartialEq, Eq` from the `#[derive(...)]`, keeping only
`#[derive(Serialize, Deserialize)]`, and adds four hand-written impls that bound nothing on `T`:

- `impl<T> Clone for OffloadHandle<T>` — reconstructs `_phantom` as `PhantomData`, delegates `key`
- `impl<T> std::fmt::Debug for OffloadHandle<T>` — prints only `key` via `debug_struct`
- `impl<T> PartialEq for OffloadHandle<T>` — delegates `self.key == other.key`
- `impl<T> Eq for OffloadHandle<T>` — marker, no body needed

`PhantomData<fn() -> T>` is unconditionally `Clone/Debug/PartialEq/Eq` in std for any `T`; it
is never touched in the impl bodies. The phantom variant is left exactly as-is (Pitfall 2 avoided).

The SC#4 compile-PASS trybuild fixture (`ferro-macros/tests/ui/offload/pass/offload_handle.rs`
extended with a `SerdeOnly` type) is deferred to Plan 03, which runs after these impls are in place.

### Task 2a — WR-02 (SC#2)

The invariant "two successive `WorkerLoop::from_registry` calls register each job exactly once"
was already satisfied by construction:

- Each `from_registry` allocates a fresh `WorkerLoop` with a fresh `HashMap`.
- `HashMap::insert` is per-key idempotent — inserting the same key twice overwrites with an
  identical handler, leaving `handlers.len()` unchanged.
- The inventory path re-iterates a static collection that cannot be drained; the runtime Vec path
  (`apply_registrars`) is equally re-applied, but the resulting count is stable because the map is fresh.

`db.rs` is untouched. The destructive `registrars.clear()` suggested in the 244 review was
explicitly rejected (D-05): it would empty the Vec that `has_registered_jobs()` and
`registered_queue_names()` read, permanently destroying those signals on any second call.

The fix is the missing test: `double_from_registry_does_not_double_register` in
`ferro-queue/tests/offload_round_trip.rs` calls `from_registry` twice, asserts
`registered_job_count()` equality across both instances, and asserts `count1 >= 1`. It reuses
`InventoryJob` (already submitted to the process-global inventory by Test C) and carries
`#[serial_test::serial]` to serialize against the other env-mutating tests. The test passes
with no source change.
