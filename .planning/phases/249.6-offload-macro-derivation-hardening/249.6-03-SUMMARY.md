## SC#3 Decision: Code-Property Only, No Runtime Test

The `?` operator on a `Result` provably cannot panic on the `Err` path — it is a compile-time guarantee. A behavioral runtime test in `ferro-queue/tests/` is not feasible: `framework` (the crate providing `ferro::App`) is absent from `ferro-queue`'s dev-dependencies, and adding it would be circular. RESEARCH (§WR-03 SC#3 semantic clarification) designates the `?` property as the primary acceptance criterion. No new runtime test is added; the existing `offload_round_trip.rs` Test A exercises the generated `handle()` path with a registered service (green path), and SC#3 is the negative-path guarantee by construction.

Grep evidence:
- `grep -c ".expect(" ferro-macros/src/offload.rs` → `0`
- `grep -c "ok_or_else" ferro-macros/src/offload.rs` → `2` (lines 394, 411)
