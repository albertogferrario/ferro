<objective>
Wave 0: refactor `ferro-ai`'s feature surface so its `confirmation` module can be consumed without dragging `reqwest`/`reqwest-eventsource` into `ferro-mcp-server` (D-06, the central decision), audit every other `ferro-ai` consumer so the workspace still builds, add the `confirmation` Cargo feature + `ConfirmationRequired` error variant to `ferro-mcp-server`, and write the RED confirmation tests so they compile under `--features confirmation`.

Purpose: This is the load-bearing dependency-hygiene work. Until `ferro-ai` is feature-split and every consumer re-verified, no confirmation code in `ferro-mcp-server` can compile without an HTTP client in the default graph — which violates the toolchain-only build rule. The RED tests lock the SC contracts before implementation (Nyquist Wave 0).

Output: A feature-split `ferro-ai` (default `llm`, plus reqwest-free `confirmation`), a `ferro-mcp-server` that can opt into `ferro-ai` behind a `confirmation` feature with no HTTP client, the `ConfirmationRequired` error variant, and compiling-but-failing tests for SC#1-#4 + guard-at-confirm.
