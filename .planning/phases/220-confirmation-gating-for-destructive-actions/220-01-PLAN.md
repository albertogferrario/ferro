#[cfg(feature = "confirmation")]
fn generate_confirmation_token() -> String {
    use rand::Rng;
    const BASE62: &[u8] = b"0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz";
    let mut rng = rand::thread_rng();
    let random: String = (0..43).map(|_| BASE62[rng.gen_range(0..62usize)] as char).collect();

}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent → MCP `tools/call` | Untrusted tool name + arguments; the confirmation gate decides whether a destructive write executes. |
| agent-supplied token → store | The agent cannot forge a valid token; only `store.confirm()` existence + binding match authorize execution. |
| request step → confirm step | Live DB state may change across the gap; guards re-evaluated at confirm. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-220-01 | Tampering | bare destructive write at D-08 seam | mitigate | Task 1: seam returns `Err(ConfirmationRequired)` for `transition_trigger.is_some() && !is_confirmed`; the only execution path is request_confirm→confirm. Test: `sc1_bare_destructive_without_token` (executor not called). |
| T-220-02a | Spoofing | forged confirmation token | mitigate | Task 1+2: token is server-generated CSPRNG (`cfm_` + 43 BASE62 chars ≈ 256-bit), never an agent input to request_confirm; `confirm()` validates existence in the store. |
| T-220-02b | Tampering | expired token | mitigate | Task 2: `store.confirm()` returns None after TTL → `confirmation_expired`, no execution. Test: `sc3_expired_token_rejected` (paused clock). |
| T-220-02c | Tampering | wrong-action / wrong-record token | mitigate | Task 2: (tenant,action,record) binding stored at request; verified at confirm → `confirmation_mismatch`. Tests: `sc4_token_mismatch_action`, `sc4_token_mismatch_record`. |
| T-220-02d | Tampering | token reuse (double-execute) | mitigate | Task 2: `confirm()` consumes the entry (single-use); second confirm → None. Test: `sc2_two_step_flow_executes_once` (executor called exactly once). |

| T-220-CR01 | Information Disclosure | leaked internal errors to agent | mitigate | All outcomes use `write_tool_error_result` / `CallToolResult::structured` with `error_kind`+`message` only (reuse 219 CR-01 redaction); strict-deser test asserts envelope shape (Task 3). |
