   - Public `execute(project_root: &Path, filter: Option<&str>) -> ProjectionList`
   - `ProjectionList` struct: `projections: Vec<ProjectionInfo>`, `total: usize`
   - `ProjectionInfo` struct: `name: String` (function name), `file: String` (relative path), `service_name: Option<String>` (extracted from `ServiceDef::new("...")`)`, `display_name: Option<String>` (extracted from `.display_name("...")`)
   - Scan `src/projections/` directory for `.rs` files (not mod.rs)
   - Use regex to find functions returning `ServiceDef`: `pub\s+fn\s+(\w+)\s*\(.*\).*->\s*ServiceDef`
   - Extract service_name via regex: `ServiceDef::new\("([^"]+)"\)`
   - Extract display_name via regex: `\.display_name\("([^"]+)"\)`

   - Add tests: `test_empty_project` (non-existent dir returns empty), `test_serialization`

   - Public `execute(project_root: &Path, name: &str) -> ProjectionDetail`
   - `ProjectionDetail` struct: `name: String`, `file: String`, `service_name: String`, `display_name: Option<String>`, `fields: Vec<FieldInfo>`, `relationships: Vec<String>`, `actions: Vec<String>`, `has_state_machine: bool`, `intent_hints: Vec<String>`
   - `FieldInfo` struct: `name: String`, `data_type: String`, `meaning: String`, `readable: bool`, `writable: bool`
   - Parse the source file more deeply using regex to extract:
     - `.field("name", DataType::X, FieldMeaning::Y)` calls → FieldInfo
     - `.read_only_field(...)` and `.write_only_field(...)` calls → FieldInfo with readable/writable flags
     - `.relationship(...)` / `.has_many(...)` / `.belongs_to(...)` / `.has_one(...)` calls → relationship names
     - `.action(...)` calls → action names
     - `.state_machine(...)` presence → has_state_machine: true
     - `.intent_hint(...)` calls → intent hint strings
   - If the named projection is not found, return an error struct: `ProjectionNotFound { name: String, available: Vec<String> }`
   - Add tests: `test_not_found` (returns error with available list), `test_serialization`

4. Add `pub mod list_projections;` and `pub mod inspect_projection;` to `ferro-mcp/src/tools/mod.rs`

<task type="auto">
  <name>Task 2: Create render_projection tool and register all 3 tools in service.rs</name>
  <files>ferro-mcp/src/tools/render_projection.rs, ferro-mcp/src/tools/mod.rs, ferro-mcp/src/service.rs</files>

1. Create `ferro-mcp/src/tools/render_projection.rs`:
   - Public `execute(project_root: &Path, name: &str, mode: Option<&str>, intent_index: Option<usize>) -> Result<RenderResult, String>`
   - `RenderResult` struct: `service_name: String`, `intent: String` (primary intent name), `confidence: f64`, `mode: String` ("display"/"input"), `json_ui: serde_json::Value` (rendered output), `all_intents: Vec<IntentInfo>`
   - `IntentInfo` struct: `intent: String`, `confidence: f64`, `signals: Vec<String>`
   - This tool CANNOT dynamically execute Rust code — it must parse the source file to reconstruct the ServiceDef. Strategy:
     a. Use inspect_projection to get the parsed field/relationship/action data
     b. Reconstruct a `ServiceDef` programmatically from the parsed source data
     c. Call `ferro_projections::derive_intents()` and `JsonUiRenderer.render()`
     d. Return the rendered JSON-UI output
   - Parse mode parameter: "display" (default) → RenderMode::Display, "input" → RenderMode::Input
   - Parse intent_index parameter: defaults to 0 (primary intent)
   - Reconstruct ServiceDef from parsed data:
     - Use list_projections to find the file, then parse fields/relationships/actions/state machine from source
     - Build ServiceDef using the builder API: `ServiceDef::new(name).field(...)...`
     - Call `derive_intents(&service)` to get intents
     - Call `JsonUiRenderer.render(&service, &intents, &ctx)` to get rendered JSON-UI
   - If reconstruction fails (unsupported syntax), return error with explanation
   - Add tests: `test_render_result_serialization`, `test_mode_parsing`

2. Add `pub mod render_projection;` to `ferro-mcp/src/tools/mod.rs`

3. In `ferro-mcp/src/service.rs`:
   - Add 3 param structs:
     ```rust
     #[derive(Debug, Clone, Deserialize, Serialize, JsonSchema)]
     pub struct ListProjectionsParams {
         /// Optional filter by name (case-insensitive substring)
         pub filter: Option<String>,
     }

     #[derive(Debug, Clone, Deserialize, Serialize, JsonSchema)]
     pub struct InspectProjectionParams {
         /// Name of the projection function (e.g., "user_service")
         pub name: String,
     }

     #[derive(Debug, Clone, Deserialize, Serialize, JsonSchema)]
     pub struct RenderProjectionParams {
         /// Name of the projection function (e.g., "user_service")
         pub name: String,
         /// Render mode: "display" (default) or "input"
         pub mode: Option<String>,
         /// Intent index to render (default: 0, primary intent)
         pub intent_index: Option<usize>,
     }
     ```

   - Add 3 tool methods in the `#[tool_router]` impl block:
     ```rust
     #[tool(
         name = "list_projections",
         description = "List service projections defined in the project.\n\n\
             **When to use:** Discovering what ServiceDef projections exist, \
             understanding the projection surface area.\n\n\
             **Returns:** List of projection functions with service names and file locations.\n\n\
             **Combine with:** `inspect_projection` for field details, `render_projection` for rendered JSON-UI."
     )]
     pub async fn list_projections(&self, params: Parameters<ListProjectionsParams>) -> String { ... }

     #[tool(
         name = "inspect_projection",
         description = "Inspect a service projection's structure (fields, relationships, actions, state machine).\n\n\
             **When to use:** Understanding what a ServiceDef contains, checking field semantics, \
             reviewing relationships before rendering.\n\n\
             **Returns:** Detailed projection structure with fields, data types, meanings, relationships.\n\n\
             **Combine with:** `render_projection` to see the rendered JSON-UI output."
     )]
     pub async fn inspect_projection(&self, params: Parameters<InspectProjectionParams>) -> String { ... }

     #[tool(
         name = "render_projection",
         description = "Render a service projection to JSON-UI output.\n\n\
             **When to use:** Previewing how a ServiceDef renders to UI components, \
             checking intent derivation results, comparing display vs input modes.\n\n\
             **Returns:** Derived intents with confidence scores and rendered JSON-UI component tree.\n\n\
             **Combine with:** `inspect_projection` to understand the source ServiceDef."
     )]
     pub async fn render_projection(&self, params: Parameters<RenderProjectionParams>) -> String { ... }
     ```

   - Each tool handler calls the corresponding `tools::*::execute()` function and serializes the result to JSON string (matching the established pattern in all other tool handlers)
