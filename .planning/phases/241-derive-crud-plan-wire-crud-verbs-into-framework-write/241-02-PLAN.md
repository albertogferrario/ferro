```rust
async fn execute_crud_plan(
    plan: &CrudPlan,
    _tenant_id: i64, // unused in 241 (tenant_column is None); Phase 242 binds it
    db: &DatabaseConnection,
) -> WriteResult<Value> {
    let backend = db.get_database_backend();
    let now_expr = "datetime('now')"; // SQLite; for Postgres use "now()" — branch on backend
    match plan {
        CrudPlan::Create { table, columns, tenant_column: _ } => {
            // identifiers from plan only; values bound. created_at per Plan 01 contract:
            //   if executor-injected: append "created_at" to the column list with now_expr
            //   as a literal SQL expression (NOT a bound placeholder).
            // Build: INSERT INTO {table} ({col_list}) VALUES ({placeholders/now_expr})
            //        RETURNING *   (SQLite >= 3.35 + Postgres both support it — RESEARCH Q4)
            // db.query_one(stmt) → map the returned row to a serde_json::Value record.
            // If RETURNING * proves unavailable: INSERT then SELECT last_insert_rowid()
            //   then SELECT * FROM {table} WHERE id = ? (RESEARCH Q4 fallback — only if tests fail).
        }
        CrudPlan::Update { table, id_column, id_value, patch, soft_delete_column, tenant_column: _ } => {
            // UPDATE {table} SET {col=?, ...} WHERE {id_column}=? AND {soft_delete_column} IS NULL
            // db.execute(stmt) → ExecResult::rows_affected(); 0 → Err(WriteError::RecordNotFound)
            // then SELECT * FROM {table} WHERE {id_column}=? → returned record Value
        }
        CrudPlan::Delete { table, id_column, id_value, soft_delete_column, tenant_column: _ } => {
            // UPDATE {table} SET {soft_delete_column}={now_expr} WHERE {id_column}=? AND {soft_delete_column} IS NULL
            // db.execute(stmt) → rows_affected(); 0 → Err(WriteError::RecordNotFound)
            // return json!({ "id": id_value, "deleted": true })
        }
    }
    .map_err(|e: sea_orm::DbErr| WriteError::Database(e.to_string()))? // adapt as needed
}
```

Pin the now-expression per backend.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CrudPlan → SQL (execute_crud_plan) | plan-declared identifiers + agent-derived values cross into executed SQL |
| agent call → dispatch_write | untrusted call may target a soft-deleted or unconfirmed-delete row |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-241-05 | Tampering (SQL injection) | execute_crud_plan | mitigate | ALL values bound via `sea_orm::Value` through `Statement::from_sql_and_values` (never string-interpolated). Table/column identifiers originate ONLY from the `CrudPlan` (developer-authored projection declaration), never from agent input. Verified by acceptance grep + the dispatch tests exercising real values. |
| T-241-06 | Tampering | update/delete of soft-deleted row | mitigate | execute_crud_plan emits `AND <soft_delete_column> IS NULL` on both Update and Delete; `crud_update_soft_deleted_not_found` and `crud_deleted_row_hidden_from_list` assert a soft-deleted target is unaddressable (CRUD-03 / SC#2). |
| T-241-07 | Elevation of Privilege | delete without confirmation | mitigate | Step-3 seam extension `\|\| matches!(crud_plan, Some(CrudPlan::Delete{..}))` returns ConfirmationRequired; `crud_delete_requires_confirmation` proves the executor never fires for a bare delete. |
| T-241-08 | Information Disclosure | Sensitive field in audit payload | mitigate | The Create/Update column sets are derived (Plan 01) with `is_write_excluded_field` excluding Sensitive fields, so the executor's returned record / audit `.after(result)` cannot carry a Sensitive value. The Delete return is a minimal `{id, deleted}` object. |
| T-241-09 | Tampering | cross-tenant idempotency replay | mitigate (reused) | Idempotency lookup is scoped by `(tenant_id, idempotency_key)` UNCHANGED (kernel step 2); CRUD reuses it verbatim. |

**Out of scope (DEFERRED to Phase 242):** server-side `tenant_id` injection and cross-tenant non-disclosure — `tenant_column` is `None` and `execute_crud_plan` adds no tenant predicate by design (D-09). The runtime `tenant_id: i64` flows as a parameter but is intentionally unused for predicates here. The checker should NOT flag tenant scoping as missing in Plan 02.
</threat_model>
