## Sampling Rate

- **After every task commit:** Run the offload regression guards (the three unit/integration
  commands below).
- **After every plan wave:** Run `cargo fmt --all -- --check && cargo clippy --all --all-targets -- -D warnings` then the offload guards.
- **Before `/gsd-verify-work`:** `cargo test --all-features` must be green AND the SC#2 structural grep must be clean.
- **Max feedback latency:** ~30 seconds for the targeted offload guards.

## Regression Guard Commands (verified to resolve to real tests)

> Ferro collapses multiple `#[tokio::test]` scenarios into one outer suite fn (OnceLock
> workaround) — filtering on a scenario sub-fn name silently matches 0 tests. Always filter on
> the **outer suite name**. Every command below was `-- --list`-verified to resolve to ≥1 test.

```bash
# SC#1 / SC#3 — single-path registration + delta broadcast behavior unchanged (1 suite fn,
# 4 internal scenarios: cross_replica_delta, request_returns_before_worker,
# offload_failed_delta_is_redacted, resolve_already_complete)
cargo test --package ferro-rs --test offload_delta_broadcast offload_delta_broadcast_suite

# SC#3 — offload unit suite (result round-trip; updated to call the surviving registration fn)
cargo test --package ferro-rs --test offload_result_round_trip offload_result_round_trip

# D-04 — Pending variant serde-additivity guard (KEEP the test; only reword the comment)
cargo test --package ferro-rs offload_result_pending_round_trip

# WR-01 / D-07 — worker/serve boot scenarios preserved after run_common_boot linearization
cargo test --package ferro-rs --test worker_boot worker_boot_suite
```
