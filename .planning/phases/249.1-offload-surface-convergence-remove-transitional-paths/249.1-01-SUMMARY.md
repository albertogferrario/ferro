# Phase 249.1 Plan 01: Offload Surface Convergence — Remove Transitional Paths Summary

Behavior-preserving deletion and linearization of the `#[offload]` work-distribution surface
built across phases 244–249: single canonical `register_offload_hooks_with_broadcaster`
registration path, linearized `run_common_boot`, framework-default in-process `Broadcaster`
for worker-only boots.

---

## What Was Built

### Task 1 — Install default Broadcaster, linearize run_common_boot, delete persist-only fn (commit `4b9421d7`)

**`framework/src/app.rs` — `run_common_boot` linearized (D-02 five steps):**

The function had four hook-registration call sites and three `spawn_in_process_worker` calls,
using two early `return;` statements to exit the `redis-transport` feature block before reaching
the bottom `if/else`. The bottom `else` arm contained `register_offload_hooks()` — the
persist-only fallback for headless worker-only boots.

After linearization, `run_common_boot` is a single sequential flow with no early returns:

1. Run `bootstrap_fn`; init the queue DB connection (unchanged guards).
2. Install a framework-default in-process `Broadcaster` when bootstrap registered none
   (`App::get::<Broadcaster>().is_none()` guard → `App::singleton(Broadcaster::new())`).
3. Attach the Redis shared transport when configured (`redis-transport` feature + URL set);
   on failure, warn and continue with the in-process hub. D-07 feature-off + URL-set warn
   emitted in the `#[cfg(not(feature = "redis-transport"))]` block.
4. Register the offload result hook once:
   `register_offload_hooks_with_broadcaster(Arc::new(App::get::<Broadcaster>().expect(...)))`.
5. Spawn the in-process worker once: `if !no_worker && Queue::has_registered_jobs()`.

Step 2 guarantees `App::get::<Broadcaster>()` is always `Some` at Step 4, so the
`expect(...)` in Step 4 cannot panic in production.

**`framework/src/offload.rs` — persist-only fn deleted:**

`pub fn register_offload_hooks()` (lines 265–294) and its full doc comment were deleted.
The trailing cross-reference sentence in `register_offload_hooks_with_broadcaster`'s doc
("When broadcasting is not configured, use `register_offload_hooks` instead.") was also
removed to prevent a `cargo doc -Dwarnings` intra-doc-link failure.

`broadcast_delta`, `register_offload_hooks_with_broadcaster`, `OffloadResult`, and all tests
are untouched.

**`framework/tests/offload_result_round_trip.rs` — hidden caller updated:**

Import changed from `register_offload_hooks` to `register_offload_hooks_with_broadcaster`;
`use ferro_broadcast::Broadcaster` and `use std::sync::Arc` added; call site at line 242
changed from `register_offload_hooks()` to
`register_offload_hooks_with_broadcaster(Arc::new(Broadcaster::new()))`. No test logic or
assertions altered — the in-process hub passes zero-subscriber sends silently, so the test's
persist-path assertions remain valid.
