<task type="auto">
  <name>Task 1: Add ferro projection:check CLI command</name>
  <files>ferro-cli/src/commands/mod.rs, ferro-cli/src/main.rs</files>
  <action>
  1. Create `ferro-cli/src/commands/projection_check.rs`:
     - The command scans `src/projections/` for ServiceDef functions (reuse the same regex patterns from list_projections: `pub fn (\w+)\(.*\).*-> ServiceDef`, `ServiceDef::new("...")`, `.display_name("...")`).
     - For each discovered projection, reconstruct the ServiceDef from source using regex parsing (replicate the reconstruction logic from render_projection.rs — parse fields, relationships, actions, state machine, intent hints). This is source-level analysis, no compilation needed.
     - Call `ServiceDef::validate()` on the reconstructed ServiceDef. This requires ferro-projections as a dependency of ferro-cli.
     - Print results in the established CLI style:
       ```
       Checking projections...
         ✓ order_service (src/projections/order.rs) — 0 warnings
         ⚠ user_service (src/projections/user.rs) — 2 warnings
           - UnreachableState: state "archived" is not reachable from initial state
           - UnusedGuard: guard "is_admin" is defined but never referenced
         ✓ product_service (src/projections/product.rs) — 0 warnings

       3 projections checked, 2 warnings in 1 projection
       ```
     - Exit code 0 if no errors (warnings are OK), exit code 1 if validation errors found.
     - Accept optional `--name` flag to check a single projection instead of all.

  2. Add ferro-projections as an optional dependency of ferro-cli behind a `projections` feature flag in ferro-cli/Cargo.toml. Gate the projection_check module behind `#[cfg(feature = "projections")]`. Add the feature to the default features list.

  3. Register in `ferro-cli/src/main.rs`:
     ```
     #[command(name = "projection:check")]
     ProjectionCheck {
         #[arg(long)]
         name: Option<String>,
     }
     ```
     Route to `commands::projection_check::execute(name.as_deref())`.

  4. In `ferro-cli/src/commands/mod.rs`, add `#[cfg(feature = "projections")] pub mod projection_check;`.

  Avoid:
  - Don't attempt to compile user projections — use regex-based source parsing like render_projection does
  - Don't treat warnings as errors — validate() returns Result<Vec<Warning>, Error>, only Err is fatal
  - Don't duplicate the reconstruction logic as a separate function if you can structure it as a reusable internal function within projection_check.rs
  </action>
  <verify>
  cargo fmt --all -- --check && cargo clippy --all --all-targets -- -D warnings && cargo test --all-features
  </verify>
  <done>
  - `ferro projection:check` scans src/projections/, reconstructs ServiceDefs, validates, and prints results
  - `ferro projection:check --name user_service` checks a single projection
  - Exit code 0 for clean/warnings-only, 1 for validation errors
  - Tests for the command logic
  </done>
</task>

  <name>Task 2: Add validate_projection MCP tool</name>
  <files>ferro-mcp/src/tools/validate_projection.rs, ferro-mcp/src/tools/mod.rs, ferro-mcp/src/service.rs</files>
  <action>
  1. Create `ferro-mcp/src/tools/validate_projection.rs`:
     - Define `ValidationResult` struct with: service_name, file, warnings (Vec of strings), errors (Vec of strings), valid (bool).
     - Accept a `name` parameter (projection function name) and optional `all` boolean.
     - When `name` provided: find the projection via list_projections, reconstruct via render_projection's `reconstruct_service_def`, call `validate()`, return structured result.
     - When `all` is true: scan all projections, validate each, return Vec<ValidationResult> with summary (total, valid_count, warning_count, error_count).
     - Reuse `reconstruct_service_def` from render_projection.rs. Make it `pub(crate)` if currently private, so validate_projection can call it.

  2. In `ferro-mcp/src/tools/mod.rs`, add `pub mod validate_projection;`.

  3. In `ferro-mcp/src/service.rs`:
     - Add `ValidateProjectionParams` struct: `name: Option<String>`, `all: Option<bool>`.
     - Register the tool with `#[tool]` attribute:
       ```
       name = "validate_projection",
       description = "Validate a service projection for structural issues (unreachable states, unused guards, etc.)."
       ```
     - Implement: if `name` is Some, validate that one; if `all` is Some(true), validate all; if neither, return error asking for name or --all.
     - Format: `{Debug}` for Warning/Error variants → human-readable strings.

  4. Add tests:
     - Test serialization of ValidationResult
     - Test with a valid minimal projection (0 warnings)
     - Test reconstruction + validation of a projection with known issues (orphan state)

  - Tests for validation result serialization and basic validation logic
