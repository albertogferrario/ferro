<task type="auto">
  <name>Task 1: Add --from-model flag and model-aware template generation</name>
  <files>ferro-cli/src/commands/make_projection.rs, ferro-cli/src/main.rs</files>
  <action>
  1. In `ferro-cli/src/main.rs`, add `--from-model` optional flag to the `MakeProjection` variant:
     ```
     MakeProjection {
         name: String,
         #[arg(long)]
         from_model: bool,
     }
     ```
     Pass `from_model` to `make_projection::execute(&name, from_model)`.

  2. In `make_projection.rs`, update the `execute` function signature to accept `from_model: bool`.

  3. When `from_model` is true:
     - Reuse make_api's model scanning approach: use `syn::visit::Visit` to parse `src/models/` for the matching model. Implement a lightweight model field extractor directly in make_projection.rs (don't import from make_api — its types are private). The extractor needs: field name (String), rust_type (String), is_nullable (bool), is_primary_key (bool). This mirrors make_api's FieldInfo but is self-contained.
     - Match the requested projection name against available models (case-insensitive, singular form). If no match, print available models and exit.
     - For each model field, map:
       - Rust type → DataType using: String→String, i32/i64/u32/u64/i16/u16→Integer, f32/f64→Float, bool→Boolean, DateTime/NaiveDateTime/DateTimeUtc/DateTimeWithTimeZone→DateTime, NaiveDate/Date→Date, Uuid→Uuid, Vec&lt;u8&gt;→Binary, Json/serde_json::Value→Json, fallback→String
       - Field name → FieldMeaning using `infer_meaning()` logic (replicate the rules from ferro-projections/src/field.rs inline — exact matches for id/email/created_at/updated_at, suffix _id→ForeignKey, suffix _at→DateTime, prefix is_/has_→Boolean, sensitive patterns→Sensitive, fallback→Custom). Do NOT add ferro-projections as a dependency of ferro-cli — replicate the logic.
     - Determine field builder method:
       - Sensitive fields → skip entirely (don't include in projection)
       - Primary key or created_at/updated_at/ForeignKey → `read_only_field`
       - Optional fields (is_nullable) → `optional_field`
       - Everything else → `field`
     - Detect foreign key fields (*_id suffix) and generate `.belongs_to()` calls. Strip the `_id` suffix to get the relationship name and target service name: `user_id` → `.belongs_to("user", "user")`.
     - Generate the template using a new `model_aware_template()` function that builds the complete ServiceDef code string with all field and relationship builder calls.
     - Include a doc comment noting which model the projection was derived from.

  4. When `from_model` is false, keep existing behavior unchanged (call `projection_template`).

  Avoid:
  - Don't add ferro-projections as a cargo dependency of ferro-cli (it would create a circular dependency risk and isn't needed — replicate the simple mapping logic)
  - Don't try to detect has_many relationships (requires scanning other models for reverse FKs — too complex for scaffolding)
  - Don't panic on unknown types — fall back to DataType::String with the field included
  </action>
  <verify>
  cargo fmt --all -- --check && cargo clippy --all --all-targets -- -D warnings && cargo test --all-features
  </verify>
  <done>
  - `ferro make:projection order --from-model` reads Order model and generates a projection with populated fields, correct DataTypes, inferred FieldMeanings, read_only timestamps, excluded sensitive fields, and belongs_to from FK fields
  - `ferro make:projection order` (without --from-model) still generates the empty template as before
  - All existing make_projection tests still pass
  </done>
</task>
