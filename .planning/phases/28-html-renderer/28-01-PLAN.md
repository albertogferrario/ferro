  <name>Task 1: Create render module with tree walker and leaf component renderers</name>

  <action>
Create `ferro-json-ui/src/render.rs` with the HTML render engine.

**Public API:**

```rust
pub fn render_to_html(view: &JsonUiView, data: &serde_json::Value) -> String
```

Walks the view's component tree and produces a complete HTML fragment (not a full page — the framework wrapper in `framework/src/json_ui/mod.rs` handles html/head/body). Returns a `<div>` containing the rendered component tree.

**Internal structure:**

```rust
fn render_node(node: &ComponentNode, data: &Value) -> String
fn render_component(component: &Component, data: &Value) -> String
fn html_escape(s: &str) -> String  // & < > " ' escaping
```

`render_node` handles the ComponentNode wrapper:
- If the node has an action with a resolved `url` and the action method is GET, wrap the component output in `<a href="{url}" class="...">`. For non-GET methods, render the component as-is (forms handle their own actions; other methods need JS which is out of scope for SSR).
- Call `render_component` for the actual component HTML.
- Visibility is NOT evaluated in Phase 28 — all components render regardless of visibility rules. Visibility evaluation requires runtime data matching and will be addressed when the frontend or a dedicated phase handles it.

`render_component` dispatches to per-component render functions based on the Component enum variant.

**Leaf component renderers (12 components):**

1. **Text** — Render as the specified HTML element with escaped content:
   - `P` → `<p class="text-base text-gray-700">{content}</p>`
   - `H1` → `<h1 class="text-3xl font-bold text-gray-900">{content}</h1>`
   - `H2` → `<h2 class="text-2xl font-semibold text-gray-900">{content}</h2>`
   - `H3` → `<h3 class="text-xl font-semibold text-gray-900">{content}</h3>`
   - `Span` → `<span class="text-base text-gray-700">{content}</span>`

2. **Button** — `<button>` with variant-specific classes:
   - Default: `bg-blue-600 text-white hover:bg-blue-700`
   - Secondary: `bg-gray-100 text-gray-900 hover:bg-gray-200`
   - Destructive: `bg-red-600 text-white hover:bg-red-700`
   - Outline: `border border-gray-300 bg-white text-gray-700 hover:bg-gray-50`
   - Ghost: `text-gray-700 hover:bg-gray-100`
   - Link: `text-blue-600 underline hover:text-blue-700`
   - Size maps: Xs→`px-2 py-1 text-xs`, Sm→`px-3 py-1.5 text-sm`, Default→`px-4 py-2 text-sm`, Lg→`px-6 py-3 text-base`
   - Include `disabled` attribute and `opacity-50 cursor-not-allowed` when disabled is Some(true)
   - If icon is Some, render icon name as a `<span>` placeholder before/after label based on icon_position
   - All buttons get base classes: `inline-flex items-center justify-center rounded-md font-medium transition-colors`

3. **Badge** — `<span>` with variant colors:
   - Default: `bg-blue-100 text-blue-800`
   - Secondary: `bg-gray-100 text-gray-800`
   - Destructive: `bg-red-100 text-red-800`
   - Outline: `border border-gray-300 text-gray-700`
   - Base: `inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-medium`

4. **Alert** — `<div role="alert">` with variant-specific border + background:
   - Info: `bg-blue-50 border-blue-200 text-blue-800`
   - Success: `bg-green-50 border-green-200 text-green-800`
   - Warning: `bg-yellow-50 border-yellow-200 text-yellow-800`
   - Error: `bg-red-50 border-red-200 text-red-800`
   - Structure: `<div role="alert" class="rounded-md border p-4 {variant}">` with optional `<h4 class="font-semibold mb-1">` for title, then `<p>{message}</p>`

5. **Separator** — Horizontal: `<hr class="my-4 border-gray-200">`, Vertical: `<div class="mx-4 h-full w-px bg-gray-200"></div>`

6. **Progress** — Outer bar + inner filled bar:
   ```html
   <div class="w-full">
     {optional label: <div class="mb-1 text-sm text-gray-600">{label}</div>}
     <div class="w-full rounded-full bg-gray-200 h-2.5">
       <div class="rounded-full bg-blue-600 h-2.5" style="width: {pct}%"></div>
     </div>
   </div>
   ```
   Percentage = `value * 100 / max.unwrap_or(100)`, clamped to 0-100.

7. **Avatar** — If `src` is Some, render `<img>`. Otherwise render fallback initials in a circle:
   - Size: Xs→`h-6 w-6 text-xs`, Sm→`h-8 w-8 text-sm`, Default→`h-10 w-10 text-sm`, Lg→`h-12 w-12 text-base`
   - Image: `<img src="{src}" alt="{alt}" class="rounded-full object-cover {size}">`
   - Fallback: `<span class="inline-flex items-center justify-center rounded-full bg-gray-200 text-gray-600 {size}">{fallback or first chars of alt}</span>`

8. **Skeleton** — Animated placeholder:
   ```html
   <div class="animate-pulse bg-gray-200 {rounded}" style="{width}; {height}"></div>
   ```
   Default width/height: `width: 100%` / `height: 1rem`. Rounded: `rounded-full` if true, `rounded-md` otherwise.

9. **Breadcrumb** — `<nav>` with linked items separated by `/`:
   ```html
   <nav class="flex items-center space-x-2 text-sm text-gray-500">
     <a href="{url}" class="hover:text-gray-700">{label}</a>
     <span>/</span>
     ...
     <span class="text-gray-900 font-medium">{last_label}</span>
   </nav>
   ```
   Items with a url get `<a>`, the last item (or items without url) get plain `<span>`.

10. **Pagination** — Page number navigation:
    ```html
    <nav class="flex items-center space-x-1">
      {prev button if current_page > 1}
      {page number buttons}
      {next button if current_page < total_pages}
    </nav>
    ```
    Compute `total_pages = (total + per_page - 1) / per_page`. Base URL defaults to `"?"`. Current page gets `bg-blue-600 text-white`, others get `bg-white text-gray-700 hover:bg-gray-50`. Show up to 7 page links with ellipsis for large page counts. Each page link: `<a href="{base_url}page={n}" class="...">`.

11. **DescriptionList** — `<dl>` with dt/dd pairs:
    ```html
    <dl class="grid grid-cols-{columns or 1} gap-4">
      <div>
        <dt class="text-sm font-medium text-gray-500">{label}</dt>
        <dd class="mt-1 text-sm text-gray-900">{value}</dd>
      </div>
      ...
    </dl>
    ```
    ColumnFormat is display-only metadata — the value is already a string. No format transformation in SSR (frontend can use format hints for richer formatting).

**Important constraints:**
- All user-provided strings (title, label, content, value, etc.) MUST be HTML-escaped before output. Use the `html_escape` function. Do NOT double-escape — the `html_escape` in this module is separate from the one in `framework/src/json_ui/mod.rs`.
- The `html_escape` function must handle: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, `'` → `&#x27;`
- No external dependencies — string formatting only.
- Follow the resolve.rs tree walker pattern for the match arms.

**Export from lib.rs:**
Add `pub mod render;` to `ferro-json-ui/src/lib.rs` and add `pub use render::render_to_html;` to the re-exports.
