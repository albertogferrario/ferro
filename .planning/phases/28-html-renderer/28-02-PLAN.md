Add rendering for the remaining 8 container/form components to `ferro-json-ui/src/render.rs`.

**Container components:**

1. **Card** — Rounded card with optional header, children, and footer:
   ```html
   <div class="rounded-lg border border-gray-200 bg-white shadow-sm">
     <div class="p-6">
       <h3 class="text-lg font-semibold text-gray-900">{title}</h3>
       {optional: <p class="mt-1 text-sm text-gray-500">{description}</p>}
       {if children not empty:
         <div class="mt-4 space-y-4">
           {render each child node recursively}
         </div>
       }
     </div>
     {if footer not empty:
       <div class="border-t border-gray-200 px-6 py-4 flex items-center gap-2">
         {render each footer node recursively}
       </div>
     }
   </div>
   ```

2. **Modal** — Renders as a `<details>` element for no-JS interactivity:
   ```html
   <details class="group">
     <summary class="inline-flex items-center justify-center rounded-md bg-blue-600 text-white px-4 py-2 text-sm font-medium cursor-pointer">
       {trigger_label or "Open"}
     </summary>
     <div class="fixed inset-0 z-50 flex items-center justify-center bg-black/50 group-open:block hidden">
       <div class="relative bg-white rounded-lg shadow-lg max-w-lg w-full mx-4 p-6">
         <h3 class="text-lg font-semibold text-gray-900">{title}</h3>
         {optional: <p class="mt-1 text-sm text-gray-500">{description}</p>}
         <div class="mt-4 space-y-4">
           {render each child node}
         </div>
         {if footer not empty:
           <div class="mt-6 flex items-center justify-end gap-2">
             {render each footer node}
           </div>
         }
       </div>
     </div>
   </details>
   ```
   Note: This is a progressive-enhancement approach. A `<details>` renders without JS. Production apps will likely use a JS-enhanced modal, but the SSR output is functional.

3. **Tabs** — Render all tabs with the default_tab content visible:
   ```html
   <div>
     <div class="border-b border-gray-200">
       <nav class="flex -mb-px space-x-4">
         {for each tab:
           if tab.value == default_tab:
             <span class="border-b-2 border-blue-600 text-blue-600 px-3 py-2 text-sm font-medium">{label}</span>
           else:
             <span class="border-b-2 border-transparent text-gray-500 px-3 py-2 text-sm font-medium">{label}</span>
         }
       </nav>
     </div>
     {render ONLY the default_tab's children:
       <div class="pt-4 space-y-4">
         {render each child of the matching tab}
       </div>
     }
   </div>
   ```
   SSR renders only the default tab content. Tab switching requires JS (out of scope for Phase 28).

**Form field components:**

4. **Form** — `<form>` with action URL and method:
   ```html
   <form action="{action.url or '#'}" method="{form_method}" class="space-y-4">
     {if method is PUT/PATCH/DELETE:
       <input type="hidden" name="_method" value="{actual_method}">
       (form method becomes POST for method spoofing)
     }
     {render each field node recursively}
   </form>
   ```
   The form's `method` prop overrides `action.method` if set. For PUT/PATCH/DELETE, use POST as the HTML form method with a hidden `_method` field (standard Laravel/Ferro convention).

5. **Input** — Label + input element with error display:
   ```html
   <div class="space-y-1">
     <label class="block text-sm font-medium text-gray-700" for="{field}">{label}</label>
     {optional: <p class="text-sm text-gray-500">{description}</p>}
     {if input_type == Textarea:
       <textarea id="{field}" name="{field}" class="block w-full rounded-md border {border_class} px-3 py-2 text-sm shadow-sm focus:border-blue-500 focus:ring-1 focus:ring-blue-500 {error_class}" placeholder="{placeholder}" {required} {disabled}>{default_value or data_path resolved value}</textarea>
     else if input_type == Hidden:
       <input type="hidden" id="{field}" name="{field}" value="{default_value or resolved}">
     else:
       <input type="{type}" id="{field}" name="{field}" class="block w-full rounded-md border {border_class} px-3 py-2 text-sm shadow-sm focus:border-blue-500 focus:ring-1 focus:ring-blue-500 {error_class}" placeholder="{placeholder}" value="{default_value or resolved}" {required} {disabled}>
     }
     {if error Some: <p class="text-sm text-red-600">{error}</p>}
   </div>
   ```
   Border class: `border-red-500` if error present, `border-gray-300` otherwise.
   Resolve default value: if `default_value` is Some, use it. Else if `data_path` is Some, use `resolve_path_string(data, path)`. Else empty.

6. **Select** — Label + select element with options:
   ```html
   <div class="space-y-1">
     <label class="block text-sm font-medium text-gray-700" for="{field}">{label}</label>
     {optional: <p class="text-sm text-gray-500">{description}</p>}
     <select id="{field}" name="{field}" class="block w-full rounded-md border {border_class} px-3 py-2 text-sm shadow-sm focus:border-blue-500 focus:ring-1 focus:ring-blue-500" {required} {disabled}>
       {if placeholder: <option value="">{placeholder}</option>}
       {for each option:
         <option value="{value}" {selected if matches default}>{label}</option>
       }
     </select>
     {if error Some: <p class="text-sm text-red-600">{error}</p>}
   </div>
   ```
   Selected: compare option value against `default_value` or `data_path` resolved value.

7. **Checkbox** — Inline checkbox with label:
   ```html
   <div class="space-y-1">
     <div class="flex items-center gap-2">
       <input type="checkbox" id="{field}" name="{field}" value="1" class="h-4 w-4 rounded border-gray-300 text-blue-600 focus:ring-blue-500" {checked} {required} {disabled}>
       <label class="text-sm font-medium text-gray-700" for="{field}">{label}</label>
     </div>
     {optional: <p class="ml-6 text-sm text-gray-500">{description}</p>}
     {if error Some: <p class="ml-6 text-sm text-red-600">{error}</p>}
   </div>
   ```
   Checked: from `checked` prop. If None, resolve from `data_path` (truthy value = checked).

8. **Switch** — Styled as a toggle (same markup as checkbox with different visual styling via classes):
   ```html
   <div class="space-y-1">
     <div class="flex items-center justify-between">
       <div>
         <label class="text-sm font-medium text-gray-700" for="{field}">{label}</label>
         {optional: <p class="text-sm text-gray-500">{description}</p>}
       </div>
       <label class="relative inline-flex items-center cursor-pointer">
         <input type="checkbox" id="{field}" name="{field}" value="1" class="sr-only peer" {checked} {required} {disabled}>
         <div class="w-11 h-6 bg-gray-200 rounded-full peer peer-checked:bg-blue-600 peer-focus:ring-2 peer-focus:ring-blue-300 after:content-[''] after:absolute after:top-0.5 after:left-[2px] after:bg-white after:rounded-full after:h-5 after:w-5 after:transition-all peer-checked:after:translate-x-full"></div>
       </label>
     </div>
     {if error Some: <p class="text-sm text-red-600">{error}</p>}
   </div>
   ```

9. **Table** — Data table with columns resolved from data_path:
   ```html
   <div class="overflow-x-auto">
     <table class="min-w-full divide-y divide-gray-200">
       <thead class="bg-gray-50">
         <tr>
           {for each column:
             <th class="px-6 py-3 text-left text-xs font-medium uppercase tracking-wider text-gray-500">{label}</th>
           }
           {if row_actions: <th class="px-6 py-3 text-right text-xs font-medium uppercase tracking-wider text-gray-500">Actions</th>}
         </tr>
       </thead>
       <tbody class="divide-y divide-gray-200 bg-white">
         {resolve data_path against data to get array of rows.
          For each row (a JSON object):
           <tr>
             {for each column:
               <td class="px-6 py-4 text-sm text-gray-900 whitespace-nowrap">{row[column.key] as string}</td>
             }
             {if row_actions:
               <td class="px-6 py-4 text-right text-sm space-x-2">
                 {for each action: <a href="{url}" class="text-blue-600 hover:text-blue-800">{handler name after dot}</a>}
               </td>
             }
           </tr>
         }
         {if no rows and empty_message:
           <tr><td colspan="{col_count}" class="px-6 py-8 text-center text-sm text-gray-500">{empty_message}</td></tr>
         }
       </tbody>
     </table>
   </div>
   ```
   Use `resolve_path(data, &data_path)` to get the array. If it resolves to a JSON array, iterate rows. If not, show empty_message. For each cell, get `row[column.key]` — if string use directly, if number/bool use to_string(), if null show empty, if object/array show JSON.

Update `framework/src/json_ui/mod.rs` to replace the placeholder `<pre>` dump with actual rendered HTML from `render_to_html()`.

**Changes to `JsonUi::render_with_config()`:**
1. After resolving actions (existing code), call `ferro_json_ui::render_to_html(&view, data)` to get the HTML fragment.
2. Replace the `<pre>` block in the HTML template with the rendered HTML fragment.
3. Keep the `data-view` and `data-props` attributes on the wrapper div (for potential JS hydration).
4. The wrapper structure becomes:
   ```html
   <div id="ferro-json-ui"
        data-view="{view_escaped}"
        data-props="{data_escaped}">
     {rendered_html}
   </div>
   ```

**Changes to `render_with_errors_config()`:**
Same pattern — replace `<pre>` with rendered HTML. The errors are already resolved on the view before this point.

**Do NOT change:**
- The `render_json` / `render_json_with_errors` methods (they return JSON, not HTML)
- The html/head/body wrapper structure
- The `html_escape` / `html_escape_attr` functions (keep them for title and attribute escaping)
- The `JsonUiConfig` handling (tailwind_cdn, custom_head, body_class)

**Framework re-exports:**
Add `render_to_html` to the ferro_json_ui re-exports in `framework/src/lib.rs` so users can call it directly if needed.

**Update existing tests:**
The existing tests in `framework/src/json_ui/mod.rs` that check for the `<pre>` placeholder comment should be updated:
- `render_produces_valid_html` — should still find `<!DOCTYPE html>`, title, data-view, data-props
- `empty_view_renders_valid_html` — should still produce valid HTML
- The rendered body should now contain actual component HTML (e.g., Card title text) instead of JSON dump
- Keep all XSS tests — they should still pass since `render_to_html` escapes content
