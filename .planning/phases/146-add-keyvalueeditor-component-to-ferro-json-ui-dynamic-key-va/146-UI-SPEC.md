## Spacing Scale

Standard 8-point scale used throughout ferro-json-ui. All values are multiples of 4.

| Token | Tailwind Class | Usage in KeyValueEditor |
|-------|---------------|-------------------------|
| xs | `gap-1` / `p-1` (4px) | Icon-only button inner padding |
| sm | `gap-2` / `px-2 py-1` (8px) | Delete button padding |
| md | `gap-3` / `px-3 py-2` (12/8px) | Input field padding — matches existing Input/Select |
| lg | `gap-4` (16px) | Row-to-row gap, editor block internal spacing |
| xl | `space-y-4` (16px) | Wrapper vertical spacing (matches `space-y-1` on each row group) |

Row layout column sizing: `grid grid-cols-[1fr_1fr_auto]` — key and value columns expand equally, delete button column is `auto` (minimum width to fit the icon button).

Exceptions: delete button touch target is `min-w-[32px] min-h-[32px]` to ensure adequate click area on mobile, even though the icon is 16px. No 44px exception required because the button is not an isolated touch target — it sits inline with the row.

## Color Contract

Semantic token names only — resolved by the consumer's Tailwind v4 theme configuration.

| Role | Token | Usage | Source |
|------|-------|-------|--------|
| Dominant surface (60%) | `bg-background` | Page background behind the component | Default |
| Secondary surface (30%) | `bg-card` / `bg-surface` | Not used by KeyValueEditor directly | Default |
| Input border (normal) | `border-border` | Key input, value input border in default state | render.rs pattern |
| Input border (error) | `border-destructive` | All row inputs when `error` is set on the editor | render.rs pattern |
| Focus ring (normal) | `focus-visible:ring-primary` | Key and value inputs in normal state | render.rs pattern |
| Focus ring (error) | `focus-visible:ring-destructive` | Key and value inputs when error is set | render.rs pattern |
| Label text | `text-text` | Block label, row column headers (if any) | render.rs pattern |
| Muted text | `text-text-muted` | Placeholder text, helper text | render.rs pattern |
| Error text | `text-destructive` | Error message paragraph below the editor | render.rs pattern |
| Accent (10%) | `text-primary` / `bg-primary` | "Add row" button text and border | render.rs pattern |
| Delete button | `text-text-muted hover:text-destructive` | Per-row delete (×) button — muted default, destructive on hover | Design default |

Accent reserved for: the "Add row" button label and its border/focus ring only. Delete buttons use muted-to-destructive hover transition, not the primary accent.

## Component Structure

### HTML Skeleton

The rendered HTML for a `KeyValueEditor` with label, two pre-filled rows, a `<datalist>`, and an error message:

```html
<div class="space-y-1" data-kv-editor data-kv-field="{field}">

  <!-- Optional block label -->
  <label class="block text-sm font-medium text-text" for="{field}">
    {label}
  </label>

  <!-- Row list -->
  <div class="space-y-2" data-kv-rows>

    <!-- Each row (key + value + delete) -->
    <div class="grid grid-cols-[1fr_1fr_auto] gap-2 items-center" data-kv-row>
      <!-- allow_custom_keys = true: free-text input with optional datalist -->
      <input
        type="text"
        class="block w-full rounded-md border border-border px-3 py-2 text-base shadow-sm transition-colors duration-150 motion-reduce:transition-none focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2"
        placeholder="Key"
        list="{field}-suggestions"
        data-kv-key
        value="{pre-filled key}"
      >
      <!-- allow_custom_keys = false: select instead of free-text input -->
      <!-- <select class="block w-full appearance-none bg-background rounded-md border border-border px-3 py-2 text-base shadow-sm ..."> -->

      <input
        type="text"
```

### Error State Variant

When `error` is `Some(_)`, all key and value inputs in every row receive:
- Border: replace `border-border` with `border-destructive`
- Focus ring: replace `focus-visible:ring-primary` with `focus-visible:ring-destructive`
- ARIA: add `aria-invalid="true" aria-describedby="err-{field}"` to each key and value input

The delete button and add-row button are not affected by the error state.

### Empty State (no rows)

When `data_path` resolves to `{}` or is absent, the row list is empty: `<div data-kv-rows></div>` with no child rows. The `<template>` and "Add row" button are always present. The hidden field value is `{}`.

### allow_custom_keys = false (select variant)

The key input in every row (including the `<template>`) renders as `<select>` instead of `<input type="text">`:

```html
<select
  class="block w-full appearance-none bg-background rounded-md border border-border px-3 py-2 text-base shadow-sm transition-colors duration-150 motion-reduce:transition-none focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2"
  data-kv-key
>
  <option value="">Select key</option>
  <option value="{key1}">{key1}</option>
  <!-- ... -->
</select>
```

The chevron SVG decoration used in `render_select` is NOT added here — the select sits in a compact grid row and the `appearance-none` + chevron pattern is not needed at this size. The `appearance-none` class is kept for consistency.

## Runtime Behavior

Module: `ferro-json-ui/src/runtime/key_value_editor.rs`
Entry point: `setupKeyValueEditor()`
Selector: `[data-kv-editor]` (wrapper element)
JS style: Vanilla JS, ES5-compatible (`var`, no arrow functions, no closures capturing `this`)

### Data Attributes

| Attribute | Element | Purpose |
|-----------|---------|---------|
| `data-kv-editor` | wrapper `<div>` | Marks the component boundary; `setupKeyValueEditor` selects all instances |
| `data-kv-field` | wrapper `<div>` | Name of the hidden input to sync — value equals `field` prop |
| `data-kv-rows` | rows container `<div>` | Target for appending new rows |
| `data-kv-row` | each row `<div>` | Unit of deletion; parent when reading key/value inputs |
| `data-kv-row-template` | `<template>` element | Source for `cloneNode(true)` when adding a row |
| `data-kv-key` | key `<input>` or `<select>` | Key field within a row |
| `data-kv-value` | value `<input>` | Value field within a row |
| `data-kv-delete` | delete `<button>` | Triggers row removal |
| `data-kv-add` | add-row `<button>` | Triggers row append |

### Event Wiring

1. **Add row** — `data-kv-add` click:
   - Find `[data-kv-row-template]` within the same `data-kv-editor` wrapper.
   - Clone its content via `template.content.cloneNode(true)`.
   - Append cloned row to `[data-kv-rows]`.
   - Sync hidden field.

2. **Delete row** — delegated `click` on `[data-kv-rows]`, target matches `[data-kv-delete]`:
   - Walk up from target to nearest `[data-kv-row]`.
   - Remove that row element from the DOM.
   - Sync hidden field.

3. **Input change** — delegated `input` event on `[data-kv-rows]`, target matches `[data-kv-key]` or `[data-kv-value]`:
   - Sync hidden field.

### Serialization Logic

```
function syncHiddenField(editor) {
    var fieldName = editor.getAttribute('data-kv-field');
    var hiddenInput = editor.querySelector('input[name="' + fieldName + '"][type="hidden"]');
    var rows = editor.querySelectorAll('[data-kv-row]');
    var obj = {};
    for (var i = 0; i < rows.length; i++) {
        var keyEl = rows[i].querySelector('[data-kv-key]');
        var valEl = rows[i].querySelector('[data-kv-value]');
        var k = keyEl ? keyEl.value.trim() : '';
        var v = valEl ? valEl.value : '';
        if (k !== '') {
            obj[k] = v;  // last-write wins on duplicate keys (D-10)
        }
    }
    hiddenInput.value = JSON.stringify(obj);
}
```

Empty rows (blank key) are excluded from serialization (D-08). Blank values are included if the key is non-empty.

### Initialization

`setupKeyValueEditor()` is called once on `DOMContentLoaded` by the `ferroRuntime()` dispatcher. It queries all `[data-kv-editor]` elements and wires event listeners on each using delegation (no per-row listeners).
