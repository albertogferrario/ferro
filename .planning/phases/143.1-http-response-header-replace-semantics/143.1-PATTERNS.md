#### Consuming-builder pattern (lines 87-121)

All builder methods take `mut self` and return `Self`. The `status` and `set_body` methods are canonical examples:

```rust
// framework/src/http/response.rs lines 87-97
pub fn set_body(mut self, body: impl Into<String>) -> Self {
    let s: String = body.into();
    self.body = Bytes::from(s);
    self
}

pub fn status(mut self, status: u16) -> Self {
    self.status = status;
    self
}
```

All string parameters use `impl Into<String>`. The `header()` method (line 118) follows the same shape — it is the one being replaced:

```rust
// framework/src/http/response.rs lines 117-121  (CURRENT — to be replaced)
/// Add a header to the response
pub fn header(mut self, name: impl Into<String>, value: impl Into<String>) -> Self {
    self.headers.push((name.into(), value.into()));
    self
}
```

**Replacement (D-01):** retain+push with `eq_ignore_ascii_case`:

```rust
pub fn header(mut self, name: impl Into<String>, value: impl Into<String>) -> Self {
    let name = name.into();
    self.headers.retain(|(n, _)| !n.eq_ignore_ascii_case(&name));
    self.headers.push((name, value.into()));
    self
}
```

#### `cookie()` re-routing (D-03)

Current implementation at lines 134-137 calls `self.header(...)`, which after D-01 would strip prior `Set-Cookie` entries:

```rust
// framework/src/http/response.rs lines 134-137  (CURRENT — to be replaced)
pub fn cookie(self, cookie: Cookie) -> Self {
    let header_value = cookie.to_header_value();

}
```

Replacement routes through `append_header()`:

```rust
pub fn cookie(self, cookie: Cookie) -> Self {
    let header_value = cookie.to_header_value();
    self.append_header("Set-Cookie", header_value)
}
```

#### Test structure (D-07)

Existing tests in `#[cfg(test)]` block (lines 450-563) access `resp.headers` directly as a private field (same module). After `headers()` is added, the new tests must use the public accessor instead (to match the success-criteria wording and to validate the accessor itself).
