# Phase 143.1: HttpResponse header replace semantics — Context

**Gathered:** 2026-04-21
**Status:** Ready for planning
**Marker:** INSERTED (urgent — Safari still broken after phase 143 shipped)

<domain>
## Phase Boundary

Fix `HttpResponse::header()` to use replace semantics (case-insensitive name match), add an `append_header()` escape hatch for genuinely multi-value headers, and route `cookie()` through `append_header()` to preserve multi-cookie support.

Single affected file: `framework/src/http/response.rs`. No API removal. No behaviour change for any other method or crate.

</domain>

<decisions>
## Implementation Decisions

### D-01: header() semantics
Replace-semantics, case-insensitive:
```rust
pub fn header(mut self, name: impl Into<String>, value: impl Into<String>) -> Self {
    let name = name.into();
    self.headers.retain(|(n, _)| !n.eq_ignore_ascii_case(&name));
    self.headers.push((name, value.into()));
    self
}
```

### D-02: append_header() method
Add as `pub` (externally callable escape hatch for `Set-Cookie`, `Vary`, `Link`, and other legitimate multi-value headers):
```rust
pub fn append_header(mut self, name: impl Into<String>, value: impl Into<String>) -> Self {
    self.headers.push((name.into(), value.into()));
    self
}
```

### D-03: cookie() routing
Route through `append_header()` — `Set-Cookie` is the only legitimate multi-value header used internally. Multi-cookie behaviour must be preserved:
```rust
pub fn cookie(self, cookie: Cookie) -> Self {
    let header_value = cookie.to_header_value();
    self.append_header("Set-Cookie", header_value)
}
```

### D-04: Public headers accessor
Add `pub fn headers(&self) -> &[(String, String)]` — success criteria reference this method; adds clean API surface for tests and downstream consumers.

### D-05: ResponseExt trait
No change needed. `ResponseExt::header()` delegates to `HttpResponse::header()` and automatically gets replace semantics.

### D-06: Header storage
Keep `Vec<(String, String)>`. No migration to `HashMap` or similar — that is explicitly out of scope. The `Vec` works correctly once replace-semantics lands.

### D-07: Tests
Three unit tests required in the existing `#[cfg(test)]` block in `response.rs`:
1. Replace: `HttpResponse::text("x").header("Content-Type", "text/html")` → exactly one `Content-Type` entry with value `text/html`.
2. Multi-cookie: two `.cookie()` calls → two `Set-Cookie` entries.
3. Case-insensitive: `.header("Content-Type", ...)` replaces a prior `"content-type"` (lowercase).

### D-08: Version bump
Bump `framework/Cargo.toml` version 0.2.5 → 0.2.6 as part of this phase. Patch-level change — behaviour fix, not a breaking change.

### Claude's Discretion
- Whether to also test `append_header()` directly (beyond the cookie test) — implementation choice.
- Docstring wording for the updated methods.

</decisions>

<specifics>
## Specific Ideas

### Problem statement (verbatim for downstream context)

`HttpResponse::text()` prepopulates `Content-Type: text/plain`. Calling `.header("Content-Type", "text/html; charset=utf-8")` afterwards appends a second entry. HTTP intermediaries (Cloudflare) comma-join them → `text/plain,text/html; charset=utf-8`. Safari reads the first value and renders the response as plain text — raw HTML source on the page. Chrome/Firefox use the second value; the bug was invisible in dev and CI.

Every `JsonUi::render()` response — every page in every ferro app — ships the double header. Call site: `framework/src/json_ui/mod.rs:140-142`.

### Relationship to phase 143

Phase 143 diagnosed the Safari failure as `@tailwindcss/browser@4` not running in WebKit. Wrong diagnosis. The runtime never executed because Safari interpreted the whole response as plain text. Phase 143's static CSS pipeline is still a net architectural improvement (dev-only CDN out of prod, no WASM download) but did not and could not fix this bug. Do not roll back 143.

### Success criteria

1. `HttpResponse::text("x").header("Content-Type", "text/html").headers()` returns exactly one `Content-Type` entry with value `text/html`.
2. Two `.cookie()` calls on one response → two `Set-Cookie` entries (multi-cookie behaviour preserved).
3. Case-insensitive replace: `.header("Content-Type", ...)` replaces a prior `"content-type"`.
4. gestiscilo.it `/accedi` wire response: `content-type: text/html; charset=utf-8` — no comma, no `text/plain`.
5. Safari desktop + iOS render gestiscilo.it pages as styled HTML.

</specifics>
