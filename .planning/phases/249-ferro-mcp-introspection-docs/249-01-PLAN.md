Implement three helpers and the second-pass driver in `list_services.rs`.

1. `fn detect_offload_attr(trimmed: &str) -> Option<String>`:
   - If `trimmed == "#[offload]"` → `Some("default".to_string())`.
   - If `trimmed.starts_with("#[offload(")` → find `queue = "` , read to the next `"`, return
     `Some(that_literal)`; if the arg form is present but no `queue = "..."` is found, still return
     `Some("default".to_string())` (bare-equivalent). Otherwise `None`.

2. `fn extract_method_params(inner: &str) -> Vec<OffloadParam>` where `inner` is the text between
   the method's `(` and its matching `)`:
   - Bracket-aware split on `,` (Pitfall 2): maintain a depth counter, `+1` on `<` and `[`, `-1`
     on `>` and `]`, only split at depth 0.
   - Drop the receiver segment (the first segment if it is `&self` / `self` / `&mut self` /
     `mut self` after trimming).
   - For each remaining segment, split on the FIRST `:` into `(name, ty)`; trim both.
   - Apply text-level `owned_type` substitution on `ty` (mirror ferro-macros exactly):
     `&str`→`String`; `&[X]`→`Vec<X>` (X = content between `[` and `]`); a leading `&` on any other
     non-`&mut` type → strip the `&`; everything else verbatim. Leave `&mut T` verbatim (the macro
     rejects it at compile time; the read surface need not).
   - Push `OffloadParam { name, rust_type }`.

3. `fn scan_offload_methods_from_files(project_root: &Path, services: &mut Vec<ServiceItem>)` — the
   second pass. Walk `{project_root}/src/**/*.rs` with the SAME `WalkDir` filter the existing
   `scan_services_from_files` uses. Per file, run a three-state machine over `content.lines()`:
   - Track the currently open service: when a line `trimmed.starts_with("#[service(")`, remember
     the concrete name from inside the parens (mirror the existing extraction); also, on the
     following `pub trait TraitName` / `trait TraitName` line, remember the trait name. Keep BOTH
     the concrete name and the trait name of the current block so correlation can match either.
   - State `Idle`: on `detect_offload_attr(trimmed) == Some(q)` → `OffloadPending(q)`.
   - State `OffloadPending(q)`: skip `///`, `//`, and other `#[...]` lines; on a line containing
     `fn ` capture the method name (the ident after `fn `, before `(`) and begin
     `FnCollecting(method, q, buf)` seeded with the remainder of the `fn` line from `(` onward.
   - State `FnCollecting`: append each subsequent line to `buf` until `buf` contains a `)` that
     closes the param list (track paren depth from the first `(`); on close, extract the text
     between the outer `(` and its matching `)`, call `extract_method_params`, and push an
     `OffloadableMethod { name, queue, params }` onto the current service's collected list; return
     to `Idle`.
   - Correlation (Pitfall 3): after the file walk, for each collected method attach it to the
     `ServiceItem` in `services` whose `name` matches EITHER the remembered concrete name OR the
     trait name of the block the method came from. If neither matches an existing `ServiceItem`,
     skip the method (unregistered service — do not fabricate an entry).

Then wire it into `execute()` on BOTH branches (D-05 — runtime `/_ferro/services` endpoint itself

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local filesystem → ferro-mcp static parser | The parser reads `{project_root}/src/**/*.rs` — files already inside the trusted project root the MCP server was initialized against. No new path is opened that `scan_services_from_files` did not already read. |
| ferro-mcp → agent (MCP client) | `list_services` returns JSON already served to the agent; this change only adds additive `methods` data derived from source the agent can already read. |

No new network endpoint, no untrusted remote input, no secret, no auth/privilege boundary is
introduced. The `/_ferro/services` runtime endpoint is NOT modified (D-05). Parser input is local
source text under a trusted root; parser output is a best-effort read surface (no code execution,
no eval, no deserialization of untrusted bytes — the `Deserialize` derive on `ServiceItem` is only
exercised against the app's own `/_ferro/services` response, which is same-origin localhost).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-249-01 | Tampering | static parser reading local `src/**/*.rs` | accept | Files are under the trusted project root already read by the existing `scan_services_from_files`; no new read surface, no write. Low-value local read of the developer's own source. |
| T-249-02 | Information disclosure | `methods` array in `list_services` output | accept | Exposes only method names, queue names, and Rust type strings already present in readable source; no secrets, no PII, no credentials. Same information the agent could obtain by reading the trait directly. |
| T-249-03 | Denial of service | pathological source triggering unbounded `FnCollecting` accumulation | mitigate | The state machine appends line-by-line and closes `FnCollecting` on paren-depth reaching zero; a malformed signature that never closes is bounded by the file's own line count (files are finite, read fully into memory already by the existing parser). No unbounded loop is introduced beyond the existing per-file `lines()` iteration. |

No HIGH or MEDIUM severity threat. This is a read-only static-analysis + tool-metadata change;
the realistic surface is a local source read the framework already performs.
