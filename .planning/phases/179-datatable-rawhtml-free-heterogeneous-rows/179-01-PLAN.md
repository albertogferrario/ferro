# Plan 179-01: Badge column format + DropdownMenuAction.visible_if

## Objective

Add two small additive primitives to `ferro-json-ui` so DataTable callers can express heterogeneous per-row UI without HTML strings:

1. **`ColumnFormat::Badge`** — cell value is `{variant: BadgeVariant, label: String}`, renders the same `<span>` shape as the standalone Badge component.
2. **`DropdownMenuAction.visible_if: Option<String>`** — when set, the action item is only emitted for rows where `row[visible_if]` is truthy (treating absent/false/null/empty-string as hidden; treating `true`, non-zero numbers, and non-empty strings as visible).

After this plan the gestiscilo `documenti_unified` table can drop its per-row `build_*_actions_html` HTML builders entirely and emit structured `stato: {variant, label}` + per-row `can_*: bool` flags.

## Threat Model

- **T-179-S1 (LOW)**: Badge column format reads `variant` from row data. If a caller emits an invalid variant string, the cell should render a decode diagnostic comment (matching existing `decode_diagnostic` pattern at `atoms.rs:252`), NOT crash the table or render an unknown CSS class. Mitigation: deserialize via existing `BadgeVariant` enum; fall back to `BadgeVariant::Default` for unknown values to keep rendering robust.
- **T-179-S2 (LOW)**: `visible_if` reads from row data and could be exploited if the field name is operator-controlled. In practice the field name is declared server-side in the view spec, so this is purely a robustness concern: an absent field MUST hide the action (fail-closed), not show it (fail-open). Otherwise a typo in the view spec would expose all actions on every row.

### Task 3: Filter `template_actions` by `visible_if`

**Action:**

In `ferro-json-ui/src/render/data.rs::template_actions` (line ~371):

1. Before the existing `.map(|a| { ... })` URL-substitution closure, add a `.filter(|a| { ... })` that:
   - If `a.visible_if.is_none()`: keep the action (no gate).
   - If `a.visible_if = Some(field)`: look up `row.get(field)`. Keep iff the value is truthy. Truthy definition:
     - `Value::Bool(true)` → keep
     - `Value::Bool(false)` → drop
     - `Value::Number(n)` → keep iff `n != 0` (try `as_i64` then `as_f64`)
     - `Value::String(s)` → keep iff `!s.is_empty()`
     - `Value::Null` → drop (fail-closed)
     - `Value::Array` / `Value::Object` → keep iff non-empty (defensive — should not normally appear)
     - Field missing entirely → drop (fail-closed per T-179-S2)

2. Behaviour applies identically in desktop and mobile dropdown rendering — they both go through `template_actions`.
