<task type="auto">
  <name>Task 1: Add LangConfig and enrich LangError in ferro-lang</name>
  <files>ferro-lang/src/config.rs, ferro-lang/src/error.rs, ferro-lang/src/lib.rs</files>
  <action>
1. Create `ferro-lang/src/config.rs` with a `LangConfig` struct:
   - `locale: String` — default locale (from `APP_LOCALE` env, default `"en"`)
   - `fallback_locale: String` — fallback locale (from `APP_FALLBACK_LOCALE` env, default `"en"`)
   - `path: String` — translation files directory (from `LANG_PATH` env, default `"lang"`)
   - Implement `from_env()` using `std::env::var` with defaults (matching AppConfig pattern but without importing framework config helpers since ferro-lang is a standalone crate)
   - Implement `Default` via `from_env()` (same as AppConfig)
   - Add a `LangConfigBuilder` with `locale()`, `fallback_locale()`, `path()` methods and `build()` that fills unset fields from `from_env()` — same builder pattern as AppConfigBuilder
   - Derive `Debug, Clone` on LangConfig

2. Enrich `ferro-lang/src/error.rs` — add two new variants to `LangError`:
   - `InvalidLocale { locale: String }` — for when a requested locale is not loaded
   - `ConfigError { message: String }` — for configuration-level issues (e.g., lang path doesn't exist)
   Keep existing IoError, JsonError, NoTranslationsLoaded variants unchanged.

3. Update `ferro-lang/src/lib.rs`:
   - Add `pub mod config;`
   - Add `pub use config::{LangConfig, LangConfigBuilder};` to re-exports
   - Keep existing `pub use error::LangError;` and `pub use translator::Translator;`
  </action>
  <verify>cd ferro-lang && cargo check && cargo test</verify>
  <done>LangConfig::from_env() returns config with defaults, LangConfigBuilder works, LangError has 5 variants, all existing tests pass</done>
</task>
