## Decisions Made

- **Sanitization in golden.rs.** The golden test previously rendered with the raw Cargo package name, silently bypassing Plan 02's fix. To assert the mkmenu → mkmenu-ferro transformation end-to-end, `golden.rs` now mirrors `do_init::run`: sanitize the name and rename the server bin before handing bins to both `DockerfileContext` and `AppYamlContext`.
- **Path-stem exclusion.** `is_test_like_bin` checks `Path::file_stem` rather than the full path, so pathological cases like `[[bin]] name = "odd_name", path = "src/bin/test_parser.rs"` are correctly excluded.
- **required-features deferred.** D-15 is not honored yet because `project::BinEntry` does not expose `required-features`. TODO comment left in place; name/path heuristic already covers the mkmenu UAT case.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] golden.rs did not apply name sanitization**
- **Found during:** Task 2 (reviewing render_for before regenerating)
- **Issue:** `render_for` in `tests/golden.rs` passed the raw package name directly to both DockerfileContext and AppYamlContext, bypassing the Plan 02 fix. Without this, the regenerated mkmenu golden would have `name: mkmenu_ferro` (wrong) instead of `name: mkmenu-ferro`.
- **Fix:** Mirror `do_init::run` — compute `app_name = sanitize_do_app_name(&pkg)`, rename any bin matching raw `pkg` to `app_name`, pass `app_name` as `package_name` to both contexts.
- **Files modified:** `ferro-cli/tests/golden.rs`
- **Committed in:** `992c1915`

**Total deviations:** 1 auto-fixed (1 blocking)
**Impact on plan:** Necessary to correctly express plan intent ("MUST contain `name: mkmenu-ferro`"). The plan assumed golden.rs already sanitized; it did not.
