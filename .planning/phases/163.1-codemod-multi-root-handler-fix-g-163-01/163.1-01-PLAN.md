<objective>
Close WR-01 from 163-REVIEW.md. The `ferro json-ui:migrate-v1` codemod silently
orphans elements when a v1 handler has multiple top-level nodes — `root` is set
to the first node only, remaining elements end up in `elements` but are
unreachable from `root`. Apply Option B from the review (verbatim, lines 90-92
of 163-REVIEW.md): detect `top_ids.len() != 1` after `flatten_nodes` and return
`HandlerResult::Unsupported`. This routes through the existing TODO-marker
path; no new code paths, no new components, no catalog changes. Aligns with
D-11 from Phase 163 CONTEXT (codemod is best-effort; cases it cannot translate
get a TODO marker, not a silent skip) and respects D-06 (Fragment/Group
explicitly NOT added).

Purpose: Prevent silent data loss in the codemod. A user running
`ferro json-ui:migrate-v1` on a multi-root v1 handler today receives a JSON
spec that renders only the first top-level node. After this phase, that user
receives a TODO marker pointing at a handler they must hand-migrate — the
correct outcome for a best-effort tool.

Output: A 3-line guard in `try_migrate_handler`, one deleted fixture
(`out_auth_login_form.json`), one deleted fixture (`out_auth.rs`), three new
fixtures (`in_single_root.rs`, `out_single_root.rs`,
`out_single_root_dashboard.json`), and a rewritten integration test that
exercises both branches.
</objective>
