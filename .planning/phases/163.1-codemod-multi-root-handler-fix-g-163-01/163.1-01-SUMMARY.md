# Phase 163.1 Plan 01: Codemod Multi-Root Handler Fix (WR-01) Summary

**One-liner:** Guard `try_migrate_handler` against multi-root v1 inputs with `top_ids.len() != 1` returning `HandlerResult::Unsupported` before spec construction, closing WR-01 silent data-loss bug.

## What Was Built

Closed WR-01 from 163-REVIEW.md. The `ferro json-ui:migrate-v1` codemod previously set `root` to the first top-level node when a handler had multiple top-level nodes in its `vec![...]`, leaving remaining elements unreachable in the spec. The fix adds a 3-line guard that routes multi-root inputs through the existing TODO-marker path instead.

### Exact Change in `try_migrate_handler` (before/after)

**Before (lines 250-256):**
```rust
// Build the flat element map. Root is the first top-level node.
let mut elements = Map::<String, Value>::new();

let top_ids = flatten_nodes(view.nodes, &mut elements);
let Some(root) = top_ids.first().cloned() else {
    return HandlerResult::Unsupported;
};
```

**After (lines 250-263):**
```rust
// Build the flat element map. v2 requires exactly one root; reject both
// empty (top_ids.is_empty()) and multi-root (top_ids.len() > 1) handlers
// as Unsupported so they pass through the TODO-marker path. WR-01 fix
// (Phase 163.1) — see 163-REVIEW.md Option B.
let mut elements = Map::<String, Value>::new();

let top_ids = flatten_nodes(view.nodes, &mut elements);
if top_ids.len() != 1 {
    return HandlerResult::Unsupported;
}
let root = top_ids
    .into_iter()
    .next()
    .expect("len == 1 checked above");
```
