<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe (signature-verified) → handlers | Typed events enter handle_* after upstream verify_webhook |
| handler → DB (status transitions) | Guarded updates are the race fence between webhook and reaper |
| handler → Stripe (auto-refund) | Outbound refund on un-honorable capture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-235-09 | Repudiation (replay/double-apply) | `handle_*` idempotency | mitigate | `processed_log.try_mark_processed(event_id)` fast-path (`Ok(false)` ⇒ return) + idempotent `mark_*` GuardedUpdates. Proven by `handle_session_completed_replay`. |
| T-235-10 | Tampering (double-honor) | webhook + reaper race | mitigate | `mark_paid`/`mark_released` are atomic GuardedUpdates with a status precondition — exactly one wins; the loser is a no-op or auto-refund. Proven by `webhook_reaper_race` + `paid_after_released`. |
| T-235-11 | Money lost (capture not honored) | auto-refund fallback | mitigate | Loader `Err`/`None`, `mark_paid` `Ok(false)`, and `on_paid` `Err` all route to `trigger_auto_refund` (by payment_intent). Proven by `auto_refund_loader_error` / `auto_refund_billable_vanished` / `handle_session_completed_side_state_conflict`. Phase-236 reconcile reaper is the safety net. |
| T-235-12 | Tampering (double-refund) | `trigger_auto_refund` | mitigate | Snapshot `refund_amount_cents` under `WHERE refund_amount_cents IS NULL`; `Ok(false)` ⇒ no Stripe call. No compensate-reset on Stripe failure (D-11) — avoids double-refund on a lost-response; 236 reconcile recovers the stuck row. |
| T-235-13 | DoS (retry storm) | error bridge | mitigate | Only transient `Db`/`Stripe` errors map to `Err(Error::Stripe(..))` (Stripe retries, made safe by idempotency); terminal outcomes are absorbed (`Ok(())`) so Stripe does not retry. Anti-pattern guard: handlers never return `AutoRefundTriggered` to the dispatcher. |
</threat_model>
