<objective>
Fix three issues in ferro-cache's MemoryStore: per-entry TTL is silently ignored, tags accumulate stale references, and counters grow unboundedly.

Purpose: The MemoryStore's `put_raw` discards the TTL parameter (`let _ = ttl`), tags DashMap retains references to evicted keys, and counters DashMap has no eviction. All three cause correctness bugs or memory leaks in long-running servers.
Output: MemoryStore with working per-entry TTL, self-cleaning tags, and bounded counters.
</objective>

<task type="auto">
  <name>Task 1: Fix per-entry TTL, deduplicate tags, and add eviction listener</name>
  <files>ferro-cache/src/stores/memory.rs</files>
  <action>
  Three fixes in the MemoryStore:

  **Fix A: Per-entry TTL (currently ignored)**

  The `put_raw` method discards TTL: `let _ = ttl;`. Fix this by switching to moka's per-entry expiry:

  1. Create a `CacheValue` wrapper: `struct CacheValue { data: Vec<u8>, ttl: Duration }`.
  2. Implement `moka::Expiry<String, CacheValue>` with `expire_after_create` returning `Some(value.ttl)`.
  3. Change cache type from `MokaCache<String, Vec<u8>>` to `MokaCache<String, CacheValue>`.
  4. Build cache with `.expire_after(expiry_impl)` in addition to existing `.max_capacity()`.
  5. Update `put_raw` to wrap value in CacheValue with the TTL.
  6. Update `get_raw` to extract `.data` from CacheValue.
  7. Update `has` — no change needed (contains_key still works).
  8. Update `forget` — remove returns Option<CacheValue>, check is_some().

  **Fix B: Tags deduplication**

  Change tags from `DashMap<String, Vec<String>>` to `DashMap<String, HashSet<String>>`:
  1. Change the type (add `use std::collections::HashSet;`).
  2. In `tag_add`: use `.insert()` on HashSet instead of `.push()` — prevents duplicates.
  3. In `tag_members`: collect HashSet into Vec for return type compatibility.
  4. In `tag_flush`: iterate HashSet instead of Vec (works the same).
  5. In `flush`: `.clear()` works the same on both.

  **Fix C: Eviction listener for tag cleanup**

  Register a Moka eviction listener so that when entries are evicted (by TTL or LRU), their keys are removed from all tag sets:

  1. Clone the `Arc<DashMap<String, HashSet<String>>>` tags reference.
  2. In the cache builder, add `.eviction_listener(move |key, _value, _cause| { ... })`.
  3. In the listener: iterate all tag entries, remove the evicted key from each HashSet. Remove any tag entry whose HashSet becomes empty (use `retain`).

  Note: The eviction listener receives `Arc<String>` for the key in moka 0.12. Dereference as needed.
  </action>
  <verify>cargo test -p ferro-cache -- --nocapture</verify>
  <done>Per-entry TTL applied on insert. Tags use HashSet (no duplicates). Eviction listener cleans stale tag references. All existing tests pass.</done>
</task>

  **Fix D: Bounded counters**

  Replace `counters: Arc<DashMap<String, i64>>` with a second `MokaCache<String, i64>`:
  1. Add a `counters: MokaCache<String, i64>` field (using moka::future::Cache).
  2. Build with same `max_capacity` as the main cache (accept from constructor, default 10,000).
  3. Update `increment`: use `counters.get()` + `counters.insert()` pattern. If key doesn't exist, start from 0.
  4. Update `decrement`: same pattern, subtract instead.
  5. Update `forget`: also remove from counters cache (`.remove(&key).await`).
  6. Update `flush`: also `counters.invalidate_all()`.
  7. Remove `dashmap` import if no longer used (tags still uses DashMap, so keep it).

  **New tests:**

  1. `test_per_entry_ttl_respected`: Put a value with 100ms TTL. Verify it exists immediately. Sleep 200ms. Verify `get_raw` returns None. This confirms TTL is no longer ignored.

  2. `test_tag_deduplication`: Add same key to same tag twice via `tag_add`. Verify `tag_members` returns the key only once.

  3. `test_eviction_cleans_tags`: Create a MemoryStore with small capacity (e.g., 50). Add entries with tags. Insert enough entries to trigger eviction. Verify evicted keys are removed from tag sets. Note: Moka eviction is async — may need a small delay or `cache.run_pending_tasks().await` to ensure listener fires.

  4. `test_counters_bounded`: Create a MemoryStore with small capacity. Increment many unique counter keys. Verify the counter count doesn't exceed capacity significantly.
