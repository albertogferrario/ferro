<objective>
Replace the framework's hand-rolled InMemoryCache (RwLock<HashMap> with lazy TTL) with moka::sync::Cache, providing bounded capacity, per-entry TTL, proactive eviction, and lock-free reads.

Purpose: The current implementation never evicts expired entries that aren't read, and has no capacity limit — both cause unbounded memory growth in long-running servers.
Output: Drop-in replacement behind the same CacheStore trait. Same public API, bounded memory.
</objective>

<task type="auto">
  <name>Task 1: Add moka dependency and replace InMemoryCache implementation</name>
  <files>framework/Cargo.toml, framework/src/cache/memory.rs</files>
  <action>
  1. Add moka to `framework/Cargo.toml` dependencies: `moka = "0.12"` (sync::Cache is included by default, no feature flags needed). Note: moka is already used in ferro-cache so it's a known workspace dependency.

  2. Replace the entire InMemoryCache implementation in `framework/src/cache/memory.rs`:

  **Internal value type:** Create a `CacheValue` struct holding `value: String` and `ttl: Option<Duration>`. This lets the Expiry trait read the per-entry TTL.

  **Expiry implementation:** Implement `moka::Expiry<String, CacheValue>` with:
  - `expire_after_create`: Return `value.ttl` (Some(dur) = expire after dur, None = no expiry, LRU only)
  - `expire_after_read`: Return `None` (don't change expiry on read — matches current behavior)
  - `expire_after_update`: Return `value.ttl` (refresh expiry on update — needed for `expire()` method)

  **InMemoryCache struct:** Replace `store: RwLock<HashMap<String, CacheEntry>>` with `cache: moka::sync::Cache<String, CacheValue>`. Keep `prefix: String`.

  **Constructor:** Build with `moka::sync::Cache::builder().max_capacity(10_000).expire_after(CacheTtlExpiry).build()`.

  **Add `with_capacity(capacity: u64)` constructor** for custom sizing (same pattern as ferro-cache MemoryStore).

  **CacheStore trait mapping:**
  - `get_raw`: `self.cache.get(&key)` → extract `.value` from CacheValue. Moka handles TTL checks automatically.
  - `put_raw`: `self.cache.insert(key, CacheValue { value, ttl })`. Moka calls Expiry::expire_after_create.
  - `has`: `self.cache.contains_key(&key)`. Moka filters expired entries.
  - `forget`: `self.cache.remove(&key)`. Returns whether it existed.
  - `flush`: `self.cache.invalidate_all()`.
  - `increment`: Get current value, parse as i64, add amount, insert with `expires_at: None`. If entry doesn't exist or is expired, start from 0.
  - `decrement`: Delegate to `increment(key, -amount)` (same as current).
  - `expire`: Get current value, re-insert with new TTL. Moka calls Expiry::expire_after_update which reads the new TTL. Return false if key not found.

  **Remove:** The old `CacheEntry` struct and its `is_expired()` method. Remove `use std::collections::HashMap` and `use std::sync::RwLock`.
  </action>
