## Readiness signalling (WR-02)

| Option | Description | Selected |
|--------|-------------|----------|
| oneshot readiness param + async `with_transport` awaits attach | `subscribe_loop` takes a `oneshot::Sender<()>`, fired after subscribe; `with_transport` becomes async and awaits it, degrading to local-only + `warn!` on timeout/err (D-06). Window closed by construction for all callers. | ✓ |
| Sync `with_transport` + separate `async fn ready()` (watch-backed) | Keeps the builder sync; callers await `ready()` before first publish. | |
| Split the trait into `subscribe()` + `recv()` loop | Establish the subscription synchronously, then loop. | |

**Auto-selected:** oneshot readiness param + async `with_transport`.
**Notes:** The defect class is "callers rely on timing" — an async builder that gates by
construction removes the need for caller discipline entirely, whereas a separate `ready()`
re-introduces a "must remember to gate" hazard. Splitting the trait is more invasive given the
redis pubsub stream borrows `pubsub`. The production call site (`app.rs:449-456`) is already
async, so the async builder is a clean fit and makes startup await attachment before serving
traffic. Bounded-timeout value left to Claude's discretion (connect() pre-validates reachability).

## State preservation & clone coherence (WR-03)

| Option | Description | Selected |
|--------|-------------|----------|
| Single shared `Arc<Inner>`, `transport`/`authorizer` behind `parking_lot::RwLock<Option<Arc<…>>>`, builders mutate in place | Fixes registration drop AND clone-divergence; `parking_lot` already a dep. | ✓ |
| `arc_swap::ArcSwapOption` for the transport field | Lock-free reads on the publish path. | |
| Move existing `DashMap`s into a newly-allocated inner | Preserve state without interior mutability. | |

**Auto-selected:** single shared inner with `parking_lot::RwLock` interior mutability.
**Notes:** `arc_swap` would add a dependency; `parking_lot` is already present
(`ferro-broadcast/Cargo.toml:22`) and the field is write-once-at-startup / read-mostly, so a
brief read lock on the publish path is adequate. Moving the `DashMap`s into a fresh inner fights
`Arc` sharing and does not fix clone-divergence (clones taken before `with_transport` would keep
the old inner). `with_authorizer` carries the identical defect and is folded into the same
structural fix — same root cause, not a new capability.
