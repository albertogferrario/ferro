<domain>
## Phase Boundary

Close the two concurrency defects recorded in 246.1-REVIEW.md for `ferro-broadcast`'s
shared fan-out transport, and only those:

- **WR-02 — lost-wakeup window.** `with_transport` spawns the SUBSCRIBE loop as a detached
  task, but the bus subscription happens asynchronously inside it; a delta published before
  the first subscription completes is dropped. The window is currently masked by `sleep`s in
  the tests. Replace the timing assumption with a deterministic readiness signal so
  publication observes an established subscription.
- **WR-03 — registration drop / clone divergence.** `with_transport` (and the identical
  `with_authorizer`) allocate a fresh `BroadcasterInner` with empty `DashMap`s, discarding any
  client/channel registered before the call; `#[derive(Clone)]` compounds this — a clone taken
  before `with_transport` keeps the old `transport: None` inner. Preserve pre-registered state
  across transport installation and make every clone observe the installed transport.

Out of scope: WR-01, IN-01..IN-05, cross-replica presence, and any new transport or feature
capability. This is a hardening phase; the six v16.4 requirements are already satisfied.

</domain>

<decisions>
## Implementation Decisions

### Readiness signalling (WR-02)
- **D-01:** Add a readiness signal to `BroadcastTransport::subscribe_loop` — a
  `tokio::sync::oneshot::Sender<()>` parameter each implementation fires immediately after its
  subscription is established (`InMemoryTransport` right after `self.tx.subscribe()`;
  `RedisTransport` right after `pubsub.subscribe(&channel).await` returns `Ok`). The
  implementation is the only place that knows when attachment completes, so the signal
  originates there. This is a breaking change to the public `BroadcastTransport` trait —
  acceptable pre-1.0.
- **D-02:** `with_transport` becomes `async` and awaits the readiness receiver before
  returning, so the returned `Broadcaster` is guaranteed attached and the lost-wakeup window
  is closed by construction for every caller — not only those who remember to gate. On
  readiness failure (the receiver resolves `Err`, i.e. the loop ended before signalling) or a
  bounded timeout, log `warn!` and return anyway, degrading to local-only. This is consistent
  with 246.1 D-06 (a bus error never fails the caller).

### State preservation & clone coherence (WR-03)
- **D-03:** Keep a single shared `Arc<BroadcasterInner>` for the broadcaster's life and all
  clones. Make `transport` (and `authorizer`, for coherence) interior-mutable via
  `parking_lot::RwLock<Option<Arc<...>>>`. `with_transport`/`with_authorizer` keep the
  `(self) -> Self` shape but mutate the shared inner in place instead of allocating fresh
  empty `DashMap`s. Pre-registered clients/channels survive transport installation, and every
  clone observes the installed transport (clone-divergence resolved).
- **D-04:** `with_authorizer`'s identical reallocation defect is fixed by the same shared-inner
  change — same root cause, not a new capability. The "call builders before any client
  connects" contract in `app.rs` is no longer load-bearing for correctness.

### Test strategy (SC#1 / SC#2 / SC#3)
- **D-05 (SC#1):** Add a `ferro-broadcast/tests/shared_transport.rs` test that awaits readiness
  (via async `with_transport`) then publishes immediately, with no `sleep`, asserting
  cross-process delivery — structured so it would time out under the old, sleep-removed timing.
  Remove the existing `sleep`s from the shared-transport tests.
- **D-06 (SC#2):** Add a test that registers a client and subscribes it to a channel *before*
  `with_transport`, installs the transport, then has a peer replica publish, asserting the
  pre-registered client receives the delta. Include a clone-divergence guard: a `Broadcaster`
  clone taken before `with_transport` still fans out after installation.
- **D-07 (SC#3):** Keep the `broadcaster.rs` unit tests and the Phase 247 / OFFLOAD-04
  integration suite (`framework/tests/offload_delta_broadcast.rs`) green; the single-process
  path (`transport == None`) behaves identically. Update every `with_transport` call site for
  the async signature (production `app.rs` wiring is already in an async context).

### Claude's Discretion
- The exact bounded-timeout value in D-02, or whether a timeout is warranted at all — the
  production path (`app.rs`) has already validated Redis reachability via `RedisTransport::connect`
  before `with_transport` runs, so a short defensive bound suffices.
- Whether an additional reusable `ready()` accessor (latching `watch`) is exposed alongside the
  async `with_transport`; the locked shape is the async builder.
- The interior-mutability primitive detail for `authorizer` (same `RwLock` wrapper or a narrower
  one), provided state is preserved and clones stay coherent.
- Exact test names and fixture wiring.
