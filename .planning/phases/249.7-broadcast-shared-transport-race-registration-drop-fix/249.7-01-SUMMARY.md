# Phase 249.7 Plan 01: WR-02 + WR-03 shared-transport race and registration-drop fix — Summary

One-liner: async `with_transport` with oneshot readiness + `parking_lot::RwLock` interior-mutable `BroadcasterInner` closing the lost-wakeup window and clone-divergence defects across `ferro-broadcast`.

## What Was Built

Closed two concurrency defects recorded in 246.1-REVIEW for `ferro-broadcast`'s shared fan-out transport path:

**WR-02 (lost-wakeup window):** A delta published immediately after `with_transport` returned could be silently dropped because the background SUBSCRIBE loop had not yet called `self.tx.subscribe()`. Fixed by adding a `tokio::sync::oneshot::Sender<()>` `ready` parameter to `BroadcastTransport::subscribe_loop`; each implementation fires it the instant the subscription is established (`InMemoryTransport` after `tx.subscribe()`; `RedisTransport` after `pubsub.subscribe().await`). `with_transport` is now `async` and awaits the receiver with a 5-second timeout before returning. On timeout or sender-drop without firing, it logs `warn!` and returns degraded to local-only (D-06 preserved — never fails the caller).

**WR-03 (registration drop / clone divergence):** `with_transport` and `with_authorizer` previously allocated a fresh `Arc<BroadcasterInner>` with empty `DashMap`s, discarding any pre-registered clients and channels. A `Broadcaster` clone taken before the call would retain the old `transport: None` inner and never fan out. Fixed by making `transport` and `authorizer` interior-mutable via `parking_lot::RwLock<Option<Arc<...>>>`. Both builders now mutate the shared inner in place (`*self.inner.transport.write() = Some(...)`), preserving existing clients, channels, and all existing clones.

**Lock-across-await hazard:** `fan_out`, `subscribe`, and `check_auth` all read the interior-mutable fields before calling async methods. Each uses the scoped clone-then-drop pattern to ensure no `parking_lot` guard is held across a yield point — satisfying `clippy::await_holding_lock`.

**Call-site sweep:** Every `with_transport` call across the workspace was updated to `.await`: `framework/src/app.rs` (Step 3 boot), `ferro-broadcast/tests/shared_transport.rs` (6 call sites), `ferro-broadcast/tests/redis_integration.rs` (2 call sites), `framework/tests/offload_delta_broadcast.rs` (4 call sites). The `FailingTransport` mock's `subscribe_loop` was updated to accept and drop `ready`, exercising the D-06 degradation path.

**Sleep removal:** The `sleep(20ms)` calls in `shared_transport.rs` and `sleep(150ms)` in `redis_integration.rs` were removed. Readiness is now guaranteed by construction.

## Deviations from Plan

**1. [Rule 1 - Bug] Scoped block required for authorizer read guard in `subscribe`**

- **Found during:** Task 1
- **Issue:** The pattern `else if let Some(authorizer) = self.inner.authorizer.read().clone()` does not drop the `RwLockReadGuard` before the `.await` on the subsequent line. Clippy correctly flagged `await_holding_lock`. A single-expression `.read().clone()` in an `if let` condition does not terminate the guard lifetime at the closing `)`.
- **Fix:** Wrapped the read and clone in a scoped block — `{ let guard = self.inner.authorizer.read(); guard.clone() }` — ensuring the guard is dropped at the closing `}` before any `.await`. Applied identically to both `subscribe` and `check_auth`.
- **Files modified:** `ferro-broadcast/src/broadcaster.rs`
- **Commit:** 6d47e1d8

No other deviations. The plan executed as specified.
