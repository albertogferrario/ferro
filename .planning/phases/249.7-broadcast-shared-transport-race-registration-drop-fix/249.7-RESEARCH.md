## Summary

This is a tightly-scoped hardening phase that closes two concurrency defects in `ferro-broadcast`'s shared-transport path. Both defects were found during the 246.1 REVIEW (WR-02 and WR-03) and are already fully diagnosed; the implementation decisions are locked in CONTEXT.md. Research confirms the design is sound and documents the exact Rust mechanics each implementer needs.

**WR-02 (lost-wakeup window):** `with_transport` spawns the SUBSCRIBE loop as a detached task, but subscription to the underlying bus happens asynchronously inside that task. Any delta published between `with_transport` returning and the bus subscription completing is silently dropped. The current tests paper over this with `tokio::time::sleep` calls (20 ms in `shared_transport.rs`, 150 ms in `redis_integration.rs`). The fix is a `tokio::sync::oneshot` readiness signal from inside `subscribe_loop` to `with_transport`, which then awaits it before returning. `oneshot::Receiver` resolves `Err(RecvError)` when the sender is dropped without sending — confirmed by official docs — which handles the "loop crashed before signalling" case.

**WR-03 (registration drop / clone divergence):** Both `with_transport` and `with_authorizer` allocate a fresh `BroadcasterInner` with empty `DashMap`s, discarding pre-registered clients and channels. `#[derive(Clone)]` on `Broadcaster` clones the `Arc<BroadcasterInner>`, so a clone taken before `with_transport` retains the old `transport: None` inner and will never fan out. The fix is to make `transport` and `authorizer` interior-mutable via `parking_lot::RwLock<Option<Arc<...>>>`, mutating the shared inner in place rather than reallocating. `parking_lot` is already a declared dependency (Cargo.toml:22); no new crate is required.

**Primary recommendation:** Implement D-01/D-02 first (readiness signal), then D-03/D-04 (shared-inner mutability). Both changes touch `broadcaster.rs` and `transport/mod.rs`; coordinate them in a single plan rather than separate waves to avoid intermediate broken states.

## Architecture Patterns

### WR-02: Readiness signal flow

```
with_transport(transport) -> async Self
│
├─ let (ready_tx, ready_rx) = oneshot::channel::<()>();
├─ spawn: subscribe_loop(sink, ready_tx) ── fires ready_tx after subscription attaches
│
│   InMemoryTransport::subscribe_loop:
│     let mut rx = self.tx.subscribe();   ← subscription established here
│     let _ = ready_tx.send(());          ← fire immediately after
│     loop { recv ... }
│
│   RedisTransport::subscribe_loop:
│     pubsub.subscribe(&self.channel).await?;  ← subscription established here
│     let _ = ready_tx.send(());               ← fire immediately after
│     let mut stream = pubsub.into_on_message();
│     loop { stream.next() ... }
│
└─ tokio::time::timeout(READY_TIMEOUT, ready_rx).await
     Ok(Ok(())) → attached, return broadcaster
     Ok(Err(_)) → sender dropped (loop errored before firing) → warn! + return anyway
     Err(_)     → timeout elapsed → warn! + return anyway
```

### WR-03: Interior-mutable shared inner

```
Before (fresh-inner reallocation):
  with_transport(self) -> Self {
      Arc::new(BroadcasterInner { clients: DashMap::new(), ... })  ← drops pre-registered state
  }

After (mutate in place):
  BroadcasterInner {
      clients:    DashMap<...>,
      channels:   DashMap<...>,
      authorizer: parking_lot::RwLock<Option<Arc<dyn ChannelAuthorizer>>>,
      transport:  parking_lot::RwLock<Option<Arc<dyn BroadcastTransport + Send + Sync>>>,
      ...
  }

  with_transport(self, transport) -> async Self {
      *self.inner.transport.write() = Some(transport.clone());
      // spawn subscribe_loop, await readiness
      self   ← same Arc<BroadcasterInner>, same DashMaps, same clones observe update
  }

  fan_out path (async, must not hold RwLock guard across .await):
      let transport = self.inner.transport.read().clone();  ← clone the Arc, drop the guard
      drop guard before any .await
      if let Some(t) = transport { t.publish(...).await }
```

### Trait signature change

```rust
// transport/mod.rs  — BEFORE
async fn subscribe_loop(
    &self,
    sink: tokio::sync::mpsc::Sender<BusEnvelope>,
) -> Result<(), Error>;

// transport/mod.rs  — AFTER
async fn subscribe_loop(
    &self,
    sink: tokio::sync::mpsc::Sender<BusEnvelope>,
    ready: tokio::sync::oneshot::Sender<()>,
) -> Result<(), Error>;
```

`#[async_trait]` desugars async methods into boxed futures and handles the `dyn Trait` vtable; adding a parameter is safe and does not break object safety. The macro's handling of `Send + Sync` bounds is unchanged. [VERIFIED: dtolnay/async-trait docs]

### `FailingTransport` mock update (shared_transport.rs)

The `FailingTransport` mock in `shared_transport.rs` implements `subscribe_loop` with a park-until-closed body. After the signature change it must accept and drop the `ready` sender (or fire it if the test requires readiness):

```rust
async fn subscribe_loop(
    &self,
    sink: tokio::sync::mpsc::Sender<BusEnvelope>,
    ready: tokio::sync::oneshot::Sender<()>,
) -> Result<(), Error> {
    drop(ready);          // signal not sent → caller gets Err(RecvError) → degrades gracefully
    sink.closed().await;
    Ok(())
}
```

Whether `FailingTransport` fires `ready` or drops it determines whether `with_transport` awaits successfully or degrades. For the `publish_error_does_not_propagate` test the subscription path is not under test, so dropping `ready` (and relying on D-02 degradation) is correct.

### Anti-Patterns to Avoid

- **Holding a `parking_lot::RwLock` guard across an `.await` point.** `parking_lot` locks are synchronous and will block the executor thread if held across a yield. The correct pattern for `fan_out` is to clone the `Arc` out from under the guard, drop the guard, then call `transport.publish(...)`.await`. [ASSUMED — standard async Rust guideline; consistent with parking_lot's own documentation warning about `async` usage]
- **Firing `ready_tx.send(())` inside an `.await` that may not return.** Signal readiness immediately after the subscription call returns, before entering the receive loop. If the `pubsub.subscribe` call itself fails with `?`, `ready_tx` is dropped without firing, which is the correct degradation path.
- **Adding `with_transport` to the `FailingTransport` test without updating `FailingTransport`'s `subscribe_loop` signature.** The trait is object-safe under `#[async_trait]`, but the impl must match the updated signature or the test will not compile.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Readiness signalling | A sleep, a `Mutex<bool>` poll loop, or a custom channel | `tokio::sync::oneshot` | One-shot semantics are exactly the requirement; `Receiver` resolves `Err` on sender drop, which maps cleanly to the "loop crashed" degradation case |
| Interior mutability on async path | `std::sync::RwLock` | `parking_lot::RwLock` | `std::sync::RwLock` is poisoning and noisier; parking_lot is already declared; for the specific read-clone-drop pattern on the async fan_out path, either works, but parking_lot is the project precedent |
| Bounded timeout on readiness | A spawned timer task | `tokio::time::timeout` | One-liner wrapping; the `Elapsed` error type makes the degradation path explicit |

**Key insight:** The oneshot is the minimal mechanism for "wait until one event happens exactly once." A `Notify` or `watch` would also work but carry more overhead and no inherent "dropped sender = error" semantics.

## Common Pitfalls

### Pitfall 1: Holding RwLock guard across `.await` in `fan_out`

**What goes wrong:** The compiler may not reject `parking_lot::RwLockReadGuard` across an await point in all configurations (parking_lot guards are `!Send` but the guard is a local variable in an async fn, which becomes a generator). The executor may deadlock or panic at runtime when another task tries to acquire the write lock.
**Why it happens:** `parking_lot` is a synchronous mutex crate; its guards are not `async`-aware and block the thread.
**How to avoid:** Clone the `Arc<dyn BroadcastTransport>` while under the lock, then drop the guard explicitly before any `.await`:
```rust
let transport = self.inner.transport.read().clone(); // clone Arc, guard drops here
if let Some(t) = transport {
    t.publish(&envelope).await?;
}
```
**Warning signs:** Clippy may emit `clippy::await_holding_lock` if the guard is held across an await point.

### Pitfall 2: `ready_tx.send(())` after the await point that may fail

**What goes wrong:** In `RedisTransport::subscribe_loop`, if `ready_tx.send(())` is placed after `pubsub.into_on_message()` or inside the receive loop, a brief connection delay causes `with_transport` to timeout/degrade even though the subscription did succeed.
**Why it happens:** The subscription is established when `pubsub.subscribe(&channel).await` returns `Ok`; `into_on_message()` consumes the pubsub into a stream but does not re-establish the subscription.
**How to avoid:** Fire `ready_tx.send(())` on the line immediately after `pubsub.subscribe(&channel).await?` succeeds, before calling `into_on_message()`.

### Pitfall 3: Clone divergence survives if `Arc<BroadcasterInner>` is not shared

**What goes wrong:** If the WR-03 fix is done by storing a new `Arc` per `with_transport` call (rather than mutating the existing one), clones taken before the call still see the old inner — the divergence is not fixed.
**Why it happens:** `Broadcaster` holds `inner: Arc<BroadcasterInner>`; `#[derive(Clone)]` clones the `Arc` pointer, not the inner. Two `Broadcaster`s sharing the same `Arc` will both observe a mutation to the inner's `RwLock` fields.
**How to avoid:** `with_transport` must NOT construct a new `Arc<BroadcasterInner>`. It writes through `self.inner.transport.write()` and returns `self` (same `Arc`).

### Pitfall 4: `with_transport` async signature breaks the `offload_delta_broadcast.rs` tests

**What goes wrong:** The four `Broadcaster::new().with_transport(bus)` call sites in `offload_delta_broadcast.rs` are currently synchronous method calls in an `async fn`. After `with_transport` becomes `async`, omitting `.await` silently produces a `Future` that is immediately dropped — the transport is never attached and the test fails non-obviously.
**Why it happens:** Rust does not warn by default when a `Future` returned from an `async fn` is dropped without awaiting (it only warns when `#[must_use]` is applied).
**How to avoid:** Add `#[must_use = "with_transport is async; .await is required"]` to the method, or rely on the compiler: the return type mismatch (`Future<Output=Self>` where `Self` is expected) will produce a type error at the call sites, making the update mechanical. Either way, update all four call sites.

### Pitfall 5: `FailingTransport.subscribe_loop` drops `ready` — `with_transport` must degrade, not panic

**What goes wrong:** After the signature change, `with_transport` awaits `ready_rx`. If `FailingTransport` drops `ready_tx` without sending, `ready_rx.await` resolves `Err(RecvError)`. The D-02 contract says: log warn, return anyway. If the implementer accidentally panics or returns an error from `with_transport`, the `publish_error_does_not_propagate` test breaks.
**How to avoid:** The degradation path in `with_transport` must be `Err(_) => { warn!(...); self }`, not `?` or `unwrap()`.

## Code Examples

### Oneshot readiness signal — confirmed semantics

```rust
// Source: https://docs.rs/tokio/1.49.0/tokio/sync/oneshot/struct.Receiver.html
// When the Sender is dropped without sending, the Receiver resolves Err(RecvError).
use tokio::sync::oneshot;

let (tx, rx) = oneshot::channel::<()>();
drop(tx);
match rx.await {
    Ok(())  => { /* attached */ }
    Err(_)  => { /* sender dropped without firing — loop crashed before attach */ }
}
```

### Bounded wait in `with_transport` (D-02 timeout)

```rust
// Source: https://docs.rs/tokio/1.49.0/tokio/time/fn.timeout.html
use tokio::time::{timeout, Duration};
use tokio::sync::oneshot;

let (ready_tx, ready_rx) = oneshot::channel::<()>();
// ... spawn subscribe_loop(sink, ready_tx) ...
match timeout(Duration::from_secs(5), ready_rx).await {
    Ok(Ok(())) => { /* subscription established */ }
    Ok(Err(_)) => { warn!("transport subscribe_loop ended before signalling ready"); }
    Err(_)     => { warn!("timed out waiting for transport to attach"); }
}
// return self in all cases (D-06 / D-02 degradation)
```

### Interior-mutable transport read on async path (parking_lot pattern)

```rust
// Guard must not be held across .await; clone the Arc first.
async fn fan_out(&self, channel_name: &str, msg: &ServerMessage) {
    let transport = self.inner.transport.read().clone(); // RwLockReadGuard drops here
    let Some(t) = transport else { return; };
    if !matches!(msg, ServerMessage::Event(_)) { return; }
    let envelope = BusEnvelope { ... };
    if let Err(e) = t.publish(&envelope).await {

    }

```

### `with_transport` mutating in place (WR-03 fix shape)

```rust
pub async fn with_transport(
    self,
    transport: Arc<dyn BroadcastTransport + Send + Sync>,
) -> Self {
    // Mutate the shared inner — all existing clones observe the change.
    *self.inner.transport.write() = Some(transport.clone());

    // Spawn SUBSCRIBE loop with readiness signal.
    let (ready_tx, ready_rx) = tokio::sync::oneshot::channel::<()>();
    let (sink_tx, mut sink_rx) = tokio::sync::mpsc::channel::<BusEnvelope>(256);
    let loop_transport = transport.clone();
    tokio::spawn(async move {
        if let Err(e) = loop_transport.subscribe_loop(sink_tx, ready_tx).await {
            warn!(error = %e, "broadcast transport subscribe loop ended");
        }
    });

    // Delivery task (same as before, but sink_rx moved here).
    let deliver = self.clone();
    tokio::spawn(async move {
        while let Some(env) = sink_rx.recv().await {
            if env.origin == deliver.inner.origin_id { continue; }
            deliver.send_to_channel_local_only(&env.channel, &env.message).await;
        }
    });

    // Await readiness (D-02).
    match tokio::time::timeout(Duration::from_secs(5), ready_rx).await {
        Ok(Ok(())) => {}
        Ok(Err(_)) => { warn!("subscribe_loop ended before signalling ready — degraded"); }
        Err(_)     => { warn!("timed out waiting for transport attach — degraded"); }
    }
    self
}
```

### SC#1 determinism proof

The distinguishing property of the new SC#1 test (vs the existing `sc1_cross_process_delivery`) is that there is **no `sleep`**. The test publishes on replica A immediately after `Broadcaster::new().with_transport(bus).await` returns on replica B. If the readiness signal is removed or the `with_transport` does not await it, this test will timeout because the bus subscription is not yet active when publication occurs.

Structurally:

```rust
#[tokio::test]
async fn sc1_cross_process_delivery_no_sleep() {
    let bus = Arc::new(InMemoryTransport::new(64));
    let a = Broadcaster::with_config(Default::default()).with_transport(bus.clone()).await;
    let b = Broadcaster::with_config(Default::default()).with_transport(bus.clone()).await;
    // subscribe b's client BEFORE with_transport (tests SC#2); or after (tests SC#1 readiness)
    b.add_client("socket_b".into(), tx_b);
    b.subscribe("socket_b", "orders.1", None, None).await.unwrap();
    // No sleep. Publish immediately.
    a.broadcast("orders.1", "OrderUpdated", json!({"id": 1})).await.unwrap();
    // Must receive within a short hard timeout (100 ms is generous for in-memory).
    let msg = timeout(Duration::from_millis(100), rx_b.recv()).await
        .expect("timed out — lost-wakeup window not closed");
    // assert ...
}
```

Under the old `with_transport` (synchronous, timing-dependent), this test would timeout because the `rx.subscribe()` call inside the spawned task has not executed yet when `broadcast` fires.

### SC#2 pre-registration proof

```rust
#[tokio::test]
async fn sc2_pre_registered_survives_transport() {
    let bus = Arc::new(InMemoryTransport::new(64));
    // Register client and subscribe BEFORE with_transport.
    let b = Broadcaster::with_config(Default::default());  // no transport yet
    b.add_client("socket_b".into(), tx_b);
    b.subscribe("socket_b", "orders.1", None, None).await.unwrap();
    assert_eq!(b.client_count(), 1);

    // Install transport AFTER registration.
    let b = b.with_transport(bus.clone()).await;

    // State must be preserved.
    assert_eq!(b.client_count(), 1, "pre-registered client was dropped");

    // Cross-process delivery must still work.
    let a = Broadcaster::with_config(Default::default()).with_transport(bus).await;
    a.broadcast("orders.1", "OrderUpdated", json!({})).await.unwrap();
    let msg = timeout(Duration::from_millis(100), rx_b.recv()).await
        .expect("pre-registered client did not receive delta");
    assert!(matches!(msg.unwrap(), ServerMessage::Event(_)));
}
```

Under the old `with_transport`, `b.client_count()` after `with_transport` would be 0 (empty DashMap), and the `timeout` assertion would fail.

### Clone-divergence guard

```rust
#[tokio::test]
async fn sc2_clone_divergence_guard() {
    let bus = Arc::new(InMemoryTransport::new(64));
    let b = Broadcaster::with_config(Default::default());
    let b_clone = b.clone();  // clone before transport install

    // Install transport on original.
    let b = b.with_transport(bus.clone()).await;
    let a = Broadcaster::with_config(Default::default()).with_transport(bus).await;

    // Both b and b_clone must fan out (they share Arc<BroadcasterInner>).
    b_clone.add_client("socket_c".into(), tx_c);
    b_clone.subscribe("socket_c", "orders.2", None, None).await.unwrap();
    a.broadcast("orders.2", "Evt", json!({})).await.unwrap();
    let msg = timeout(Duration::from_millis(100), rx_c.recv()).await
        .expect("clone taken before with_transport did not observe installed transport");
    assert!(matches!(msg.unwrap(), ServerMessage::Event(_)));
}
```
