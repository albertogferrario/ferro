<authoritative_facts>
<!-- The facts the docs must state (from RESEARCH.md + PATTERNS.md). Do not invent; copy these. -->
- LiveFragment props: projection (string, ferro-projection NAME), key (string, per-key selector), template (object, child JSON-UI spec rendered against the snapshot as data scope).
- Container HTML: <div data-live-fragment data-channel="projection.{name}.{key}">...</div>; both channel segments HTML-escaped server-side (server-controlled, not user-injectable).
- Client runtime: opens ONE shared WebSocket to /_ferro/ws, subscribes per data-channel, swaps container innerHTML on a `fragment` event. No WASM, no client reactive state, no eval.
- First paint with no snapshot: container renders empty (child receives {}).
- Non-goal: no list/collection reconciliation (whole container HTML is replaced each delta); one binding pattern only.
- asset!("path") -> content-hashed &'static str URL; include_bytes! call-site-relative; lazy OnceLock register-once; MIME inferred from extension. App must mount ferro::bundle serving (ferro::bundle::serve) or the URL 404s.
- ferro assets fetch iconify | fontsource — downloads third-party assets at author time; NOT auto-wired into asset!() calls.
- #[memoize] (use ferro::memoize): request-scoped task-local dedup; runs body at most once per (callsite, args) per request; coalesces concurrent callers; errors cached; graceful no-op outside request scope; COMPLEMENTS eager_loading/BatchLoad; NOT cross-request (that stays ferro-cache).
</authoritative_facts>

```markdown
### LiveFragment

Binds a child template to a ferro-projection per-key snapshot and re-renders it in place when the projection emits a delta — server-authoritatively, without a page reload or client-side state.

| Prop | Type | Description |
|------|------|-------------|
| `projection` | `string` | ferro-projection NAME (the `Projection::NAME` const) |
| `key` | `string` | Per-key channel selector; combined with `projection` to form the subscription channel |
| `template` | `object` | Child JSON-UI spec rendered against the snapshot as its data scope |

```json
"live_stock": {
  "type": "LiveFragment",
  "props": {
    "projection": "inventory",
    "key": "warehouse-a",
    "template": {
      "$schema": "ferro-json-ui/v2",
      "root": "count",
      "elements": {
        "count": { "type": "Text", "props": { "content": { "$data": "/count" } } }
      }
    }
  }
}
```

When no snapshot exists for the key at first paint, the container renders empty (the child template receives `{}` as data). On each delta the client runtime swaps the container's `innerHTML`. One binding pattern is supported (a single per-key snapshot); there is no list or collection reconciliation — the whole container HTML is replaced on each delta.
```
The `"inventory"` / `"warehouse-a"` values are a sample; keep them inside the example block.
