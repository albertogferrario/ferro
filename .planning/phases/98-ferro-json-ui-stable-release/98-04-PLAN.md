Add tests to the existing `#[cfg(test)] mod tests` block in component.rs:

**Serde round-trip tests (1 per new component = 6 tests):**
For each of StatCard, Checklist, Toast, NotificationDropdown, Sidebar, Header:
1. Create a Component variant with representative props (including optional fields both present and absent)
2. Serialize to JSON string via `serde_json::to_string`
3. Assert JSON contains `"type":"StatCard"` (etc.)
4. Deserialize back from JSON string
5. Assert round-tripped value equals original

Example pattern:
```rust
#[test]
fn test_stat_card_serde_round_trip() {
    let component = Component::StatCard(StatCardProps {
        label: "Orders".into(),
        value: "42".into(),
        icon: Some("package".into()),
        subtitle: Some("today".into()),
        sse_target: Some("orders_today".into()),
    });
    let json = serde_json::to_string(&component).unwrap();
    assert!(json.contains("\"type\":\"StatCard\""));
    assert!(json.contains("\"sse_target\":\"orders_today\""));
    let deserialized: Component = serde_json::from_str(&json).unwrap();
    assert_eq!(component, deserialized);
}
```

**Convenience constructor tests (6 tests — one per new component):**
Test that each `ComponentNode::stat_card(key, props)` etc. produces the correct ComponentNode with action=None and visibility=None.

- SidebarGroup round-trip (collapsed true/false, with items)
- NotificationItem round-trip (read/unread, with/without action_url)

**Edge case tests (4 tests):**
- StatCard with all optionals None
- Checklist with empty items vec
- Sidebar with empty groups and empty fixed_top/fixed_bottom
- NotificationDropdown with empty notifications (should use empty_text)

**Optional field skip_serializing tests (2 tests):**
- Assert StatCard JSON omits `sse_target` key when None
- Assert Toast JSON omits `timeout` key when None

Total new tests in component.rs: ~21
