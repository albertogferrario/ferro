NOTE: This plan runs after Plan 02. Plan 02 added DashboardLayout to layout.rs, runtime.rs module to lib.rs, and DashboardLayout/DashboardLayoutConfig exports. All visibility decisions below account for Plan 02's additions.

**Step 1: Demote internal helpers in ferro-json-ui**

Make `pub(crate)` and remove from lib.rs `pub use`:
- `resolve_path`, `resolve_path_string` in data.rs — used only internally by render.rs
- `collect_plugin_types` in render.rs — render pipeline internal

Keep pub in their source files but remove from lib.rs top-level re-exports (framework accesses via crate path):
- `render_to_html_with_plugins` — stays pub in render.rs, stays in lib.rs re-export (framework/src/json_ui/mod.rs imports it as `ferro_json_ui::render_to_html_with_plugins`). Remove only from framework/src/lib.rs user-facing re-exports.
- `render_layout`, `register_layout` — stay pub in layout.rs, stay in lib.rs re-export (framework/src/json_ui/mod.rs uses them). Remove only from framework/src/lib.rs user-facing re-exports.

**Step 2: Demote layout internals**

In layout.rs, `AppLayout`, `AuthLayout`, `DefaultLayout` struct definitions stay pub (framework may reference them). Remove them from lib.rs top-level re-exports and from framework/src/lib.rs user-facing re-exports. Users interact with layouts by name string ("dashboard", "app", "auth"), not by struct.

Remove from lib.rs top-level re-exports and from framework/src/lib.rs:
- `navigation`, `sidebar`, `footer` layout partials — superseded by DashboardLayout
- `global_registry` — framework-internal

**Step 3: Update framework/src/lib.rs re-exports**

Remove from the `#[cfg(feature = "json-ui")] pub use ferro_json_ui::{...}` block:
- `resolve_path`, `resolve_path_string` (now pub(crate))
- `collect_plugin_types` (now pub(crate))
- `footer`, `navigation`, `sidebar` (layout partials — internal)
- `global_registry`, `register_layout`, `render_layout` (layout registry — internal)
- `AppLayout`, `AuthLayout`, `DefaultLayout` (layout structs — internal)
- `render_to_html` (users use `JsonUi::render`, not raw render)
- `render_to_html_with_plugins` (framework-internal, not user-facing)

Add to framework/src/lib.rs re-exports (new types from Plans 01 and 02):
- Plan 01: StatCardProps, ChecklistProps, ChecklistItem, ToastProps, ToastVariant, NotificationDropdownProps, NotificationItem, SidebarProps, SidebarNavItem, SidebarGroup, HeaderProps
- Plan 02: DashboardLayout, DashboardLayoutConfig

Keep in framework re-exports: all component types, Action types, Visibility types, JsonUiView, JsonUiConfig, LayoutContext, Layout, LayoutRegistry, ComponentNode, plugin types (JsonUiPlugin, PluginRegistry, Asset, register_plugin, etc.).

**Step 4: Remove serde_json re-export**

Remove `pub use serde_json;` from lib.rs.

**Step 5: Remove experimental disclaimer**

Update the lib.rs module doc comment: remove "**Experimental:** The component schema and plugin interface may evolve." Replace with stable API description.

**Step 6: Verify workspace compiles**

Run `cargo build --all` to verify ferro-projections and ferro-mcp still compile. ferro-mcp imports `ferro_json_ui::with_plugin` which stays pub.
