<objective>
Factor the framework boot path so `serve` and a new worker entry point share ONE bootstrap
control surface (`run_common_boot`), add the distinct-queue derivation the "all registered
queues" default needs (`Queue::registered_queue_names()`), and wire the WR-01 shared broadcast
transport from configuration at boot. This is the load-bearing plumbing plan: the CLI arm
(Plan 03) and the macro routing (Plan 02) build on the entry point and queue-set API produced
here.

Purpose: satisfy D-05 (serve consumes all queues), D-06/D-07 (framework-owned transport wiring
with a safe feature-off fallback), and expose `run_worker` for Plan 03 — all without forking
the boot logic (no-duplicate-control-surface).
Output: `ferro-queue/src/db.rs` gains `registered_queue_names()` + a `queue` field on
`JobRegistrarEntry`; `framework/src/app.rs` gains `run_common_boot` + `run_worker` + the WR-01
attach; `framework/src/lib.rs` re-exports `run_worker`; `app/src/bootstrap.rs` stops owning
transport wiring; `framework/tests/worker_boot.rs` D-07 scenario is un-stubbed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → framework boot | `BROADCAST_REDIS_URL`/`REDIS_URL` read from the process environment into `BroadcastConfig`, then used to open a Redis connection. Operator-controlled, not request-controlled. |
| framework → Redis | Outbound pub/sub connection established at boot when the feature and URL are present. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-248-01-01 | Denial of Service | `RedisTransport::connect` at boot | mitigate | Connect failure is caught (`Err` arm) → `tracing::warn!` + in-process-hub fallback; boot does not abort (D-07). No unbounded retry loop introduced. |
| T-248-01-02 | Information Disclosure | Redis URL (may embed credentials) in logs | mitigate | Warn logs `error = %e` and a static message; do NOT log the URL string. Verify the warn! args contain no `url`. |
| T-248-01-03 | Tampering | `App::singleton` re-registration of the transport-attached Broadcaster | accept | Overwrite is by `TypeId` and occurs before any WebSocket client connects (inside `run_common_boot`, before `Server::run()`) — verified ordering (RESEARCH WR-03). |
| T-248-01-04 | Elevation of Privilege | worker boot process model | accept | Worker runs under the same process model / same env-sourced credentials as `serve`; no new auth path (RESEARCH § Security Domain). |

No HIGH threats: this phase adds no auth/authz/sensitive-data path. Redis URL handling is confined
to boot-time connection with a non-fatal fallback; credentials are not logged.
</threat_model>
