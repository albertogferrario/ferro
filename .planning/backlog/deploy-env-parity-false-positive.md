# Bug: deploy_env_parity reports keys as missing that exist in .do/app.yaml

**Source:** gestiscilo-it field test, 2026-04-14
**Severity:** Low (warning only, exit code 0)
**ferro version:** 0.2.2

## Symptom

`ferro doctor` reports 45 keys "missing from .do/app.yaml" but all 45 keys are present in the file's global `envs:` block.

```
⚠ deploy_env_parity — 45 key(s) missing from .do/app.yaml
    missing: APP_NAME, APP_ENV, APP_DEBUG, APP_URL, ...
```

## Reproducer

```bash
cd gestiscilo-it/app
ferro doctor  # reports deploy_env_parity warning
grep "key: APP_NAME" .do/app.yaml  # key exists in the file
```

## Root cause (suspected)

The `deploy_env_parity` checker likely parses `envs:` blocks nested under individual `services:` entries but does not read the top-level global `envs:` block in `.do/app.yaml`. DigitalOcean App Platform supports both — global envs apply to all services/workers.

gestiscilo's `.do/app.yaml` uses the global `envs:` pattern (generated by `ferro do:init`), so the checker finds zero keys and reports all as missing.

## Expected behavior

The checker should read both global `envs:` and per-service `envs:` blocks, union the keys, and compare against `.env.example`.

## Impact

Noise only — the warning is non-blocking (exit code 0). But it makes `ferro doctor` output noisy and trains developers to ignore warnings.
