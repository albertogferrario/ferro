## Critical Gap (blocker)

**The default `serve` path does not execute `#[offload]` jobs for apps that use `#[offload]` exclusively.**

- `framework/src/app.rs:488` gates `spawn_in_process_worker()` on `has_registered_jobs()`.
- `ferro-queue/src/db.rs:76-77` — `has_registered_jobs()` checks only the runtime `JOB_REGISTRARS`
  Vec (populated by manual `Queue::register()`), NOT `inventory::iter::<JobRegistrarEntry>`.
- `#[offload]`-derived jobs register **only** through inventory. A pure-`#[offload]` app that never
  calls `Queue::register()` therefore returns `false` from the gate; the in-process worker is never
  spawned on `serve`; enqueued jobs sit unclaimed with no error.
- The sibling `registered_queue_names()` (db.rs:84-105, used *inside* `spawn_in_process_worker` and by
  the dedicated `worker` subcommand) **does** check inventory — the two "is work registered"
  predicates disagree, so the dedicated `worker` process is unaffected while the default `serve` is not.

**Fix (one line):**

```rust
pub fn has_registered_jobs() -> bool {
    !JOB_REGISTRARS.lock().unwrap().is_empty()
        || inventory::iter::<JobRegistrarEntry>.into_iter().next().is_some()
}
```
